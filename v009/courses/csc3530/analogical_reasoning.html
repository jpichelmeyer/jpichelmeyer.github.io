This is the lesson Hofstadter and Sander would call the core of cognition. An analogy maps the structure of one situation onto another so that knowledge about the first can be used in the second. Case-based reasoning reused solutions from similar problems in the same domain. Analogy reaches further, across domains, by matching relations rather than surface features. And every ARC task is an analogy: the test input is to its output as the train inputs are to theirs.

Part 1. Relations Over Attributes

The analogy process, as in Goel and Joyner's KBAI. Retrieval and storage are shared with case-based reasoning; mapping and transfer are what is new.

Dedre Gentner's structure-mapping theory (1983) makes three claims about which analogies people find good:

  • Relations, not attributes. The atom is like the solar system because the nucleus attracts the electron as the sun attracts the planet, not because either is yellow or hot.
  • One-to-one mapping. Each element of the source maps to at most one element of the target.
  • Systematicity. Prefer mappings that preserve connected systems of relations, especially higher-order relations like CAUSE. A matched causal structure licenses inferences; isolated matches do not.
Rutherford's analogy as structure mapping. Matching "attracts" and "more massive" fixes the mapping; the source's causal structure then predicts that the electron revolves around the nucleus. "Hotter" and "yellow" are not carried over.
Human cognition connection

Children undergo a relational shift (Gentner and colleagues): young children match by appearance (a round red ball is "like" an apple), and older children and adults match by relations (a cloud is "like" a sponge because both hold water). Douglas Hofstadter and Melanie Mitchell's Copycat program studied analogy in a tiny world of letter strings, the subject of this week's reading. Its point is that analogy depends on perception: before you can map abc→abd onto iijjkk, you have to see iijjkk as three groups. ARC is the same kind of world, in two dimensions and ten colours.

Copycat's classic puzzle. If abc changes to abd, what does iijjkk change to? Several answers are defensible; the preferred one depends on seeing "groups" and mapping "letter" to "group."

Part 2. A Structure-Mapping Agent

Facts are tuples; a higher-order fact (CAUSE) takes other facts as its arguments.

sme_agent.py: two domains Python
# Facts are tuples: (relation, arg, arg). Higher-order facts take facts as args. SOLAR = { ('more-massive', 'sun', 'planet'), ('attracts', 'sun', 'planet'), ('revolves-around', 'planet', 'sun'), ('hotter', 'sun', 'planet'), ('yellow', 'sun', None), ('cause', ('attracts', 'sun', 'planet'), ('revolves-around', 'planet', 'sun')), } ATOM = { ('more-massive', 'nucleus', 'electron'), ('attracts', 'nucleus', 'electron'), } def objects(domain): out = set() for f in domain: for a in f[1:]: if isinstance(a, tuple): out |= set(objects({a})) elif a is not None: out.add(a) return sorted(out)

The agent considers every one-to-one mapping of objects and scores each by the relations it preserves. Relations that sit inside a higher-order relation score double: that is systematicity. Single-object attributes like yellow do not score at all.

sme_agent.py: scoring mappings Python
def translate(fact, m): if fact is None or isinstance(fact, str): return m.get(fact, fact) return (fact[0],) + tuple(translate(a, m) for a in fact[1:]) def score(mapping, base, target): """Shared relations under the mapping. A matched relation counts 1; a relation that sits inside a higher-order relation counts extra, because systematic structure is what makes an analogy deep.""" s = 0 for f in base: if f[0] in ('yellow',): # attributes of single objects don't count continue if translate(f, mapping) in target: inside = any(isinstance(a, tuple) and a == f for g in base for a in g[1:]) s += 2 if inside else 1 return s def all_mappings(base, target): """Every one-to-one pairing of base objects with target objects.""" bo, to = objects(base), objects(target) for p in permutations(to, len(bo)): yield dict(zip(bo, p))

Once the mapping is chosen, candidate inferences are source facts in the matched causal structure that the target is missing.

sme_agent.py: transfer Python
def candidate_inferences(mapping, base, target): """Carry over base facts that belong to the matched causal structure but are missing in the target.""" out = [] for f in base: if f[0] == 'cause': cause, effect = f[1], f[2] if translate(cause, mapping) in target and translate(effect, mapping) not in target: out.append(translate(effect, mapping)) out.append(translate(f, mapping)) return out for m in all_mappings(SOLAR, ATOM): print('mapping', m, '-> score', score(m, SOLAR, ATOM)) m = max(all_mappings(SOLAR, ATOM), key=lambda m: score(m, SOLAR, ATOM)) for inf in candidate_inferences(m, SOLAR, ATOM): print('infer:', inf) print('not carried over:', translate(('hotter', 'sun', 'planet'), m), translate(('yellow', 'sun', None), m))
Shell output Output
mapping {'planet': 'electron', 'sun': 'nucleus'} -> score 3 mapping {'planet': 'nucleus', 'sun': 'electron'} -> score 0 infer: ('revolves-around', 'electron', 'nucleus') infer: ('cause', ('attracts', 'nucleus', 'electron'), ('revolves-around', 'electron', 'nucleus')) not carried over: ('hotter', 'nucleus', 'electron') ('yellow', 'nucleus', None)

A real structure-mapping engine (Falkenhainer, Forbus and Gentner, 1989) builds mappings incrementally instead of trying every permutation, which matters when domains have dozens of objects. The principle is the same.

Part 3. A Taste of ARC: Mapping Roles, Not Features

Two weeks ago, concept learning described which objects change by their attributes ("size = 6"), and it failed on aedd82e4 because an irrelevant attribute stuck. Analogy suggests a different description: by relations among the objects in the same grid. "The tallest bar" is a role defined relative to the other bars, and it can be mapped from a train grid to the test grid even if the tallest test bar has a height no train bar ever had. Task 08ed6ac7:

Task 08ed6ac7. Grey bars are coloured blue, red, green, yellow by height.
arc_analogy.py: relational roles Python
def ranks(objs, key): """Each object's rank on some measure (0 = smallest). Ties share a rank.""" values = sorted({key(o) for o in objs}) return [values.index(key(o)) for o in objs] RELATIONS = { 'rank by size': lambda o: o['size'], 'rank by height': lambda o: o['height'], 'rank by width': lambda o: o['width'], 'rank left-to-right': lambda o: o['left'], 'rank top-to-bottom': lambda o: o['top'], } def roles(grid, relation, reverse): objs = find_objects(grid, bg=0) r = ranks(objs, RELATIONS[relation]) if reverse and r: # count from the other end (0 = largest) top = max(r) r = [top - x for x in r] return objs, r
arc_analogy.py: map roles to outcomes, transfer to the test Python
def learn_mapping(task): """Find a relational role that maps consistently onto output colours: in every train pair, the object in role k becomes colour c_k.""" if any(dims(p['input']) != dims(p['output']) for p in task['train']): return None for relation in RELATIONS: for reverse in (True, False): table, ok = {}, True for p in task['train']: objs, r = roles(p['input'], relation, reverse) for o, k in zip(objs, r): out = {p['output'][y][x] for y, x in o['cells']} if len(out) != 1 or table.setdefault(k, min(out)) != min(out): ok = False if ok and table: return relation, reverse, table return None def transfer(mapping, grid): relation, reverse, table = mapping objs, r = roles(grid, relation, reverse) out = [row[:] for row in grid] for o, k in zip(objs, r): if k not in table: return None # a role the train pairs never showed for y, x in o['cells']: out[y][x] = table[k] return out if __name__ == '__main__': task = load_task('data/training/08ed6ac7.json') mapping = learn_mapping(task) print('08ed6ac7:', mapping[0], '(largest first)' if mapping[1] else '', '-> colours', mapping[2]) print('test correct:', transfer(mapping, task['test'][0]['input']) == task['test'][0]['output'])
Shell output Output
08ed6ac7: rank by size (largest first) -> colours {0: 1, 1: 2, 2: 3, 3: 4} test correct: True
The mapping the agent found: role (rank by size) to colour. The test bars have different heights, but their ranks map one-to-one onto the same colours.

This is Gentner's first claim at work in ARC: relational descriptions transfer, attribute descriptions overfit.

SAM lens

Analogy spans the agent. The Perceptor must produce relational descriptions (ranks, groups, "the one that differs"), or there is nothing to map. Mapping and transfer are the Decider. Evaluating candidate inferences is the Monitor's job, because analogies are suggestive, not guaranteed. Storing good mappings builds long-term Memory.
