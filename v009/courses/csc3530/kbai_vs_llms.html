Part 1. Two Traditions

A language model is trained to predict the next piece of text given everything before it. Trained at enormous scale, that single objective produces systems that write, translate, summarize, code, and answer questions across almost every domain. Since 2024, reasoning models also spend extra computation at answer time, generating long chains of intermediate steps before answering, which has improved them sharply on mathematics, programming, and ARC.

Knowledge-based AI makes the opposite bet. Represent knowledge explicitly (semantic networks, frames, rules, cases, scripts), reason over it with general methods (search, analogy, constraint propagation), and make every step inspectable. The McShane reading argues that this is still the right foundation for systems people must trust, with machine learning plugged in where it is strongest. Bennett's reading argues that LLMs, however fluent, lack an inner model of the world that they can simulate.

Human cognition connection

Which one is more like a person? Neither, quite. People learn language from far less data than an LLM, and can learn a new ARC rule from three examples, which looks like this course's agents. But people also have fast, intuitive pattern recognition that no hand-written rule set captures, which looks more like a neural network. Dual-process theories (Kahneman's System 1 and System 2) and the "reflexive vs deliberative" split in McShane's OntoAgent both suggest that a mind is a hybrid, and the interesting question is how the parts cooperate.

Part 2. Interpolating Versus Inducing

Here is a deliberately simple contrast. An n-gram model predicts the next number from how often each number followed the previous two in its training data. A rule inducer finds a constant difference and extrapolates. Real language models generalize far, far better than an n-gram model, so treat this as a cartoon. But the cartoon captures the question at the heart of the debate: does the system interpolate from what it has seen, or induce a rule it can apply anywhere?

ngram_vs_rules.py Python
# Pattern statistics versus rule induction on number sequences. from collections import Counter, defaultdict # --- corpus --- # "Training data": many sequences that count up by 2 or by 3, starting at 1-20. corpus = [] for start in range(1, 21): for step in (2, 3): corpus.append([start + step * i for i in range(6)]) # --- ngram --- # A statistical model: given the last two numbers, which number most often # came next in the training data? table = defaultdict(Counter) for seq in corpus: for a, b, c in zip(seq, seq[1:], seq[2:]): table[(a, b)][c] += 1 def ngram_next(seq): options = table.get(tuple(seq[-2:])) return options.most_common(1)[0][0] if options else None # --- rule --- # An induced rule: find the constant difference, check it, extrapolate. def rule_next(seq): d = seq[1] - seq[0] if all(b - a == d for a, b in zip(seq, seq[1:])): return seq[-1] + d return None # --- compare --- tests = {'seen pattern': [4, 6, 8, 10], 'beyond the data': [101, 103, 105, 107], 'a new step size': [5, 12, 19, 26]} for name, seq in tests.items(): print(f'{name:18} {seq} -> n-gram: {ngram_next(seq)}, rule: {rule_next(seq)}')
Shell output Output

The statistical model is perfect inside its training distribution and silent outside it. The rule extrapolates, but only for the one kind of rule it knows. Modern LLMs sit in between: they handle many novel sequences, and they still fail in ways that look like interpolation when a problem is far enough from anything they have seen. That is the bet Chollet made with ARC, and ARC-AGI-2 and -3 are attempts to keep the problems far enough away.

Part 3. A Taste of ARC: The Hybrid Loop

What does ARC look like to a language model? Text:

def to_text(grid): return '\n'.join(' '.join(str(v) for v in row) for row in grid) def build_prompt(task): """Serialize an ARC task as text, the way a language model must see it.""" parts = ['Each example maps an input grid to an output grid. Find the rule.', 'Answer with a Python function solve(grid) -> grid (grids are lists of lists of ints).', ''] for i, p in enumerate(task['train'], 1): parts += [f'Example {i} input:', to_text(p['input']), f'Example {i} output:', to_text(p['output']), ''] parts += ['Test input:', to_text(task['test'][0]['input'])] return '\n'.join(parts) task = load_task('data/training/b1948b0a.json') prompt = build_prompt(task) print(prompt[:320] + '\n...')

Notice what is lost. The grid's two-dimensional structure becomes a stream of numbers; "the cell below" is now dozens of tokens away. Objects, symmetry, and insideness, which your Perceptor computes directly, the model must reconstruct from a flat sequence. That is one reason LLMs found ARC so hard for so long.

The most successful approaches in 2024 combined the two traditions. A language model is asked for candidate programs, many of them, and a symbolic verifier, exactly like your agent's Monitor, runs each program on the train pairs and keeps only those that fit. Ryan Greenblatt reached about half of ARC-AGI-1's public evaluation set this way in 2024, sampling thousands of programs per task. The ARC Prize 2024 winners instead fine-tuned a model on each task's own train pairs at test time. Here is the verification half:

arc_hybrid.py: the symbolic verifier Python
# Pretend a language model proposed these three programs as text. CANDIDATES = [ "def solve(grid):\n return [[2 if v == 6 else v for v in row] for row in grid]", "def solve(grid):\n return [[2 for v in row] for row in grid]", "def solve(grid):\n return grid.transpose()", ] SAFE_BUILTINS = {'range': range, 'len': len, 'min': min, 'max': max, 'sum': sum, 'list': list, 'enumerate': enumerate, 'zip': zip, 'sorted': sorted} def verify(source, task): """The symbolic half: run the proposed program on every train pair and accept it only if all of them come out exactly right. (Restricting the builtins limits accidents; it is NOT a security sandbox.)""" env = {'__builtins__': SAFE_BUILTINS} try: exec(source, env) solve = env['solve'] return all(solve(p['input']) == p['output'] for p in task['train']), solve except Exception as e: return False, f'crashed: {type(e).__name__}' for k, src in enumerate(CANDIDATES, 1): ok, result = verify(src, task) status = 'accepted' if ok else ('rejected' if callable(result) else result) print(f'candidate {k}: {status}') if ok: print(' test correct:', result(task['test'][0]['input']) == task['test'][0]['output'])
Shell output Output
candidate 1: accepted test correct: True candidate 2: rejected candidate 3: crashed: AttributeError

The verifier does not care where a candidate came from. A generator that is broad but unreliable (a language model) and a tester that is narrow but exact (the train pairs) make a strong pair: generate and test from week 3, with a far smarter generator. To try the full loop, paste the printed prompt into any chatbot, paste back the function it writes, and verify it. You will quickly see where models do well (recolourings, flips) and where they flounder (counting, multi-step object manipulation).

Part 4. Where Things Stand, and the Debate

  • ARC-AGI-1 (2019) resisted AI for five years, then fell largely to reasoning models in late 2024, at high compute cost per task.
  • ARC-AGI-2 (2025) was built to resist brute force. The 2025 Kaggle competition was won with 24% under strict compute limits, and its top paper award went to a tiny recursive network (Jolicoeur-Martineau, "Less is More"), not a giant model. The best frontier systems passed 50% by the end of 2025.
  • ARC-AGI-3 (2026) is interactive: explore, discover the goal, build a model, plan, and learn from mistakes. At launch, frontier AI scored under 1% while people could beat every game. Its skills are Module 3 of this course.

SAM lens

In SAM terms, an LLM is a Decider with a vast, implicit long-term Memory and no explicit Monitor: nothing inside it checks an answer against the evidence unless you add one. The hybrid loop adds that Monitor back. Your semester agent has every unit explicit, which is what makes it explainable, and also what limits it to what you had time to build.
