Recording cases answers new problems by copying old answers. Case-based reasoning (CBR) goes one step further: it retrieves an old solution and then adapts it to fit the new problem, checks the result, and stores the new case for next time. Roger Schank built the idea out of a theory of human memory: we understand and solve new situations by being reminded of old ones. Much of everyday expertise (a doctor recognizing a presentation, a mechanic recognizing a noise) looks more like this than like reasoning from first principles.

Part 1. The CBR Cycle

The case-based reasoning cycle (often summarized as retrieve, reuse, revise, retain). Every solved problem enlarges the library, so the agent gets faster with experience.

Each step hides a real design question:

  • Retrieval: what counts as similar, and how do you find similar cases quickly in a large library? Cases are usually indexed by the features that matter for solving them, not by every feature they have.
  • Adaptation: how do you change an old solution? Common methods are tweaking parameters, substituting one part for a related part, and patching the ends with a little search (the method used below).
  • Evaluation: by simulation, by testing, or by asking an expert. If the adapted solution fails, adapt again or retrieve the next case.
  • Storage: store everything, or only cases that teach something new?
Human cognition connection

People are good at using a case once they have it, and surprisingly bad at retrieving the right one. Mary Gick and Keith Holyoak (1980) gave people a story about a general who captures a fortress by splitting his army into small groups that converge from all sides. Then they posed Duncker's radiation problem: how can a doctor destroy a tumour with rays that would harm healthy tissue at full strength? The solution is the same: many weak rays converging. Most people did not think to use the story until told it might help; once told, most solved it. Retrieval runs on surface features (armies, fortresses), while usefulness depends on deep structure. This week's Hofstadter reading argues that good encodings capture both, which is why "reminding" can work across years and continents.

Part 2. A CBR Agent for Routes

The agent plans walking routes through a small town. Finding a route from scratch means a breadth-first search. With CBR, it retrieves the stored route whose endpoints are nearest the new ones, and adapts it by searching only for short legs at each end.

The town map used by the route agent.
route_cbr.py: the town and route search from scratch Python
TOWN = ['.....#....', '.###.#.##.', '.#.......#', '.#.##.##..', '....#.....', '.##...###.', '..........'] def streets(cell): r, c = cell for dr, dc in [(1, 0), (-1, 0), (0, 1), (0, -1)]: nr, nc = r + dr, c + dc if 0 <= nr < len(TOWN) and 0 <= nc < len(TOWN[0]) and TOWN[nr][nc] == '.': yield nr, nc def bfs(a, b): """From-scratch route finding (expensive): breadth-first search.""" prev, q = {a: None}, deque([a]) while q: x = q.popleft() if x == b: path = [] while x: path.append(x) x = prev[x] return path[::-1], len(prev) for n in streets(x): if n not in prev: prev[n] = x q.append(n) return None, len(prev)
route_cbr.py: retrieve, adapt, evaluate, store Python
LIBRARY = [] # cases: (start, goal, route) def dist(a, b): return abs(a[0] - b[0]) + abs(a[1] - b[1]) def retrieve(start, goal): return min(LIBRARY, key=lambda case: dist(start, case[0]) + dist(goal, case[1])) def adapt(case, start, goal): """Reuse the old route; patch on short searched legs at each end.""" head, n1 = bfs(start, case[0]) tail, n2 = bfs(case[1], goal) return head[:-1] + case[2] + tail[1:], n1 + n2 def evaluate(route, start, goal): """Is it a real route, and not absurdly longer than a straight shot?""" ok = route[0] == start and route[-1] == goal and \ all(b in streets(a) for a, b in zip(route, route[1:])) return ok and len(route) - 1 <= dist(start, goal) + 6 def solve(start, goal): if LIBRARY: case = retrieve(start, goal) route, effort = adapt(case, start, goal) if evaluate(route, start, goal): print(f' {start}->{goal}: adapted the case {case[0]}->{case[1]}, ' f'{len(route) - 1} steps, {effort} cells searched') LIBRARY.append((start, goal, route)) # store return route print(f' {start}->{goal}: adapted route has {len(route) - 1} steps: rejected') route, effort = bfs(start, goal) print(f' {start}->{goal}: solved from scratch, {len(route) - 1} steps, {effort} cells searched') LIBRARY.append((start, goal, route)) return route

for trip in [((0, 0), (6, 9)), ((0, 1), (6, 8)), ((1, 0), (5, 9)), ((6, 0), (0, 9))]: solve(*trip) print('cases stored:', len(LIBRARY))
Shell output Output
(0, 0)->(6, 9): solved from scratch, 15 steps, 50 cells searched (0, 1)->(6, 8): adapted the case (0, 0)->(6, 9), 17 steps, 8 cells searched (1, 0)->(5, 9): adapted the case (0, 0)->(6, 9), 17 steps, 7 cells searched (6, 0)->(0, 9): adapted route has 33 steps: rejected (6, 0)->(0, 9): solved from scratch, 15 steps, 49 cells searched cases stored: 4

The first trip has nothing to be reminded of, so it is solved from scratch (50 cells searched). The next two reuse it and search only 7 or 8 cells, at the cost of routes slightly longer than optimal. The fourth trip goes the other way across town; the nearest case adapts into a 33-step detour, evaluation rejects it, and the agent falls back on search. Evaluation is what keeps a case-based reasoner from confidently reusing the wrong experience.

Part 3. A Taste of ARC: Being Reminded of Old Tasks

Your agent will solve tasks all semester. Each solved task is a case: the task, plus the program that solved it. When a new task arrives, the agent can index it by a few features a person notices first, retrieve the most similar solved tasks, and adapt their programs by substituting related primitives (a horizontal flip for a vertical one, doubling the width for doubling the height).

arc_cbr.py: a small case library Python
# Cases recorded from tasks solved earlier: (training task, program that solved it) LIBRARY = [('a416b8f3', ('double_w',)), ('3af2c5a8', ('mirror_w', 'mirror_h')), ('67a3c6ac', ('flip_h',)), ('74dd1130', ('transpose',)), ('c59eb873', ('scale2',)), ('9172f3a0', ('scale3',)), ('1cf80156', ('crop_all',)), ('be94b721', ('largest',)), ('1e0a9b12', ('gravity',)), ('28bf18c6', ('crop_all', 'double_w')), ('7468f01a', ('flip_h', 'crop_all')), ('6d0aefbc', ('mirror_w',)), ('496994bd', ('top_half', 'mirror_h')), ('3c9b0459', ('rot180',))]
arc_cbr.py: indexing features Python
def features(task): """How a task is indexed: the things a person notices first.""" p = task['train'][0] hi, wi = dims(p['input']) ho, wo = dims(p['output']) return {'same_size': (hi, wi) == (ho, wo), 'ratio': (round(ho / hi, 2), round(wo / wi, 2)), 'shrinks': ho * wo < hi * wi, 'new_colors': bool(colors(p['output']) - colors(p['input'])), 'square_in': hi == wi} def similarity(f1, f2): return sum(f1[k] == f2[k] for k in f1)
Cases indexed by features. A new task that keeps its size and adds no colours is retrieved alongside the flips and rotations, not the crops.
arc_cbr.py: adaptation by substitution Python
RELATED = {'flip_h': ['flip_v', 'transpose'], 'flip_v': ['flip_h'], 'rot90': ['rot270', 'rot180'], 'rot270': ['rot90'], 'rot180': ['rot90', 'rot270', 'flip_h', 'flip_v'], 'double_w': ['double_h', 'mirror_w'], 'double_h': ['double_w', 'mirror_h'], 'mirror_w': ['mirror_h', 'double_w'], 'mirror_h': ['mirror_w', 'double_h'], 'scale2': ['scale3'], 'scale3': ['scale2'], 'largest': ['smallest', 'crop_all'], 'smallest': ['largest'], 'crop_all': ['largest'], 'top_half': ['left_half'], 'left_half': ['top_half'], 'transpose': ['rot90', 'rot270'], 'gravity': []} def adaptations(prog): """The old program first, then every one-step substitution.""" yield prog for i, step in enumerate(prog): for alt in RELATED.get(step, []): yield prog[:i] + (alt,) + prog[i + 1:] def fits(prog, task): try: return all(run(prog, p['input']) == p['output'] for p in task['train']) except Exception: return False
arc_cbr.py: the CBR loop Python
def cbr(task, k=3): """Retrieve the k most similar cases, adapt, evaluate on the train pairs.""" f = features(task) ranked = sorted(LIBRARY, key=lambda c: -similarity(f, features(CASE_TASKS[c[0]]))) tried = 0 for case_id, prog in ranked[:k]: for candidate in adaptations(prog): tried += 1 if fits(candidate, task): return case_id, candidate, tried return None, None, tried CASE_TASKS = {cid: load_task(f'data/training/{cid}.json') for cid, _ in LIBRARY}
arc_cbr.py: try it on tasks the library has never seen Python
if __name__ == '__main__': for split in ['training', 'evaluation']: solved, tried_total = [], 0 for name in sorted(os.listdir('data/' + split)): tid = name[:-5] if tid in CASE_TASKS: continue # don't test on the library task = load_task(f'data/{split}/{name}') case_id, prog, tried = cbr(task) tried_total += tried if prog and all(run(prog, t['input']) == t['output'] for t in task['test']): solved.append((tid, case_id, prog)) LIBRARY.append((tid, prog)) # store the new case CASE_TASKS[tid] = task print(f'{split}: solved {len(solved)}, trying {tried_total} programs in all') for tid, case_id, prog in solved: print(f' {tid}: reminded of {case_id} -> {" then ".join(prog)}')

On unseen training tasks, fourteen cases plus substitution solve six more, trying about eight programs per task (week 3's blind search needed around 16,600 full checks across the training set). Look at 67e8384a: it was reminded of 62c24649, a case the agent had stored only moments before.

The evaluation set tells a humbler story: one task. The evaluation tasks are harder and less like the training tasks, so there is less to be reminded of. Blind program search also solves exactly one evaluation task. CBR is only as good as the library and the index, and a library of fourteen flips and crops will not go far. That is a real lesson about expertise: it is broad because the case library is enormous.

SAM lens

CBR is the first full loop through every SAM unit at once: the Perceptor computes the index features, long-term episodic Memory holds the cases, the Decider adapts, the Monitor evaluates on the train pairs, and the learning arrow stores the result.

Discuss

  3. Should an agent store every solved case, or only surprising ones? What would each policy do to the library over a whole semester?
