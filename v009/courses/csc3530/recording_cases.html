Module 2 is about memory and analogy. It starts with the simplest kind of learning there is: remember what happened, and when something new comes along, find the most similar thing you remember and assume the same outcome. No rules, no generalization, just a growing library of cases. The method is simple, often surprisingly good, and it raises the question that runs through the whole module: what does "similar" mean?

Part 1. Cases, Similarity, and Recall

A case is a recorded experience: a description of a situation and what happened (or what worked). Learning by recording cases stores each one as it comes. Using them means three things:

  • A representation for situations, so that two cases can be compared. Here, a block's width and height.
  • A similarity measure. The simplest is distance in feature space; with more than one neighbour (k-nearest neighbours), the neighbours vote.
  • A retrieval method: find the closest stored case. With a few cases, check them all; with millions, you need an index (next lesson).
Eight recorded blocks, coloured by outcome. The new block (white square) is nearest the orange case at (3, 3). The purple borderline block has a red case nearest, but two orange cases close behind: with k = 3, orange wins the vote.
Human cognition connection

One major theory of human categorization says people do exactly this. The exemplar theory (Medin and Schaffer, 1978; Nosofsky's Generalized Context Model, 1986) holds that a category is nothing more than the stored memories of its members, and a new item is classified by its summed similarity to them. The rival prototype theory says people store an average or ideal instead. Both fit many experiments, and the evidence suggests people use both. This week's Hofstadter reading shows the strange power of human case memory: a father watching a friend pick up bottle caps by an Egyptian temple is instantly reminded of his toddler playing with ants at the Grand Canyon fifteen years before. Whatever was recorded, it was not the surface details.

blocks_cases.py: recall by nearest neighbour Python
def distance(a, b): return math.dist(a, b) # straight-line distance def nearest(query, cases, k=1): ranked = sorted(cases, key=lambda case: distance(query, case[0])) return ranked[:k] def classify(query, cases, k=1): near = nearest(query, cases, k) votes = {} for _, label in near: votes[label] = votes.get(label, 0) + 1 return max(votes, key=votes.get), near
blocks_cases.py: classify some new blocks Python
for q in [(1.2, 1.1), (4.5, 1.2), (2.6, 2.9), (2.5, 4.0)]: label, near = classify(q, CASES) print(f'block {q}: nearest case {near[0][0]} -> {label}')

With one neighbour the answer can hang on a single nearby case. Asking several neighbours to vote is more robust, but it changes answers near the boundaries:

blocks_cases.py: one neighbour or three? Python
print('a borderline block with k = 1 and k = 3:') for k in (1, 3): label, near = classify((2.2, 2.2), CASES, k) print(f' k={k}: {label} from {[c[1] for c in near]}')
blocks_cases.py: learning is just recording Python
CASES.append(((2.2, 2.2), 'red')) # a teacher says it was red print('after recording the correction:', classify((2.3, 2.1), CASES)[0])
Shell output Output
a borderline block with k = 1 and k = 3: k=1: red from ['red'] k=3: orange from ['red', 'orange', 'orange'] after recording the correction: red

Learning is a single line: append a case. That is the method's great strength (learning is instant, and nothing is ever forgotten or overgeneralized) and its weakness (it never extracts a rule, so every answer depends on how good the similarity measure is, and on whether width and height were even the right features).

Part 3. A Taste of ARC: A Memory of Patches

Within a single ARC task, the train pairs are a small set of recorded experiences. One way to record them: for every cell, store its 3×3 input neighbourhood as the situation and the colour that cell had in the output as the outcome. To answer the test, look up each test cell's neighbourhood in memory.

Task a699fb00. A red cell appears between two blue cells that are one apart horizontally.
One recorded case from train pair 1: this neighbourhood, centred between two blue cells, had a red centre in the output.
arc_patch_cases.py: recording Python
def patch(grid, r, c): """The 3x3 neighbourhood around a cell, as a tuple (-1 = off the grid).""" h, w = dims(grid) return tuple(grid[y][x] if 0 <= y < h and 0 <= x < w else -1 for y in (r - 1, r, r + 1) for x in (c - 1, c, c + 1)) def record(task): """Case library: every 3x3 input patch seen in training, with the output colour of its centre cell. Fails if outputs differ in size from inputs.""" library = {} for pair in task['train']: inp, out = pair['input'], pair['output'] if dims(inp) != dims(out): return None for r in range(len(inp)): for c in range(len(inp[0])): library.setdefault(patch(inp, r, c), []).append(out[r][c]) return library

When a test neighbourhood is not in memory exactly, the agent has a choice to make. It can trust the nearest recorded case however different it is, trust it only if it is very close, or ignore memory and leave the cell alone.

arc_patch_cases.py: recall with a similarity threshold Python
def recall(library, grid, max_diff): """Answer each cell from memory. Use the exact patch if it was recorded; otherwise the most similar recorded patch, but only if it differs in at most max_diff of its 9 cells; otherwise just keep the cell's colour.""" out = [] for r in range(len(grid)): row = [] for c in range(len(grid[0])): key = patch(grid, r, c) best = key if key in library else min( library, key=lambda k: sum(a != b for a, b in zip(k, key))) diff = sum(a != b for a, b in zip(best, key)) if diff <= max_diff: votes = library[best] row.append(max(set(votes), key=votes.count)) else: row.append(grid[r][c]) out.append(row) return out

Each policy solves six or seven tasks, but not the same ones: eleven different tasks in all. Strict recall wins when unfamiliar cells should simply be left alone; loose recall wins when the rule really does generalize to slightly different neighbourhoods. No single threshold is best. Deciding how far to trust a memory, task by task, is a metacognitive judgment, and Module 3 returns to it.

SAM lens

The case library is long-term episodic memory. Recording is the learning arrow; retrieval is a Decider that answers by recall instead of reasoning. The similarity threshold is a policy the Monitor should eventually set. Across tasks, your agent should also record which methods solved which tasks: that is next week's raw material.

Discuss
  1. The block agent used width and height. What would go wrong if one feature were measured in millimetres and the other in metres? How do people avoid that problem?
  2. Exemplar or prototype: when you recognize a new ARC task as "one of those gravity ones," which are you using?
  3. Hofstadter calls the Grand Canyon memory a "canonical reminding." What features would the father's memory need to have stored for that reminding to happen? Could an agent store them?
