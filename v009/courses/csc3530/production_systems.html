A production system is a set of condition-action rules, IF this situation THEN do that, plus a working memory of facts and a loop that keeps choosing a rule to fire. It is the oldest serious theory of how human problem solving works (Allen Newell and Herbert Simon, 1972), the engine inside the Soar and ACT-R cognitive architectures, and a surprisingly effective way to describe many ARC transformations.

Part 1. Rules, Working Memory, and the Recognize-Act Cycle

A production rule has a left-hand side (conditions that must be in working memory) and a right-hand side (actions: add or remove facts, or do something in the world). The system runs in a cycle:

The recognize-act cycle. Match every rule against working memory; collect the ones that match (the conflict set); resolve the conflict by choosing one; act; repeat. Acting changes working memory, so different rules match next time.

The resolution step matters more than it looks. When several rules match, the agent needs a principled way to choose. Common strategies are fixed priority, specificity (a rule with more conditions is about a more particular situation, so it wins), recency (prefer rules matching the newest facts), and refraction (never fire the same rule on the same facts twice). This week's Bennett reading shows a nematode doing conflict resolution with inhibitory neurons: "you can go in only one direction at a time."

Human cognition connection

Newell and Simon recorded people thinking aloud while solving puzzles and found they could model each person's moves as a small set of production rules. Rules also explain skill learning. In Soar, every time the system solves a subproblem it saves the solution as a new rule, a chunk. Newell and Rosenbloom (1981) showed that chunking naturally produces the power law of practice: the time to do a task falls as a power function of the number of times you have done it, a pattern found in people learning everything from typing to cigar rolling.

Part 2. A Soar-Style Agent: Proposals, Impasses, and Chunking

Soar treats every decision as choosing an operator. Rules first propose operators. If exactly one is proposed, or if preference knowledge picks among them, the agent applies it. If not, the agent is at an impasse, and it sets up a subgoal to resolve the impasse with whatever other knowledge it has. When the subgoal succeeds, Soar compiles the result into a new rule (a chunk), so the same impasse never happens again.

Soar's decision cycle with impasses and chunking, simplified.

Our example (after Goel and Joyner's KBAI course) is a baseball pitcher deciding what to throw. First, a pattern matcher. Variables start with ?, and ('not', pattern) means the pattern must be absent:

pitcher_agent.py: pattern matching Python
def match(patterns, wm, bindings=None): """Yield every set of variable bindings under which all patterns are in working memory. Variables start with '?'. ('not', p) means p is absent.""" bindings = bindings or {} if not patterns: yield bindings return first, rest = patterns[0], patterns[1:] if first[0] == 'not': if not any(True for _ in match([first[1]], wm, bindings)): yield from match(rest, wm, bindings) return for fact in wm: if len(fact) != len(first): continue b = dict(bindings) for p, f in zip(first, fact): if isinstance(p, str) and p.startswith('?'): if b.setdefault(p, f) != f: break elif p != f: break else: yield from match(rest, wm, b)
pitcher_agent.py: proposal rules Python
# Each rule: name, IF patterns, THEN a proposed operator (may use variables) RULES = [ ('throw-strikes', [('count', 'balls', 3)], 'fastball'), ('fool-a-lefty', [('batter', 'left')], 'curveball'), ('walk-a-slugger', [('batter-skill', 'strong'), ('base', 'first', 'empty'), ('outs', '?n')], 'intentional-walk'), ('hold-runner', [('base', '?b', 'runner'), ('not', ('base', 'first', 'empty'))], 'pickoff'), ] def propose(wm, rules): """Elaboration phase: fire every matching rule, collect proposals.""" proposals = {} for name, conds, op in rules: for b in match(conds, wm): proposals.setdefault(op, []).append(name) break return proposals

The hold-runner rule shows a negative condition: it proposes a pickoff only if first base is not empty. The decision procedure tries learned preferences first. If none applies and the proposals tie, it falls into an impasse, consults episodic memory, and chunks:

pitcher_agent.py: deciding, impasses, chunking Python
EPISODES = [ # long-term episodic memory: what worked before ({('batter', 'left'), ('count', 'balls', 3), ('batter-skill', 'strong')}, 'intentional-walk'), ({('batter', 'right'), ('count', 'balls', 3)}, 'fastball'), ] PREFERENCES = [] # preference rules: IF patterns THEN prefer an operator def decide(wm): proposals = propose(wm, RULES) print(' proposals:', proposals) if len(proposals) == 1: return next(iter(proposals)) for name, conds, op in PREFERENCES: # does a learned rule break the tie? if op in proposals and any(True for _ in match(conds, wm)): print(f' tie broken by {name}') return op # IMPASSE: several operators, no knowledge to choose between them. print(' impasse! consulting episodic memory') best = max(EPISODES, key=lambda ep: len(ep[0] & wm)) choice = best[1] if best[1] in proposals else sorted(proposals)[0] # CHUNKING: save how the impasse was resolved as a new preference rule, # so this situation never causes an impasse again. chunk = ('chunk-1', sorted(best[0] & wm), choice) PREFERENCES.append(chunk) print(' learned', chunk) return choice
pitcher_agent.py: two identical at-bats Python
situation = {('batter', 'left'), ('batter-skill', 'strong'), ('count', 'balls', 3), ('outs', 2), ('base', 'first', 'empty'), ('base', 'second', 'runner')} for at_bat in (1, 2): print(f'at-bat {at_bat}:') print(' pitch:', decide(situation))

The second at-bat is the same situation, and the same three rules fire, but the learned preference breaks the tie at once. The agent went from deliberating to recognizing. That shift is what skill acquisition feels like from the inside.

Part 3. A Taste of ARC: Inducing Local Rules

Many ARC tasks are naturally described by local production rules. In 0ca9ddb6 (from the ARC-AGI lesson) a person might say: IF a cell is red THEN its diagonal neighbours become yellow; IF a cell is blue THEN its side neighbours become orange.

The two rules of 0ca9ddb6 drawn as before-and-after stencils.

Instead of writing those rules by hand, the agent can induce them. For every coloured cell in every train input, record what the output holds at each of the nine neighbouring positions. A candidate rule colour c → position (dy, dx) becomes k survives only if it was true every single time its condition occurred. One counterexample kills it.

arc_rules.py: inducing rules from the train pairs Python
def induce_rules(task): """Propose rules IF a cell has colour c THEN the cell at offset (dy, dx) becomes colour k. Keep a rule only if it holds every time its condition occurs in every train pair (no counterexamples).""" seen = {} # (c, dy, dx) -> set of k for pair in task['train']: inp, out = pair['input'], pair['output'] if dims(inp) != dims(out): return None bg = background(inp) h, w = dims(inp) for r in range(h): for c in range(w): col = inp[r][c] if col == bg: continue for dy, dx in OFFSETS: y, x = r + dy, c + dx if 0 <= y < h and 0 <= x < w and (inp[y][x] == bg or (dy, dx) == (0, 0)): seen.setdefault((col, dy, dx), set()).add(out[y][x]) rules = [] for (col, dy, dx), ks in seen.items(): if len(ks) == 1: k = ks.pop() unchanged = (k == col) if (dy, dx) == (0, 0) else (k == bg) if not unchanged: # only rules that DO something rules.append((col, dy, dx, k)) return rules
arc_rules.py: firing the rules Python
def fire(rules, grid): """Production cycle: every rule whose condition matches fires once. Conflict resolution: rules about the cell itself fire last (they win).""" bg = background(grid) h, w = dims(grid) out = [row[:] for row in grid] for col, dy, dx, k in sorted(rules, key=lambda r: (r[1], r[2]) == (0, 0)): for r in range(h): for c in range(w): y, x = r + dy, c + dx if grid[r][c] == col and 0 <= y < h and 0 <= x < w: if grid[y][x] == bg or (dy, dx) == (0, 0): out[y][x] = k return out
arc_rules.py: try it Python
if __name__ == '__main__': from arc_utils import COLOR_NAMES as N task = load_task('data/training/0ca9ddb6.json') rules = induce_rules(task) for col, dy, dx, k in sorted(rules): print(f'IF cell is {N[col]:6} THEN cell at ({dy:+d},{dx:+d}) := {N[k]}') ok = all(fire(rules, p['input']) == p['output'] for p in task['train']) print('fits train:', ok, '| test correct:', fire(rules, task['test'][0]['input']) == task['test'][0]['output'])

Richer conditions (matching on objects and relations from your semantic network) are the obvious next step.

SAM lens

Production rules are long-term procedural memory. The match-resolve-act cycle is a Decider. Conflict resolution and impasse detection are early forms of the Monitor. Chunking is the learning arrow from Decider back to Memory.
