Recording cases never generalizes; it just remembers. Most of the time we want more: from a handful of examples, a concept that applies to examples we have never seen. Incremental concept learning builds that concept one example at a time, generalizing when a new positive example does not fit and specializing when a negative example fits too well. It is how a toddler grows a category from one member, and how your agent can learn which objects a rule applies to.

Part 1. Generalize on Positives, Specialize on Near Misses

Patrick Winston's 1970 program learned the concept arch from a short, carefully ordered sequence of examples. It starts with the full description of the first example as its concept (as specific as possible) and adjusts:

Teaching "arch." Each example changes the concept in one specific way. The negative examples are near misses: they differ from an arch in exactly one important respect, so the learner knows what to blame.
Winston's learning heuristics. Positives push the concept toward general; near misses push it toward specific.

Two ideas make this work. First, background knowledge: climb-tree needs to know that bricks and wedges are both blocks. Second, a cooperative teacher who orders examples sensibly and chooses near misses that differ in just one way. With a random stream of examples, a learner cannot tell which of many differences made an example negative.

Human cognition connection

Children's word learning shows both directions. They overextend ("doggie" for every four-legged animal), then specialize as they meet near misses ("no, that's a cow"). They underextend ("bird" only for the sparrows at the feeder, not for penguins), then generalize. This week's Hofstadter reading follows a toddler, Tim, whose category mommy starts with exactly one member, his own Mommy, and grows by superimposing new examples until it covers other children's mothers. The McShane reading shows a working agent doing the same with stop signs, refining a learned width as each new example arrives.

ISA = {'brick': 'block', 'wedge': 'block', 'cylinder': 'block', 'block': 'thing'} def climb(a, b): """Lowest common ancestor of two classes in the is-a tree.""" chain = [a] while chain[-1] in ISA: chain.append(ISA[chain[-1]]) while b not in chain: b = ISA[b] return b def is_a(x, y): while x != y and x in ISA: x = ISA[x] return x == y

arch_agent.py: the learner Python
class Concept: def __init__(self, first): self.types = dict(first['types']) self.colors = {p: {c} for p, c in first['colors'].items()} self.relations = set(first['relations']) # may be dropped later self.must, self.must_not = set(), set() def covers(self, ex): return (all(is_a(ex['types'][p], t) for p, t in self.types.items()) and all(ex['colors'][p] in cs for p, cs in self.colors.items()) and self.must <= ex['relations'] and not (self.must_not & ex['relations'])) def positive(self, ex): for p, t in self.types.items(): # climb-tree if not is_a(ex['types'][p], t): self.types[p] = climb(t, ex['types'][p]) print(f' climb-tree: {p} can be any {self.types[p]}') for p, cs in self.colors.items(): # enlarge-set if ex['colors'][p] not in cs: cs.add(ex['colors'][p]) print(f' enlarge-set: {p} colour in {sorted(cs)}') for r in self.relations - ex['relations'] - self.must: # drop-link self.relations.discard(r) print(f' drop-link: {r} is not needed') def negative(self, ex): for r in self.relations - ex['relations']: # require-link self.must.add(r) print(f' require-link: must have {r}') for r in ex['relations'] - self.relations: # forbid-link self.must_not.add(r) print(f' forbid-link: must not have {r}')
arch_agent.py: a teaching sequence Python
lessons = [ ('+', scene('brick', 'red', False, True), 'an arch'), ('-', scene('brick', 'red', True, True), 'posts touch: not an arch'), ('-', scene('brick', 'red', False, False), 'top lies beside the posts: not an arch'), ('+', scene('wedge', 'red', False, True), 'a wedge on top is still an arch'), ('+', scene('brick', 'blue', False, True), 'a blue top is still an arch'), ] concept = None for sign, ex, note in lessons: print(f'{sign} {note}') if concept is None: concept = Concept(ex) elif sign == '+': concept.positive(ex) else: concept.negative(ex) print('test: cylinder top, green, posts apart ->', concept.covers(scene('cylinder', 'green', False, True))) print('test: cylinder top, blue, posts apart ->', concept.covers(scene('cylinder', 'blue', False, True)))
Shell output Output

The last two lines are worth a moment. A cylinder top is accepted because climb-tree generalized wedge or brick to any block. A green top is rejected, because the learner has only seen red and blue tops and enlarge-set is cautious. Is that a bug? It is the learner refusing to generalize beyond its evidence. People would probably accept green, because they bring a belief that colour rarely matters for structures. That belief is more background knowledge, and the learner does not have it.

Part 3. A Taste of ARC: Which Objects Get Changed?

A very common ARC pattern: some objects are recoloured and others are not, and the solver must work out which. That is concept learning. Each object in each train input is an example, labelled by the colour it has in the output. Task d2abd087:

Task d2abd087. Grey shapes become red or blue. What decides it?
arc_icl.py: object features Python
BG = {'black': lambda g: 0 if any(0 in row for row in g) else background(g), 'majority': background} # two theories of what the background is def features(obj, grid): h, w = dims(grid) solid = obj['size'] == obj['height'] * obj['width'] return {'color': obj['color'], 'size': obj['size'], 'single_cell': obj['size'] == 1, 'height': obj['height'], 'width': obj['width'], 'solid_rectangle': solid, 'touches_edge': obj['top'] == 0 or obj['left'] == 0 or obj['bottom'] == h - 1 or obj['right'] == w - 1}

The learner below starts from the first example's full description and generalizes on each new positive: enlarge-set on a second value, drop the feature on a third. (For true/false features, seeing both values drops the feature immediately.)

arc_icl.py: the concept learner Python
class Concept: """Most specific conjunction consistent with the positives so far. Each feature is either a set of allowed values or dropped (None).""" def __init__(self, first): self.allowed = {f: {v} for f, v in first.items()} def covers(self, ex): return all(vals is None or ex[f] in vals for f, vals in self.allowed.items()) def positive(self, ex, log): for f, vals in self.allowed.items(): if vals is not None and ex[f] not in vals: if len(vals) >= 2 or isinstance(ex[f], bool): # every value allowed: drop it self.allowed[f] = None log.append(f'drop {f}') else: vals.add(ex[f]) log.append(f'enlarge {f} to {sorted(vals)}') def specificity(self): return sum(v is not None for v in self.allowed.values()) def describe(self): return ', '.join(f'{f} in {sorted(v)}' if len(v) > 1 else f'{f} = {next(iter(v))}' for f, v in self.allowed.items() if v is not None)
arc_icl.py: objects as labelled examples Python
def labelled_objects(pair, bg): """Each input object, labelled with the single colour it has in the output (or None if it changed in some other way).""" out = pair['output'] for obj in find_objects(pair['input'], bg=BG[bg](pair['input'])): cols = {out[r][c] for r, c in obj['cells']} yield features(obj, pair['input']), (cols.pop() if len(cols) == 1 else None)
arc_icl.py: learning one concept per output colour Python
def learn(task, bg='black', verbose=False): """For each new colour, incrementally learn which objects turn that colour.""" if any(dims(p['input']) != dims(p['output']) for p in task['train']): return None concepts, negatives = {}, {} for i, pair in enumerate(task['train']): for feats, label in labelled_objects(pair, bg): if label is None: return None if label == feats['color']: negatives.setdefault('kept', []).append(feats) continue log = [] if label not in concepts: concepts[label] = Concept(feats) log.append('first example') else: concepts[label].positive(feats, log) if verbose and log: print(f' pair {i}, an object becomes {label}: ' + '; '.join(log)) for feats in negatives.get('kept', []): if any(c.covers(feats) for c in concepts.values()): return None # a concept covers an object that stayed put return concepts def apply(concepts, grid, bg='black'): out = [row[:] for row in grid] for obj in find_objects(grid, bg=BG[bg](grid)): f = features(obj, grid) hits = [k for k, c in concepts.items() if c.covers(f)] if hits: # conflict resolution: the most specific concept wins k = max(hits, key=lambda k: concepts[k].specificity()) for r, c in obj['cells']: out[r][c] = k return out

The concept for red kept size = 6 through every example, while the concept for blue dropped size. That is the rule: shapes of six cells turn red, all others blue. When an object matches both concepts, the more specific one wins, the same specificity rule as conflict resolution in production systems.

Incremental learning has a classic failure, and ARC shows it immediately:

arc_icl.py: a concept that is too specific Python
if __name__ == '__main__': task = load_task('data/training/aedd82e4.json') concepts = learn(task) print('aedd82e4, objects that become 1:', concepts[1].describe()) print(' fits train:', all(apply(concepts, p['input']) == p['output'] for p in task['train']), '| test correct:', apply(concepts, task['test'][0]['input']) == task['test'][0]['output'])
Shell output Output
aedd82e4, objects that become 1: color = 2, size = 1, single_cell = True, height = 1, width = 1, solid_rectangle = True, touches_edge = True fits train: True | test correct: False

In aedd82e4, isolated red cells turn blue. Every isolated cell in the train pairs happened to touch the edge of the grid, so touches_edge = True never got dropped. The test has an isolated cell in the middle, and the agent leaves it red. No near miss ever taught it that the edge was irrelevant. A person would not make this mistake, because a person has a prior that "touching the edge" is rarely what an ARC rule is about. Which features to ignore by default is knowledge too.

arc_icl.py: sweep, trying two theories of the background Python
if __name__ == '__main__': solved = [] for name in sorted(os.listdir('data/training')): t = load_task('data/training/' + name) for bg in BG: # if one theory of background fails, try the other cs = learn(t, bg) if cs and all(apply(cs, p['input'], bg) == p['output'] for p in t['train']): if all(apply(cs, p['input'], bg) == p['output'] for p in t['test']): solved.append(f'{name[:-5]} ({bg})') break print(len(solved), 'tasks:', ', '.join(solved))
Shell output Output

Three tasks, and one of them (e8593010) needed the agent to drop the usual "black is background" assumption: there, the objects are black holes in a grey sheet. Few tasks, but this learner is narrow on purpose. Its value is that it will slot into everything else: once the Decider has found a rule like "recolour", concept learning works out where to apply it.

SAM lens

Concepts live in long-term semantic Memory; the learner is the learning arrow. The near-miss idea is a lesson for the Monitor: when a concept fails, the useful question is "what is the smallest difference between what worked and what did not?" That question returns as credit assignment in week 13.
