Classification maps a situation onto one of a set of known categories, so that everything you know about the category becomes available. Hofstadter and Sander put it bluntly: "nonstop categorization is every bit as indispensable to our survival in the world as is the nonstop beating of our hearts." For an agent, classification is how a huge space of possible situations collapses into a few kinds, each with its own actions. For ARC, it is both a kind of task (some tasks literally ask "which kind of input is this?") and the agent's first move on every task ("what kind of task is this?").

Part 1. Concept Hierarchies

Categories are organized in hierarchies. Each node is a concept; children are more specific than parents. Classification moves through the hierarchy in one of two directions:

  • Top-down (establish and refine): confirm that the situation belongs to a general concept, then try to narrow it down to one of that concept's children. Efficient, because each step rules out whole subtrees.
  • Bottom-up: from observed features, find the leaf concepts that match and generalize upward. Useful when features arrive piecemeal.
Establish and refine. "Has feathers" establishes bird; "does not fly, swims" refines it to penguin. Mammals and fish are never examined.

Not every concept is defined the same way. Goel and Joyner distinguish three kinds, which match three positions in cognitive psychology:

Three kinds of concepts. Mathematics and rules of the road are axiomatic; most everyday categories are prototype-like; some are just remembered members.
Human cognition connection

Eleanor Rosch (1970s) showed that human categories have a privileged middle level, the basic level. Shown a picture, people say "chair" before "furniture" (superordinate) or "kitchen chair" (subordinate); basic-level names are learned first, recognized fastest, and are the most informative for the effort. She also showed that categories have typicality gradients: a robin is a better bird than a penguin. This week's Hofstadter reading finds the same structure in schoolbook geometry: most people hold only two or three levels of the quadrilateral hierarchy, while experts hold four, and "is a square a rectangle?" depends on which levels you have. The Bennett reading names the two problems every classifier faces: telling similar things apart (discrimination) and treating different-looking things as the same (generalization).

Part 2. A Hierarchical Classifier

Each node lists the features needed to establish it, and the features typical of it (a prototype). An unobserved feature counts as unknown, not false, so the classifier can stop and say what it would need to know to go further.

animal_classifier.py: the hierarchy Python
# node: (parent, features that must hold to ESTABLISH it, typical features) TREE = { 'animal': (None, {}, {}), 'bird': ('animal', {'covering': 'feathers'}, {'flies': True, 'size': 'small'}), 'mammal': ('animal', {'covering': 'fur'}, {'flies': False, 'legs': 4}), 'fish': ('animal', {'covering': 'scales', 'gills': True}, {'swims': True}), 'robin': ('bird', {'breast': 'red'}, {'flies': True, 'size': 'small'}), 'penguin': ('bird', {'flies': False, 'swims': True}, {'size': 'medium'}), 'eagle': ('bird', {'hooked_beak': True}, {'flies': True, 'size': 'large'}), 'bat': ('mammal', {'flies': True}, {'size': 'small'}), 'dog': ('mammal', {'barks': True}, {'legs': 4}), } def children(node): return [n for n, (p, _, _) in TREE.items() if p == node]
animal_classifier.py: establish and refine Python
def establishes(node, obs): """A node is established if every required feature is observed to hold. A feature we have not observed counts as unknown, not as false.""" need = TREE[node][1] if any(f in obs and obs[f] != v for f, v in need.items()): return False return all(f in obs for f in need) def typicality(node, obs): typ = TREE[node][2] known = [f for f in typ if f in obs] return sum(obs[f] == typ[f] for f in known) / len(known) if known else None def classify(obs): """Top-down: establish a node, then try to refine it into a child.""" node, path = 'animal', ['animal'] while True: winners = [c for c in children(node) if establishes(c, obs)] if len(winners) != 1: return path, winners node = winners[0] path.append(node)

Two things to notice. The penguin is classified correctly, yet its typicality as a bird is 0: it violates the bird prototype. Membership and typicality are different questions, exactly as Rosch found. And the last animal (feathers, large) cannot be refined; instead of guessing, the classifier reports which observations would decide it. A classifier that knows what it does not know is a step toward metacognition.

Part 3. A Taste of ARC: Tasks That Are Classification

Some ARC tasks output one of a few fixed answers. In 44f52bb0 every output is a single cell, blue or orange:

Task 44f52bb0. Each input is a small red pattern; each output a single cell. What decides the colour?

The agent describes each input with a few features, then looks for a single feature whose value predicts the answer without exception: a one-level decision tree, called a decision stump.

arc_classify.py: grid features Python
def features(g): """A feature vector for a whole input grid.""" objs = find_objects(g, bg=0) cnt = Counter(v for row in g for v in row if v != 0) return { 'mirror_lr': g == flip_h(g), 'mirror_ud': g == flip_v(g), 'diag_sym': dims(g)[0] == dims(g)[1] and g == transpose(g), 'n_colors': len(colors(g) - {0}), 'n_objects': len(objs), 'top_color': cnt.most_common(1)[0][0] if cnt else 0, 'rare_color': cnt.most_common()[-1][0] if cnt else 0, 'shape': tuple(tuple(v != 0 for v in row) for row in g), # the mask itself }
arc_classify.py: learning a decision stump Python
def learn_stump(task): """Classification task? (outputs come from a small set of answers). Find ONE feature whose value predicts the answer with no exceptions.""" labels = [str(p['output']) for p in task['train']] if len(set(labels)) == len(labels): # every answer different: not classification return None answers = {str(p['output']): p['output'] for p in task['train']} feats = [features(p['input']) for p in task['train']] for f in feats[0]: table = {} if all(table.setdefault(fv[f], lab) == lab for fv, lab in zip(feats, labels)): if len(table) > 1: # the feature must actually split return f, {v: answers[lab] for v, lab in table.items()} return None def predict(stump, grid): f, table = stump return table.get(features(grid)[f])

Five tasks. Look closely at 27a28665: a person sees that each answer goes with a particular shape, but the stump found that the number of separate objects also happens to separate the answers in the train pairs, and it got the test right. Right answer, possibly wrong reason. With only a few train pairs, many features will separate the classes by accident. Preferring features that people find natural (shape over object count, symmetry over cell count) is a bias your agent needs, and it is the same lesson as last week's touches_edge.

SAM lens

Concept hierarchies are long-term semantic Memory. Establish-and-refine is a Decider. For your ARC agent, the most valuable classifier is one that labels tasks ("same size, recolouring" vs "output smaller, cropping"), because that label tells the Decider which methods to try first.

Intermediate

  1. Make the classifier bottom-up: from the observations, collect all leaves that are not ruled out and report them with typicality scores.
  2. Extend the stump to a depth-2 decision tree. Do more tasks fall? Do any break?

Advanced

  1. Write a task classifier: label each training task with one of a handful of task types you define (for example "same size, colours change"). Hand-label 30 tasks, learn a stump or tree from your labels, and test it on 30 more.

For your ARC agent
