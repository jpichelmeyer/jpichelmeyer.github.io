How should an agent store what it knows? The first answer this course gives is the oldest structured representation in AI: the semantic network. It is a graph whose nodes stand for things or concepts and whose labelled edges stand for relations between them. Semantic networks were proposed as a model of human memory, they are easy to draw and to code, and they turn out to be a natural way to describe what changes between an ARC input and its output.

Reading
  • Hofstadter & Sander, Ch. 1: The Structure of Categories and of Conceptual Space; The Endless Chunking of Concepts (pp. 49–53 · PDF 64–68 · 5 pages)
    Concepts as nodes at different distances from each other, each one unpackable into more concepts. A psychologist's semantic network.

Part 1. Knowledge as a Network

In 1969 Allan Collins and Ross Quillian proposed that people store concepts in a hierarchy like the one below. Each concept is a node. is-a edges connect a concept to a more general one, and properties are stored at the most general level where they hold. Penguins are the exception: "can't fly" is stored on penguin itself and overrides what bird says.

A Collins and Quillian style semantic network. Properties live on the most general node they apply to, so "a canary has skin" is stored two levels up.
Human cognition connection

Collins and Quillian tested the model by timing people. "A canary can sing" (a property stored on canary) was verified faster than "a canary can fly" (one link up), which was faster than "a canary has skin" (two links up). The network predicted reaction times. Later work showed the picture is too tidy: typical members ("a robin is a bird") are verified faster than atypical ones ("a penguin is a bird") regardless of distance. Collins and Loftus (1975) replaced strict hierarchy with spreading activation over links of different strengths. This week's Hofstadter reading pushes further: conceptual distance is fluid and context-dependent.

A semantic network has three ingredients:

  • Lexicon: the vocabulary of node types (circle, square; red object, blue object).
  • Structure: nodes connected by directed, labelled edges (inside, above, bigger-than).
  • Semantics: the interpretation that lets an agent draw inferences from the structure (if y inside x and x inside z, then y inside z).

A representation is good when it makes the important relationships explicit and hides the unimportant ones. The same picture can be described by a dozen different networks, and the choice largely decides how hard the problem is.

Part 2. A Semantic-Network Agent for Visual Analogies

Here is a classic intelligence-test item, the kind found in Raven's Progressive Matrices: A is to B as C is to which candidate?

A 2×2 visual analogy. A large circle with a small filled triangle inside becomes the large circle alone. What should happen to C?

The agent represents each figure as a semantic network. It then builds a transformation network from A to B, describing each object's fate, and compares it with the transformation from C to each candidate. The best answer is the candidate whose transformation most resembles A→B.

A and B as semantic networks, and the transformation between them. Objects are described by role (the first object, the second object) so that the description can transfer from A/B to C/D, where the shapes are different.
raven_agent.py: the network Python
class SemanticNet: """Nodes are objects (with attributes); edges are labelled relations.""" def __init__(self): self.nodes = {} # name -> {attribute: value} self.edges = set() # (from, relation, to) def add(self, name, **attrs): self.nodes[name] = attrs return self def relate(self, a, relation, b): self.edges.add((a, relation, b)) return self def relations_of(self, name): return {(r, b) for a, r, b in self.edges if a == name}

A = (SemanticNet().add('x', shape='circle', size='large', fill='no') .add('y', shape='triangle', size='small', fill='yes') .relate('y', 'inside', 'x')) B = SemanticNet().add('x', shape='circle', size='large', fill='no') C = (SemanticNet().add('p', shape='square', size='large', fill='no') .add('q', shape='circle', size='small', fill='yes') .relate('q', 'inside', 'p')) candidates = { 1: SemanticNet().add('p', shape='square', size='large', fill='no'), 2: SemanticNet().add('p', shape='square', size='small', fill='no'), 3: (SemanticNet().add('p', shape='square', size='large', fill='no') .add('q', shape='circle', size='small', fill='yes') .relate('q', 'above', 'p')), 4: SemanticNet().add('q', shape='circle', size='large', fill='no'), }

To compare networks, the agent first decides which object in one figure corresponds to which object in the other. This correspondence problem is where much of the intelligence hides. Here the rule is simple (match same shapes first), but in Module 2 it becomes analogy-making.

raven_agent.py: transformations Python
# How similar each kind of change is (bigger = more similar), in the # spirit of the weights in Goel & Joyner's KBAI lectures. WEIGHTS = {'unchanged': 5, 'size changed': 3, 'fill changed': 3, 'relation changed': 2, 'shape changed': 1, 'deleted': 1, 'added': 1} def transform(net1, net2, mapping): """Describe how net1 becomes net2, given which object maps to which. Objects are described by ROLE (their position in the mapping), not name.""" changes = [] for role, (o1, o2) in enumerate(mapping): if o2 is None: changes.append((role, 'deleted')) continue a, b = net1.nodes[o1], net2.nodes[o2] diffs = [f'{k} changed' for k in a if a[k] != b.get(k)] rel1 = {r for r, _ in net1.relations_of(o1)} rel2 = {r for r, _ in net2.relations_of(o2)} if rel1 != rel2: diffs.append('relation changed') changes += [(role, d) for d in diffs] or [(role, 'unchanged')] return sorted(changes) def correspond(net1, net2): """Pair objects: same shape first, then by order; leftovers are deleted.""" pairs, used = [], set() for o1, a in net1.nodes.items(): match = next((o2 for o2, b in net2.nodes.items() if o2 not in used and b['shape'] == a['shape']), None) if match is None: match = next((o2 for o2 in net2.nodes if o2 not in used), None) if match: used.add(match) pairs.append((o1, match)) return pairs
raven_agent.py: choosing an answer Python
def score(t1, t2): """Weighted overlap of two transformations; mismatches cost points.""" s = sum(WEIGHTS[kind] for role, kind in t1 if (role, kind) in t2) return s - len(set(t1) ^ set(t2)) def solve(A, B, C, candidates): ab = transform(A, B, correspond(A, B)) print('A -> B:', ab) best = None for k, D in candidates.items(): cd = transform(C, D, correspond(C, D)) s = score(ab, cd) print(f' C -> {k}: {cd} score {s}') if best is None or s > best[1]: best = (k, s) return best[0] print('answer:', solve(A, B, C, candidates))
Shell output Output
A -> B: [(0, 'unchanged'), (1, 'deleted')] C -> 1: [(0, 'unchanged'), (1, 'deleted')] score 6 C -> 2: [(0, 'size changed'), (1, 'deleted')] score -1 C -> 3: [(0, 'unchanged'), (1, 'relation changed')] score 3 C -> 4: [(0, 'shape changed'), (1, 'deleted')] score -1 answer: 1

The weights encode a judgment about which changes are "small." Keeping an object unchanged is the most similar transformation; deleting it or changing its shape is the least. Change the weights and the agent will prefer different answers, which is one way to model different people's preferences.

Part 3. A Taste of ARC: Networks of Objects

An ARC pair is a visual analogy with one figure missing: train input is to train output as test input is to ?. So the same move works. Describe each grid as a network of objects, compare input with output, and read a rule off the differences. Task aabf363d:

Task aabf363d. A large shape and a single cell in the bottom-left corner. In the output the shape takes the colour of the single cell, and the single cell disappears.
arc_semnet.py: build a network for a grid Python
from arc_utils import load_task, find_objects, show, COLOR_NAMES def build_net(grid): """A semantic network for one grid: object nodes plus relations.""" objs = find_objects(grid, bg=0) nodes = {f'o{i}': o for i, o in enumerate(objs)} edges = set() for a, oa in nodes.items(): for b, ob in nodes.items(): if a == b: continue if oa['size'] > ob['size']: edges.add((a, 'bigger-than', b)) if oa['color'] == ob['color']: edges.add((a, 'same-color', b)) if oa['bottom'] < ob['top']: edges.add((a, 'above', b)) if oa['right'] < ob['left']: edges.add((a, 'left-of', b)) return nodes, edges def describe(nodes, edges): for n, o in nodes.items(): print(f' {n}: {COLOR_NAMES[o["color"]]}, size {o["size"]}') for e in sorted(edges): print(' ', *e)
arc_semnet.py: compare input with output Python
def compare(net_in, grid_out): """Match each input object to what is in the output at its cells.""" nodes, _ = net_in report = [] for n, o in nodes.items(): out_colors = {grid_out[r][c] for r, c in o['cells']} if out_colors == {o['color']}: report.append((n, 'kept', None)) elif out_colors == {0}: report.append((n, 'deleted', None)) elif len(out_colors) == 1: report.append((n, 'recolored', out_colors.pop())) else: report.append((n, 'changed', None)) return report task = load_task('data/training/aabf363d.json') pair = task['train'][0] net = build_net(pair['input']) print('input network:') describe(*net) print('what happened to each node:') for row in compare(net, pair['output']): print(' ', row)
Shell output Output
input network: o0: red, size 12 o1: yellow, size 1 o0 above o1 o0 bigger-than o1 o1 left-of o0 what happened to each node: ('o0', 'recolored', 4) ('o1', 'deleted', None)
The input network for train pair 1, and what the comparison found. The important relation, "the new colour of o0 is the old colour of o1," is a relation between the input and the output networks.

The comparison says what happened to o0 and o1, but those names mean nothing in the test grid. The rule has to be stated in terms of roles that exist in any grid, like largest and smallest, exactly as the Raven agent described objects by role.

arc_semnet.py: a rule stated in roles Python
def roles(nodes): by_size = sorted(nodes, key=lambda n: nodes[n]['size']) return {'smallest': by_size[0], 'largest': by_size[-1]} def apply_rule(grid): """Rule read off the network comparison: the largest object takes the colour of the smallest object, and the smallest object disappears.""" nodes, _ = build_net(grid) r = roles(nodes) big, small = nodes[r['largest']], nodes[r['smallest']] out = [row[:] for row in grid] for y, x in big['cells']: out[y][x] = small['color'] for y, x in small['cells']: out[y][x] = 0 return out print('rule fits every train pair:', all(apply_rule(p['input']) == p['output'] for p in task['train'])) print('test correct:', apply_rule(task['test'][0]['input']) == task['test'][0]['output'])
Shell output Output
rule fits every train pair: True test correct: True

Here the rule was written by hand after reading the comparison. Turning "read a rule off the comparison" into something the agent does by itself is the work of the next several weeks: production rules (week 2), generate and test (week 3), and learning concepts from examples (week 7).

SAM lens

Semantic networks live in Memory. The input network is the agent's working-memory model of the grid, built by the Perceptor. Concept hierarchies (like bird is-a animal) are long-term semantic memory. Upgrading your Perceptor from "list of cells" to "network of objects and relations" is the single biggest improvement you can make this month.
