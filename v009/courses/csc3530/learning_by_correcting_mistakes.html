Every agent makes mistakes. A learning agent uses them. Learning by correcting mistakes starts when the agent's own knowledge produces a wrong answer, and asks the hardest question in learning: which piece of knowledge was to blame? An agent with a hundred rules, a dozen perceptual assumptions, and a case library can be wrong for a hundred reasons. Fixing the right one, and only that one, is the credit assignment problem.

Part 1. Blame Assignment

Learning by correcting mistakes. The new step, compared with earlier kinds of learning, is assigning blame inside the agent's own knowledge.

Goel and Joyner's example: an agent has learned that a cup is anything with a handle and a concavity. It then calls a pail a cup, and a basket. Those are false positives. To repair the concept it compares what the false positives share with what the true cups have, looking for suspicious features: present in every false positive, absent from every true positive.

Credit assignment by comparison. Features shared by both groups cannot explain the mistake; a feature found only (and always) among the mistakes is the suspect.
Human cognition connection

Error-driven learning is one of psychology's best-supported ideas. In the Rescorla-Wagner model (1972), an animal learns in proportion to its prediction error: a surprise teaches; an expected outcome teaches nothing. That explains blocking (Kamin, 1969): if a tone already predicts a shock, adding a light alongside the tone teaches the animal nothing about the light, because nothing was surprising. This week's Bennett reading describes blocking and other ancient solutions to credit assignment. The Hofstadter reading turns errors around: speech errors ("she'll be hard shoes to fill") are windows onto the hidden machinery that produced them. A mistake carries information about its cause, if you know how to read it.

Part 2. Correcting a Concept

cup_mistakes.py: the current rule and its experience Python
rule = {'require': {'has-handle', 'has-concavity'}, 'forbid': set()} def is_cup(obj): return rule['require'] <= obj and not (rule['forbid'] & obj) # Objects the agent met, with what they really turned out to be. experience = [ ({'has-handle', 'has-concavity', 'light', 'handle-on-side', 'porcelain'}, True), ({'has-handle', 'has-concavity', 'light', 'handle-on-side', 'plastic'}, True), ({'has-handle', 'has-concavity', 'heavy', 'handle-on-top', 'metal'}, False), # a pail ({'has-handle', 'has-concavity', 'light', 'handle-on-top', 'plastic'}, False), # a basket ({'has-handle', 'has-concavity', 'light', 'handle-on-side', 'metal'}, True), ]
cup_mistakes.py: assigning blame Python
def mistakes(): fp = [o for o, truth in experience if is_cup(o) and not truth] # wrongly accepted fn = [o for o, truth in experience if not is_cup(o) and truth] # wrongly rejected tp = [o for o, truth in experience if is_cup(o) and truth] return fp, fn, tp def assign_blame(fp, tp): """Suspicious false-success features: in EVERY false positive and in NO true positive. Forbidding any of them would fix the mistakes without breaking the successes.""" common_fp = set.intersection(*fp) in_any_tp = set.union(*tp) if tp else set() return common_fp - in_any_tp fp, fn, tp = mistakes() print('rule:', rule) print('false positives:', len(fp), '| false negatives:', len(fn)) suspects = assign_blame(fp, tp) print('suspicious features:', suspects)
cup_mistakes.py: correcting Python
rule['forbid'] |= suspects fp, fn, tp = mistakes() print('corrected rule:', rule) print('false positives:', len(fp), '| false negatives:', len(fn))
Shell output Output
rule: {'require': {'has-concavity', 'has-handle'}, 'forbid': set()} false positives: 2 | false negatives: 0 suspicious features: {'handle-on-top'} corrected rule: {'require': {'has-concavity', 'has-handle'}, 'forbid': {'handle-on-top'}} false positives: 0 | false negatives: 0

One feature explained both mistakes: a handle on top. The repair is surgical. It forbids that feature and leaves the rest of the rule alone, and the experiences the rule already got right stay right. Had the false positives shared nothing that the true positives lacked, the agent would know it needs a new feature in its representation, which is also worth knowing. The symmetric case (false negatives, things wrongly rejected) uses features in every true positive and no false negative, to decide what to require or what to stop requiring.

Part 3. A Taste of ARC: Blaming a Perceptual Assumption

Your ARC agent makes assumptions it hardly notices: that black is background, that objects are made of cells touching side by side (not diagonally), that an object has one colour. When an assumption is wrong for a task, everything downstream fails, and the obvious response (search harder in the Decider) is the wrong one. The train pairs provide feedback: fit a decision on pair 1, check it on pair 2, and treat a wrong answer as a mistake to be blamed.

Blame assignment in a pipeline: change one component at a time, refit, and see which change makes the mistake go away.
arc_blame.py: perception and decision Python
# The agent's answer depends on PERCEPTUAL assumptions (how objects are # found) and on a DECISION (which objects to change, and how). DEFAULT = {'connect_diagonally': False, 'background': 'black', 'one_colour_objects': True} def perceive(grid, assumptions): bg = 0 if assumptions['background'] == 'black' else \ Counter(v for row in grid for v in row).most_common(1)[0][0] return find_objects(grid, bg=bg, diagonal=assumptions['connect_diagonally'], by_color=assumptions['one_colour_objects']), bg SELECT = {'smallest': lambda objs, o: o['size'] == min(x['size'] for x in objs), 'largest': lambda objs, o: o['size'] == max(x['size'] for x in objs), 'not largest': lambda objs, o: o['size'] != max(x['size'] for x in objs), 'single cells': lambda objs, o: o['size'] == 1, 'all': lambda objs, o: True} def act(grid, assumptions, decision): objs, bg = perceive(grid, assumptions) if not objs: return None select, new_color = decision out = [row[:] for row in grid] for o in objs: if SELECT[select](objs, o): for r, c in o['cells']: out[r][c] = bg if new_color == 'erase' else new_color return out def fit_decision(pair, assumptions): """Choose the decision that reproduces one pair, under given assumptions.""" colors = sorted({v for row in pair['output'] for v in row}) + ['erase'] for select in SELECT: for k in colors: if act(pair['input'], assumptions, (select, k)) == pair['output']: return (select, k) return None
arc_blame.py: learning from mistakes on later pairs Python
def learn(task, verbose=False): """Fit on pair 1 under the default assumptions. Each later pair that comes out WRONG is a mistake: assign blame by changing one assumption at a time; keep the change that fixes the mistake without breaking the pairs already explained.""" assumptions = dict(DEFAULT) seen = [task['train'][0]] decision = fit_decision(seen[0], assumptions) for i, pair in enumerate(task['train'][1:], start=2): if decision and act(pair['input'], assumptions, decision) == pair['output']: seen.append(pair) continue if verbose: print(f' mistake on pair {i}') fixed = False for name, alt in [('connect_diagonally', not assumptions['connect_diagonally']), ('background', 'majority' if assumptions['background'] == 'black' else 'black'), ('one_colour_objects', not assumptions['one_colour_objects'])]: trial = dict(assumptions, **{name: alt}) d = fit_decision(seen[0], trial) if d and all(act(p['input'], trial, d) == p['output'] for p in seen + [pair]): if verbose: print(f' blame: the assumption {name}={assumptions[name]}; changed to {alt}') assumptions, decision, fixed = trial, d, True break if not fixed: return None, None seen.append(pair) return assumptions, decision

Shell output Output
42a50994 mistake on pair 2 blame: the assumption connect_diagonally=False; changed to True learned: {'connect_diagonally': True, 'background': 'black', 'one_colour_objects': True} ('smallest', 0)

On pair 1, "erase the smallest objects" happened to work with side-by-side connectivity. Pair 2 contained cells touching only at a corner, which the default treated as separate (smallest) objects, and the answer came out wrong. The agent flipped one assumption at a time, starting with connectivity, which fixed the mistake while leaving pair 1 correct. Blame landed on that assumption, and nothing else in the agent was touched.

Shell output Output
4 tasks: 42a50994 (corrected: connect_diagonally) 9565186b aedd82e4 b1948b0a (corrected: connect_diagonally)

Two of the four tasks needed a correction. One correction (b1948b0a) is suspicious: diagonal connectivity has nothing to do with a task that just swaps one colour for another. It fixed the mistake on the train pairs by accident. Blame assignment by intervention finds a change that removes the error, not necessarily the cause. That is the credit assignment problem in miniature, and why the Monitor next week will want to ask whether a correction makes sense.

SAM lens

Learning by correcting mistakes is the Monitor closing the learning loop: it detects the failure, assigns blame among the agent's own components (Perceptor assumptions, Memory contents, Decider choices), and edits only the blamed one. The cup agent edits semantic Memory; the ARC agent edits the Perceptor.

Discuss
  1. Rescorla-Wagner says surprise drives learning. Which ARC train pairs are the most "surprising" for your agent, and does it learn most from them?
  2. Blocking: once the agent explains a task with one feature, should it stop considering others? When does that help and when does it hurt?
  3. The b1948b0a correction worked for the wrong reason. How could the agent tell a sensible correction from an accidental one?
