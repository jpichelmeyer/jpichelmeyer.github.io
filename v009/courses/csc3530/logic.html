Logic is the most precise form of reasoning we have: from premises we believe, it derives conclusions that are guaranteed to be true. Knowledge-based AI uses logic in two ways: as a language for writing knowledge down unambiguously, and as a set of inference methods that work regardless of what the knowledge is about. This lesson covers the propositional core, forward and backward chaining, and resolution, and then finds a little family of ARC tasks that are logic problems in disguise.

Reading
  • Hofstadter & Sander, Ch. 7: Everyday Concepts Versus Scientific Concepts (pp. 391–394 · PDF 406–409 · 4 pages)

Part 1. Propositions, Connectives, and Truth

A proposition is a statement that is true or false: it has feathers, this cell is coloured. Connectives build bigger ones. Their meaning is fixed by a truth table:

Truth tables. Note the last column: "P implies Q" is false only when P is true and Q is false. In particular, it is true whenever P is false, which surprises almost everyone.

The two inference rules you will meet most often:

  • Modus ponens: from P and P ⇒ Q, conclude Q. (It has feathers; feathers imply bird; so it is a bird.)
  • Modus tollens: from not Q and P ⇒ Q, conclude not P. (It is not a bird; feathers imply bird; so it has no feathers.)

Predicate logic adds objects, relations, and quantifiers ("for all x, if x is a bird then x has wings"). The ideas below carry over, with variables and matching, as in the pattern matcher from the production systems lesson.

Human cognition connection

People are not natural logicians. In Peter Wason's selection task (1966), participants see four cards showing A, K, 4, 7 and are told "if a card has a vowel on one side, it has an even number on the other." Which cards must you turn over to test the rule? Most people pick A and 4; the correct answer is A and 7 (modus tollens). Yet when the same logic is dressed as a social rule, "if someone is drinking beer, they must be over 21," most people get it right. Content, not form, drives much human reasoning. This week's Hofstadter reading makes the same point about mathematical concepts: we hold them through familiar analogies, not their formal definitions.

Part 2. A Logic Agent: Chaining and Resolution

The knowledge base is a set of Horn clauses: rules of the form premise and premise and ... ⇒ conclusion, plus some facts.

logic_agent.py: knowledge base Python
# Horn clauses: (set of premises, conclusion) RULES = [ ({'has-feathers'}, 'bird'), ({'bird', 'can-not-fly', 'swims'}, 'penguin'), ({'bird', 'flies', 'sings'}, 'songbird'), ({'songbird', 'yellow'}, 'canary'), ] FACTS = {'has-feathers', 'flies', 'sings', 'yellow'}

Forward chaining starts from the facts and fires every rule whose premises are all known, repeatedly, until nothing new appears. Backward chaining starts from a question and works back to the facts, which is what you want when the knowledge base is large and you care about one conclusion.

The same knowledge used two ways. Forward chaining derives everything that follows from the facts. Backward chaining derives only what is needed to answer the question.
logic_agent.py: forward chaining Python
def forward_chain(facts, rules): """Data-driven: keep firing any rule whose premises are all known.""" known, changed = set(facts), True while changed: changed = False for premises, conclusion in rules: if premises <= known and conclusion not in known: print(f' {" & ".join(sorted(premises))} => {conclusion}') known.add(conclusion) changed = True return known print('forward chaining:') forward_chain(FACTS, RULES)
logic_agent.py: backward chaining Python
def backward_chain(goal, facts, rules, depth=0): """Goal-driven: to prove a goal, find a rule that concludes it and prove each premise. Prints the proof tree as it goes.""" pad = ' ' * depth if goal in facts: print(f'{pad}{goal}: given') return True for premises, conclusion in rules: if conclusion == goal: print(f'{pad}{goal}: try rule needing {sorted(premises)}') if all(backward_chain(p, facts, rules, depth + 1) for p in sorted(premises)): return True print(f'{pad}{goal}: cannot prove') return False print('backward chaining: is it a canary?') backward_chain('canary', FACTS, RULES)
Shell output Output
forward chaining: has-feathers => bird bird & flies & sings => songbird songbird & yellow => canary backward chaining: is it a canary? canary: try rule needing ['songbird', 'yellow'] songbird: try rule needing ['bird', 'flies', 'sings'] bird: try rule needing ['has-feathers'] has-feathers: given flies: given sings: given yellow: given

Horn clauses cannot express everything (for example, "it flies or it is a penguin"). Resolution handles any statement written in clause form (an OR of literals). To prove a query, add its negation and keep resolving pairs of clauses; if you ever derive the empty clause, the negated query contradicts what you know, so the query is true.

logic_agent.py: resolution refutation Python
def resolve(c1, c2): """All resolvents of two clauses (frozensets of literals, '-' = not).""" out = [] for lit in c1: neg = lit[1:] if lit.startswith('-') else '-' + lit if neg in c2: out.append((c1 - {lit}) | (c2 - {neg})) return out def refute(clauses, query): """Proof by contradiction: add NOT query; if the empty clause can be derived, the query follows from the clauses.""" neg = query[1:] if query.startswith('-') else '-' + query clauses = {frozenset(c) for c in clauses} | {frozenset([neg])} while True: new = set() for a in clauses: for b in clauses: if a < b or a == b: continue for r in resolve(a, b): if not r: print(f' {set(a)} + {set(b)} -> empty clause: contradiction') return True new.add(frozenset(r)) if new <= clauses: return False clauses |= new # "Penguins are birds", "birds fly unless they are penguins", "Pingu is a penguin" # in clause form: -penguin | bird ; -bird | penguin | flies ; penguin print('resolution: does Pingu fly?', refute([{'-penguin', 'bird'}, {'-bird', 'penguin', 'flies'}, {'penguin'}], 'flies')) print('resolution: is Pingu a bird?') print(' proved:', refute([{'-penguin', 'bird'}, {'-bird', 'penguin', 'flies'}, {'penguin'}], 'bird'))
Shell output Output
resolution: does Pingu fly? False resolution: is Pingu a bird? {'bird'} + {'-bird'} -> empty clause: contradiction proved: True
The resolution proof that Pingu is a bird.

"Does Pingu fly?" came back False, but read carefully: that means "cannot be proved," not "Pingu does not fly." Nothing in the knowledge base says penguins do not fly. Logic is sound (it never proves false things from true premises), but it only knows what you told it. Common sense needs far more knowledge than this, which is the subject of week 9.

Part 3. A Taste of ARC: Learning Truth Tables

Some ARC tasks show two halves of a grid and ask for a combination of them. Task 0520fde7:

Task 0520fde7. A grey column splits each input into two halves.
Read each half as a grid of propositions (coloured = true). The output is red exactly where both halves are true: P AND Q.

The agent does not need to know in advance which connective it is looking for. It treats each output cell as a function of two propositions and learns the truth table from the train pairs, rejecting the task if any combination of inputs ever maps to two different outputs. Then it names the table, if it has a name.

arc_logic.py: split into halves Python
def split(grid): """Cut a grid into two equal halves: at a full line of one colour through the middle if there is one, otherwise straight down the middle.""" h, w = dims(grid) mid_col = {grid[r][w // 2] for r in range(h)} mid_row = set(grid[h // 2]) if w % 2 == 1 and len(mid_col) == 1 and mid_col != {0}: # separator column return [row[:w // 2] for row in grid], [row[w // 2 + 1:] for row in grid] if h % 2 == 1 and len(mid_row) == 1 and mid_row != {0}: # separator row return grid[:h // 2], grid[h // 2 + 1:] if w % 2 == 0 and w >= h: return [row[:w // 2] for row in grid], [row[w // 2:] for row in grid] if h % 2 == 0: return grid[:h // 2], grid[h // 2:] return None
arc_logic.py: learn a truth table Python
def learn_truth_table(task): """Treat each cell of each half as a proposition (coloured = True). Record which output colour goes with each (left, right) combination; fail if any combination ever maps to two different outputs.""" table = {} for pair in task['train']: halves = split(pair['input']) if not halves or dims(halves[0]) != dims(pair['output']): return None a, b = halves for r, row in enumerate(pair['output']): for c, v in enumerate(row): key = (a[r][c] != 0, b[r][c] != 0) if table.setdefault(key, v) != v: return None return table NAMES = {(False, False, False, True): 'AND', (False, True, True, True): 'OR', (False, True, True, False): 'XOR', (True, False, False, False): 'NOR', (True, True, True, False): 'NAND', (True, False, False, True): 'XNOR'} def name_of(table): bits = tuple(table.get(k, 0) != 0 for k in [(False, False), (False, True), (True, False), (True, True)]) return NAMES.get(bits, 'other') def apply(table, grid): a, b = split(grid) return [[table[(a[r][c] != 0, b[r][c] != 0)] for c in range(len(a[0]))] for r in range(len(a))]
arc_logic.py: sweep the training set Python
if __name__ == '__main__': for name in sorted(os.listdir('data/training')): task = load_task('data/training/' + name) table = learn_truth_table(task) if table and len(table) == 4: test = task['test'][0] ok = apply(table, test['input']) == test['output'] print(f'{name[:-5]}: {name_of(table):4} test {"correct" if ok else "wrong"}')

SAM lens

Logic gives the Decider sound inference and gives long-term Memory an unambiguous language. Backward chaining is goal-driven, the style of reasoning MEA and planning use. In ARC, logic is best used as one more representation the Perceptor can offer: "these two regions are propositions."

Discuss
  1. Why does the Wason selection task get easier when it is about drinking ages? What does that suggest about how people store rules?
  2. The logic agent says "cannot prove" rather than "false." When would an agent be justified in treating "cannot prove" as "false" (the closed-world assumption)? Is that justified in ARC?
  3. Hofstadter and Sander argue that nobody really thinks with the epsilon-delta definition of continuity. Does that make formal logic a poor model of human thought, a good normative standard, or both?

Checkpoint

Before moving on, make sure you can:

  1. Evaluate compound propositions with truth tables, including implication.
  2. Apply modus ponens and modus tollens.
  3. Contrast forward and backward chaining and say when each is better.
  4. Carry out a short resolution refutation and interpret a failed proof correctly.
  5. Learn a truth table from ARC train pairs.
