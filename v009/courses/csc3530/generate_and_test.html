The simplest problem-solving method there is: propose a candidate solution, check it, and repeat until one passes. Generate and test sounds too simple to be interesting, but almost every method in this course is generate and test with a cleverer generator, a cleverer tester, or both. It is also, at heart, how most competitive ARC programs work.

Part 1. Generators and Testers

Generate and test. All the intelligence lives in how good the generator is at proposing plausible candidates, and how good the tester is at rejecting bad ones cheaply.

With a dumb generator and a dumb tester, generate and test is hopeless: the number of candidates explodes. The method becomes powerful when knowledge is pushed into one side or the other:

  • A smart generator never proposes candidates that are obviously wrong. In ARC, if every train output is twice the width of its input, do not generate programs that keep the width the same.
  • A smart tester checks cheap conditions first and remembers what it has already rejected, so the same bad candidate is never examined twice.

There is a trade-off. Knowledge moved into the generator makes it complicated and possibly wrong (it might never propose the true answer). Knowledge moved into the tester keeps the generator simple but wastes effort on candidates that a little thought would have skipped.

Human cognition connection

People rarely generate blindly. This week's Bennett reading describes Edward Tolman's rats pausing at a fork in a maze and looking down each path before choosing, which Tolman called vicarious trial and error: generating options in imagination and testing them before acting. The McShane reading makes the opposite point: experts mostly do not search at all; they retrieve a solution from structured knowledge. In ARC, people typically consider only a handful of candidate rules per task. Their generators are extraordinarily smart, and modeling that smartness is what the rest of this course is about.

Part 2. Generate and Test as State-Space Search

Our first mini-agent solves a classic puzzle. Three guards and three prisoners must cross a river in a boat that holds one or two people. On neither bank may prisoners outnumber guards, unless there are no guards on that bank. A state records how many guards and prisoners are on the left bank and where the boat is.

The first level of the state space. Of the five possible boat loads, two lead to illegal states. One legal move followed by its reverse leads straight back to the start, which a smart tester should notice.
river_agent.py: states and moves Python
# A state is (guards on left, prisoners on left, boat on left?) START, GOAL = (3, 3, True), (0, 0, False) LOADS = [(1, 0), (2, 0), (0, 1), (0, 2), (1, 1)] # (guards, prisoners) in boat
river_agent.py: the generator Python
def generate(state): """Every successor reachable with one boat trip (no checking).""" g, p, left = state sign = -1 if left else 1 for dg, dp in LOADS: yield (g + sign * dg, p + sign * dp, not left), (dg, dp)
river_agent.py: the tester Python
def legal(state): g, p, _ = state if not (0 <= g <= 3 and 0 <= p <= 3): return False right_g, right_p = 3 - g, 3 - p return (g == 0 or g >= p) and (right_g == 0 or right_g >= right_p)

The search loop below is breadth-first: it keeps a queue of states to expand and always expands the oldest first, so the first solution it finds uses the fewest crossings. The only difference between the naive and smart versions is one condition: whether the tester rejects states it has seen before.

river_agent.py: breadth-first generate and test Python
def solve(smart): """Breadth-first generate and test. A 'smart' tester also rejects states we have already seen; a naive one only checks legality.""" frontier, seen, tested = deque([(START, [])]), {START}, 0 while frontier: state, path = frontier.popleft() if state == GOAL: return path, tested for nxt, move in generate(state): tested += 1 if not legal(nxt) or (smart and nxt in seen): continue seen.add(nxt) frontier.append((nxt, path + [move])) if tested > 100000: return None, tested for smart in (False, True): path, tested = solve(smart) print('smart tester' if smart else 'naive tester', '-> states tested:', tested) print('solution in', len(path), 'crossings:', path)
Shell output Output
naive tester -> states tested: 58760 smart tester -> states tested: 70 solution in 11 crossings: [(0, 2), (0, 1), (0, 2), (0, 1), (2, 0), (1, 1), (2, 0), (0, 1), (0, 2), (1, 0), (1, 1)]

Remembering visited states cut the work from almost 59,000 tested states to 70. That one line of "memory" in the tester is worth more than any amount of speed.

The same method finds paths. Here the generator yields the open neighbouring cells, and the tester asks "is this the goal?" Breadth-first search guarantees the shortest path:

maze_agent.py Python
# Pathfinding as generate and test: breadth-first search on a grid maze. from collections import deque MAZE = ['S.#.....', '.##.###.', '....#...', '.##.#.#.', '.#..#.#G'] def find(ch): for r, row in enumerate(MAZE): if ch in row: return r, row.index(ch) def neighbours(cell): # the generator r, c = cell for dr, dc in [(1, 0), (-1, 0), (0, 1), (0, -1)]: nr, nc = r + dr, c + dc if 0 <= nr < len(MAZE) and 0 <= nc < len(MAZE[0]) and MAZE[nr][nc] != '#': yield nr, nc def bfs(start, goal): frontier, came_from = deque([start]), {start: None} while frontier: cell = frontier.popleft() if cell == goal: # the tester path = [] while cell: path.append(cell) cell = came_from[cell] return path[::-1], len(came_from) for nxt in neighbours(cell): if nxt not in came_from: came_from[nxt] = cell frontier.append(nxt) return None, len(came_from) path, explored = bfs(find('S'), find('G')) print(f'path of {len(path) - 1} steps, {explored} cells explored') for r, row in enumerate(MAZE): print(''.join('*' if (r, c) in path and ch == '.' else ch for c, ch in enumerate(row)))

Part 3. A Taste of ARC: Searching a Space of Programs

For ARC, a candidate solution is a program: a short sequence of grid operations. The generator lists programs, shortest first. The tester runs each program on every train input and compares with the train output. Here are 19 primitive operations, from flips and rotations to "crop to the largest object" and "let every cell fall":

arc_gt.py: primitives Python
def crop_all(g): bg = background(g) cells = [(r, c) for r, row in enumerate(g) for c, v in enumerate(row) if v != bg] rs, cs = [r for r, _ in cells], [c for _, c in cells] return crop(g, min(rs), min(cs), max(rs), max(cs)) def largest(g): return crop_object(g, max(find_objects(g), key=lambda o: o['size'])) def smallest(g): return crop_object(g, min(find_objects(g), key=lambda o: o['size'])) def gravity(g): # every non-background cell falls down bg, (h, w) = background(g), dims(g) out = [[bg] * w for _ in range(h)] for c in range(w): col = [g[r][c] for r in range(h) if g[r][c] != bg] for k, v in enumerate(reversed(col)): out[h - 1 - k][c] = v return out PRIMS = { 'flip_h': flip_h, 'flip_v': flip_v, 'transpose': transpose, 'rot90': rotate90, 'rot180': rotate180, 'rot270': rotate270, 'scale2': lambda g: scale(g, 2), 'scale3': lambda g: scale(g, 3), 'double_w': lambda g: hconcat(g, g), 'double_h': lambda g: vconcat(g, g), 'mirror_w': lambda g: hconcat(g, flip_h(g)), 'mirror_h': lambda g: vconcat(g, flip_v(g)), 'tile3': lambda g: vconcat(vconcat(hconcat(hconcat(g, g), g), hconcat(hconcat(g, g), g)), hconcat(hconcat(g, g), g)), 'left_half': lambda g: [r[:len(r) // 2] for r in g], 'top_half': lambda g: g[:len(g) // 2], 'crop_all': crop_all, 'largest': largest, 'smallest': smallest, 'gravity': gravity, }
arc_gt.py: generator Python
def programs(depth=2): """Every sequence of up to `depth` primitives, shortest first.""" for n in range(1, depth + 1): yield from itertools.product(PRIMS, repeat=n) def run(prog, g): for name in prog: g = PRIMS[name](g) return g
arc_gt.py: tester Python
def fits(prog, task, smart): """Test a program on every train pair. A smart tester checks the cheap thing first: does the first output even have the right size?""" try: if smart: first = task['train'][0] if dims(run(prog, first['input'])) != dims(first['output']): return False, 'size' return all(run(prog, p['input']) == p['output'] for p in task['train']), 'full' except Exception: return False, 'error' def solve(task, smart=True): full_checks = 0 for prog in programs(): ok, how = fits(prog, task, smart) full_checks += how == 'full' if ok: return prog, full_checks return None, full_checks

Blind generation runs out of steam quickly. The rest of the term is about making the generator smarter.

SAM lens

Generate and test splits the Decider (the generator) from the Monitor (the tester). The visited-state set is a small piece of working Memory that serves the Monitor. Most improvements to your ARC agent this term will be improvements to one of these two halves.
