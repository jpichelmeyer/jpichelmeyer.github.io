Concept learning needed many examples and a careful teacher. People often learn from a single example, when they can explain why the example is what it is. Explanation-based learning (EBL) captures that: use background knowledge to explain an example, then keep exactly the parts of the example the explanation needed. Everything else, however vivid, is dropped as irrelevant.

  • Hofstadter & Sander, Ch. 6: Caricature Analogies Help Us Explain Things to Ourselves (pp. 327–328 · PDF 342–343 · 2 pages)

Part 1. Learning by Explaining

Explanation-based learning. The example is explained with rules the agent already has; the explanation decides what generalizes.

Goel and Joyner's example: an agent knows what a cup is for (it is stable and lets you drink), and it has learned a few things from other objects: a brick is stable because of its flat bottom, a glass lets you drink because you can lift it and it holds liquid, a briefcase is liftable because it is light and has a handle, a bowl holds liquid because it is concave. Now it sees a red, chipped porcelain mug with a logo. Is it a cup?

The explanation (proof) that the mug is a cup. Its leaves are four observations; the mug's colour, material, logo, and chip played no part.

EBL does not generalize from statistics. It generalizes from structure: the proof says which features matter, so a single example suffices. The price is that the background knowledge must already be there and must be right. EBL learns something new in one sense only: it turns knowledge the agent already had, spread across several rules, into one rule it can apply directly. That is the same compiling-for-speed that Soar's chunking does.

Human cognition connection

Michelene Chi and colleagues (1989) studied students working through physics examples. The students who learned most were the ones who explained each step to themselves ("this force is here because the block is on an incline"), not the ones who read more slowly or more often. The self-explanation effect has been replicated many times. This week's McShane reading shows an agent doing the same: it learns a whole new disease from one sentence, because it can interpret the sentence with what it already knows. The Hofstadter reading describes the human version of the generalization step: caricaturing a situation to strip it down to its conceptual skeleton.

Part 2. An EBL Agent

cup_agent.py: background knowledge Python
# Background rules, each learned earlier from one example (in brackets). RULES = { 'cup': [['stable', 'enables-drinking']], # the definition of a cup 'stable': [['flat-bottom']], # [a brick] 'enables-drinking': [['liftable', 'carries-liquids']], # [a glass] 'liftable': [['light', 'has-handle']], # [a briefcase] 'carries-liquids': [['has-concavity']], # [a bowl] }
cup_agent.py: building an explanation Python
def explain(goal, facts, depth=0): """Backward-chain a proof. Returns the proof tree, or None.""" if goal in facts: return goal for body in RULES.get(goal, []): parts = [explain(g, facts, depth + 1) for g in body] if all(parts): return (goal, parts) return None def show(tree, depth=0): if isinstance(tree, str): print(' ' * depth + tree + ' <- observed') else: print(' ' * depth + tree[0]) for t in tree[1]: show(t, depth + 1) def leaves(tree): return [tree] if isinstance(tree, str) else [l for t in tree[1] for l in leaves(t)]
cup_agent.py: one example Python
mug = {'light', 'has-handle', 'has-concavity', 'flat-bottom', 'red', 'porcelain', 'has-logo', 'chipped'} proof = explain('cup', mug) print('Why is this object a cup?') show(proof)
cup_agent.py: generalize and use the new rule Python
# Keep only the observations the proof actually used: that IS the new rule. learned = sorted(leaves(proof)) print('learned rule: cup <-', ' AND '.join(learned)) print('ignored as irrelevant:', sorted(mug - set(learned))) def is_cup_fast(obj): return set(learned) <= obj for name, obj in [('blue plastic cup', {'light', 'has-handle', 'has-concavity', 'flat-bottom', 'blue'}), ('heavy iron pot', {'has-handle', 'has-concavity', 'flat-bottom'}), ('paper cone', {'light', 'has-concavity'})]: print(f'{name}: cup? {is_cup_fast(obj)}')

From one mug the agent learned a rule that correctly accepts a blue plastic cup it has never seen and rejects an iron pot (not light) and a paper cone (no handle, no flat bottom). Whether rejecting the paper cone is right depends on the background knowledge: the agent only knows one way to be liftable. Knowledge gaps become learning gaps.

Part 3. A Taste of ARC: Explaining Where a Colour Comes From

ARC gives several train pairs, but EBL suggests a different way to use them: explain the first pair thoroughly, then let the explanation say what should generalize. Suppose the agent finds that pair 1 is reproduced by "fill the grid with yellow." The constant yellow is the suspicious part. Why yellow? The agent tries to explain it from the input with a small vocabulary of roles:

arc_ebl.py: program skeletons with a colour constant Python
# Program skeletons with one colour constant c. def fill(g, c): # every cell becomes c return [[c] * len(g[0]) for _ in g] def paint_shapes(g, c): # every non-black cell becomes c return [[c if v else 0 for v in row] for row in g] def single_cell(g, c): # the answer is one cell of colour c return [[c]] def crop_color(g, c): # cut out the box around colour c cells = [(r, x) for r, row in enumerate(g) for x, v in enumerate(row) if v == c] rs, cs = [r for r, _ in cells], [x for _, x in cells] return [row[min(cs):max(cs) + 1] for row in g[min(rs):max(rs) + 1]] def keep_only(g, c): # erase every colour except c return [[v if v == c else 0 for v in row] for row in g] SKELETONS = {'fill': fill, 'paint_shapes': paint_shapes, 'single_cell': single_cell, 'crop_color': crop_color, 'keep_only': keep_only}
arc_ebl.py: roles that can explain a colour Python
# Ways to EXPLAIN where a colour comes from, using what the input shows. def counts(g): return Counter(v for row in g for v in row if v != 0) ROLES = { 'most common colour': lambda g: counts(g).most_common(1)[0][0], 'least common colour': lambda g: counts(g).most_common()[-1][0], 'colour of the largest object': lambda g: max(find_objects(g, bg=0), key=lambda o: o['size'])['color'], 'colour of the smallest object': lambda g: min(find_objects(g, bg=0), key=lambda o: o['size'])['color'], 'colour in the top-left corner': lambda g: g[0][0], }
arc_ebl.py: explaining one pair Python
def explain_pair(pair): """Explain ONE train pair: find a skeleton and constant that reproduce it, then every role that accounts for that constant.""" found = [] for sname, sk in SKELETONS.items(): for c in range(10): try: fits = sk(pair['input'], c) == pair['output'] except ValueError: # e.g. colour c is not in the grid fits = False if fits: for rname, role in ROLES.items(): try: if role(pair['input']) == c: found.append((sname, c, rname)) except (ValueError, IndexError): pass return found

Each explanation is then generalized by replacing the constant with its role ("fill with the most common colour"), and checked on the remaining pairs.

arc_ebl.py: generalize and check Python
def learn(task, verbose=False): """Explain the first pair; generalize each explanation by replacing the constant with its role; keep the first one that holds on every pair.""" chosen = None for sname, c, rname in explain_pair(task['train'][0]): rule = lambda g, s=SKELETONS[sname], r=ROLES[rname]: s(g, r(g)) try: ok = all(rule(p['input']) == p['output'] for p in task['train'][1:]) except (ValueError, IndexError): ok = False if verbose: print(f' {sname}({COLOR_NAMES[c]}) because {COLOR_NAMES[c]} is the {rname}: ' + ('holds on every pair' if ok else 'fails on another pair')) if ok and chosen is None: chosen = rule return chosen
arc_ebl.py: two tasks Python
if __name__ == '__main__': for tid in ['5582e5ca', 'be94b721']: task = load_task(f'data/training/{tid}.json') print(tid) rule = learn(task, verbose=True) print(' test correct:', rule(task['test'][0]['input']) == task['test'][0]['output'])

Explaining the constant in task 5582e5ca. Three roles explain "yellow" in pair 1, and only one survives the other pairs.

In be94b721 two explanations survive: the cropped shape is both the most common colour and the largest object. With the train pairs given, the agent cannot tell which explanation is the real one. Both happen to give the right test answer here, but an agent that keeps both and notices the ambiguity is better prepared than one that silently picks the first.

Eight tasks, five of them "crop out a colour," each solved by explaining which colour. Program search from week 3 also found some of these (as largest or crop_all), but here each answer comes with an explanation of the constant, which is what makes it transfer to a test grid with different colours.

SAM lens

EBL is a learning arrow that runs through the Decider: the proof is reasoning, and its result is written back to long-term Memory as a faster rule. The roles vocabulary (most common, largest, corner) belongs in your Perceptor: the more roles it can compute, the more constants your agent can explain.

Discuss
  1. EBL learned from one mug, but only because it already knew a lot. Is that "learning"? What exactly is new after EBL runs?
  2. Chi found that self-explanation helps students. Try it on an ARC task: explain each train pair in one sentence before guessing the rule. Did it change what you noticed?
  3. Two explanations survived on be94b721. If they had predicted different test outputs, which should the agent use as attempt 1, and why?

Intermediate

Advanced
