Diagnosis is reasoning from observed malfunctions back to their causes: a doctor from symptoms to a disease, a mechanic from a noise to a part, a programmer from a failing test to a bug. It is a kind of abduction: inference to the best explanation. For a cognitive agent, the most important thing to diagnose is often itself. When your ARC agent gets a train pair wrong, what did it get wrong, and what would fix it?

Reading
  • McShane, Nirenburg & English, Ch. 8, §8.5: Detecting jumping to conclusions (pp. 245–248 · PDF 256–259 · 4 pages)

Part 1. Diagnosis as Abduction

Deduction runs from causes to effects: if the patient has Alphaitis, then A will be high. Diagnosis runs the other way: A is high, so what could cause that? Many causes could, so diagnosis must choose among explanations by several principles:

  • Coverage: the explanation must account for all the observations.
  • Parsimony: prefer fewer hypotheses (one disease rather than three).
  • Plausibility: prefer common causes over rare ones, other things being equal.
  • Interactions: two causes can mask each other's effects, so an observation's absence does not rule a cause out.
Diagnosis maps the data space onto the hypothesis space. Here one disorder covers all four observations; a pair of others also covers them, because one raises C and the other lowers it.
Human cognition connection

Arthur Elstein and colleagues (1978) watched physicians diagnose simulated patients. Contrary to the textbook picture of gathering all the data first, doctors formed a few hypotheses within the first minutes and then gathered data to test them. That is efficient, and it carries a characteristic failure: premature closure, settling on a diagnosis before the evidence warrants it. This week's McShane reading describes a tutoring agent built to catch exactly that, checking a learner's diagnosis against the clinical preconditions for it and naming which findings are still missing.

Part 2. An Abductive Diagnosis Agent

The agent's knowledge: what each disorder does to six lab values.
doctor_agent.py: knowledge Python
# Each disorder raises (+) or lowers (-) some lab values. DISORDERS = { 'Alphaitis': {'A': '+', 'C': '-', 'F': '+'}, 'Betatosis': {'B': '+', 'C': '+', 'D': '-'}, 'Gammonia': {'A': '-', 'E': '+'}, 'Deltacol': {'B': '-', 'F': '+'}, 'Epsilitis': {'C': '+', 'D': '-', 'E': '+'}, 'Zetad': {'A': '+', 'B': '+', 'D': '-', 'F': '+'}, } PRIOR = {'Alphaitis': 0.10, 'Betatosis': 0.05, 'Gammonia': 0.02, 'Deltacol': 0.08, 'Epsilitis': 0.03, 'Zetad': 0.01}
doctor_agent.py: predicting combined effects (with cancellation) Python
def predict(hypotheses): """Combined effect of several disorders: opposite effects cancel.""" total = {} for h in hypotheses: for test, sign in DISORDERS[h].items(): total[test] = total.get(test, 0) + (1 if sign == '+' else -1) return {t: ('+' if v > 0 else '-') for t, v in total.items() if v != 0}
doctor_agent.py: coverage, parsimony, plausibility Python
def diagnose(observed, max_size=3): """Coverage: the prediction must match the observations exactly. Parsimony: try one disorder, then pairs, then triples, and stop at the smallest size that works. Plausibility: rank ties by prior probability.""" for size in range(1, max_size + 1): found = [set(c) for c in combinations(DISORDERS, size) if predict(c) == observed] if found: return sorted(found, key=lambda c: -min(PRIOR[h] for h in c)) return []
doctor_agent.py: three patients Python
for observed in [{'A': '+', 'C': '-', 'F': '+'}, {'A': '+', 'B': '+', 'D': '-', 'F': '+'}, {'B': '+', 'D': '-', 'F': '+', 'A': '+', 'C': '+'}]: print('observed:', observed) for expl in diagnose(observed): print(' explained by', sorted(expl), ' prior', min(PRIOR[h] for h in expl))
doctor_agent.py: an interaction Python
obs = {'A': '+', 'B': '+', 'D': '-', 'F': '+'} pairs = [sorted(c) for c in combinations(DISORDERS, 2) if predict(c) == obs] print('pairs that also explain case 2:', pairs) print(' Alphaitis lowers C and Betatosis raises it: the effects cancel.')

Patient 2 shows the principles in tension. Parsimony picks Zetad, a single disorder, though it is rare (prior 0.01). Alphaitis and Betatosis together also explain everything, each is more common, and their effects on C cancel so C looks normal. Which is right depends on how much you trust parsimony versus base rates, and a real diagnostician would order one more test to tell them apart. Patient 3 needs two disorders: no single one covers everything.

Part 3. A Taste of ARC: Diagnosing Your Own Wrong Answers

Week 3's program search threw away every program that missed a train pair. But some misses are informative. A program that produces the right shapes in the wrong colours is nearly right: diagnose the fault, and the repair is obvious. Here is a small fault taxonomy for wrong ARC answers:

Kinds of fault in a wrong ARC answer, and what each suggests.
arc_diagnose.py: localizing the fault Python
def diagnose(got, want): """Localize the fault in a wrong answer. Returns the kind of fault and, where possible, the information needed to repair it.""" if not got or not got[0]: return ('crashed', None) if dims(got) != dims(want): return ('wrong size', None) diff = [(r, c) for r in range(len(want)) for c in range(len(want[0])) if got[r][c] != want[r][c]] if not diff: return ('correct', None) mapping = {} for r, c in diff: if mapping.setdefault(got[r][c], want[r][c]) != want[r][c]: return ('wrong cells', len(diff)) # every wrong cell of colour x should have been colour y: a colour fault, # but only if no correct cell of colour x would be broken by the fix if any(got[r][c] in mapping for r in range(len(got)) for c in range(len(got[0])) if (r, c) not in diff): return ('wrong cells', len(diff)) return ('wrong colours', mapping)

Shell output Output

Each verdict is useful. "Wrong size" says the program is the wrong kind entirely. "Wrong cells, 2" says it was very close but not in a way a colour fix will mend. "Wrong colours" comes with its own repair: a colour mapping. The agent now uses diagnosis to repair near misses:

arc_diagnose.py: diagnose, then repair Python
def repair(task): """Take each one-step program whose answers have the right SIZE on every train pair, diagnose its errors, and if every pair shows the same colour fault, repair it by appending a recolouring step.""" for prog in [()] + [(name,) for name in PRIMS]: # () = leave the grid as it is faults = [] for p in task['train']: try: got = run(prog, p['input']) except Exception: got = None faults.append(diagnose(got, p['output'])) kinds = {k for k, _ in faults} if kinds == {'correct'}: return prog, None, faults if kinds <= {'correct', 'wrong colours'}: mapping = {} for k, m in faults: if k == 'wrong colours': mapping.update(m) fixed = lambda g, prog=prog, m=mapping: [[m.get(v, v) for v in row] for row in run(prog, g)] if all(fixed(p['input']) == p['output'] for p in task['train']): return prog, mapping, faults return None, None, None
arc_diagnose.py: sweep Python
if __name__ == '__main__': fixed = [] for name in sorted(os.listdir('data/training')): t = load_task('data/training/' + name) prog, mapping, faults = repair(t) if prog is not None and mapping: f = lambda g: [[mapping.get(v, v) for v in row] for row in run(prog, g)] if all(f(p['input']) == p['output'] for p in t['test']): fixed.append(f'{name[:-5]} ({prog[0] if prog else "identity"} + recolour {mapping})') print(len(fixed), 'tasks repaired after diagnosis:') for s in fixed: print(' ', s)

The repairs are only accepted after they reproduce every train pair, which is the diagnostic version of not jumping to conclusions.

SAM lens

Diagnosis is the Monitor turning a failure signal into a specific account of what went wrong, and repair is the Monitor directing the Decider. The fault taxonomy itself is knowledge in long-term Memory, and it should grow: every new kind of near miss you notice in your agent's failures is a new branch.
