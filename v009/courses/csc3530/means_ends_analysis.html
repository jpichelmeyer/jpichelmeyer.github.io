Generate and test proposes candidates without looking where it is going. Means-ends analysis (MEA) looks. It compares where it is with where it wants to be, finds the differences, and picks an operator that reduces them. It was the core of the first general AI problem solver, Newell, Shaw and Simon's GPS (1959), and it was built directly from transcripts of people thinking aloud while solving puzzles.

Reading
  • Hofstadter & Sander, Ch. 5: Unwitting Default Assumptions; Flitting from One Essence to Another (pp. 293–295 · PDF 308–310 · 3 pages)
    Children solving the Towers of Hanoi take about thirty moves instead of seven because of one silent assumption about what a "move" is. Representation decides how hard search is.

Part 1. Reducing Differences

Means-ends analysis. If the operator that would reduce a difference cannot be applied yet, achieving its preconditions becomes a subgoal: the "means" to the "end."

GPS stored its knowledge in a table of connections: for each kind of difference, which operators are relevant. For ARC, a first version of that table might look like this:

A GPS-style table of connections for ARC. If the output is a different size from the input, only size-changing operators are relevant, which shrinks the search enormously.

MEA is greedy, and greed has two failure modes. First, a plateau: no operator reduces the difference, so MEA has no guidance. Second, a trap: reducing one difference now makes another impossible later, so the agent has to temporarily make things worse to get better. The classic example is the Sussman anomaly in the blocks world.

Human cognition connection

People are recognizably MEA-like. On the Towers of Hanoi, solvers say things like "I need the big disk on the right peg, so first I have to get the two small ones out of the way," which is subgoaling in plain words. People also show the trap: they resist moves that seem to go backwards, even when such a move is required. This week's Hofstadter reading adds a twist. Eight-year-olds took about 30 moves on a three-disk Tower of Hanoi because they silently assumed a disk could not jump from the first peg to the third. Their difference-reduction was fine; their representation of the operator was wrong.

Part 2. An MEA Agent in the Blocks World

A state says what each block is sitting on. The only operator moves a clear block onto the table or onto another clear block.

blocks_agent.py: the world Python
# A state maps each block to what it sits on ('table' or another block). def clear(state, b): return all(under != b for under in state.values()) def moves(state): """Operator Move(block, dest): legal if the block is clear and the destination is clear (the table always is).""" for b in state: if not clear(state, b): continue for dest in ['table'] + [d for d in state if d != b]: if dest != state[b] and (dest == 'table' or clear(state, dest)): new = dict(state) new[b] = dest yield (b, dest), new

The difference is the number of goal conditions not yet true. MEA applies whichever legal move leaves the smallest difference, refusing to revisit a state or to undo a protected condition.

blocks_agent.py: means-ends analysis Python
def holds(state, cond): kind, x, *y = cond return state[x] == y[0] if kind == 'on' else clear(state, x) def difference(state, goals): """How many goal conditions are not yet true.""" return sum(not holds(state, g) for g in goals) def mea(state, goals, protect=(), limit=8, verbose=True): """Repeatedly apply the operator that most reduces the difference. Never break a protected condition, never revisit a state.""" plan, seen = [], {tuple(sorted(state.items()))} while difference(state, goals) > 0: options = [(difference(new, goals), op, new) for op, new in moves(state) if tuple(sorted(new.items())) not in seen and all(holds(new, p) for p in protect)] if not options or len(plan) >= limit: if verbose: print(' stuck: every move repeats a state or breaks a protected goal') return None, state d, op, state = min(options, key=lambda o: o[0]) seen.add(tuple(sorted(state.items()))) plan.append(op) if verbose: print(f' move {op[0]} onto {op[1]:5} difference now {d}') return plan, state
blocks_agent.py: a problem MEA solves Python
print('Problem 1: B sits on A; goal: A on C') mea({'A': 'table', 'B': 'A', 'C': 'table'}, [('on', 'A', 'C')])
Shell output Output
Problem 1: B sits on A; goal: A on C move B onto table difference now 1 move A onto C difference now 0

The first move does not reduce the difference at all (it stays 1). MEA crossed a small plateau by picking the first equally good option, which happened to clear A. Now the anomaly:

The Sussman anomaly (Gerald Sussman, 1973). Achieving either goal first, the obvious way, blocks the other one.
blocks_agent.py: the Sussman anomaly Python
START = {'A': 'table', 'B': 'table', 'C': 'A'} GOAL = [('on', 'A', 'B'), ('on', 'B', 'C')] print('Problem 2 (the Sussman anomaly): C on A; goal: A on B and B on C') mea(START, GOAL)
Shell output Output
Problem 2 (the Sussman anomaly): C on A; goal: A on B and B on C move B onto C difference now 1 stuck: every move repeats a state or breaks a protected goal

MEA moved B onto C because that satisfied one goal immediately. Now A is buried under C, under B, and nothing it can do reduces the difference without undoing its progress. The fix is problem reduction: break the goal into subgoals, including the preconditions (a block must be clear before it can move or receive another block), and find an order in which the subgoals can be achieved one after another.

blocks_agent.py: problem reduction Python
def reduce(state, goals): """Problem reduction: break the goal into subgoals (every block involved must be clear at some point, then each 'on' must hold), and search for an order of subgoals that MEA can achieve one at a time. Each 'on' is protected once achieved so later steps cannot undo it.""" blocks = sorted({b for _, x, y in goals for b in (x, y) if b != 'table'}) subgoals = [('clear', b) for b in blocks] + list(goals) for tried, order in enumerate(permutations(subgoals), 1): s, plan, protect = dict(state), [], [] for g in order: steps, s = mea(s, [g], protect=protect, verbose=False) if steps is None: break plan += steps if g[0] == 'on': protect.append(g) if difference(s, goals) == 0: return order, plan, tried return None, None, tried print('Problem 2 with problem reduction:') order, plan, tried = reduce(START, GOAL) print(' orders tried:', tried) print(' subgoal order:', order) print(' plan:', plan)
Shell output Output
Problem 2 with problem reduction: orders tried: 2 subgoal order: (('clear', 'A'), ('clear', 'B'), ('clear', 'C'), ('on', 'B', 'C'), ('on', 'A', 'B')) plan: [('C', 'table'), ('B', 'C'), ('A', 'B')]

The first ordering stacked A on B first and got stuck. The second clears everything, then builds from the bottom up, and gives the three-move plan a person would find. The lesson generalizes: the order of subgoals matters, and protecting what you have achieved can make a problem unsolvable if the order is wrong. Planning, next week, attacks this head-on.

Part 3. Means-Ends Pathfinding

On a map, the obvious difference between where you are and where you want to be is the distance to the goal. Searching by always expanding the cell with the smallest remaining difference is greedy best-first search, which is MEA for pathfinding. Adding the cost already paid to the difference gives A*, which keeps MEA's focus but cannot be trapped into a long detour:

maze_mea.py Python
# Pathfinding guided by the difference to the goal: greedy best-first vs A*. import heapq MAZE = ['S...#.....', '.##.#.###.', '.#..#...#.', '.#.####.#.', '.#......#G', '.########.', '..........'] START, GOAL = (0, 0), (4, 9) def neighbours(cell): r, c = cell for dr, dc in [(1, 0), (-1, 0), (0, 1), (0, -1)]: nr, nc = r + dr, c + dc if 0 <= nr < len(MAZE) and 0 <= nc < len(MAZE[0]) and MAZE[nr][nc] != '#': yield nr, nc def difference(cell): # Manhattan distance to the goal return abs(cell[0] - GOAL[0]) + abs(cell[1] - GOAL[1]) def search(use_cost): """Always expand the cell with the smallest score. greedy (means-ends): score = difference still to remove A*: score = steps taken so far + difference""" frontier = [(difference(START), 0, START, [START])] done = set() while frontier: _, cost, cell, path = heapq.heappop(frontier) if cell == GOAL: return path, len(done) if cell in done: continue done.add(cell) for nxt in neighbours(cell): if nxt not in done: score = difference(nxt) + (cost + 1 if use_cost else 0) heapq.heappush(frontier, (score, cost + 1, nxt, path + [nxt])) for name, use_cost in [('greedy', False), ('A*', True)]: path, expanded = search(use_cost) print(f'{name:6}: path of {len(path) - 1} steps, {expanded} cells expanded') for r, row in enumerate(MAZE): print(' ', ''.join('*' if (r, c) in path and ch == '.' else ch for c, ch in enumerate(row)))
Shell output Output
greedy: path of 27 steps, 27 cells expanded S***#***** .##*#*###* .#**#***#* .#*####*#* .#******#G .########. .......... A* : path of 17 steps, 31 cells expanded S...#..... *##.#.###. *#..#...#. *#.####.#. *#......#G *########* **********

The goal is just behind a wall. Greedy search heads straight at it, keeps getting closer, and ends up taking the long way round: 27 steps. A* expands four more cells and finds the 17-step path. Breadth-first search from last lesson would also find 17 steps but expands more cells, because it ignores the goal entirely.

Part 4. A Taste of ARC: Move Until Touching

Some ARC tasks are literally means-ends problems. In 05f2a901 a red shape slides toward an azure square until they touch.

Task 05f2a901. The difference to reduce is the gap between the two objects; the operators are one-cell moves.
arc_mea.py Python
from arc_utils import load_task, find_objects, dims # --- difference --- def gap(cells_a, cells_b): """Difference measure: empty cells between two objects (0 means they touch side by side).""" return min(abs(r1 - r2) + abs(c1 - c2) for r1, c1 in cells_a for r2, c2 in cells_b) - 1 # --- operators --- STEPS = {'up': (-1, 0), 'down': (1, 0), 'left': (0, -1), 'right': (0, 1)} def shift(cells, step): dy, dx = STEPS[step] return [(r + dy, c + dx) for r, c in cells] # --- mea --- def move_until_touching(grid, mover_color, target_color, trace=False): """Means-ends analysis: while there is a difference (a gap), apply the operator that reduces it the most.""" objs = {o['color']: o for o in find_objects(grid, bg=0)} mover, target = objs[mover_color]['cells'], objs[target_color]['cells'] h, w = dims(grid) while gap(mover, target) > 0: best = min(STEPS, key=lambda s: gap(shift(mover, s), target)) if gap(shift(mover, best), target) >= gap(mover, target): break # no operator helps: give up mover = shift(mover, best) if trace: print(f' {best:5} -> gap {gap(mover, target)}') out = [[0] * w for _ in range(h)] for r, c in objs[target_color]['cells']: out[r][c] = target_color for r, c in mover: out[r][c] = mover_color return out task = load_task('data/training/05f2a901.json') print('train pair 1:') move_until_touching(task['train'][0]['input'], 2, 8, trace=True) solve = lambda g: move_until_touching(g, 2, 8) print('fits every train pair:', all(solve(p['input']) == p['output'] for p in task['train'])) print('test correct:', solve(task['test'][0]['input']) == task['test'][0]['output'])
Shell output Output
train pair 1: down -> gap 5 down -> gap 4 down -> gap 3 down -> gap 2 down -> gap 1 down -> gap 0 fits every train pair: True test correct: True

The agent never searched. At each step it measured the gap, chose the move that shrank it most, and stopped when the gap was zero. MEA also helps ARC at the level of programs, not just objects: compare a train input with its output, find the differences (size, colours, positions, counts), and use the table of connections to decide which kind of operator to try first. That is a smart generator for last week's program search.

SAM lens

MEA is a Decider driven by a comparison that the Perceptor must make possible: the agent can only reduce differences it can represent. The table of connections is long-term procedural Memory. Detecting a plateau or a trap is a job for the Monitor.
