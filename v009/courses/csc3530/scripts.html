A frame describes a thing. A script describes a stereotyped sequence of events: going to a restaurant, a birthday party, a visit to the doctor. Roger Schank and Robert Abelson introduced scripts (1977) to explain how people understand stories so effortlessly: we fill in everything the story leaves out from our script for that kind of situation. Scripts are also how experts work: a stereotyped plan with slots, ready to be instantiated.

Part 1. What a Script Contains

The restaurant script. Entry conditions must hold for the script to apply; results hold afterward; roles and props are filled by the particular people and things in a story. Real scripts have several tracks (fast food, sit-down, cafeteria) that share most structure.

A script makes understanding cheap. A three-sentence story activates the script, the mentioned events are matched to scenes, and every scene in between is assumed. Ask "did John eat?" and the answer is yes, though the story never said so.

Understanding a story with a script. Four events were stated; five were filled in.

The danger is the same as with frame defaults: scripts fill in things that did not happen. A good script-based understander notices deviations (events that are not in the script, or that block it) and becomes cautious about what it infers afterward.

Human cognition connection

Gordon Bower, John Black and Terrence Turner (1979) asked people to list the events of common activities. Their lists agreed closely: people share scripts. Then they had people read script-based stories and later recognize sentences. People confidently "remembered" script events that were never in the story, especially ones in the middle of the sequence. Our memory of a story is partly the script itself. This week's McShane reading shows how a working agent stores scripts, including the script for its own operation (perceive, interpret, deliberate, act), and how a script becomes a plan once its path and roles are chosen.

def understand(story, script): """Match each sentence to a scene by its verb, then fill in every scene that must have happened between the first and last matched scenes. A sentence that matches no scene is a possible DEVIATION: scenes inferred after it are only guesses.""" scenes = script['scenes'] matched, deviation_at = {}, None for sentence in story: words = set(sentence.lower().strip('.').split()) hits = [i for i, (event, verbs) in enumerate(scenes) if words & verbs] if hits: for i in hits: matched[i] = sentence elif deviation_at is None: deviation_at = max(matched) if matched else 0 print(f' ! "{sentence}" is not in the script: possible deviation') first, last = min(matched), max(matched) account = [] for i in range(first, last + 1): if i in matched: how = 'stated' elif deviation_at is not None and i > deviation_at: how = 'UNCERTAIN (after a deviation)' else: how = 'inferred from the script' account.append((scenes[i][0], how)) return account

def did_eat(account): how = dict(account).get('customer eats', 'not mentioned') return {'stated': 'yes', 'inferred from the script': 'yes (inferred)'}.get(how, 'unknown') for story in [['John went to a restaurant.', 'He ordered lobster.', 'He paid and left a big tip.'], ['Mary went to a restaurant.', 'She ordered soup.', 'She waited an hour.', 'She left.']]: print(' '.join(story)) account = understand(story, RESTAURANT) for event, how in account: print(f' {event:28} {how}') print(' Did they eat?', did_eat(account))

In John's story the agent filled in five scenes, including eating. Mary's story contains a sentence the script does not know ("she waited an hour"). That is the signal of an obstacle in Schank and Abelson's terms, and the agent stops trusting the script's defaults after it. Without that check it would have concluded that Mary ate and paid.

Part 3. A Taste of ARC: Task Scripts

Solve enough ARC tasks and you start recognizing kinds of tasks, each with its own stereotyped solution. The most common might be called the "object task" script: find the objects, select some of them, do something to each, draw the result. The fixed steps are the script; the selection and the action are its slots.

The object-task script. Program search searched over all sequences of primitives; the script searches only over slot fillers, a far smaller space shaped by experience.
arc_script.py: the script and its slots Python
# The "object task" script: a stereotyped sequence with open slots. # 1. find the objects (fixed) # 2. SELECT some of them (slot) # 3. apply an ACTION to each (slot) # 4. draw the result (fixed) SELECT = { 'all': lambda objs, o: True, 'largest': lambda objs, o: o['size'] == max(x['size'] for x in objs), 'smallest': lambda objs, o: o['size'] == min(x['size'] for x in objs), 'not largest': lambda objs, o: o['size'] != max(x['size'] for x in objs), 'single cells': lambda objs, o: o['size'] == 1, 'touching the edge': lambda objs, o: o['edge'], 'not touching the edge': lambda objs, o: not o['edge'], } ACTIONS = ['recolor', 'delete', 'keep only these'] def run_script(grid, select, action, color=None, of_color=None): h, w = dims(grid) objs = find_objects(grid, bg=0, diagonal=True) for o in objs: o['edge'] = o['top'] == 0 or o['left'] == 0 or o['bottom'] == h - 1 or o['right'] == w - 1 chosen = [o for o in objs if SELECT[select](objs, o) and (of_color is None or o['color'] == of_color)] out = [row[:] for row in grid] if action == 'keep only these': out = [[0] * w for _ in range(h)] for o in chosen: for r, c in o['cells']: out[r][c] = grid[r][c] for o in chosen: for r, c in o['cells']: if action == 'recolor': out[r][c] = color elif action == 'delete': out[r][c] = 0 return out
arc_script.py: instantiating it Python
def instantiate(task): """Fill the script's slots so that every train pair is reproduced. The recolour constant is read off the first pair.""" p0 = task['train'][0] if dims(p0['input']) != dims(p0['output']): return None out_colors = sorted({v for row in p0['output'] for v in row} - {0}) in_colors = [None] + sorted({v for row in p0['input'] for v in row} - {0}) for of_color in in_colors: # optional extra slot: only objects of one colour for select in SELECT: for action in ACTIONS: for color in (out_colors if action == 'recolor' else [None]): if all(run_script(p['input'], select, action, color, of_color) == p['output'] for p in task['train']): return select, action, color, of_color return None

Four tasks from one script, and every answer reads like a sentence: select the smallest objects; delete them. The point of scripts is not one script, though. It is a library of them, one per task family you recognize (object tasks, tiling tasks, gravity tasks, "complete the symmetry" tasks), each with a handful of slots. Recognizing which script applies is classification; filling its slots is a small, focused search. That is how experts in any field look so fast.

SAM lens

Scripts are long-term semantic Memory about events, and a script for a solution method is procedural Memory. Activating the right script is the Perceptor's job (recognition); filling slots is the Decider's. Noticing deviations from the script is the Monitor's, as in Mary's story.
