Last week you got an agent circling on its own, and then wandering, using nothing but a rotation method and _move_forward. Steering behaviors are the same two primitives, just with a reason to turn: instead of a fixed rate or a random one, the agent's rotation reacts to something in the world.

Part 1. What Is a Steering Behavior?

The idea (originally Craig Reynolds, 1986; the same person behind the boids you'll build in a couple lessons) is that an agent computes a heading it wants (toward a target, away from a target, whatever the behavior calls for), and turns toward it gradually rather than snapping instantly. The magenta agent above is mid-turn toward the cyan one, not yet facing it exactly, which is the normal, in-progress state a steering agent spends most of its time in.

Game developers reach for a fairly small, well-known set of these. Up to eight you'll see referenced constantly (bold marks the ones this lesson actually works with):

  1. Seek: turn toward a target and move forward.
  2. Flee: turn away from a target and move forward.
  3. Arrive: Seek, but slow down smoothly on approach instead of overshooting.
  4. Pursue: Seek, but aim at where a moving target will be, not where it is.
  5. Evade: Flee's version of Pursue, running from a predicted future position.
  6. Wander: drift with a randomized turn rate, no target at all (already built last lesson).
  7. Obstacle Avoidance: steer around solid geometry in the way (its own lesson this week).
  8. Flocking (Separation, Alignment, Cohesion): steer relative to a group of neighbors instead of a fixed target (also its own lesson this week).

Part 2. Choosing a Behavior

Right now, _process hardcodes which rotation method it calls. To let different agents do different things, and to switch behaviors at all, that needs to become a choice rather than a fixed call. Same dictionary-of-functions idea you may have seen elsewhere: a string picks which method runs.

agent.gd GDScript
@export var speed_max: float = RATE_MOVE @export var turn_rate: float = RATE_ROTATION @export var target: Node2D @export var steering_type: String = "wander" var rotation_method_from_type = { "wander" : _rotation_wander, } func _process(delta: float) -> void: var move_speed: float = speed_max if steering_type in rotation_method_from_type.keys(): move_speed = rotation_method_from_type[steering_type].call(delta, turn_rate) _move_forward(delta, move_speed)

One small change to last week's two rotation methods: instead of returning nothing, each one now also reports back how fast to move forward this frame.

agent.gd GDScript
func _rotation_auto_simple(delta_passed: float, rotation_angle: float) -> float: rotation += delta_passed * rotation_angle return speed_max func _rotation_wander(delta_passed: float, rotation_angle_max: float) -> float: rotation += delta_passed * randf_range(-rotation_angle_max, rotation_angle_max) return speed_max

Nothing changes visibly yet (both still just return speed_max every time), but this is what lets Arrive slow the agent down later without needing a second, parallel system alongside the rotation dictionary. We left "auto_simple" out of the dictionary since Wander already covers similar ground, but the function is still sitting in your script if you want it back.

Part 3. Implementing Seek

Seek asks the agent to turn toward a target, at full speed. Vector2.UP.angle_to(direction) gives the rotation needed so that the agent's forward vector (recall, -transform.y, which points the same way as Vector2.UP.rotated(rotation)) ends up pointing at direction. angle_difference(from, to) is a built-in Godot function returning the shortest signed distance between two angles, which matters near the wraparound point (350° and 10° are only 20° apart, not 340°, and plain subtraction gets that wrong).

agent.gd GDScript
var rotation_method_from_type = { "wander" : _rotation_wander, "seek" : _rotation_seek, } func _rotation_seek(delta_passed: float, turn_rate_value: float) -> float: var direction: Vector2 = target.global_position - global_position var desired_angle: float = Vector2.UP.angle_to(direction) var diff: float = angle_difference(rotation, desired_angle) rotation += clamp(diff, -turn_rate_value * delta_passed, turn_rate_value * delta_passed) return speed_max
Magenta turns to face and close on cyan.

Part 5. Try It Yourself: Arrive and Flee

Both follow the exact same shape as _rotation_seek.

agent.gd GDScript
func _rotation_flee(delta_passed: float, turn_rate_value: float) -> float: pass func _rotation_arrive(delta_passed: float, turn_rate_value: float) -> float: pass
Same heading as Seek, shorter arrow inside the radius: less returned speed.
Same setup as Seek, direction and facing flipped.

For Flee, the direction just points the opposite way: global_position - target.global_position instead of target.global_position - global_position. Everything else, the angle math and the returned speed, stays identical to Seek.

For Arrive, keep Seek's angle exactly as it is, and add a slowing_radius export. Measure the distance to the target, and return speed_max outside that radius, scaling it down toward zero the closer the agent gets inside it. Because _process already reads whatever speed a rotation method returns, that distance-based scaling is the only new idea needed.

Add both to rotation_method_from_type the same way "seek" was added, and try switching AgentA's steering_type between them.
