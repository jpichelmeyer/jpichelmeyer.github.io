A variable has never actually been "a box that holds a value," even though that's usually a harmless way to think about it. It's closer to a label attached to a value sitting somewhere in the computer's memory. For numbers and strings, that difference almost never shows up. For lists, it shows up constantly, and it's worth seeing exactly why once, directly.

Part 1. A Variable Is a Label, Not a Box

id() returns a number identifying exactly where in memory a value actually lives. Two names that refer to the literal same value in memory will always report the same id.

memory.py Python
a = [1, 2, 3] b = a print(a is b) # True, b isn't a copy, it's a second label on the same list

is checks exactly this, whether two names point at the same object in memory, which is a genuinely different question from == (whether two things merely look equal, even if they're stored separately).

Part 2. Two Names, One List

Since a and b are two labels on the same list, changing the list through either name changes what both of them see, there was only ever one list to begin with.

memory.py Python
a = [1, 2, 3] b = a b.append(4) print(a) # [1, 2, 3, 4], a changed too, even though only b.append() was called

Nothing about this is a bug or a special case, it's the direct, honest consequence of b = a never having copied anything. It only ever attached a second name to the list that already existed.

Part 3. Copying On Purpose

To actually get a second, independent list, you have to ask for a copy explicitly.

memory.py Python
a = [1, 2, 3] b = a.copy() b.append(4) print(a) # [1, 2, 3], untouched print(b) # [1, 2, 3, 4] print(a is b) # False, two separate lists now

Part 4. The Same Thing Happens With Function Arguments

Passing a list into a function doesn't copy it either, the parameter inside the function is just one more label on the same list the caller already had.

memory.py Python
def add_item(lst): lst.append("surprise") my_list = [1, 2, 3] add_item(my_list) print(my_list) # [1, 2, 3, 'surprise'], changed by the function

This is exactly the same phenomenon as Part 2, wearing a different outfit: lst inside the function and my_list outside it are two names for one list, so a change made through either one is visible through both.
