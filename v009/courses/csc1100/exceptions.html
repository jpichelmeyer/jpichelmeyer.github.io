The errors in the last lesson all crashed the program outright. An exception is the same underlying thing, a runtime error, except now you get a chance to catch it and decide what happens next, instead of the whole program stopping.

Part 1. try / except

Code inside a try block runs normally, unless it raises an exception, in which case Python jumps straight to a matching except block instead of crashing.

exceptions.py Python
try: x = int("abc") except ValueError: print("that wasn't a number")

int("abc") raises a ValueError on its own, uncaught, that would crash the program with a traceback just like last lesson. Wrapped in try/except, the program instead runs the except block and keeps going.

Part 2. Matching the Right Exception

except only catches the exception type you name. Naming ValueError won't catch a ZeroDivisionError, you need a matching except for each kind of failure you actually expect.

exceptions.py Python
try: print(10 / 0) except ZeroDivisionError: print("can't divide by zero")

Part 3. Multiple except Clauses

A function can guard against more than one kind of failure at once, one except per exception type it's prepared to handle.

exceptions.py Python
def safe_divide(a, b): try: return a / b except ZeroDivisionError: return None except TypeError: return None print(safe_divide(10, 2)) print(safe_divide(10, 0))

The first call divides cleanly and returns a real number. The second hits a ZeroDivisionError, which the matching except catches, returning None instead of crashing.

Part 4. else and finally

else runs only if the try block succeeded with no exception at all. finally runs no matter what happened, exception or not, useful for cleanup that has to happen either way.

exceptions.py Python
try: x = int("42") except ValueError: print("bad input") else: print("parsed:", x) finally: print("done")

Part 5. Raising Your Own

raise triggers an exception on purpose, the same mechanism as the errors Python raises for you, just aimed at a problem specific to your own code.

exceptions.py Python
def set_age(age): if age < 0: raise ValueError("age can't be negative") return age print(set_age(25)) try: set_age(-5) except ValueError as e: print("caught:", e)

as e captures the exception itself, letting you access its message with e, rather than only knowing that something went wrong.

Checkpoint

Before moving on, make sure you can:

  1. Wrap risky code in try/except and explain what happens if the exception type doesn't match.
  2. Handle more than one kind of exception from the same try block.
  3. Explain the difference between else and finally.
  4. Raise your own exception with a meaningful message, and catch it with as to read that message back.
