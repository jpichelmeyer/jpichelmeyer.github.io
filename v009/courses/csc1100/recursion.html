A function is allowed to call itself. That's the whole idea behind recursion: a function whose own definition includes a call to that same function, working on a smaller version of the same problem each time.

Part 1. Base Case and Recursive Case

A recursive function needs exactly two parts to actually work rather than call itself forever: a base case, simple enough to answer directly with no further calls, and a recursive case, which calls the function again on a smaller version of the problem, getting closer to the base case every single time.

recursion.py Python
def factorial(n): if n <= 1: return 1 # base case return n * factorial(n - 1) # recursive case print(factorial(4))

Every recursive call passes a smaller n than the one before it, n - 1, specifically, which is exactly what guarantees the base case eventually gets reached instead of the calls continuing forever.

Part 2. Going Down: The Calls Stack Up

factorial(4) can't finish until factorial(3) finishes, which can't finish until factorial(2) finishes, and so on. Each call has to wait, paused, for the one below it to return before it can do its own multiplication. Python (like most languages) keeps track of every paused call on something called the call stack, one frame per call still waiting on an answer.

Every call above the base case is paused, waiting on the one below it to return, before any multiplication can happen.

Part 3. Coming Back Up: The Stack Unwinds

The base case is the only one that returns immediately, with no waiting. Once it does, every paused call above it can finally finish, one at a time, from the bottom up: each one takes the value it was waiting on, multiplies, and returns its own answer to whichever call is waiting on it.

The base case returns first; every value above it multiplies in its own n only once the call below it actually answers.

Nothing about this is unique to computers, it's exactly the same process you'd use tracing it by hand on paper: write down the chain of calls going down, then work your way back up the chain filling in real numbers once you hit something you can answer directly.

Part 4. A Second Example

Summing the numbers from n down to 1 follows the identical shape: a base case for the smallest input, a recursive case that peels off one piece and calls itself on the rest.

recursion.py Python
def sum_to(n): if n == 0: return 0 # base case return n + sum_to(n - 1) # recursive case print(sum_to(4))

Trace it yourself before running it: sum_to(4) needs 4 + sum_to(3), which needs 3 + sum_to(2), down to sum_to(0) returning 0 with nothing left to wait on. Unwinding: 0, 1+0, 2+1, 3+3, 4+6, landing on 10.

Part 5. What Happens Without a Base Case

Delete the base case, or write one that's never actually reached, and the recursive case keeps calling itself with no way out. Unlike a runaway while loop, which can genuinely run forever, Python actually catches this for you: it keeps a limit on how many calls can be waiting at once, and once that limit is hit, it stops the program with a RecursionError rather than freezing. Still a bug worth avoiding, just a noisier, more honest one than a silent infinite loop.
