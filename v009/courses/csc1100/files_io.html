Everything your programs have produced so far disappears the moment they stop running. Writing to a file is how a program's output outlives the program itself, and reading one back is how it picks up where it left off.

One honest note about the examples on this page: the editor below runs inside your browser, using a small sandboxed filesystem that exists only for this page, not your actual computer's hard drive. The code and its behavior are completely real, open(), write(), and read() work exactly as shown, but a file you create here won't show up anywhere on your machine. On your own computer, in Thonny, the exact same code creates a real file sitting right next to your script.

Part 1. Opening and Writing

open(filename, mode) gives you a file object to work with. "w" mode opens a file for writing, creating it if it doesn't exist yet, and erasing whatever was already there if it does.

files.py Python
f = open("notes.txt", "w") f.write("hello file\n") f.write("second line\n") f.close()

write() doesn't add a newline for you the way print() does, that's why \n shows up explicitly at the end of each line above. close() matters too: it's what actually makes sure everything you wrote gets saved.

Part 2. Reading It Back

files.py Python
f = open("notes.txt", "r") content = f.read() print(content) f.close()

"r" mode opens for reading, and read() pulls in the entire contents as one string, newlines and all.

Part 3. The with Statement

Forgetting close() is an easy, common mistake, and it can leave a file's changes unsaved. with closes the file automatically once its indented block finishes, even if something goes wrong partway through, which makes it the standard, preferred way to work with files.

files.py Python
with open("notes.txt", "r") as f: content = f.read() print(content)

No f.close() anywhere, and none is needed, it happens on its own the moment the with block ends.

Part 4. Reading Line by Line

A file object can be looped over directly, one line at a time, without loading the whole thing into a single string first.

files.py Python
with open("notes.txt", "r") as f: for line in f: print(line.strip())

.strip() is doing real work there, not just tidying up: each line still has its trailing \n attached, and print() would otherwise add a second newline on top of it, leaving a blank line between every line of output.

Part 5. Appending

"a" mode opens for appending: new writes get added to the end of whatever's already in the file, instead of erasing it the way "w" does.

files.py Python
with open("notes.txt", "a") as f: f.write("third line\n") with open("notes.txt", "r") as f: print(f.read())
