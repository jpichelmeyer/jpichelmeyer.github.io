So far, every variable has held exactly one value. A collection holds many, as a single thing you can pass around, loop over, and grow. Python has four you'll use constantly, and each one makes a different tradeoff: ordered or not, changeable or not, unique values or not.

Part 1. Lists

A list is an ordered, changeable sequence, written with square brackets. Indexing and slicing work exactly the way they did for strings.

collections.py Python
nums = [10, 20, 30] print(nums[0]) # 10 print(len(nums)) # 3 nums.append(40) print(nums) # [10, 20, 30, 40] for n in nums: print(n)

Unlike a string, a list is mutable, you can change it in place without building a new one.

collections.py Python
nums = [10, 20, 30] nums[0] = 99 print(nums) # [99, 20, 30], the same list, changed in place

Part 2. Tuples

A tuple looks like a list but uses parentheses, and once built, it can't be changed, no appending, no reassigning an index. Reach for a tuple when a fixed, small group of values belongs together and shouldn't be modified, coordinates, for instance.

collections.py Python
point = (3, 4) print(point[0]) # 3 x, y = point # unpacking: pull both values out by position print(x, y) # 3 4

Unpacking is the feature that makes tuples genuinely convenient, not just "a list that can't change": x, y = point assigns both names in one line, matched up by position.

Part 3. Sets

A set is unordered and never contains duplicates, written with curly braces. Adding a value that's already there quietly does nothing.

collections.py Python
s1 = {1, 2, 2, 3, 3, 3} print(s1) # {1, 2, 3}, duplicates collapsed automatically s1.add(4) print(3 in s1) # True, membership checks are what sets are built for

A common, genuinely useful trick: wrap a list in set(...) to strip out duplicates, then convert back to a list if order matters again afterward.

collections.py Python
nums = [1, 2, 2, 3, 3, 3, 4] unique = list(set(nums)) print(sorted(unique)) # [1, 2, 3, 4]

Note the sorted(...) around the final print there: a set has no guaranteed order, so it's wrapped before printing specifically to get a predictable result to compare against, don't be surprised if printing a set directly comes out in whatever order Python happens to store it in.

Part 4. Dictionaries

A dictionary stores key-value pairs: instead of looking something up by position, you look it up by name. Also written with curly braces, but with a colon separating each key from its value.

collections.py Python
d = {"name": "Ada", "age": 30} print(d["name"]) # Ada d["age"] = 31 # update an existing key d["job"] = "programmer" # add a new key print(d)

.items() loops over both the key and the value together, which is almost always what you actually want:

collections.py Python
for key, value in d.items(): print(key, value)

Unlike sets, dictionaries do guarantee their order, a modern Python dictionary always iterates in the order keys were first inserted, not some arbitrary internal order.

Part 5. Choosing the Right One

  • Need order, and might change it later? list.
  • A small, fixed group that shouldn't change? tuple.
  • Only care about uniqueness or fast membership checks, not order? set.
  • Looking things up by name instead of position? dict.

def most_common_word(sentence): counts = {} for word in sentence.lower().split(): counts[word] = counts.get(word, 0) + 1 best_word = "" best_count = 0 for word, count in counts.items(): if count > best_count: best_word = word best_count = count return best_word print(most_common_word("the cat and the hat and the bat")) print(most_common_word("Red blue RED green blue red")) print(most_common_word("one two two one"))
