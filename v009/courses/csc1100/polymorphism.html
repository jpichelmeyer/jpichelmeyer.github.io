Last lesson's Dog overrode speak() with its own version. Nothing stops a second, unrelated child class from overriding it a completely different way, same method name, same call, genuinely different behavior depending on which actual type you're holding. That's polymorphism: one interface, many shapes underneath it.

Part 1. Two Overrides of the Same Method

polymorphism.py Python
class Animal: def __init__(self, name): self.name = name def speak(self): return "..." class Dog(Animal): def speak(self): return self.name + " says Woof!" class Cat(Animal): def speak(self): return self.name + " says Meow!"

Dog and Cat aren't related to each other at all, they only share Animal as a common parent. Each overrides speak() independently, with no knowledge of what the other one does.

Part 2. Calling It Without Checking the Type

Here's the actual payoff: a loop can call .speak() on a whole list of different animal types, never once checking which one it's currently holding, and each object still does the right thing for its own type.

polymorphism.py Python
animals = [Dog("Rex"), Cat("Whiskers"), Dog("Fido")] for a in animals: print(a.speak())

The loop body is exactly three characters long past the variable name, a.speak(), and it never mentions Dog or Cat at all. Each object already knows how to answer for itself.

Part 3. Without Polymorphism

Worth seeing the alternative once, just to appreciate what got avoided. Without overriding speak() per class, the same loop would need to check the type of every single object itself before deciding what to do with it.

(illustrative, not recommended) Python
for a in animals: if isinstance(a, Dog): print(a.name + " says Woof!") elif isinstance(a, Cat): print(a.name + " says Meow!") # and one more elif for every new animal type you ever add, forever

Every new animal type would mean going back and adding another branch to every single place in the code that does this kind of check, instead of just writing one new class with its own speak() and being done. That growing pile of type checks scattered everywhere is exactly what polymorphism exists to avoid.

Warm Up

Exercise 1: Add a Cow. Add a Cow class that overrides speak() to say Moo, and add a cow to the list. The loop itself must not change at all: that's the whole point.

Exercise 2: Shapes with area(). Write three classes, Circle(radius), Square(side), and Triangle(base, height), each with its own area() method (triangle area is base × height / 2; use math.pi for the circle). The loop prints each area rounded to 2 places, without checking which kind of shape it is.

Exercise 3: No Parent Required. Python doesn't actually require a shared parent class for this to work, only that each object has a method with the right name. Write two completely unrelated classes, Robot and Person, each with a greet() method that returns a different greeting. Put one of each in a list and loop over them calling greet(). (This style is often called duck typing: if it has a greet(), you can greet it.)

Intermediate

Exercise 4: Total Area. Using the shape classes from Exercise 2 (copy them in), write a function total_area(shapes) that returns the sum of the areas of every shape in a list, however many kinds of shape it contains. Print the result rounded to 2 places. Then add a Rectangle(width, height) class and a rectangle to the list: total_area should need no changes.

Exercise 5: Payroll. Three kinds of employee are paid differently each week. Write subclasses of Employee, each overriding weekly_pay():

  • Salaried(name, annual_salary): annual salary divided by 52.
  • Hourly(name, rate, hours): rate × hours, plus time-and-a-half (1.5 × rate) for every hour over 40.
  • Commissioned(name, base, sales): base plus 10% of sales.

The payroll loop prints each person's pay to 2 decimal places.

Exercise 6: Replace the Type Checks. send_all uses an isinstance chain, the pattern Part 3 warns about. Refactor it: give each notification class its own send() method returning the same text as before, and rewrite send_all so its loop body is a single line with no if at all. The output must not change.

Advanced

Exercise 7: The Template Method. A base class method can call a method that subclasses override. Animal.introduce() below calls self.speak() and self.move(). Write Dog, Bird, and Snake classes that override one or both. Snake should override only move(), leaving the default speak(). Predict each line of output before running.

Exercise 8: The Biggest Shape. Give each shape class a __str__ (like Circle(r=2)) and write largest(shapes), which returns the shape with the biggest area using only area(), never checking types. Print the largest shape and then every shape whose area is above the average area.

Exercise 9: One Round of Battle. Build a tiny turn-based game. Every Character has a name and hp (hit points). Each subclass overrides take_turn(target), which changes hp values and returns a sentence describing what happened:

  • Warrior: deals 12 damage to the target.
  • Mage: deals 20 damage to the target but loses 5 of its own hp.
  • Healer: ignores the target and heals itself for 10.

The main loop gives every character one turn against the boss, printing each sentence, then prints the boss's remaining hp.

Exercise 5: Payroll
polymorphism.py Python
class Employee: def __init__(self, name): self.name = name def weekly_pay(self): return 0 class Salaried(Employee): def __init__(self, name, annual_salary): super().__init__(name) self.annual_salary = annual_salary def weekly_pay(self): return self.annual_salary / 52 class Hourly(Employee): def __init__(self, name, rate, hours): super().__init__(name) self.rate = rate self.hours = hours def weekly_pay(self): if self.hours <= 40: return self.rate * self.hours overtime = self.hours - 40 return self.rate * 40 + overtime * self.rate * 1.5 class Commissioned(Employee): def __init__(self, name, base, sales): super().__init__(name) self.base = base self.sales = sales def weekly_pay(self): return self.base + 0.10 * self.sales staff = [Salaried("Ada", 78000), Hourly("Alan", 20, 45), Commissioned("Grace", 300, 4000)] for e in staff: print(f"{e.name}: ${e.weekly_pay():.2f}")

Exercise 7: The Template Method
polymorphism.py Python
class Animal: def __init__(self, name): self.name = name def speak(self): return "makes no sound" def move(self): return "walks" def introduce(self): return f"{self.name} {self.speak()} and {self.move()}." class Dog(Animal): def speak(self): return "barks" class Bird(Animal): def speak(self): return "chirps" def move(self): return "flies" class Snake(Animal): def move(self): return "slithers" for a in [Dog("Rex"), Bird("Tweety"), Snake("Kaa")]: print(a.introduce())
Exercise 8: The Biggest Shape
polymorphism.py Python
import math class Circle: def __init__(self, r): self.r = r def area(self): return math.pi * self.r ** 2 def __str__(self): return f"Circle(r={self.r})" class Rect: def __init__(self, w, h): self.w = w self.h = h def area(self): return self.w * self.h def __str__(self): return f"Rect({self.w}x{self.h})" def largest(shapes): best = shapes[0] for s in shapes: if s.area() > best.area(): best = s return best shapes = [Circle(2), Rect(3, 3), Rect(1, 20), Circle(1)] print(largest(shapes)) total = 0 for s in shapes: total += s.area() average = total / len(shapes) for s in shapes: if s.area() > average: print(s)
Exercise 9: One Round of Battle
polymorphism.py Python
class Character: def __init__(self, name, hp): self.name = name self.hp = hp def take_turn(self, target): return self.name + " waits." class Warrior(Character): def take_turn(self, target): target.hp -= 12 return f"{self.name} strikes {target.name} for 12." class Mage(Character): def take_turn(self, target): target.hp -= 20 self.hp -= 5 return f"{self.name} casts a fireball at {target.name} for 20 (costs 5 hp, now {self.hp})." class Healer(Character): def take_turn(self, target): self.hp += 10 return f"{self.name} heals to {self.hp} hp." boss = Character("Dragon", 100) party = [Warrior("Ada", 50), Mage("Alan", 30), Healer("Grace", 40)] for hero in party: print(hero.take_turn(boss)) print(boss.name + " has " + str(boss.hp) + " hp left")
