The recursion lesson showed each paused call as a box stacked on top of the one before it, waiting for an answer before it could finish. That wasn't just a helpful drawing. It's a literal description of a real, finite region of memory called the call stack, and now that you've felt what it does, it's worth actually naming what it is.

Part 1. What's Actually Sitting in a Frame

Every time a function is called, Python sets aside a small block of memory for that specific call, called a stack frame. It holds that call's local variables (like n inside factorial) and a note on exactly where to resume in whichever call made this one, once this one finishes. factorial(4) calling factorial(3) doesn't replace factorial(4)'s frame, it adds a new one on top, leaving factorial(4)'s own frame sitting there, paused, underneath it.

Part 2. Last In, First Out

A stack always resolves in reverse order: whichever frame was added most recently is exactly the one that finishes first, since it's sitting on top and every call above it has to be done before you can get back down to it. That's the "last in, first out" ordering the recursion diagrams showed directly: factorial(1), the last one added, was the first one to actually return.

Part 3. The Limit Is Real Memory, Not an Arbitrary Rule

The recursion lesson mentioned that a missing base case eventually raises RecursionError rather than hanging forever. Here's the actual reason: the memory set aside for the call stack is finite, and every unfinished call takes up its own frame on it. Python keeps a running limit on how deep the stack is allowed to get specifically so a runaway recursive function fails loudly and immediately, instead of quietly consuming memory until something much worse happens.

import sys print(sys.getrecursionlimit())

Run it yourself, the exact number can vary depending on what you're running Python in, which is itself worth noticing: this isn't a fixed rule baked into the language, it's a real, environment-dependent number tied to actual available memory.

Part 4. Where the Term "Stack Overflow" Actually Comes From

You've probably heard "Stack Overflow" as the name of a website programmers use constantly to look things up. The name isn't arbitrary: a stack overflow is exactly this failure, the call stack growing past the memory set aside for it, most commonly from recursion with no working base case. It's such a common, recognizable failure that an entire programming Q&A site was named after it. You now know, precisely, what that name is actually describing.
