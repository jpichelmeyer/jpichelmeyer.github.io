Seek gets an agent to a target, but it has no idea anything else exists. Point it at a target on the far side of a wall and it walks straight into the wall. Obstacle avoidance is the fix: look a short distance ahead, and if something solid is there, steer around it instead of through it.

Part 1. The Idea

The classic approach is a lookahead ray: cast a short line out in front of the agent, and check whether it hits anything. If it doesn't, do nothing extra. If it does, steer away from whatever the ray hit, using the surface's collision normal (the direction pointing straight out from the surface) as the new desired heading.

The lookahead ray (dashed) hits the obstacle before the agent reaches it.

Part 2. Adding an Obstacle

In Environment, add a StaticBody2D with a CollisionShape2D child (a RectangleShape2D works well), plus a ColorRect or Sprite2D so it's visible, an orange or grey rounded rectangle reads clearly as "not an agent" next to the disc-and-point sprite. Place one or two of these somewhere between AgentA and AgentB, so Seek actually has something to run into.

Notice the agent itself still doesn't need a CollisionShape2D of its own: since movement here is global_position += delta_passed * move_speed * _get_agent_forward() rather than move_and_slide(), nothing is resolving physical collisions for the agent's body. Only the ray below needs to sense the obstacle.

Part 3. A Lookahead Ray

Add a RayCast2D as a child of Agent, named AvoidRay, with Enabled checked, and set its Target Position to (0, -80) in the Inspector. A ray's target position is in its own local space, so pointing it "up" once, in the editor, is enough; as Agent rotates, the ray automatically keeps pointing wherever it's currently facing. Nothing needs to be recomputed in code every frame.

Part 4. Implementing Avoidance

agent.gd GDScript
@onready var avoid_ray: RayCast2D = $AvoidRay func _rotation_avoid(delta_passed: float, turn_rate_value: float) -> float: avoid_ray.force_raycast_update() if avoid_ray.is_colliding(): var normal: Vector2 = avoid_ray.get_collision_normal() var desired_angle: float = Vector2.UP.angle_to(normal) var diff: float = angle_difference(rotation, desired_angle) rotation += clamp(diff, -turn_rate_value * delta_passed, turn_rate_value * delta_passed) return speed_max

A few notes on what's happening here:

  • force_raycast_update() makes the ray check for a collision immediately, rather than waiting for its own next physics step; without it, the result would lag a frame behind.
  • The collision normal points straight out from whatever surface got hit, which makes it a reasonable heading to steer toward: away from the obstacle, not into it. Vector2.UP.angle_to(normal) converts that into the rotation actually needed, the same conversion Seek used last lesson.
  • When the ray isn't colliding, rotation is simply left alone, and speed_max is still returned so the agent keeps moving forward.

Add "avoid" : _rotation_avoid to rotation_method_from_type, set an agent's steering_type to "avoid", and send it toward an obstacle to see it turn away.

Part 5. Combining Avoidance with Seek

On its own, "avoid" isn't very useful: an agent that only avoids has no goal to head toward in the first place. In practice, obstacle avoidance almost always runs alongside another behavior, overriding it only when something is actually in the way. That's a small change to _rotation_seek rather than a whole new method:

agent.gd GDScript
func _rotation_seek(delta_passed: float, turn_rate_value: float) -> float: avoid_ray.force_raycast_update() var direction: Vector2 = target.global_position - global_position if avoid_ray.is_colliding(): direction = avoid_ray.get_collision_normal() var desired_angle: float = Vector2.UP.angle_to(direction) var diff: float = angle_difference(rotation, desired_angle) rotation += clamp(diff, -turn_rate_value * delta_passed, turn_rate_value * delta_passed) return speed_max

Seek checks the same ray first, and only falls back to heading for the target when the ray comes back clear. The target reasserts itself the moment nothing's in the way anymore.

Worth pausing on the shape of that if avoid_ray.is_colliding(): ... else ... logic: it's choosing between two possible behaviors (Avoid, Seek) based on what the agent currently senses, with Avoid taking priority whenever it applies. That's a small, working preview of what finite state machines and behavior trees formalize later in the course; a behavior tree in particular would call this exact pattern, "try one behavior, fall through to another if it doesn't apply," a priority selector. Nothing to build now, just worth recognizing the shape when it comes back around.
