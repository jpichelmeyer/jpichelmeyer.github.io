Classification and regression both need a correct answer supplied up front, a label or an ideal number, for every training example. Reinforcement learning doesn't have that. The aliens don't get told the correct dodge for any given shot; all they get, after the fact, is whether it worked. Everything they learn comes from trying things and feeling the consequences.

Part 1. State, Action, Reward

The reinforcement learning loop, and how this project fills in each piece.

Three pieces of vocabulary, all directly visible in alien_hive_mind.gd:

  • State: what the agent currently observes about its situation. Here, a bucketed distance to the sentry (near/medium/far) combined with whether it's currently being targeted, six possible states total.
  • Action: what the agent can choose to do. Here, exactly three options: STRAIGHT, JUKE_UP, JUKE_DOWN.
  • Reward: a number describing how that action turned out. Here, +1 if the resulting shot missed, -1 if it hit.
alien_hive_mind.gd GDScript
func get_state(distance:float, is_targeted:bool) -> int: var bucket:int = 2 if distance < DISTANCE_NEAR: bucket = 0 elif distance < DISTANCE_MEDIUM: bucket = 1 var targeted_index:int = 1 if is_targeted else 0 return bucket * N_TARGETED_STATES + targeted_index

Part 2. The Q-Table

The policy itself is a table, q_table[state][action], one number per (state, action) pair, an estimate of how good that action tends to be in that state. Picking an action just means looking across a state's row and taking whichever action currently has the highest value:

alien_hive_mind.gd GDScript
func choose_action(state:int) -> int: if randf() < EXPLORATION_CHANCE: return randi() % N_ACTIONS var best_action:int = 0 var best_value:float = q_table[state][0] for a in range(1, N_ACTIONS): if q_table[state][a] > best_value: best_value = q_table[state][a] best_action = a return best_action

Note the check before any of that: with probability EXPLORATION_CHANCE, skip the table entirely and pick a uniformly random action instead. This is the explore/exploit tradeoff, one of the central ideas in reinforcement learning. Always taking the current best-known action (pure exploitation) means never discovering that some other action might actually be better; always acting randomly (pure exploration) means never using anything that's been learned. A small, constant chance of a random action is a simple way to keep doing a little of both, forever.

Part 3. Training: A Running Average, Not Full Q-Learning

The project's own comments are direct about this, worth reading in their own words:

alien_hive_mind.gd (top-of-file comment) GDScript
# This is deliberately NOT full Q-learning: there's no bootstrapped # "value of the next state" term. Each dodge decision's consequence # (hit or missed) resolves quickly, closer to a contextual bandit # than a long-horizon sequential decision problem, so learning here # is just a running average of how well each (situation, action) # pairing has actually worked out: Q[s][a] nudged toward the reward # it just earned, nothing more.

The actual update backs that up:

alien_hive_mind.gd GDScript
func record_outcome(state:int, action:int, hit:bool) -> void: total_shots_faced += 1 if not hit: total_shots_dodged += 1 if learning_enabled: var reward:float = -1.0 if hit else 1.0 q_table[state][action] += LEARNING_RATE * (reward - q_table[state][action])

q_table[state][action] += LEARNING_RATE * (reward - q_table[state][action]) nudges that one table entry a fraction of the way toward the reward just received, exactly the same shape as Sentry's weight update from last lesson: current estimate, plus a learning rate, times an error term. Full Q-learning would also add a term for the best possible value of whatever state comes next, letting reward from several steps in the future propagate backward through earlier decisions. This project's dodge decisions resolve fast enough (one shot, one outcome) that skipping that term is a reasonable simplification, not a bug.

Part 4. One Policy, Shared by Every Alien

There's exactly one AlienHiveMind instance in the whole scene, referenced by every fleeing alien. Whatever any single alien experiences updates the same table every other alien reads from immediately afterward, hence "hive mind" rather than each alien learning independently. Practically, this means the aliens collectively accumulate experience far faster than any one of them would alone — ten aliens each dodging once contribute ten updates to one shared table, not one update each to ten separate tables.

Alien panel and the Learning toggle
The HUD's Learning toggle sets learning_enabled directly. With it off, aliens still act (reading whatever the table currently holds), they simply stop updating it -- useful for isolating whether learning is actually helping (see Part 5).

Part 5. Try It

  1. Let the simulation run with learning on until the dodge-rate plot climbs and levels off. Then toggle learning off using the HUD and watch several more cycles. Does the dodge rate hold roughly steady, or drift? What does that tell you about whether the table had actually converged to something useful?
  2. Set EXPLORATION_CHANCE to 0.0 from the very start of a run. Predict what happens to the very first few actions taken in each state (recall every q_table entry starts at exactly 0.0), then run it and check.
  3. In one paragraph: why does it make sense to call each dodge decision "closer to a contextual bandit than a long-horizon sequential decision problem"? What would have to be true about the dodge-and-shot cycle for a bootstrapped next-state term to actually matter here?
