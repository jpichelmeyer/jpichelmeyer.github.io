Last week you got an agent circling on its own, and then wandering. Steering behaviors give it a reason to turn: instead of a fixed rate or a random one, its heading reacts to something else in the world.

Part 1. What Is a Steering Behavior?

The idea (originally Craig Reynolds, 1986; the same person behind the boids you'll build in a couple lessons) is that an agent computes a heading it wants, toward a target, away from a target, whatever the behavior calls for, and moves that way. Four behaviors this lesson actually builds, bolded below, plus two you've already met or will meet soon:

  1. Face Target: snap to face a target, always move forward.
  2. Seek: move directly toward a target.
  3. Arrive: Seek, but slow down smoothly on approach instead of overshooting.
  4. Flee: move directly away from a target.
  5. Wander: drift with a smoothly varying turn rate, no target at all (already built last lesson).
  6. Flocking: steer relative to a group of neighbors instead of a fixed target (next lesson).

Obstacle avoidance isn't on this list on purpose: it's tackled a different way in this course, with grid-based pathfinding a couple lessons from now, rather than as a reactive steering behavior here.

Part 2. Choosing a Behavior

Right now, _process hardcodes which rotation method it calls. To let different agents do different things, that needs to become a choice. GDScript's enum plus match is the natural tool: a named set of options, and a block that branches on which one is active.

agent.gd GDScript
enum SteeringMode { WANDER, FACE_TARGET, } @export var target: Node2D @export var steering_mode: SteeringMode = SteeringMode.WANDER func _process(delta: float) -> void: match steering_mode: SteeringMode.FACE_TARGET: if target != null: _rotate_toward_target() _move_forward(delta, RATE_MOVE) else: _rotation_wander(delta) _move_forward(delta, RATE_MOVE) _: # SteeringMode.WANDER, or a target-requiring mode with no target set _rotation_wander(delta) _move_forward(delta, RATE_MOVE) func _rotate_toward_target() -> void: if target != null: rotation = Vector2(0, -1).angle_to(target.global_position - global_position)

steering_mode is @exported, so it shows up as a dropdown in the Inspector, exactly like any other exported variable. Vector2(0, -1).angle_to(direction) computes the exact rotation needed so the agent's forward direction (recall, -transform.y, which points the same way as Vector2(0, -1) at rotation zero) ends up pointing at direction. Notice this snaps instantly, there's no easing at all, which is exactly why Face Target can look a little robotic once its target starts moving quickly. That's intentional: it's the simplest possible reactive behavior, a stepping stone before the smoother movement coming up next.

The match block's fallback case (_:) handles both plain Wander and any target-requiring mode where target hasn't been set, an agent with nothing to react to just wanders, the same as last lesson.

Part 4. A Different Kind of Movement: Velocity

Face Target and Wander both work the same way: rotate, then thrust forward in whatever direction that rotation faces. The next few behaviors work the other way around: pick a velocity directly, and let rotation follow wherever that velocity happens to point.

agent.gd GDScript
var velocity: Vector2 = Vector2.ZERO func _apply_velocity(delta_passed: float, desired_velocity: Vector2) -> void: velocity = desired_velocity if velocity.length_squared() > 0.01: rotation = Vector2(0, -1).angle_to(velocity) global_position += velocity * delta_passed

Every behavior from here just needs to answer one question, "what velocity do I want right now," and hand it to _apply_velocity. Facing takes care of itself: whichever way velocity points is whichever way the agent ends up facing, every frame.

Part 5. Seek

Seek wants a velocity that points straight at the target, at a fixed speed.

agent.gd GDScript
const RATE_MOVE_SEEK: float = 75.0 func _steer_seek(delta_passed: float) -> void: if target == null: return var desired: Vector2 = (target.global_position - global_position).normalized() * RATE_MOVE_SEEK _apply_velocity(delta_passed, desired)

Add SEEK to the enum and a case to the match block calling _steer_seek(delta). Notice Seek gets its own speed constant, RATE_MOVE_SEEK (75), deliberately slower and separate from RATE_MOVE (the general 100 from last lesson); nothing forces the two to match.

Set AgentA's steering_mode to Seek and its target to AgentB (which is itself still heading for the Marker). Press Play: AgentA chases AgentB, recomputing its desired velocity fresh every frame rather than aiming once and committing.

Part 6. Flee

agent.gd GDScript
func _steer_flee(delta_passed: float) -> void: if target == null: return var desired: Vector2 = (global_position - target.global_position).normalized() * RATE_MOVE _apply_velocity(delta_passed, desired)

The only real change from Seek: the direction is flipped, global_position - target.global_position instead of target.global_position - global_position. Flee also uses the faster RATE_MOVE rather than RATE_MOVE_SEEK, fleeing happens at the general, quicker pace; seeking is deliberately more measured.

Add FLEE to the enum and match, and try switching AgentA to it to watch the chase reverse.

Part 7. Arrive

Watch Seek closely and it overshoots: it asks for full speed right up until the last moment, then has to cancel that speed almost instantly. Arrive fixes this by scaling the desired speed down inside a radius of the target, instead of demanding full speed the whole way in.

agent.gd GDScript
const ARRIVE_SLOW_RADIUS: float = 150.0 const ARRIVE_STOP_RADIUS: float = 4.0 func _steer_arrive(delta_passed: float) -> void: if target == null: return var offset: Vector2 = target.global_position - global_position var dist: float = offset.length() if dist < ARRIVE_STOP_RADIUS: velocity = Vector2.ZERO return # Linearly ramp speed down inside the slow radius, full speed outside it var speed: float = RATE_MOVE if dist < ARRIVE_SLOW_RADIUS: speed = RATE_MOVE * (dist / ARRIVE_SLOW_RADIUS) var desired: Vector2 = offset.normalized() * speed _apply_velocity(delta_passed, desired)

Two radii, not one: ARRIVE_SLOW_RADIUS is where slowing begins, ARRIVE_STOP_RADIUS is where the agent counts as "there" and just stops outright, avoiding the endless tiny corrective jitter a shrinking-but-never-zero speed would otherwise cause right on top of the target. Add ARRIVE to the enum and match, and compare it side by side with Seek on the same target.
