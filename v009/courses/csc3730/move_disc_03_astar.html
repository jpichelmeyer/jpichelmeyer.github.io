BFS finds a shortest path, but it explores blindly: every direction gets checked equally, even cells heading straight away from the goal. A* fixes that by adding a heuristic, an estimate of how far each cell still is from the goal, and always expanding the most promising cell first.

Part 1. Cost So Far, Plus Cost To Go

A* tracks two numbers per cell: g, the actual cost of the best path found to it so far, and h, a heuristic guess at the remaining distance to the goal. Their sum, f = g + h, is what decides which cell to expand next: lowest f first. For a four-directional grid, Manhattan distance (the sum of the horizontal and vertical distance, ignoring obstacles) is a good heuristic: it never overestimates the true cost, which is exactly what keeps A* guaranteed to still find a shortest path, not just a fast one.

agent.gd GDScript
func _heuristic(cell: Vector2i, cell_target: Vector2i) -> int: # Manhattan distance: admissible for 4-directional movement with uniform cost return abs(cell.x - cell_target.x) + abs(cell.y - cell_target.y)

Part 2. Implementing A*

Real implementations often keep the open set in a proper priority queue for speed. To keep this readable, this scans for the lowest f_score by hand instead, a plain linear scan through open_set each time. Slower on a very large grid, but behaves identically, and the shape is otherwise the same as _path_find_bfs from last lesson.

agent.gd GDScript
func _path_find_a_star() -> Array: """ return Array[Vector2i], Array[Vector2i] path , searched (not in path) """ var empty_path: Array[Vector2i] = [] var empty_searched: Array[Vector2i] = [] var ret: Array = [empty_path, empty_searched] # Nullity check if target == null or path_grid == null: return ret var cell_target: Vector2i = path_grid.world_to_cell(target.global_position) var cell_self: Vector2i = path_grid.world_to_cell(global_position) # Trivial case: already there if cell_self == cell_target: var trivial_path: Array[Vector2i] = [cell_self] var trivial_searched: Array[Vector2i] = [cell_self] return [trivial_path, trivial_searched] var directions: Array[Vector2i] = [ Vector2i(1, 0), Vector2i(-1, 0), Vector2i(0, 1), Vector2i(0, -1) ] var checked = [cell_self] var open_set: Array[Vector2i] = [cell_self] var came_from: Dictionary = {} var g_score: Dictionary = {cell_self: 0} var f_score: Dictionary = {cell_self: _heuristic(cell_self, cell_target)} var found: bool = false while not open_set.is_empty(): # Pull the open_set entry with the lowest f_score (cheap linear scan; # fine for grid sizes like this, swap for a min-heap if it ever grows large) var current: Vector2i = open_set[0] var current_index: int = 0 for i in range(1, open_set.size()): if f_score.get(open_set[i], INF) < f_score.get(current, INF): current = open_set[i] current_index = i open_set.remove_at(current_index) if current == cell_target: found = true break for dir in directions: var next: Vector2i = current + dir # Skip if out of bounds or blocked if next.x < 0 or next.x >= path_grid.grid_width: continue if next.y < 0 or next.y >= path_grid.grid_height: continue if not path_grid.is_walkable(next): continue # Cost of a single grid step is 1 var tentative_g: int = g_score[current] + 1 if tentative_g < g_score.get(next, INF): came_from[next] = current g_score[next] = tentative_g f_score[next] = tentative_g + _heuristic(next, cell_target) if next not in open_set: open_set.append(next) checked.append(next) if not found: return ret # Walk backwards from target to start, then reverse var path_array: Array[Vector2i] = [] var step: Vector2i = cell_target while step != cell_self: path_array.append(step) step = came_from[step] path_array.append(cell_self) path_array.reverse() var searched: Array[Vector2i] = [] for cell in checked: if cell not in path_array: searched.append(cell) return [path_array, searched]

Line up the shapes: this is BFS with two additions. Instead of always popping the oldest entry in the frontier, it pops whichever open cell currently has the lowest f_score. And instead of a simple visited check, it tracks the actual cost g_score to each cell, so it can update a cell's route if a cheaper path to it turns up later (that's what the tentative_g < g_score.get(next, INF) check is doing). Everything else, the neighbor bounds checks, the reconstruction, is identical to last lesson.

Part 3. Why This Actually Matters

Both algorithms find the same shortest path here (every step costs the same, so both are correct), but they get there by exploring very different numbers of cells.

On a small classroom-sized grid the difference barely matters. On a large map with a lot of open space, it's the difference between checking a few dozen cells and checking thousands, which is why A* (or something built on the same idea) is what most shipped games actually use, not BFS.

Part 4. Wiring Up a Button

Add a Search: A* button next to the BFS one, wired to a matching handler:

agent.gd GDScript
func _on_search_astar_pressed() -> void: if target != null and path_grid != null: var ret = _path_find_a_star() path_grid.display_path(ret[0], Color(0.5, 0.5, 0.75), ret[1]) _start_following(ret[0])

Same shape as _on_search_bfs_pressed, right down to reusing display_path and _start_following unchanged, only the search function called is different. _follow_path from last lesson doesn't need any changes at all either: it just walks whatever _travel_path array it's given, and has no idea, or need to know, which search algorithm produced it.

Press Search: BFS, note roughly how many cells lit up with searched-dots, then press Search: A* on the same layout and compare. Same path, visibly fewer dots.
