Regression is supervised learning where the output is a continuous number rather than a category. Sentry is this course's running example: instead of sorting people into buckets, it predicts a single number, how far ahead of a fleeing target to aim, and that number can be anything along a range, not one of a fixed few choices.

Part 1. The Problem: Leading a Moving Target

A projectile takes time to travel. Aim straight at where a fleeing target is right now and, by the time the shot arrives, the target's moved. Sentry has to predict how far ahead of the target's current position to aim, its lead, and the only thing it has to go on is the target's current distance:

sentry_agent.gd GDScript
func predict_lead(distance:float) -> float: return weights[0] + weights[1] * (distance / 100.0)

That's the entire model: a straight line. weights[0] is the line's intercept (the predicted lead at distance zero); weights[1] is its slope (how much predicted lead grows per unit of distance). "Training" means finding good values for those two numbers, and nothing else about the model's shape ever changes.

Part 2. Where the Correct Answer Comes From

Classification needs a ground-truth label for every training example; regression needs a ground-truth number. Sentry gets one in a way worth noticing: after every shot, geometry alone (not another model, not a guess) works out what lead would, in hindsight, have hit exactly:

projectile.gd GDScript
if target_node != null: var dist_at_fire:float = global_position.distance_to(target_node.global_position) hindsight_ideal_lead = dist_at_fire / SPEED

Every shot, hit or miss, produces one of these hindsight values, appended to Memory alongside the distance it was fired from. That's what makes this genuine regression rather than a hit/miss classifier in disguise: the label is a real, continuous, correct number for that exact shot, not just true or false.

Part 3. Loss: Measuring How Wrong a Line Is

To improve the line, the model needs a number that says how badly it's currently doing, a loss. Sentry uses squared error: for each training example, the difference between the predicted lead and the ideal lead, squared. Squaring does two things at once — it makes every error positive (so overshooting and undershooting don't cancel out), and it punishes large errors much more than small ones.

Part 4. Training: Gradient Descent

Rather than solving for the best-fit line in one shot, Sentry nudges its weights a little at a time, in whichever direction reduces the error for each example, repeated over many passes through Memory:

sentry_agent.gd GDScript
const LEARNING_RATE:float = 0.05 const TRAINING_EPOCHS:int = 300 var weights:Array = [0.0, 0.0] # [bias, distance_coefficient] func _train_on_memory() -> void: for epoch in range(TRAINING_EPOCHS): for record in memory: var x:float = record.distance / 100.0 var predicted:float = weights[0] + weights[1] * x var error:float = predicted - record.ideal_lead weights[0] -= LEARNING_RATE * error weights[1] -= LEARNING_RATE * error * x

Read the update line by line:

  • error = predicted - record.ideal_lead: positive if the model over-predicted, negative if it under-predicted.
  • weights[0] -= LEARNING_RATE * error: nudge the intercept opposite the error — if predictions are running high, pull the whole line down a little.
  • weights[1] -= LEARNING_RATE * error * x: nudge the slope too, scaled by x itself — a large-distance example with a big error moves the slope more than a small-distance one does, since the slope's effect on the prediction scales with x in the first place.

TRAINING_EPOCHS is how many full passes over Memory each training cycle makes; LEARNING_RATE is how big each individual nudge is. Both are worth experimenting with directly (see Part 5) — too high a learning rate can overshoot and never settle; too low, and 300 epochs might not be enough to get anywhere close to the best line.

The loss plot should trend downward across training cycles as the line's fit improves; a flat or rising loss plot is a sign something's off (too high a learning rate is a common culprit).

Part 5. Try It

  1. Before Sentry's first training cycle, weights is [0.0, 0.0]. What lead does predict_lead() return for any distance at that point? Watch the first several shots and confirm.
  2. Try setting LEARNING_RATE to something much larger, like 2.0. What happens to the loss plot, and why does an error-proportional update like this one break down at a high learning rate?
  3. Sentry's model only ever sees one input, distance. Name one other piece of information available in the scene (target speed, angle, anything else) that a richer model could have used as a second input to potentially predict lead more accurately.

Checkpoint

  1. Explain what makes this genuine regression rather than a classifier, in terms of where the training label comes from and what kind of value it is.
  2. Write out, in your own words, what each of the two weight-update lines is doing and why.
