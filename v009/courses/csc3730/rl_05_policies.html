An agent that has learned something has to use it, and in an MDP the thing it uses is called a policy. You've been looking at policies since the first demo: they're the arrows drawn in every cell. This lesson makes that picture precise, introduces the numbers behind it, and then asks a question you can play with directly in the demo: what happens if the agent can't see everything?

Part 1. A Policy Is a Rule for Every State

A policy answers one question: in this state, what do I do? It is usually written π(s), "pi of s," and it can be as simple as a lookup table with one action for each state. In a gridworld the whole policy is one arrow per cell.

A policy for a 4 x 4 grid: for every cell, the action to take there.

A policy is either deterministic, always the same action in a given state (the table above), or stochastic, a set of probabilities over actions. Epsilon-greedy, which you met with the bandits, is a stochastic policy: mostly the best-looking action, sometimes a random one.

Part 2. How Good Is This Place: V and Q

To improve a policy you need a way to say how good things are. Reinforcement learning uses two closely related scores:

  • V(s), the value of a state: the discounted return you expect from state s onward if you follow your policy.
  • Q(s, a), the value of an action in a state: the discounted return you expect if you take action a now, and follow your policy afterward.

Q is the one the agent in the demo stores, and the one it shows you in the four boxes under "Options (Q values)". Once an agent has a good Q, its policy writes itself: in every state, take the action with the highest Q. That choice is called the greedy policy.

A tiny example makes the numbers concrete. Here is a corridor of four cells with a +10 goal at the right end. Every move costs −1 and γ = 0.9. Work backward from the goal:

Values for a four-cell corridor with a step cost of -1 and gamma = 0.9.
  1. In cell 3, moving right enters the goal and pays +10 at once, so V(3) = 10.
  2. In cell 2, moving right costs 1 and lands you in cell 3: −1 + 0.9 × 10 = 8.0.
  3. In cell 1: −1 + 0.9 × 8.0 = 6.2.
  4. In cell 0: −1 + 0.9 × 6.2 = 4.58.

Now ask for Q in cell 2, one value per action, assuming you play well afterward. Right is 8.0, as above. Left lands in cell 1: −1 + 0.9 × 6.2 = 4.58. Up and down bump into the corridor wall: you stay in cell 2 and pay −1, so each is −1 + 0.9 × 8.0 = 6.2. A wasted move is better than going backward, because at least you haven't moved away. The greedy action is right, and the numbers tell you how much better it is than the others, not just that it wins.

Part 3. Greedy, and Epsilon-Greedy

The agent's policy in code is the same two-way choice as before. With probability epsilon it takes a random action; otherwise it takes the best one:

q_agent.gd GDScript
func choose(obs: int) -> int: if rng.randf() < current_epsilon(): last_explore = true return rng.randi_range(0, 3) last_explore = false return greedy_random(obs)
q_agent.gd GDScript
func greedy_random(obs: int) -> int: var v := peek(obs) var best: float = v.max() var ties: Array[int] = [] for a in 4: if v[a] >= best - 1e-9: ties.append(a) return ties[rng.randi_range(0, ties.size() - 1)]

Two versions of "best action" exist on purpose. greedy_random picks randomly among ties, which keeps early behavior varied, and is used when the agent is acting. greedy_fixed always takes the first of the tied actions, which is used for drawing arrows, so the picture doesn't flicker from frame to frame.

The demo also has an Explore early switch. With it on, the effective epsilon starts at 1 (pure random) and slides down to your slider's value over the first 300 episodes (shown as "Epsilon now"). The reason is in the fourth preset. A small prize sits next to the start, and a big goal sits farther away. An agent with a small fixed epsilon finds the prize first, starts exploiting it, and almost never wanders far enough to learn the big goal exists. Starting with a lot of exploration and shrinking it lets the agent see the whole map before it commits. Try the preset with the switch on and off.

The Greedy run button shows a finished policy at work: it sets epsilon to 0, turns off learning, and replays the agent's best behavior.

Part 4. What the Agent Can See

So far the agent has known exactly which cell it is in. Real agents rarely do. A robot has sensors, and sensors report what is nearby, not a map coordinate. The difference between the true situation and what the agent perceives is the difference between a state and an observation, and it is the Perceptor's job from the first week.

The demo has a dropdown for this, Agent sees. With "Its exact position," the observation is the cell number, so every cell gets its own row of Q values. With "Only left and right," the agent can sense only its two horizontal neighbors, and each reports one of four things:

  • blocked: a wall or the edge of the grid,
  • plain: an ordinary open cell,
  • good: a cell that pays more than an ordinary step,
  • bad: a cell that pays less than an ordinary step.
main.gd GDScript
func observe(c: Vector2i) -> int: if obs_mode == 0: return data.index(c) return sense(c + Vector2i(-1, 0)) * 4 + sense(c + Vector2i(1, 0))
main.gd GDScript
func sense(c: Vector2i) -> int: if not data.inside(c) or data.kind_at(c) == GridData.Kind.WALL: return 1 if rewards_mode != 0: return 0 var d := data.reward_at(c) - data.step_reward if d > 0.01: return 2 if d < -0.01: return 3 return 0

With four possibilities on each side, the agent has at most sixteen observations, no matter how big the grid is. Its Q table is indexed by observation, not by cell.

The last two lines of sense() are the connection to the other dropdown, Rewards visible. A neighbor can only look "good" or "bad" to the agent when rewards are visible during learning. If you choose "Only at the end" or "Never," the agent's sensors report only walls and open space, and it has to discover rewards by walking onto them. That same setting also controls the numbers drawn in the cells for you: "Only at the end" hides them while the agent is running and reveals them the moment you press Pause, and "Never" hides the special cells entirely and marks them with question marks.

The agent sees only its left and right neighbors. Cells that look the same to the agent have to share one action.

That last sentence is the heart of it, and it is called perceptual aliasing: different situations that produce the same observation. A single Q row means a single decision for all of them, even when the right move is different. Try it. On the plain step-cost grid, the sensor-only agent still reaches the goal, because "go up when you can, otherwise go right" works from every cell. On the maze and the cliff, in our tests, the greedy run never reached the goal after 3,000 training episodes: the agent kept doing the best average thing for what it could see and wandered until the step limit. Giving the agent better eyes (or a memory, which you'll add in an exercise) is how you fix that. This is the same trade-off as in the alien-and-sentry project you saw earlier, where the state was a coarse "near, medium, far, targeted?" description rather than exact coordinates.

Part 5. Reading the HUD

  • Options (Q values). The four boxes show Q for the agent's current observation. A green outline marks the greedy action. A blue fill marks the move it just made.
  • Policy. The mini map shows the greedy arrow for every cell, computed from the agent's observation of that cell. In sensor mode you can watch aliasing happen: whole columns of cells share one arrow.
  • Value colors. Green cells have a high best-Q, red cells a low one. Early in training only cells near the goal glow, and the glow spreads outward.
  • Policy arrows. Turns the arrows on the big grid on and off.

Part 6. Try It

  1. Run preset 2 until the policy settles. Press Greedy run and describe the path. Does the policy have an arrow for every cell, including cells the agent rarely visits?
  2. On preset 4, run three separate trials with "Explore early" off (press Reset agent between them). Does the agent find the big goal? Repeat with it on.
  3. Switch Agent sees to "Only left and right" on preset 5. Describe the policy you see. Which cells share an arrow, and why can't they have different ones?
  4. Set Rewards visible to "Only at the end" and watch the agent run for a minute with the grid hidden. Does it behave any differently than with the numbers shown? (Think about what the agent sees versus what you see.)

Exercises

Warm-up

  1. For the corridor above, recompute all four V values with γ = 0.5. How does the best action in cell 0 compare to the other actions?
  2. In sensor mode, how many distinct observations are possible if each neighbor has four possible reports?

Intermediate

  1. Add a fifth report to sense() for terminal cells, so the agent can tell a goal from an ordinary good cell. Does that help or hurt on preset 4?
  2. Make the sensors see up and down as well as left and right. How many observations are possible now?

Advanced

  1. Give the agent a memory of its last action and include it in the observation. Does the sensor-only agent now solve the maze?
  2. Add a "sight range" of two cells instead of one. What happens to the number of observations, and to the Q table?
