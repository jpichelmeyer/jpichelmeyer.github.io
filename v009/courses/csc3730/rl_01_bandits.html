Everything in the decision unit so far was written by you. The FSM and the behavior tree both followed rules you typed in ahead of time. This unit flips that around: the agent starts out knowing nothing about which choices are good, and it learns by trying things and watching what happens. The simplest version of that problem has a long, famous name, the multi-armed bandit, and it comes from the old nickname for a slot machine: a "one-armed bandit," because it has one lever and it takes your money.

Play with the demo below for a minute before reading on. Click a machine to pull it yourself, then switch on Auto-play and watch the agent do it. Don't turn on Show the true odds yet: the whole point is that nobody tells the agent those.

Part 1. One Decision, Over and Over

Here is the whole problem. There are five slot machines. Every pull costs nothing and either pays out some number of coins or pays nothing. Each machine has its own hidden rules for how often it pays and how much it pays. You get a fixed number of pulls and you want as many coins as possible by the end.

Compare this with the situations from earlier units. There is no map, no position, no "state" to track: the situation is exactly the same before every pull. The only thing the agent chooses is which arm. That makes bandits the smallest possible learning problem, and a good place to meet the one idea that every later algorithm in this unit still has to deal with.

One state, five possible actions. After each pull the agent sees only the reward from the arm it chose.

Two facts make it hard. First, the agent only ever sees the machine it actually pulled, so it learns nothing new about the other four on that turn. Second, payouts are random: a machine that pays 100 coins once might be a gold mine or might be pure luck.

Part 2. What a Machine Is

Each machine in the demo is described by two numbers: a probability of paying out, and a payout amount when it does. The agent can't see either. What matters for planning is the average coin count per pull, the expected value:

expected value = probability × payout

These are the five machines in the default set. Switch on Show the true odds in the demo and the same numbers appear under the machines.

Expected coins per pull. The best machine (C, green) is neither the one that pays most when it hits (E) nor the one that hits most often (D).

Look at what this says about intuition. Machine E has the biggest jackpot, 100 coins, but it only hits 3% of the time, so it is worth just 3.0 per pull. Machine D hits 70% of the time, but each hit is only 5 coins. The best machine, C, is a middling payout at a middling rate. An agent that chases the biggest number it has seen, or the most frequent win, will pick wrong.

Part 3. Estimating Value from Experience

The agent can't read expected values. It has to estimate them from what it has seen. The most natural estimate is the plain average: for each arm, add up the rewards it has paid and divide by how many times you pulled it. We call that estimate Q (for "quality") and write it Q(a) for arm a.

You don't need to remember every past reward to keep a running average. You only need the count so far, n, and the current estimate. Each new reward r nudges the estimate toward itself by a fraction 1/n of the gap:

Q ← Q + (r − Q) / n

bandit_agent.gd GDScript
func update(arm: int, reward: float) -> void: n[arm] += 1 q[arm] += (reward - q[arm]) / float(n[arm]) total_pulls += 1 total_reward += reward

Work it through for machine C (which pays 20 with probability 0.25). Suppose the first four pulls pay 0, 0, 20, 0:

  1. Pull 1 pays 0: n = 1, Q = 0 + (0 − 0)/1 = 0.
  2. Pull 2 pays 0: n = 2, Q = 0 + (0 − 0)/2 = 0.
  3. Pull 3 pays 20: n = 3, Q = 0 + (20 − 0)/3 = 6.67.
  4. Pull 4 pays 0: n = 4, Q = 6.67 + (0 − 6.67)/4 = 5.0.

That last value is exactly the average of the four rewards, 20/4 = 5.0, and it happens to equal the true value of C. Don't get excited: with only four samples that is luck. The early estimates are noisy, and that noise is the heart of the next part.

Part 4. Explore or Exploit

Once the agent has some estimates, an obvious rule appears: always pull the arm with the highest Q. That is called exploiting what you know, and a purely greedy agent does exactly that. It has a nasty flaw. Every estimate starts at zero, so the first arm that happens to pay anything instantly looks best, and the greedy agent keeps pulling it. The other four never get a fair test. If the arm it locked on to wasn't the best one, it will never find out.

The opposite approach is to explore, to pull arms at random just to gather information. Pure exploring learns everything and wastes every pull. A good agent has to do both, and every learning algorithm in this course has to settle the same tension. The simplest compromise is epsilon-greedy: with a small probability ε (epsilon) pick a random arm, otherwise pick the best-looking one.

Epsilon-greedy in one picture. With epsilon = 0.1 the agent explores about one pull in ten.
bandit_agent.gd GDScript
func _epsilon_greedy() -> int: if rng.randf() < epsilon: last_explore = true return rng.randi_range(0, n_arms - 1) last_explore = false return greedy()
bandit_agent.gd GDScript
func greedy() -> int: var best := -INF var ties: Array[int] = [] for i in n_arms: if q[i] > best + 1e-9: best = q[i] ties = [i] elif absf(q[i] - best) <= 1e-9: ties.append(i) return ties[rng.randi_range(0, ties.size() - 1)]

Notice what greedy() does when two arms have the same Q: it picks among the ties at random. That matters at the very start, when every arm sits at zero. Without it the agent would always begin with arm A, and every run would look alike.

To see how much exploring pays off, we ran each setting 1000 times, 1000 pulls per run, on the default five machines. The best possible average is 5.0 coins per pull.

  • epsilon = 0 (pure greedy): 3.68 per pull, pulling the best machine 17% of the time.
  • epsilon = 0.01: 3.89 per pull, 29%.
  • epsilon = 0.1: 4.24 per pull, 49%.
  • epsilon = 0.3: 4.27 per pull, 52%.
  • epsilon = 1 (always random): 3.69 per pull, 20%.

Pure greedy and pure random score about the same, for opposite reasons. The best settings sit in the middle. Also notice that 0.1 and 0.3 are nearly tied over 1000 pulls. Over a much longer run the smaller epsilon would pull ahead, because once the agent is sure, exploring is pure waste.

Part 5. Keeping Score

The line chart in the demo shows the average reward per pull as it goes. A good agent's line climbs and levels off near the green line (the best machine's expected value, which only shows when you reveal the odds). A second number, regret, measures the same thing as a cost: for every pull, count how much worse the arm you chose was than the best arm, and add it up.

regret = sum over all pulls of (best value − value of the arm chosen)

An agent that picks the best arm every time has zero regret. An agent that is still exploring pays some regret, and that is the price of learning. The goal of a bandit algorithm is to keep that total as small as possible.

Part 6. The Family Tree of Bandit Strategies

Epsilon-greedy is only one answer to the explore or exploit question. Researchers have invented many others, and they sort into a handful of families by how they decide when to explore. The rest of this lesson walks through the tree one family at a time and explains each strategy with ideas first and code later.

The family tree of bandit strategies. Each family answers the explore or exploit question in a different way.

Part 7. Semi-Uniform Strategies

These strategies use simple rules of thumb to split time between the best-looking arm and some form of random choice. They are the easiest to understand and the easiest to code.

1. Epsilon-Greedy

The idea. With a small probability ε, pick any arm at random. Otherwise pick the arm with the highest estimate. You met this in Part 4.

Picture it. You eat at your favorite restaurant most nights, but one night in ten you pick a place at random in case something better opened up.

with probability ε: random arm; otherwise: arm with the highest Q

Strengths and limits. It is simple and surprisingly hard to beat for how little it costs. It explores blindly, though: a random pick is as likely to be a terrible arm as a promising one, and it keeps wasting about ε of its pulls forever.

2. Epsilon-Decreasing (Decay)

The idea. Start with a large ε and shrink it as evidence builds. Early exploration is cheap and valuable because the agent knows nothing; late exploration costs real reward because the agent already knows a lot.

Picture it. A new student arrives in town and tries a different lunch spot every day for the first weeks, then gradually settles into a routine.

ε(t) = max(εmin, ε0 × γt)

Strengths and limits. It fixes the long-term waste of fixed ε. You must choose the schedule by hand: decay too fast and the agent locks in early on a half-tested favorite; too slowly and it behaves like plain epsilon-greedy.

3. Optimistic Initial Values

The idea. Use no random choices at all. Set every starting estimate higher than any real reward could be. Each real result is a disappointment that pulls its arm's estimate down, so the agent keeps moving on to arms that have not disappointed it yet.

Picture it. Every job on the board is rumored to pay amazingly. You try one, it pays only average, so you try the next rumor, until reality has caught up with all of them.

Q0(a) = a value above the best possible reward

Strengths and limits. It gives strong early exploration for free, but the effect is used up once every estimate has come down, so it copes poorly if payouts change later. The start value has to match the scale of your rewards.

4. Softmax (Boltzmann Exploration)

The idea. Turn the estimates into probabilities. A higher estimate means a higher chance of being picked, but every arm keeps some chance. A temperature τ controls how sharp the preference is: a high τ is nearly random and a low τ is nearly greedy.

Picture it. Choosing a dish by rolling a weighted die: the dish you love gets most of the faces, the so-so one gets a few, and the one that made you sick gets almost none.

P(a) = eQ(a)/τ / sum of eQ(b)/τ over all arms b

Strengths and limits. It explores smartly: a second-best arm is tried more than a terrible one, which epsilon-greedy cannot do. The temperature must be tuned, and its right value depends on the reward scale.

Part 8. Optimistic Bound Strategies

These follow one principle, optimism in the face of uncertainty. Build a plausible upper limit for how good each arm could be, and play the arm with the highest limit. An arm has a high limit for one of two reasons: it looks good, or it is barely tested. Both are good reasons to pull it.

5. UCB1 (Upper Confidence Bound)

The idea. Score each arm by its average plus a bonus that shrinks the more the arm has been pulled. The arm with the highest score is played. No randomness is needed.

Picture it. You are choosing between a movie with three 5-star reviews and one with 500 reviews averaging 4.5. The first one could really be better or just lucky, so it deserves a look.

score(a) = Q(a) + c × sqrt( ln(t) / n(a) )

Strengths and limits. It is deterministic and elegant, and it has strong mathematical guarantees. The constant c has to match the size of the rewards, and the method assumes the arms do not change over time.

6. UCB2

The idea. A variant of UCB1 that works in epochs. After choosing an arm it commits to playing it a stretch of times in a row before looking at the scores again, and each stretch for the same arm is longer than the last.

Picture it. A coach who picks a drill, runs it for a whole practice session, and only then reviews which drill to use next.

arm a is played τ(r+1) − τ(r) times, where τ(r) = ceiling of (1 + α)r

Strengths and limits. It means far fewer score calculations and a more patient style, which helps when switching arms is expensive. The price is a slower reaction when a commitment turns out to be wrong.

7. KL-UCB

The idea. UCB1 ignores what kind of rewards it is seeing. KL-UCB asks a sharper question: what is the largest true success rate that would still make my observed results believable? "Believable" is measured with Kullback-Leibler divergence, a number for how surprising one rate is under another.

Picture it. A detective sees 3 wins in 10 tries and asks how high the real rate could be before 3 in 10 would look suspiciously unlucky.

index(a) = largest q such that n(a) × KL(Q(a), q) ≤ ln(t)

Strengths and limits. The bounds are tighter than UCB1's for win or lose rewards, so fewer pulls are wasted. It needs a little extra math, usually solved by a quick search for q.

Part 9. Bayesian Strategies

A Bayesian agent keeps an explicit belief about each arm, a probability distribution over how good it might be, and updates the belief as results arrive. For win or lose arms the belief is a Beta distribution built from the win and loss counts.

8. Thompson Sampling

The idea. To choose, draw one random sample from every arm's belief and play the arm whose sample is highest. This is also called posterior sampling or probability matching.

Picture it. Each arm hands you a hat full of numbers. A well-understood arm's hat has numbers all about the same. A mystery arm's hat has numbers all over the place, so you often pull out a surprisingly high one and give the arm a try.

draw s(a) from Beta(1 + wins(a), 1 + losses(a)); play the arm with the largest s(a)

Strengths and limits. It is simple, has no exploration constant to tune, and is very widely used in industry. It is random, so two runs differ, and it needs a belief model that fits the rewards.

9. Bayes-UCB

The idea. Use the same beliefs as Thompson sampling but choose deterministically: take a high quantile of each belief, such as its 95th percentile, as the arm's optimistic estimate and play the highest.

Picture it. Instead of asking each arm for a random guess, you ask each one for its best-case number, the value it beats only 5 times in 100.

index(a) = the quantile of arm a's belief at level 1 − 1/t

Strengths and limits. It joins Bayesian beliefs to the clear structure of UCB, and the choices are repeatable, which helps debugging. The quantile can be awkward to compute exactly, so approximations are common.

Part 10. Contextual and Non-Stationary Strategies

So far, the best arm was the same every time and forever. These strategies relax that. A contextual bandit sees a description of the situation (a context) before choosing. A non-stationary bandit lives in a world where payoffs drift, so old data goes stale.

10. LinUCB

The idea. Assume each arm's reward is a weighted sum of the context numbers. Learn the weights for each arm from experience, and add an uncertainty bonus that is large in situations the agent has not met before.

Picture it. A game NPC picks an attack. At short range the sword works best and at long range the bow does, so a single average for each attack would hide the pattern. Knowing the distance fixes that.

score(a) = θ(a) · x + α × sqrt( xT A(a)-1 x ), where θ(a) = A(a)-1 b(a)

Strengths and limits. It is the standard choice for recommendation systems and personalization. Each update only adds one outer product to a small matrix: A += x xT and b += reward × x.

11. Contextual Thompson Sampling

The idea. Thompson sampling with context. Instead of sampling a reward, sample a whole set of plausible weights for each arm, score the current context with them, and play the best score.

Picture it. The same NPC, but instead of computing an optimistic score for each attack, it imagines one plausible version of how each attack really behaves and acts on that.

sample θ~(a) from a distribution centered on θ(a); play the arm with the largest θ~(a) · x

Strengths and limits. It blends context with Thompson's natural exploration, and often performs about as well as LinUCB. It has a spread number to tune and needs matrix math to sample correctly.

12. Discounted and Sliding-Window Bandits

The idea. Make the agent forget. A discounted bandit multiplies all its stored totals and counts by a number slightly below 1 at every step, so old pulls fade away. A sliding window keeps only the last W pulls. Either one can then run UCB on what is left.

Picture it. A delivery driver who trusts this week's traffic far more than last month's, because roads get jammed and clear again.

total(a) and count(a) are multiplied by γ (for example 0.98) every step, then the new result is added

Strengths and limits. These are essential when payoffs change with time, such as seasons or shifting player habits. The effective memory is about 1 / (1 − γ) steps; too short and the agent is jumpy, too long and it stays loyal to something that has stopped working.

Part 11. A Different Idea: Preferences

Every strategy above estimates how much each arm pays. One more important family does not estimate payoffs at all.

13. Gradient Bandit

The idea. Keep a preference number for each arm and turn the preferences into probabilities with softmax. After each reward, compare it to the running average reward (the baseline). If the reward beat the baseline, raise the chosen arm's preference and lower the others; if it fell short, do the reverse.

Picture it. A parent nudging a child's habits: praise what worked better than usual, discourage what worked worse than usual, and the habits drift toward better ones.

H(a) += α × (reward − baseline) × (1 − P(a)), and for the other arms H(b) −= α × (reward − baseline) × P(b)

Strengths and limits. It works well when only relative differences matter. The baseline is what keeps it honest: without one, a reward that is always positive would raise whichever arm happened to be chosen.

Part 12. Choosing a Strategy

  • A quick prototype, or a stable situation: epsilon-greedy, or optimistic initial values.
  • You want exploring that respects what you know: softmax.
  • You want repeatable decisions with a proven guarantee: UCB1, and KL-UCB for win or lose rewards.
  • Rewards are wins and losses and you want the best practical performance: Thompson sampling.
  • The best arm depends on the situation: LinUCB or contextual Thompson sampling.
  • The world drifts: discounted or sliding-window bandits, or a fixed step size instead of a running average.
