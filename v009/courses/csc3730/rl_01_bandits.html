Everything in the decision unit so far was written by you. The FSM and the behavior tree both followed rules you typed in ahead of time. This unit flips that around: the agent starts out knowing nothing about which choices are good, and it learns by trying things and watching what happens. The simplest version of that problem has a long, famous name, the multi-armed bandit, and it comes from the old nickname for a slot machine: a "one-armed bandit," because it has one lever and it takes your money.

Play with the demo below for a minute before reading on. Click a machine to pull it yourself, then switch on Auto-play and watch the agent do it. Don't turn on Show the true odds yet: the whole point is that nobody tells the agent those.

Part 1. One Decision, Over and Over

Here is the whole problem. There are five slot machines. Every pull costs nothing and either pays out some number of coins or pays nothing. Each machine has its own hidden rules for how often it pays and how much it pays. You get a fixed number of pulls and you want as many coins as possible by the end.

Compare this with the situations from earlier units. There is no map, no position, no "state" to track: the situation is exactly the same before every pull. The only thing the agent chooses is which arm. That makes bandits the smallest possible learning problem, and a good place to meet the one idea that every later algorithm in this unit still has to deal with.

One state, five possible actions. After each pull the agent sees only the reward from the arm it chose.

Two facts make it hard. First, the agent only ever sees the machine it actually pulled, so it learns nothing new about the other four on that turn. Second, payouts are random: a machine that pays 100 coins once might be a gold mine or might be pure luck.

Part 2. What a Machine Is

Each machine in the demo is described by two numbers: a probability of paying out, and a payout amount when it does. The agent can't see either. What matters for planning is the average coin count per pull, the expected value:

expected value = probability × payout

These are the five machines in the default set. Switch on Show the true odds in the demo and the same numbers appear under the machines.

Expected coins per pull. The best machine (C, green) is neither the one that pays most when it hits (E) nor the one that hits most often (D).

Look at what this says about intuition. Machine E has the biggest jackpot, 100 coins, but it only hits 3% of the time, so it is worth just 3.0 per pull. Machine D hits 70% of the time, but each hit is only 5 coins. The best machine, C, is a middling payout at a middling rate. An agent that chases the biggest number it has seen, or the most frequent win, will pick wrong.

Part 3. Estimating Value from Experience

The agent can't read expected values. It has to estimate them from what it has seen. The most natural estimate is the plain average: for each arm, add up the rewards it has paid and divide by how many times you pulled it. We call that estimate Q (for "quality") and write it Q(a) for arm a.

You don't need to remember every past reward to keep a running average. You only need the count so far, n, and the current estimate. Each new reward r nudges the estimate toward itself by a fraction 1/n of the gap:

Q ← Q + (r − Q) / n

bandit_agent.gd GDScript
func update(arm: int, reward: float) -> void: n[arm] += 1 q[arm] += (reward - q[arm]) / float(n[arm]) total_pulls += 1 total_reward += reward

Work it through for machine C (which pays 20 with probability 0.25). Suppose the first four pulls pay 0, 0, 20, 0:

  1. Pull 1 pays 0: n = 1, Q = 0 + (0 − 0)/1 = 0.
  2. Pull 2 pays 0: n = 2, Q = 0 + (0 − 0)/2 = 0.
  3. Pull 3 pays 20: n = 3, Q = 0 + (20 − 0)/3 = 6.67.
  4. Pull 4 pays 0: n = 4, Q = 6.67 + (0 − 6.67)/4 = 5.0.

That last value is exactly the average of the four rewards, 20/4 = 5.0, and it happens to equal the true value of C. Don't get excited: with only four samples that is luck. The early estimates are noisy, and that noise is the heart of the next part.

Part 4. Explore or Exploit

Once the agent has some estimates, an obvious rule appears: always pull the arm with the highest Q. That is called exploiting what you know, and a purely greedy agent does exactly that. It has a nasty flaw. Every estimate starts at zero, so the first arm that happens to pay anything instantly looks best, and the greedy agent keeps pulling it. The other four never get a fair test. If the arm it locked on to wasn't the best one, it will never find out.

The opposite approach is to explore, to pull arms at random just to gather information. Pure exploring learns everything and wastes every pull. A good agent has to do both, and every learning algorithm in this course has to settle the same tension. The simplest compromise is epsilon-greedy: with a small probability ε (epsilon) pick a random arm, otherwise pick the best-looking one.

Epsilon-greedy in one picture. With epsilon = 0.1 the agent explores about one pull in ten.
bandit_agent.gd GDScript
func _epsilon_greedy() -> int: if rng.randf() < epsilon: last_explore = true return rng.randi_range(0, n_arms - 1) last_explore = false return greedy()
bandit_agent.gd GDScript
func greedy() -> int: var best := -INF var ties: Array[int] = [] for i in n_arms: if q[i] > best + 1e-9: best = q[i] ties = [i] elif absf(q[i] - best) <= 1e-9: ties.append(i) return ties[rng.randi_range(0, ties.size() - 1)]

Notice what greedy() does when two arms have the same Q: it picks among the ties at random. That matters at the very start, when every arm sits at zero. Without it the agent would always begin with arm A, and every run would look alike.

To see how much exploring pays off, we ran each setting 1000 times, 1000 pulls per run, on the default five machines. The best possible average is 5.0 coins per pull.

  • epsilon = 0 (pure greedy): 3.68 per pull, pulling the best machine 17% of the time.
  • epsilon = 0.01: 3.89 per pull, 29%.
  • epsilon = 0.1: 4.24 per pull, 49%.
  • epsilon = 0.3: 4.27 per pull, 52%.
  • epsilon = 1 (always random): 3.69 per pull, 20%.

Pure greedy and pure random score about the same, for opposite reasons. The best settings sit in the middle. Also notice that 0.1 and 0.3 are nearly tied over 1000 pulls. Over a much longer run the smaller epsilon would pull ahead, because once the agent is sure, exploring is pure waste.

Part 5. Keeping Score

The line chart in the demo shows the average reward per pull as it goes. A good agent's line climbs and levels off near the green line (the best machine's expected value, which only shows when you reveal the odds). A second number, regret, measures the same thing as a cost: for every pull, count how much worse the arm you chose was than the best arm, and add it up.

regret = sum over all pulls of (best value − value of the arm chosen)

An agent that picks the best arm every time has zero regret. An agent that is still exploring pays some regret, and that is the price of learning. The goal of a bandit algorithm is to keep that total as small as possible.

Part 6. Two More Strategies

The strategy menu in the demo includes two others. Random is the always-explore baseline you computed above. UCB1 (upper confidence bound) replaces coin flips with an idea sometimes called "optimism in the face of uncertainty." Each arm gets a score equal to its estimate plus a bonus that shrinks the more it has been tried:

score = Q + c × sqrt( ln(t) / n )

bandit_agent.gd GDScript
func _ucb() -> int: for i in n_arms: if n[i] == 0: last_explore = true return i var best := -INF var pick := 0 for i in n_arms: var score := q[i] + UCB_C * sqrt(log(float(total_pulls)) / float(n[i])) if score > best: best = score pick = i last_explore = pick != greedy() return pick
UCB scores after 52 pulls with c = 10 (dark: estimate, light: bonus). The rarely tried arm wins the next pull despite a lower estimate.

UCB has no randomness and no epsilon to tune. An arm gets pulled either because it looks good or because it is under-explored, and as the counts grow the bonuses fade. In the same 1000-run test it averaged 4.39 per pull and chose the best machine 60% of the time, better than any epsilon above. The constant c is not free, though: it has to match the scale of the rewards, and with payouts up to 100 in this demo a value of 10 works well.

Part 7. Try It

  1. Leave the true odds hidden. Pull the machines yourself, about 30 times, and write down which one you believe is best. Then reveal the odds. How close were you?
  2. Set the strategy to Epsilon-greedy with epsilon at 0. Turn on Auto-play at a high speed for a few thousand pulls. Press Forget and repeat five times. How often does it find the best machine?
  3. Repeat with epsilon 0.1. Compare the final average reward and the regret.
  4. Press New bandits and run your favorite setting again. Is the best setting still the best on a different set of machines?
  5. Stretch: switch to UCB1 and watch the n= counts under each machine. In what order does it try the arms?
