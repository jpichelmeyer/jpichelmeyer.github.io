Q-learning has a sibling that differs by one small term, and that one term changes what the agent learns. SARSA updates its table using the move the agent actually makes next, not the best move it could make. That makes it an on-policy algorithm: it learns the value of the policy it is really following, exploration and all.

Switch the algorithm dropdown in the demo between Q-learning and SARSA as you read, and run the cliff preset with each.

Part 1. The Name Is the Recipe

SARSA is named after the five things the update needs, in the order they happen: the State you were in, the Action you took, the Reward you got, the new State, and the new Action you are about to take there. Compare the two updates side by side:

  • Q-learning: Q(s, a) ← Q(s, a) + α ( r + γ × max Q(s′, a′) − Q(s, a) )
  • SARSA: Q(s, a) ← Q(s, a) + α ( r + γ × Q(s′, a′) − Q(s, a) )

The difference is the max. Q-learning looks at the best thing it could do next. SARSA looks at what it is actually going to do next, which, because the agent is epsilon-greedy, is sometimes a random move.

Part 2. One Extra Decision

There is a catch in the code. To update with Q(s′, a′), the agent must already know a′. So SARSA chooses the next action before it learns, and then makes sure it really plays that action on the next turn. Here are the two places it shows up:

q_agent.gd GDScript
func learn(obs: int, action: int, reward: float, next_obs: int, done: bool, next_action: int) -> void: var target := reward if not done: if use_sarsa: target += gamma * peek(next_obs)[next_action] else: target += gamma * best_value(next_obs) var v := values(obs) v[action] += alpha * (target - v[action])
main.gd GDScript
func take(a: int) -> void: var o := observe(pos) var res := data.step(pos, a) var next_pos: Vector2i = res["pos"] var done: bool = res["done"] var reward: float = res["reward"] var o2 := observe(next_pos) episode_steps += 1 var a2 := -1 if learn_on: if agent.use_sarsa and not done: a2 = agent.choose(o2) agent.learn(o, a, reward, o2, done, a2) last_action = a last_reward = reward episode_return += reward pos = next_pos next_action = a2 if done or episode_steps >= max_steps(): end_episode()

Find a2. When SARSA is on and the episode isn't over, take() picks it with agent.choose(), hands it to learn(), and stores it in next_action. In run_step(), the next move uses next_action instead of making a new choice. The agent that learned about a move is the one that makes that move, so the table describes real behavior. With Q-learning, a2 stays −1 and the agent chooses fresh each step.

Part 3. On-Policy and Off-Policy

Why would that matter? Because an agent with an exploration rate has two selves: the careful policy it hopes to end up with, and the clumsier one it is following right now. Q-learning learns the value of the careful one: "what would happen if I played perfectly from here?" SARSA learns the value of the clumsy one: "what will happen to me if I keep playing like this, mistakes and all?" When mistakes are cheap, the two agree. When a mistake is expensive, they don't.

Part 4. Cliff Walking

Preset 3 is built to tell them apart. The bottom row between the start and the goal is a cliff: step on it and you pay −100 and go back to the start. Every other move costs −1, and the goal pays +10.

The two paths the agents typically settle on, with epsilon = 0.1.

The edge route is shortest: thirteen moves, a return of −2. The top route is seventeen moves, −6. If the agent never made a mistake, the edge would be the obvious choice. But it makes mistakes, a random move one time in ten. Walking along the edge, one stumble down means −100. Walking along the top, a stumble costs nothing.

We ran 20 agents of each kind for 500 episodes with α = 0.5, γ = 1 and a fixed epsilon of 0.1 (so with "Explore early" off), and measured both what each learned and how it did while learning:

  • Q-learning learned the edge route in 16 of 20 runs (return −2), and a route one row farther from the cliff (return −4) in the other four. While training, its average return over the last 20 episodes was about −32, because it fell off the cliff regularly.
  • SARSA learned the safe top-row route in 19 of 20 runs (return −6). While training, its average return over the last 20 episodes was about −18, far better.

Neither agent is wrong. They answer different questions. Q-learning found the best path if you could stop exploring (press Greedy run on a trained Q-learning agent and it walks the edge perfectly). SARSA found the best path given that it keeps exploring: because its estimate of an edge cell includes the chance of a random step into the cliff, edge cells look dangerous and the table steers away from them.

Part 5. Which One Should You Use?

  • If mistakes during learning are expensive, as when a physical robot is learning, or you care how the agent does while it learns, SARSA's caution is a feature.
  • If you will train in a safe simulator and then deploy the greedy policy, Q-learning will usually find a better final policy.
  • If epsilon shrinks toward zero over time (like the "Explore early" schedule), the gap between the two closes, because the agent stops making random mistakes.

Part 6. Try It

  1. Run the cliff preset with Q-learning, "Explore early" off, epsilon 0.1, α 0.5, γ 1. Run 300 episodes, then press Greedy run. Which path does it take? Repeat with SARSA.
  2. While each trains, watch the "Average (last 20)". Which one scores higher while learning, and which has the better final path?
  3. Set epsilon to 0 for the final greedy run on both. Does the SARSA agent still avoid the cliff? Why?
  4. Turn "Explore early" on and compare the two again. Does the difference shrink?
  5. Stretch: make a custom grid with a narrow bridge of reward cells over a river of −50 cells. Which algorithm crosses?
