A bandit agent faces the same situation on every turn. Real agents don't: a robot in a hallway can step forward only if there's room, a game character near a pit has different good moves than one in an open field. As soon as where you are changes what your actions do, you've left the bandit world and entered the setting where almost all of reinforcement learning lives, the Markov decision process, or MDP. The name is intimidating. The thing itself is a grid you already know how to draw.

Open the demo below and try the first preset. Pause the agent, then use the WASD or arrow keys to walk it to the green goal yourself. The number in each cell is the reward you get for stepping onto it.

Part 1. The Pieces

An MDP has five ingredients, and the gridworld has a concrete version of each:

  • States: the situations the agent can be in. Here, one state per cell. A 5 × 5 grid has 25 states.
  • Actions: what the agent can choose. Here, always four: up, down, left, right.
  • Transitions: what an action does. Move one cell in that direction, unless the move runs into a wall or the edge, in which case you stay put.
  • Rewards: a number handed back after each move, based on the cell you land on.
  • Episodes: one run from the start cell until something ends it, usually reaching a terminal cell.
Four actions from the middle cell. Each leads to a different next state and may pay a different reward.

Part 2. Transitions and Rewards in Code

The whole world fits in a few lines. GridData.step() takes a cell and an action and answers three questions: where did you end up, what reward did you get, and is the episode over?

grid_data.gd GDScript
func step(c: Vector2i, action: int) -> Dictionary: var n: Vector2i = c + DIRS[action] if not inside(n) or kind_at(n) == Kind.WALL: return {"pos": c, "reward": step_reward, "done": false} var r := reward_at(n) match kind_at(n): Kind.TERMINAL: return {"pos": n, "reward": r, "done": true} Kind.CLIFF: return {"pos": start, "reward": r, "done": false} return {"pos": n, "reward": r, "done": false}

Read the cases in order. A move into a wall or off the grid leaves you where you are and costs the ordinary step reward. Stepping onto a terminal cell pays that cell's reward and sets done to true. Stepping onto a cliff cell pays its (very negative) reward and sends you back to the start without ending the episode. Anything else just moves you and pays whatever number is stored in that cell.

Notice what isn't in this function: no probabilities, no history. The result depends only on where you are and which action you pick. That property, that the present state is all you need to know what happens next, is the Markov property, and it's the "M" in MDP. It is what lets an agent learn one number per state and action instead of having to remember every path it ever took.

Part 3. Return: Adding Up the Future

In the bandit lesson one pull gave one reward. Now an episode is a sequence of rewards: a few step costs and then, if all goes well, a big prize at the end. What the agent is really trying to maximize is the whole sum, called the return. Walk the first preset in the demo (step cost 0) and the return is 10. Walk the second (step cost −1) in the shortest possible way, eight moves, and it is 3: seven steps at −1 and then +10.

Most learning algorithms add one more ingredient, a discount factor γ (gamma) between 0 and 1. A reward that arrives k steps from now is multiplied by γ raised to the power k − 1, so rewards far in the future count for less:

return = r1 + γ r2 + γ2 r3 + γ3 r4 + ...

Two reasons to do this. A discount makes a sooner reward better than the same reward later, which gives the agent a reason to hurry even when steps cost nothing. And it keeps the total finite even if an episode could, in principle, go on forever.

What a +10 reward is worth today, depending on how many steps away it is.

With γ = 0.9, a +10 prize five steps away is worth 10 × 0.94 = 6.56 to the agent right now. With γ = 0.5 the same prize is worth only 0.63, and the agent becomes short-sighted: it prefers small rewards close by to large ones far away. You will set γ with a slider in the demo.

Part 4. Reward Design: You Get What You Reward

The agent never sees what you meant. It sees numbers. Designing those numbers, the reward function, is often the hardest part of a real project, and the six presets are six small lessons in it. Run each for a while and compare the greedy path the agent settles on.

  • 1. Sparse goal. Only the goal pays. The only thing pushing the agent to hurry is the discount γ. Nothing says one route is better, as long as it ends at the goal.
  • 2. Step cost. The same grid with a −1 charge for every move. Now the shortest path is clearly best: eight moves return 3, a wandering twelve-move path returns −1.
  • 3. Cliff. The bottom row between start and goal is a cliff worth −100 that throws the agent back to the start. The shortest route runs right along its edge and returns −2. A safer detour along the top row returns −6, a much longer trip, but one that can't fall.
  • 4. Prize, pits and a big goal. A small prize (+2) two steps to the left, a big goal (+10) five steps to the lower right, and pits (−10) around. Taking the prize returns +1; the goal returns +6. A short-sighted or under-explored agent settles for the prize.
  • 5. Maze with a puddle. A puddle cell costs −3 instead of −1. The shortest path wades through it and returns −6; a path one step longer around it returns −4. The puddle changes which path is best, not just how long it is.
  • 6. Breadcrumbs. Four cells near the start pay +2 each time you step on them. Someone meant them as a trail that guides the agent. Watch what it actually does.

The sixth preset is the important one. A reward that is paid every time you step on a cell can be collected over and over. A clever agent doesn't walk the trail to the goal; it circles on two breadcrumb cells, earning +2 per step until the time limit stops it, for a return of about 270, far more than the single +10 for finishing. The agent isn't misbehaving. It found exactly what you rewarded. If you want an agent to progress, the reward has to be tied to progress, for example paid once or paid for getting closer and charged for moving away, rather than paid for standing on a spot.

Part 5. Try It

  1. On preset 2 pause the agent and walk it with the keys. What return do you get for the shortest path? For a path with one extra step?
  2. On preset 3, walk the edge path and then the top-row path. Predict both returns before you finish, then compare to the HUD's "Return so far".
  3. On preset 6, step onto the same breadcrumb cell, off, and on again. How much did you collect? How many such steps would it take to beat the +10 at the goal?
  4. Switch to the custom grid (or just start painting on a preset). Build a grid where taking the shorter route means a worse return than a longer one.

Checkpoint

Before moving on, make sure you can:

  1. Name the five ingredients of an MDP and point to each in the gridworld.
  2. State the Markov property in one sentence and say what step() would need if it didn't hold.
  3. Compute the return for a path with four moves at a step cost of −1 that ends on a +10 goal, first with γ = 1 and then with γ = 0.9.
  4. Explain why the discount makes the agent hurry even when steps cost nothing.
  5. Explain how the breadcrumb preset breaks the designer's intent, and suggest one change to its rewards that would fix it.

Exercises

Warm-up

  1. In preset 1, if γ = 0.9, what is the discounted value of the +10 goal as seen from the start (eight moves away)?
  2. Why does a step cost of 0 give a sparse-goal agent no reason to avoid a long wandering path (before discounting)?

Intermediate

  1. In the custom grid, make a corridor with a +1 prize one step from the start and a +10 goal ten steps away. At what discount γ does the prize become better than the goal for a perfect agent?
  2. Change the breadcrumbs so they can be collected only once. What does the code need to remember that GridData.step() currently doesn't?

Advanced

  1. Add a terminal cell with reward 0 (a "do nothing" exit) to preset 2. With step cost −1, what does a perfect agent do? What if the goal is moved far away?
  2. Write the reward for a cell so the agent receives the change in distance to the goal after each move. Show that going around in a circle sums to zero.
