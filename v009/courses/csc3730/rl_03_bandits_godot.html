The last two lessons described the bandit agent as an idea. This lesson opens the project and shows where each piece lives. Nothing here is new machinery: the project is the Situated Agent Model from the first week, with a slot machine for an environment.

Part 1. The Project in One Picture

The bandit project, labeled with the Situated Agent Model. The reward is perceived, folded into memory, and memory drives the next decision.

Five script files make up the project:

  • bandit_agent.gd: the agent's brain (memory and decider). It knows nothing about pictures or buttons.
  • bandit.gd: one slot machine. It holds the true odds and knows how to draw itself.
  • reward_chart.gd: the line chart.
  • main.gd: builds the world and the HUD, runs the loop, saves and loads.
  • main.tscn: a single Node2D that runs main.gd. Everything else is created in code.

Keeping the brain in its own file, free of any Godot node, is deliberate. BanditAgent extends RefCounted, the lightest base class there is, and you could test it with no screen at all. That is exactly how we tested the numbers in the last two lessons.

Part 2. The Environment: Bandit Nodes

Each machine is an instance of the Bandit class, created in build_world(). It stores its two secret numbers, and anything the HUD wants to show about the agent's beliefs (est, pulls) is simply copied into it each refresh so it can draw them under itself.

main.gd GDScript
func build_world(seed_value: int) -> void: world_seed = seed_value for m in machines: m.queue_free() machines.clear() var params := _make_params(seed_value) best_value = -1.0 for i in ARMS: var m := Bandit.new() m.letter = char(65 + i) m.probability = params[i][0] m.payout = params[i][1] m.hue = float(i) / ARMS m.position = Vector2(180.0 + i * 230.0, MACHINE_Y) m.reveal = reveal_check != null and reveal_check.button_pressed add_child(m) machines.append(m) if m.expected_value() > best_value: best_value = m.expected_value() best_arm = i

The odds come from _make_params(seed). A seed of 0 returns the hand-picked PRESET list. Any other seed feeds a RandomNumberGenerator so the same seed always rebuilds the same five machines, which is what lets the save file store one number instead of ten.

Part 3. Drawing a Machine with Code

There are no image files for the slot machines. A Node2D can draw itself by overriding _draw(), which is called whenever the node asks for a redraw. Inside it, the draw_rect, draw_circle, draw_colored_polygon and draw_string functions paint straight onto the canvas. Here is the face and bandana:

bandit.gd GDScript
draw_rect(Rect2(-62.0, 12.0, 124.0, 84.0), Color("f2d6b3")) draw_circle(Vector2(-28.0, 38.0), 12.0, Color.WHITE) draw_circle(Vector2(28.0, 38.0), 12.0, Color.WHITE) draw_circle(Vector2(-28.0 + look * 5.0, 39.0), 5.0, dark) draw_circle(Vector2(28.0 + look * 5.0, 39.0), 5.0, dark) draw_line(Vector2(-44.0, 20.0), Vector2(-16.0, 27.0), dark, 4.0) draw_line(Vector2(44.0, 20.0), Vector2(16.0, 27.0), dark, 4.0) var red := Color("c43b3b") draw_colored_polygon(PackedVector2Array([Vector2(-62.0, 54.0), Vector2(62.0, 54.0), Vector2(0.0, 96.0)]), red) draw_rect(Rect2(-62.0, 48.0, 124.0, 10.0), Color("9e2a2a")) draw_colored_polygon(PackedVector2Array([Vector2(62.0, 46.0), Vector2(80.0, 38.0), Vector2(80.0, 66.0)]), Color("9e2a2a")) for p in [Vector2(-30.0, 64.0), Vector2(-12.0, 61.0), Vector2(26.0, 63.0), Vector2(0.0, 74.0), Vector2(14.0, 80.0)]: draw_circle(p, 3.0, Color.WHITE)

Everything is drawn in the node's own coordinate system, with the origin at the top center, so moving the whole machine is just changing position. The pupils shift by look, a number between −1 and 1 that main.gd sets each frame from the agent's position, so the machines watch the agent walk by.

Animation works the same way. show_result() only records what should happen (final reels, a spin time, a popup), and _process() advances timers and asks for a redraw:

bandit.gd GDScript
func show_result(win: bool, amount: int, spin_time: float) -> void: if win: _final = ["7", "7", "7"] else: var pool := ["7", "$", "*"] _final = [pool.pick_random(), pool.pick_random(), pool.pick_random()] if _final[0] == _final[1] and _final[1] == _final[2]: _final[2] = "#" _spin = spin_time if spin_time <= 0.0: _reels = _final.duplicate() _lever = 1.0 _pop_win = win _pop_text = "+%d" % amount if win else "0" _pop_t = 1.0

Rolling a win or loss does not happen here. The machine only decides what to show. The dice are rolled in main.gd, so one place holds all the game's randomness.

Part 4. One Pull, End to End

Every pull, whether the agent chose it or you clicked a machine, goes through do_pull(). Reading it top to bottom gives you the whole learning loop in a dozen lines:

main.gd GDScript
func do_pull(arm: int, why: String) -> void: var m := machines[arm] var reward := float(m.payout) if rng.randf() < m.probability else 0.0 agent.update(arm, reward) var spin_time := 0.35 if auto_on: spin_time = 0.0 if speed > 12.0 else minf(0.35, 0.7 / speed) m.show_result(reward > 0.0, int(reward), spin_time) agent_target_x = m.position.x mood = why if arm == best_arm: optimal_pulls += 1 regret += best_value - m.expected_value() var cumulative := agent.total_reward / float(agent.total_pulls) chart.cumulative.append(cumulative) window_sum.append(reward) if window_sum.size() > 50: window_sum.pop_front() var s := 0.0 for v in window_sum: s += v chart.recent.append(s / window_sum.size()) refresh()

It rolls the machine, hands the reward to the agent's memory with agent.update(), tells the machine what to animate, sends the agent sprite to that machine, and records bookkeeping for the chart. The agent's decision lives one function up:

main.gd GDScript
func agent_pull() -> void: var arm := agent.choose() do_pull(arm, "Exploring" if agent.last_explore else "Exploiting")

And Auto-play is just a timer accumulating in _process():

main.gd GDScript
func _process(delta: float) -> void: if auto_on: acc += delta * speed var count := 0 while acc >= 1.0 and count < 300: acc -= 1.0 count += 1 agent_pull() if count == 300: acc = 0.0

Instead of waiting for a timer node for each pull, the code adds up delta × speed and fires one pull for each whole unit that builds up. That is why the speed slider can go from one pull per second to hundreds: at high speeds the loop simply runs several pulls in one frame (with a cap, so a slow frame can't snowball).

Part 5. Try It

  1. Open main.gd and change the numbers in PRESET. Predict which machine becomes best before you run it, then confirm in the demo.
  2. In bandit_agent.gd change the first line of setup() so every q starts at 20 instead of 0 (an optimistic start). Run a greedy agent (epsilon 0). Why does it explore even though epsilon is zero?
  3. Replace q[arm] += (reward - q[arm]) / float(n[arm]) with a fixed step size, q[arm] += 0.1 * (reward - q[arm]). Describe how the estimates behave differently over the first 10 pulls and over the last 1000.
  4. Stretch: make epsilon shrink over time, for example epsilon = 1.0 / (1.0 + total_pulls * 0.01), and compare its total reward to a fixed epsilon of 0.1 over 2000 pulls.

Exercises

Warm-up

  1. Change the reel symbols and colors in bandit.gd.
  2. Make the HUD show the best machine's letter in a different color.

Intermediate

  1. Add a pull cost of 1 coin per pull so the reward is payout minus 1. How do the numbers in the chart change, and does the best machine change?
  2. Add a sixth strategy to BanditAgent: "Greedy with optimistic start." Wire it into the dropdown.

Advanced

  1. Make one machine non-stationary: its probability drifts by a small random amount each pull. Which strategy copes best?
  2. Build a second agent that plays the same machines at the same time and show both charts. Is it a fair comparison if they use different random numbers?
