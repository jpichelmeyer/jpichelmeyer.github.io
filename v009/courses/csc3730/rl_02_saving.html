Last lesson's agent learned something real: after a few hundred pulls it knew which machines were worth playing. Then you closed the program and every bit of that was gone. A learning agent that forgets everything on quit has to start from scratch every time, which is a strange thing to ask of something whose entire purpose is to remember what it has seen. This lesson adds saving and loading so an agent can keep what it has learned.

Try it first. Run the demo, let the agent play a few hundred pulls, press Save agent, then Forget, then Load agent. The estimates under every machine should come back exactly as they were.

Part 1. What the Agent Knows

The first design question is what exactly goes into a save file. The answer comes straight from the Situated Agent Model: save the agent's Memory. For the bandit agent that is small:

  • the estimate q for each arm,
  • the pull count n for each arm (it is needed to keep averaging correctly),
  • running totals for pulls and reward, and the chosen strategy and epsilon.

What does not belong in the agent's save is the true probability and payout of each machine. Those belong to the world, and the agent is not supposed to know them. If you saved them into the agent's file you would be building an agent that cheats the moment it is loaded.

The agent's memory goes in the save file. The world is described by a single number, its seed, so it can be rebuilt without storing the answers.

Part 2. From Variables to JSON

Godot can only write text and bytes to disk, not live objects, so we first flatten the memory into a Dictionary of plain numbers and lists. Then JSON.stringify() turns that dictionary into text. The agent knows how to describe itself, and how to rebuild itself from a description:

bandit_agent.gd GDScript
func to_dict() -> Dictionary: return { "q": Array(q), "n": Array(n), "pulls": total_pulls, "reward": total_reward, "strategy": strategy, "epsilon": epsilon, }
bandit_agent.gd GDScript
func from_dict(d: Dictionary) -> bool: if not (d.has("q") and d.has("n")): return false var qs: Array = d["q"] var ns: Array = d["n"] if qs.size() != n_arms or ns.size() != n_arms: return false for i in n_arms: q[i] = float(qs[i]) n[i] = int(ns[i]) total_pulls = int(d.get("pulls", 0)) total_reward = float(d.get("reward", 0.0)) strategy = int(d.get("strategy", 0)) epsilon = float(d.get("epsilon", 0.1)) return true

Two details are worth slowing down for. from_dict returns a bool: true if the data fits, false otherwise. It refuses a file whose arrays are the wrong length instead of half loading it. And d.get("pulls", 0) supplies a default when a key is missing, so a save made by an older version of the program still loads.

Here is a real save file from the demo after twelve pulls:

bandit_agent.json JSON
{ "agent": { "epsilon": 0.1, "n": [10, 0, 1, 1, 0], "pulls": 12, "q": [4.0, 0.0, 0.0, 0.0, 0.0], "reward": 40.0, "strategy": 0 }, "optimal_pulls": 1, "regret": 21.5, "version": 1, "world_seed": 0 }

You can read it like a story: ten pulls on machine A (average 4.0), one each on C and D that paid nothing. The "version" key is a note to your future self. The day you add a new field, you can check the version number and decide how to treat old files. (The file above is shown with the arrays on one line to save space; Godot writes one number per line.)

Part 3. Writing the File

Files you create at run time belong in the special user:// folder. Unlike res://, the project's own files, which are read-only once the game is exported, user:// is writable on every platform and is kept per project. On a desktop it is a folder in your account (open it from the editor with Project > Open User Data Folder). In a web build, Godot stores it in the browser's IndexedDB, so the save survives page reloads but disappears if the visitor clears their site data.

main.gd GDScript
func save_agent() -> void: var data := { "version": 1, "world_seed": world_seed, "optimal_pulls": optimal_pulls, "regret": regret, "agent": agent.to_dict(), } var f := FileAccess.open(SAVE_PATH, FileAccess.WRITE) if f == null: status_label.text = "Could not write the save file." return f.store_string(JSON.stringify(data, " ")) f.close() status_label.text = "Saved %d pulls of experience." % agent.total_pulls

Walk through it. Build the dictionary. FileAccess.open() with WRITE either gives you a file or null, so check before using it. store_string() writes the text, and close() finishes the job. The final line tells the person what happened. A save button that fails silently is worse than no save button.

Part 4. Reading It Back, Carefully

Loading is the same trip in reverse, with one big difference: you can't trust what you read. The file might not exist yet. It might have been edited by hand, damaged, or written by a different version of your program. Every one of those cases deserves a calm message rather than a crash.

main.gd GDScript
func load_agent() -> void: if not FileAccess.file_exists(SAVE_PATH): status_label.text = "No saved agent yet. Press Save agent first." return var data = JSON.parse_string(FileAccess.get_file_as_string(SAVE_PATH)) if typeof(data) != TYPE_DICTIONARY or not data.has("agent"): status_label.text = "That save file could not be read." return build_world(int(data.get("world_seed", 0))) agent.setup(ARMS) if not agent.from_dict(data["agent"]): status_label.text = "The save file does not match these machines." return reset_history() optimal_pulls = int(data.get("optimal_pulls", 0)) regret = float(data.get("regret", 0.0)) eps_slider.set_value_no_signal(agent.epsilon) eps_value.text = "%.2f" % agent.epsilon strat_option.select(agent.strategy) if agent.total_pulls > 0: chart.cumulative.append(agent.total_reward / agent.total_pulls) refresh() status_label.text = "Loaded an agent with %d pulls of experience." % agent.total_pulls

Count the guards. First file_exists(). Then JSON.parse_string(), which returns null on a parse error, so the code checks the result is a Dictionary that has an "agent" key. Then the world is rebuilt from the saved seed before the agent's numbers go in, and from_dict has the final say on whether the numbers fit. Only after everything has passed does the code overwrite the live agent.

Part 5. A Save Is a Promise About the World

The agent's estimates only mean something for the machines they were learned on. Load a memory that says "machine C pays about 5 per pull" into a world where C has been rewired, and the agent will confidently walk straight into regret. That is why the file stores "world_seed" and why loading rebuilds the same machines first. Pressing New bandits creates different machines and makes the agent forget, for the same reason.

This is a general lesson about saved learning. A trained agent is a pair: what it knows and the situation that taught it. Whenever you save one, ask what else the knowledge depends on, and save that too, or save a way to rebuild it.

Part 6. Try It

  1. Run 300 pulls, Save, Forget, Load. Confirm the Q values and counts return. The pull total and regret should too.
  2. Save, press New bandits, then press Load agent. Which machines come back? Why?
  3. On a desktop copy of the project, open the user data folder from the editor and open bandit_agent.json. Change one of the q numbers to 50 and load it. What does the agent do next, and why?
  4. Delete the "agent" key from the file and press Load. What message appears, and where in load_agent does it come from?

Checkpoint

Before moving on, make sure you can:

  1. Say what belongs in the agent's save file and what does not, and explain why.
  2. Explain the difference between res:// and user://.
  3. List three things that can go wrong when loading, and show where the code guards against each.
  4. Explain why the save file stores a world seed instead of the machines' real probabilities.
  5. Say what the "version" key is for.

  2. Change the save file name to include the strategy, for example bandit_agent_ucb.json.

Intermediate

  1. Add three save slots with a small dropdown to choose among them.
  2. Autosave every 500 pulls. Where should the check go, and how will you avoid writing the file on every single frame?

Advanced
