Every steering behavior so far answers "which way should I move" using only the target and its own position. None of them look at anything else in the scene. This lesson builds a solid obstacle and lets you watch that gap firsthand, which sets up exactly why the next few lessons take a completely different approach to getting around things.

Part 1. Building an Obstacle

In Environment, add a StaticBody2D named Obstacle, with a Sprite2D child (icon.svg, the default placeholder every Godot project ships with, works fine here) and a CollisionShape2D child using a RectangleShape2D sized to roughly match the sprite.

Save this as its own scene, obstacle.tscn, rather than building it directly inside Environment. You'll want to drop several of these into a scene later, and a reusable scene means placing a new one is drag-and-drop instead of rebuilding the node tree by hand each time.

Part 2. Watching Steering Fail

Drop one instance of obstacle.tscn into Environment, directly between AgentA and whatever it's currently seeking. Press Play.

AgentA drives straight through it. Nothing stops it, nothing deflects it, nothing even notices it's there. That's not a bug to fix in this lesson, it's the actual, honest state of the code you've built: Agent2D has no CollisionShape2D of its own, and every steering behavior so far only ever asks "where is my target," never "is anything in my way." _apply_velocity moves the agent unconditionally, every frame, regardless of what's sitting in the path.

Part 3. Two Ways Games Actually Solve This

There are two broad families of fix, and it's worth knowing both exist even though this course only builds one of them:

  • Reactive avoidance. Give the agent a way to sense obstacles directly, commonly a short raycast out in front of it, and steer away from whatever the ray hits. This keeps agents fast and simple, but they only ever react to what's immediately ahead; they have no sense of the map as a whole, and can get stuck in dead ends or bad local situations a wider view would have avoided.
  • Deliberative planning. Build a representation of the whole map (which areas are open, which are blocked), and search that representation for a route before moving at all. This sees the big picture and can guarantee a route exists (or correctly report that none does), at the cost of needing that map built and kept up to date.

This course takes the second path. Rather than teaching an agent to react to obstacles one raycast at a time, the next lesson builds a grid over the whole environment, one that already knows which cells this same Obstacle scene blocks, and searches it for a path. The obstacle you just built isn't wasted work, it's exactly what that grid is going to detect.

Checkpoint

Before moving on, make sure you can:

  1. Build a reusable obstacle.tscn with a StaticBody2D, a visible sprite, and a CollisionShape2D.
  2. Explain, precisely, why current steering agents pass straight through it rather than reacting to it.
  3. Describe the difference between reactive avoidance and deliberative planning, and which one this course is about to build.
