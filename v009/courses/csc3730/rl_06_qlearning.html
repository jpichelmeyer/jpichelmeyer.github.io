A policy is only as good as the numbers behind it, and so far those numbers have appeared by magic. This lesson shows where they come from. Q-learning is one of the most important algorithms in reinforcement learning, and the idea fits in one line: after every move, nudge your estimate of how good that move was toward what you just observed.

Open the demo on the first preset (the sparse goal) and press Step repeatedly with the speed turned down, watching the Options panel and the colors. Don't worry about understanding yet; just watch where the numbers change.

Part 1. A Table That Learns

The agent keeps a table with one row for each state and one column for each action, so each cell of the table holds one Q value. In the demo that is the dictionary q in QAgent: a state maps to a list of four numbers (up, down, left, right). It starts empty, which means all zeros. Everything the agent will ever know about the world is what it manages to write into that table.

The agent does not know the map, the rewards, or where the goal is. All it can do is move, watch the reward it gets and the state it lands in, and update one entry of its table.

Part 2. The Update

Suppose the agent was in state s, took action a, received reward r, and landed in state s′. It now knows one fresh fact about s, a: taking that action gave an immediate r, and put it somewhere whose best option is worth max Q(s′, ·). So a better estimate of Q(s, a) would be:

target = r + γ × max Q(s′, a′)

The agent doesn't swap its old number for the target, since one sample can be noisy or misleading. It moves part of the way, by a fraction α (alpha, the learning rate):

Q(s, a) ← Q(s, a) + α × ( target − Q(s, a) )

One Q-learning update. The learning rate alpha says how much of the surprise to absorb.

The "surprise," target minus old estimate, has a name in the literature, the temporal-difference (TD) error. When it is zero the table already agrees with experience, and when it is large the agent learned something. Here is the whole algorithm in the project:

q_agent.gd GDScript
func learn(obs: int, action: int, reward: float, next_obs: int, done: bool, next_action: int) -> void: var target := reward if not done: if use_sarsa: target += gamma * peek(next_obs)[next_action] else: target += gamma * best_value(next_obs) var v := values(obs) v[action] += alpha * (target - v[action])

Two cases appear. If the move ended the episode (done), there is no next state to look ahead to, so the target is just the reward. Otherwise the target adds the discounted best value of the next state. The final two lines are the update itself.

Part 3. A Hand Trace

Take the corridor from the last lesson: four cells, a +10 goal at the right end, a step cost of −1. Use α = 0.5 and γ = 0.9, with every Q value starting at 0, and suppose the agent walks straight to the goal in every episode. Only the "right" entries matter. Each episode updates cells 0, 1, 2, 3 in order, always using the other entries as they are right then:

  • Episode 1. Cell 0: target = −1 + 0.9 × 0 = −1, so Q goes from 0 to −0.5. Cells 1 and 2 do the same: −0.5. Cell 3 steps into the goal: target = 10, so Q becomes 0 + 0.5 × (10 − 0) = 5.0.
  • Episode 2. Cells 0 and 1 find their neighbors' best Q is still 0 (the other actions are untried), so they drift to −0.75. Cell 2 finally looks at cell 3: target = −1 + 0.9 × 5.0 = 3.5, so Q goes from −0.5 to −0.5 + 0.5 × (3.5 + 0.5) = 1.5. Cell 3 rises to 7.5.
  • Episode 3. Now cell 1 sees cell 2's 1.5: target = −1 + 0.9 × 1.5 = 0.35, so it jumps from −0.75 to −0.2. Cell 2 becomes 3.625 and cell 3 becomes 8.75.
  • Episode 4. Cell 1 turns positive (1.03) and cells 2 and 3 reach 5.25 and 9.38. Cell 0 still sees a best neighbor value of 0, because the untried actions in cell 1 still sit at zero, so it has to wait one more pass.

Watch what happened. The reward only exists at the goal. In episode 1, only the cell touching the goal learned about it. In episode 2, the cell before that learned. In episode 3, the one before that. Information about the reward travels backward through the table, one step per pass. That is how a reward at the end of a long path eventually shapes the decision at the very start, even though the agent never reasons about the path at all. The final answer (4.58, 6.2, 8.0, 10.0 for the best action) is exactly the value table from the last lesson, and the numbers above are on their way there.

You can watch the same thing happen on the sparse-goal preset: the colored glow starts at the goal cell and spreads outward as the episodes go by.

Part 4. The Training Loop

Everything the agent does, one move at a time, happens in two functions. run_step() picks an action (with the epsilon-greedy policy from last lesson) and hands it to take(), which plays it in the world and calls learn():

main.gd GDScript
func run_step() -> void: var o := observe(pos) var a := next_action if next_action >= 0 else agent.choose(o) take(a)
main.gd GDScript
func take(a: int) -> void: var o := observe(pos) var res := data.step(pos, a) var next_pos: Vector2i = res["pos"] var done: bool = res["done"] var reward: float = res["reward"] var o2 := observe(next_pos) episode_steps += 1 var a2 := -1 if learn_on: if agent.use_sarsa and not done: a2 = agent.choose(o2) agent.learn(o, a, reward, o2, done, a2) last_action = a last_reward = reward episode_return += reward pos = next_pos next_action = a2 if done or episode_steps >= max_steps(): end_episode()

Read take() as the four-beat rhythm of every RL system: observe where you are, act in the world, look at the reward and the new state, learn. When the episode ends (a terminal cell, or the step limit), end_episode() sends the agent back to the start with its table intact. The table is the only thing that persists, and it is what the save button writes to disk.

The "Train 200 episodes" button simply calls run_step() in a loop with no drawing between moves, which is why it finishes in a blink.

Part 5. The Three Knobs

  • α (alpha), the learning rate. How far each update moves toward the target. A tiny α learns slowly. A large α learns quickly but jumps around when the target is noisy. This world has no randomness, so large values work well, but in a world with chance in it you would use a smaller one, or one that shrinks as the agent gains experience.
  • γ (gamma), the discount. How much the future counts. At γ = 0 the agent only cares about the immediate reward and never learns to work toward a goal more than one step away. Near 1 it plans far ahead, but the backward flow of information takes more passes.
  • ε (epsilon), the exploration rate. Too small and the agent can lock onto the first decent route it finds, as the prize preset showed. Too large and it keeps throwing away good moves, which makes its online returns poor even when its table is excellent.

Part 6. Learning About the Best, Not the Chosen

Look once more at the target: it uses best_value(next_obs), the best Q in the next state, even though the agent may well choose a random action there when exploring. Q-learning pretends the agent will behave greedily from the next step on. It learns the value of the best policy while actually following a different, more adventurous one. An algorithm that learns about a policy other than the one it is following is called off-policy. That sounds like a technicality, but it has real consequences, as the next lesson shows.

Part 7. Try It

  1. On preset 1, set α to 1.0 and γ to 0.9, turn "Explore early" off and set epsilon to 0.3. Use Step a few dozen times. Which cells light up first, and how many episodes does it take for the glow to reach the start?
  2. Set γ to 0 and run preset 2 for a few hundred episodes. What do the arrows look like, and why?
  3. Set α to 0.05 and train 200 episodes. Compare the colors to a run with α = 0.5.
  4. Set epsilon to 0.9 and watch "Last return" while training. Press Greedy run. Why does the learned policy look so much better than the training runs?
  5. Stretch: use the hand trace as a recipe and compute the first two episodes for a corridor of five cells with α = 1, γ = 0.9, step cost 0.

Exercises

Warm-up

  1. Using α = 1 and γ = 0.5, compute Q(2, right) after the first time the agent reaches cell 3 when Q(3, right) = 10.
  2. In the hand trace, what would episode 1 produce if the step cost were 0 instead of −1?

Intermediate

  1. Make α decay as the agent gains experience, for example alpha = 1.0 / (1.0 + 0.02 * visits) with a per-state visit count. Does the final policy change?
  2. Count how many episodes it takes the agent to find the optimal path on preset 2, averaged over ten resets. Plot it against epsilon.

Advanced

  1. Add a stochastic "slippery floor": with probability 0.1 the chosen action is replaced by a random one. How do the learned Q values change, and why does a large α now hurt?
  2. Implement double Q-learning (two tables, alternate which one chooses and which one evaluates) and compare it on the cliff.
