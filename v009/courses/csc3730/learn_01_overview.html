The SAM lesson closed with a line worth returning to now: a lot of this semester is really just different ways of building a more capable Decider. An FSM's Decider is a set of states and transitions you write by hand. A behavior tree's Decider is a set of nodes you arrange by hand. Machine learning is a genuinely different approach: instead of writing the decision rule yourself, you write a way for the agent to discover the rule from data or experience.

Part 1. Three Agents, Three Paradigms

The simulation above runs three learning agents side by side, and each one is a different flavor of machine learning, which the next three lessons take one at a time:

  • Checker watches people arrive at a checkpoint, reads their appearance, and decides whether to let them through. It's a classification problem: the output is a discrete category, alien or not.
  • Sentry watches for a fleeing target and decides how far ahead of it to aim. It's a regression problem: the output is a continuous number, how much lead to give the shot.
  • The aliens themselves share one policy (the "Hive Mind") for deciding whether to juke up, juke down, or run straight when being shot at. It's a reinforcement learning problem: there's no "correct" dodge labeled in advance, only a reward (dodged, or didn't) discovered by trying things.

Part 2. The Three Basic Areas of Machine Learning

Classification and regression are both supervised (every training example comes with a known correct answer); reinforcement learning has no labeled correct answer at all, only a reward. Unsupervised learning (not used by any agent in this project) has neither labels nor rewards -- it looks for structure in unlabeled data on its own.
  • Supervised learning: training data is a set of (input, correct output) pairs. The model's job is to learn a function from input to output that generalizes to new inputs it hasn't seen. If the output is a category (a finite set of discrete labels), it's classification. If the output is a number that can fall anywhere along a continuum, it's regression.
  • Unsupervised learning: training data is unlabeled — just a pile of inputs, no correct-output pairing at all. The model looks for structure on its own: grouping similar inputs together (clustering), or finding a simpler underlying representation of the data. No agent in this project's demo uses it, but it's worth naming as the third basic category alongside supervised and reinforcement learning.
  • Reinforcement learning: there's no labeled correct answer for any single decision. Instead, an agent takes actions in some environment and receives a reward signal (a number saying how well that went), then adjusts its behavior to earn more reward over time. It learns by trial, error, and consequence, not by being shown correct answers upfront.

Part 3. A New Piece of Vocabulary: Training

Every Decider you've built so far reacted every single frame: an FSM's update(), a behavior tree's tick(). A learning agent adds a second mode entirely: it still acts every frame (using whatever it currently believes), but periodically it also trains, pausing to update those beliefs from what's accumulated in Memory since the last time.

Watch the simulation above for a minute and you'll see this directly: each agent alternates between acting on the world and a brief pause (labeled on screen) where it retrains on what it's collected. This collect-then-train cycle, not deciding fresh from nothing every frame, is the structural signature of a learning Decider, and it's true whether the training update is Checker's Naive Bayes refit, Sentry's gradient descent, or the aliens' shared Q-table nudge — the next three lessons.
