The moving average from Unit 1 needs a buffer of recent readings. The exponential moving average, EMA, gets nearly the same smoothing from one stored number and one line of code. It is the workhorse of embedded signal processing, and the machinery inside the z-score detector you just met.

Part 1. One Line

Each new reading nudges the average a fraction alpha of the way towards it:

ema.py MicroPython
ema = first_reading while True: x = read() ema = ema + alpha * (x - ema) # equivalently: alpha*x + (1-alpha)*ema

alpha is between 0 and 1. Small values move the average slowly (a lot of smoothing); large values follow the input closely (little smoothing). At alpha = 1 the output is simply the input.

Part 2. What It Remembers

Unrolling the line shows that each past reading contributes with weight alpha·(1−alpha)k where k is how many samples ago it arrived. Recent readings count most, and older ones fade smoothly, never quite to zero. A window average, by contrast, weighs its last N readings equally and forgets the rest at once:

Which samples an average remembers. A window average weighs the last N readings equally and forgets the rest instantly; an EMA weighs recent readings most and fades older ones smoothly, never quite to zero.

Part 3. Choosing Alpha

Alpha controls how fast the average responds. After a sudden step in the input, the output closes the gap geometrically:

How an exponential moving average responds to a sudden step. A small alpha is smooth but slow to follow; a large alpha follows quickly but passes more noise.

Two numbers describe the behaviour. The time constant is how many samples it takes to cover about 63 % of a step; after roughly three time constants it has settled to 95 %. And you can match it to a window average: an EMA behaves like a moving average of about N ≈ 2/alpha − 1 samples.

Choosing alpha. It sets how many samples the average effectively remembers, how long it takes to settle after a change, and the matching window size for a simple moving average.
The same noisy signal smoothed two ways, tuned to a similar amount of smoothing. The EMA needs one stored number; the window average needs a buffer of nine.

The two lines above smooth by a similar amount and lag by a similar amount; the difference is what they cost. The window average stores nine numbers and sums them each time (or keeps a running total); the EMA stores one.

Part 4. Practical Details

  • Initialise with the first reading, not zero. Starting from zero makes the output crawl up from nothing for the first several time constants.
  • Integers: for alpha = 1/8 you can use a shift, ema += (x − ema) >> 3, which avoids floats entirely. It rounds toward minus infinity, so a small bias builds up in the last bit; fine for smoothing, not for precision work.
  • Different alphas for different jobs: a fast EMA tracks the signal, a slow one tracks the baseline, and the difference between them is a cheap trend detector.
  • Variance too: the same idea gives a running spread, var = (1−alpha)·(var + alpha·d²) with d = x − ema, which is exactly what powers the rolling z-score.
ema.py MicroPython
class EMA: def __init__(self, alpha): self.alpha = alpha self.value = None def update(self, x): if self.value is None: self.value = x # start at the first reading else: self.value += self.alpha * (x - self.value) return self.value

Warm Up

Exercise 1: By Hand

The first three leave it at 10. For 50: 10 + 0.25 × (50 − 10) = 20. One big reading moves the average a quarter of the way; a window average of four would have moved to 20 as well, but a longer window would move less.

Exercise 2: Pick an Alpha

From the table, alpha = 0.1 settles (95 %) in about 29 samples and alpha = 0.2 in about 14; 20 lies between, so alpha ≈ 0.14. Its equivalent window is about 2 / 0.14 − 1 ≈ 13 samples.

Intermediate

Exercise 3: An Integer EMA
ema.py MicroPython
ema = 0 out = [] for x in [800] * 20: ema += (x - ema) >> 3 # alpha = 1/8 out.append(ema) print(out[:6], out[-1]) # [100, 187, 263, 330, 388, 439] 741

After 20 samples it has reached 741 and it keeps closing the gap, but because the shift rounds down it finally settles at 793, seven counts short of 800. For smoothing that is harmless; do not use it where the last count matters.

Advanced

Exercise 4: A Trend Detector
trend.py MicroPython
fast = EMA(0.3) slow = EMA(0.02) THRESH = 500 def trend(x): f, s = fast.update(x), slow.update(x) if f - s > THRESH: return "rising" if s - f > THRESH: return "falling" return "steady"

The slow average is a stable baseline; the fast one follows recent changes. When the signal rises steadily the fast one pulls ahead of the baseline, and the gap measures how fast. It needs only two numbers of memory.
