Everything so far has stayed local to one board: a sensor, a filter, a decision, an LED. This week starts the second half of the unit, getting that board talking to something else entirely, eventually the Pi 3B+ broker across the room. Step one is just getting on the network at all.

Part 1. The Chip That Makes "W" Possible

Recall from the microcontroller lesson that the RP2040 itself has no radio hardware whatsoever. All WiFi (and Bluetooth) capability on your board comes from a separate chip, the CYW43439, connected to the RP2040 over a dedicated internal link, not a regular GPIO pin.

This is the same fact from the microcontrollers lesson, applied: the onboard LED lives on the CYW43439 side of that link, addressed in MicroPython by name, Pin("LED", Pin.OUT), rather than by a GPIO number.

Part 2. Connecting: the network Module

MicroPython's network module talks to the CYW43439 for you. Connecting as a client to an existing WiFi network (as opposed to the Pico creating its own network, which is also possible but not what this course needs) uses station mode:

The two WiFi roles. This course always uses station mode: the Pico is a client of the classroom network, like a phone or laptop.
main.py MicroPython
import network from time import sleep SSID = "your-network-name" PASSWORD = "your-network-password" wlan = network.WLAN(network.STA_IF) # STA_IF = "station" (client) mode wlan.active(True) wlan.connect(SSID, PASSWORD) print("connecting", end="") while not wlan.isconnected(): print(".", end="") sleep(0.5) print() print("connected! IP address:", wlan.ifconfig()[0])

wlan.ifconfig() returns a tuple of four strings: (ip_address, subnet_mask, gateway, dns_server). The first one, your Pico's own IP address on the network, is the one you'll need constantly from here on, it's how anything else on the network (including, eventually, the broker) addresses this specific board.

What wlan.connect() does behind the scenes: find the network, prove you know the password, then ask for an IP address. Only after the last step is the Pico usable on the network.

Part 3. A Few Things That Go Wrong

  • 2.4 GHz only. The CYW43439 does not support 5 GHz WiFi. If your home or the classroom network has separate 2.4 GHz and 5 GHz names, use the 2.4 GHz one; if they share one name (band-steering), this usually isn't an issue but is worth knowing about if connection attempts mysteriously fail.
  • Captive portals won't work. Networks that require clicking "I agree" in a browser before granting internet access (common on some guest WiFi) can't be navigated by a Pico at all, there's no browser to click through. The classroom network this course uses is configured to avoid this.
  • Credentials are plain text in your script. There's no secure credential storage on the Pico; anyone with physical access to the board's flash (or the source file) can read the WiFi password. Fine for a class lab, worth knowing as a real limitation.

Intermediate

Exercise 3: Connect With a Timeout
wifi.py MicroPython
import network from time import sleep, ticks_ms, ticks_diff def connect_wifi(ssid, password, timeout_s=15): wlan = network.WLAN(network.STA_IF) wlan.active(True) wlan.connect(ssid, password) start = ticks_ms() while not wlan.isconnected(): if wlan.status() < 0 or ticks_diff(ticks_ms(), start) > timeout_s * 1000: print("failed, status", wlan.status()) return None sleep(0.25) return wlan.ifconfig()[0]

A negative status is a definite failure, so it gives up at once; the timeout covers the case where it just never finishes.

Advanced

Exercise 4: Site Survey
scan.py MicroPython
import network wlan = network.WLAN(network.STA_IF) wlan.active(True) nets = wlan.scan() # list of tuples nets.sort(key=lambda n: n[3], reverse=True) # n[3] is the RSSI for ssid, bssid, channel, rssi, security, hidden in nets: print(ssid.decode(), "ch", channel, rssi, "dBm")

Names arrive as bytes, hence .decode(). RSSI is negative, and a value closer to zero is stronger, so sorting with reverse=True puts the strongest first.
