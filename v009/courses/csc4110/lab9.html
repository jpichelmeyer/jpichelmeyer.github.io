This lab joins the multi-agent lesson, the state machines and the contract into one working system of three boards. You write each agent against a written contract, test it alone and together, and then break the system on purpose to see which agent decides what when a sensor or a coordinator disappears.

SAM lens. three boards, three agents, one contract. Each agent's Actuator writes into its own subtree and each agent's Perceptor reads only the subtrees it needs; the drills show which agent decides what when a sensor or the coordinator disappears.

This lab builds a small multi-agent system out of three boards, one per student, written to the same contract. A sensor agent measures distance, a coordinator decides, and an actuator obeys and reports. The point is not the LED, which is trivial, but making three independent programs cooperate through nothing except an agreed set of messages, and then seeing what happens when one of them lies, stops, or disappears.

The System

The Lab 9 system. Each student writes only into their own subtree; the coordinator listens to the sensor’s tele, and the actuator listens to the coordinator’s cmd.

Work in a group of three, one agent each. With fewer students, run the missing agents as the simulated peers further down. Everything in this lab uses what you have already built: hub.py, agent.py (the multi-agent lesson), ranger.py (pulse lesson), and the schema checker contract.py and the state machine files of this week. The broker and its access list are those of Lab 5 and need no change: everyone may read lab/#, and each user writes only to lab/<own name>/#.

The Contract

The Lab 9 contract. Every group in the class implements the same table, so a sensor written by one group can drive a coordinator written by another.

Every message uses the envelope of the contracts lesson. Copy contract.py (with RANGE_TELE and LED_CMD) onto every board and write your names into the constants at the top of your file: the coordinator needs the names of the sensor and the actuator, and the actuator needs the name of the coordinator and its own.

Part 1. Build Your Agent

Each student writes the agent for their role, using the base class of the multi-agent lesson. Test it alone first (with the simulated peers below) before you connect to the others. The three programs are given here in full, so that you read them as a specification rather than invent them; the work of the lab is to make them run on real hardware, test them, and break them.

Student 1: the sensor agent. It measures every 200 ms and publishes the range. It decides nothing, and knows nothing about the others.

sensor.py MicroPython
# sensor.py -- agent 1: publishes the range, nothing else from time import ticks_ms, ticks_diff from agent import Agent class RangeAgent(Agent): def __init__(self, hub, ranger): super().__init__("range", hub, period_ms=50) self.r = ranger self.last_start = ticks_ms() def sense(self): if self.r.update(): # a result arrived (None = no echo) return self.r.cm, True if not self.r.busy and ticks_diff(ticks_ms(), self.last_start) >= 200: self.last_start = ticks_ms() self.r.start() # 5 measurements per second return None, False def tell(self, obs, dec): cm, fresh = obs if fresh: # contract: cm is 2..400; "no echo" is cm 400, ok false self.hub.publish("tele/range", {"cm": 400.0 if cm is None else float(min(max(cm, 2.0), 400.0)), "ok": cm is not None})

Student 2: the coordinator. It validates every message it receives, applies a band (20 and 30 cm) so the output does not flicker, treats a silent sensor as “nothing near”, and warns once.

coordinator.py MicroPython
# coordinator.py -- agent 2: reads the sensor, commands the actuator from time import ticks_ms, ticks_diff import hub from agent import Agent from contract import check, RANGE_TELE SENSOR_USER, ACT_USER = "amy", "jsmith" # the names of your two teammates: change these class Coordinator(Agent): NEAR, FAR = 20.0, 30.0 # the band, in centimetres LOST_MS = 2000 # contract: no tele/range for 2 s means the sensor is lost REFRESH_MS = 2000 # repeat the command: the actuator expects to hear it def __init__(self, h): super().__init__("coord", h, period_ms=100) self.cm = None self.heard = ticks_ms() self.lost = False self.rejected = 0 self.state = 0 self.cmd_id = 0 self.sent = None self.sent_at = ticks_ms() h.on("lab/%s/tele/range" % SENSOR_USER, self.on_range) def on_range(self, topic, payload): # catch only: validate, remember, return d = hub.decode(payload) ok, why = check(RANGE_TELE, d) if d else (False, "bad envelope") if not ok: self.rejected += 1 return self.cm, self.heard = d["cm"], ticks_ms() if d.get("ok") is False: self.cm = None # no echo: nothing in range def sense(self): return self.cm, ticks_diff(ticks_ms(), self.heard) > self.LOST_MS def decide(self, obs): cm, silent = obs if silent: return 0 # a lost sensor is treated as "nothing near" if cm is not None and cm < self.NEAR: self.state = 1 elif cm is None or cm > self.FAR: self.state = 0 return self.state def tell(self, obs, state): _, silent = obs if silent and not self.lost: self.hub.publish("evt/warn", {"what": "sensor lost"}) # once, not on every pass self.lost = silent now = ticks_ms() if state != self.sent or ticks_diff(now, self.sent_at) >= self.REFRESH_MS: self.cmd_id += 1 self.hub.publish("cmd/led", {"to": ACT_USER, "state": state, "id": self.cmd_id}) self.sent, self.sent_at = state, now

Student 3: the actuator. It obeys only a valid command addressed to it, ignores repeats, reports the real state retained, and reverts to off if nobody has spoken for five seconds.

actuator.py MicroPython
# actuator.py -- agent 3: obeys the coordinator, reports the real state, fails safe from time import ticks_ms, ticks_diff import hub from agent import Agent from contract import check, LED_CMD COORD_USER, ME = "bob", "jsmith" # change to your teammates' names and your own class LedAgent(Agent): FAILSAFE_MS = 5000 # no valid command for this long: LED off def __init__(self, h, led): super().__init__("led", h, period_ms=100) self.led = led self.state, self.last_id, self.heard = 0, None, ticks_ms() self.reported, self.rejected = None, 0 h.on("lab/%s/cmd/led" % COORD_USER, self.on_cmd) def on_cmd(self, topic, payload): d = hub.decode(payload) ok, why = check(LED_CMD, d) if d else (False, "bad envelope") if not ok or d["to"] != ME: # not valid, or addressed to someone else if not ok: self.rejected += 1 return self.heard = ticks_ms() # any valid command renews the lease if d["id"] != self.last_id: # a repeat of the last id changes nothing self.last_id = d["id"] self.state = d["state"] def decide(self, obs): if ticks_diff(ticks_ms(), self.heard) > self.FAILSAFE_MS: self.state = 0 # nobody is talking: go safe return self.state def act(self, state): self.led.value(state) def tell(self, obs, state): if state != self.reported: # the REAL state, retained self.hub.publish("stat/led", {"state": state}, retain=True) self.reported = state

Each file ends in the same main.py shape. For the sensor, for example: build hub.Hub(), call h.presence(), create a Ranger, build the agent, and call agent.run(h, [your_agent], wdt) (the watchdog from Lab 7 is optional but recommended).

Part 3. Run the System and Test It

With all three connected, the trace of one test run on the test fixture (three hubs on one fake broker) was: the distance changed to 15 cm at 1.0 s and the LED came on at 1.1 s; it stayed on at 25 cm (inside the band), went off at 4.1 s after the range reached 35 cm at 4.0 s, and came on again at 6.1 s for 12 cm. The command went from the coordinator to the LED within one coordinator period (100 ms). Now do the tests below on real boards and compare.

The test plan. Tests 1 to 3 prove each agent against the contract alone; 4 proves the system; 5 to 8 prove it survives a bad message, a lost sensor, a lost coordinator and a restart.

In the simulation, test 5 gave rejected = 2 at the actuator (the 7 and the plain text were refused; the message for someone else was correctly ignored without being counted as an error), test 6 gave one evt/warn and the LED off about 2 s after the last range message, and test 7 gave LED off at 11.2 s when the last command was at 6.1 s: about 5 seconds after the last command, 3.2 s after the coordinator died at 8 s. Your numbers will vary with your 2 s refresh.

Intermediate

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Trace One Cycle

(1) The sensor publishes lab/amy/tele/range with a small cm. (2) The coordinator publishes lab/bob/cmd/led with state 1 and a new id. (3) The actuator drives its LED and publishes lab/jsmith/stat/led with state 1, retained. The coordinator and any dashboard now see the confirmed state, not just the request. A coordinator that wanted to be sure would also subscribe to stat/led and retry if it did not match.

Intermediate

Exercise 2: Why a Band?

With one threshold, a reading that wobbles across it flips the decision on every wobble, so at 5 readings per second the coordinator sends up to 5 commands per second and the LED flickers; the class limit of 10 messages per second is soon in sight. The band makes the decision change only when the hand has moved clearly (more than 10 cm). At rest at 25 cm with a 1 cm wobble the band sends no new commands apart from the 2-second refresh.

Advanced

Exercise 3: Confirm the State
confirm.py MicroPython
# in Coordinator.__init__: self.real = None self.mismatch_since = None h.on("lab/%s/stat/led" % ACT_USER, self.on_stat) def on_stat(self, topic, payload): d = hub.decode(payload) if d and d.get("state") in (0, 1): self.real = d["state"] # in tell(): after the command logic if self.real is not None and self.real != state: if self.mismatch_since is None: self.mismatch_since = now elif ticks_diff(now, self.mismatch_since) > 1000 and not self.warned: self.hub.publish("evt/warn", {"what": "led mismatch"}) self.warned = True else: self.mismatch_since, self.warned = None, False

Initialise self.warned = False too. The delay of 1 second is the margin for the normal round trip (the simulation took under 100 ms), so a mismatch seen for longer than that is a real one: a lost command, a dead actuator, or the wrong name in a subscription.
