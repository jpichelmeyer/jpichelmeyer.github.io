Unit 1 built a program as one loop with a timer for each job. That works, but as jobs multiply the loop turns into bookkeeping. MicroPython offers a tidier model, asyncio, where each job is written as its own simple loop and a scheduler interleaves them. It is the same idea as before, with the bookkeeping moved into the language.

Part 1. Cooperative Multitasking

asyncio runs several tasks on one processor. A task runs until it reaches an await, where it says "I am waiting, someone else can go". The scheduler then runs another ready task. Nothing interrupts a task: a task that never awaits keeps the processor to itself.

Cooperative multitasking. One processor runs one task at a time, and a task only hands over at an await. While one task waits, the others get their turn.

That is why the central rule is: never block. Blocking calls hold everyone up, while await yields.

The one rule of async code: never block. time.sleep() freezes every task for its whole duration; await asyncio.sleep() pauses only the task that asked.

Part 2. The Shape of a Program

main.py MicroPython
try: import asyncio # MicroPython 1.21 and newer except ImportError: import uasyncio as asyncio # older firmware: same API async def sensor_task(): while True: latest["value"] = read_sensor() await asyncio.sleep_ms(100) async def mqtt_task(): while True: client.check_msg() await asyncio.sleep_ms(20) async def blink_task(): while True: led.toggle() await asyncio.sleep_ms(500) async def main(): asyncio.create_task(sensor_task()) asyncio.create_task(mqtt_task()) asyncio.create_task(blink_task()) while True: await asyncio.sleep(1) # keep main alive asyncio.run(main())
The shape of an asyncio program. main() starts one task per job and then lets the scheduler run them; each task is an endless loop with an await in it.

Each task is a plain loop with an await in it. Compare this with Unit 1: there you wrote the "is it my turn?" test yourself for every job; here the scheduler wakes each task when its wait is over.

Part 3. Sharing Data Between Tasks

Because only one task runs at a time and switching happens only at an await, tasks can share ordinary variables safely, provided no await sits in the middle of an update. To make a task wait for something rather than polling for it, use an Event:

Passing data between tasks. One task writes the latest value and sets an Event; the task that publishes waits on that Event, so it wakes only when there is something new.
main.py MicroPython
new_reading = asyncio.Event() async def sensor_task(): while True: latest["value"] = read_sensor() new_reading.set() # "there is something new" await asyncio.sleep_ms(1000) async def publish_task(): while True: await new_reading.wait() # sleeps until set() new_reading.clear() client.publish(TELE, json.dumps(latest).encode())

Part 4. Where It Bites

  • Blocking library calls. umqtt.simple uses ordinary blocking sockets. check_msg() is quick when nothing is waiting, but connect() and a QoS 1 publish() can stall every task for as long as the network does. (Third-party libraries such as mqtt_as are written to be fully asynchronous.)
  • Silent task death. An exception inside a task ends that task without stopping the program. Wrap the body of each task’s loop in try/except and log, otherwise a sensor can quietly stop being read.
  • Long computations. A task that computes for 200 ms without awaiting freezes the rest for 200 ms. Split the work and await asyncio.sleep_ms(0) between pieces to let others run.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Spot the Bug

time.sleep(0.5) blocks the whole processor, so for half a second no other task runs. It should be await asyncio.sleep_ms(500), which pauses only this task.

Exercise 2: Who Runs When?

About 3 ms of work per 10 ms is roughly 30 % busy. A processor can run several light tasks like this, but once the total work per cycle approaches the cycle length, tasks start to run late, so keep each task’s work short.

Intermediate

Exercise 3: Convert a Timer Loop
main.py MicroPython
import asyncio async def blink(): while True: led.toggle() await asyncio.sleep_ms(250) async def report(): while True: print("alive") await asyncio.sleep(2) async def main(): asyncio.create_task(blink()) asyncio.create_task(report()) while True: await asyncio.sleep(1) asyncio.run(main())

The timer objects disappear: each loop describes only its own rhythm. This is the same behaviour as before with less code to get wrong.

Advanced

Exercise 4: Guard a Task
main.py MicroPython
async def sensor_task(): while True: try: latest["value"] = read_sensor() except Exception as e: print("sensor read failed:", e) # log it, then keep going await asyncio.sleep_ms(100)

The await sits outside the try so the task always yields, even after an error. Without this guard one failed read would end the task with no visible sign.
