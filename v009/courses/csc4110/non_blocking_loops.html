The publish-subscribe lesson introduced the idea of replacing sleep() with elapsed-time checks. This lesson turns that idea into a complete way of structuring a program, because almost every real embedded device is, in the end, one loop that never blocks.

Part 1. The Super-Loop

A microcontroller program usually has one while True loop, and every job the device has gets a short turn on each pass. A job that is not due simply returns at once. Seen over time, several jobs with different periods interleave without ever stopping each other:

Three jobs with different periods sharing one loop. Each job only checks whether its interval has passed, so they never hold each other up.
The shape of every non-blocking main loop: look at inputs, run whichever timed jobs are due, handle messages, repeat immediately.

Part 2. The Millisecond Clock

MicroPython provides a free-running counter for this: ticks_ms() in milliseconds and ticks_us() in microseconds. It is not wall-clock time; it counts from an arbitrary starting point and wraps around after about 12.4 days:

The millisecond counter wraps back to zero after about 12.4 days. ticks_diff() is written to give the right answer across the wrap.
  • ticks_diff(a, b) subtracts two readings correctly even across a wrap.
  • ticks_add(t, n) adds an offset to a reading, also wrap-safe, which is handy for scheduling a future time.

Never compare tick values with plain > or < or subtract them with -. The code works for twelve days and then misbehaves once, which is the worst kind of bug to find.

Part 3. A Tiny Scheduler

Writing the same "has my interval elapsed?" test over and over gets messy. Wrap it once and give each periodic job its own timer:

main.py MicroPython
from time import ticks_ms, ticks_diff class Every: def __init__(self, ms): self.ms = ms self.last = ticks_ms() def ready(self): now = ticks_ms() if ticks_diff(now, self.last) >= self.ms: self.last = now return True return False read_sensor = Every(100) publish = Every(1000) blink = Every(250) while True: if read_sensor.ready(): sample() if publish.ready(): send() if blink.ready(): led.toggle() client.check_msg() # runs on every pass

Part 4. Rules of Thumb

  • Keep every pass short. A job that takes 200 ms (a long calculation, a slow print) delays everything else by 200 ms.
  • Beware hidden blocking. Network calls can wait a long time for a reply. Give sockets a timeout so one dead connection cannot freeze the loop.
  • Know when to ask for help. Once a program has many timed jobs, MicroPython's asyncio library manages the interleaving for you (Unit 2 covers it).
  • Guard against a stuck loop. A watchdog timer reboots the board if the program stops proving it is alive:
main.py MicroPython
from machine import WDT wdt = WDT(timeout=5000) # reboot if not fed for 5 s (see the docs for the maximum) while True: # ... normal work ... wdt.feed() # "I am still running"

Warm Up

Exercise 1: When Does It Wrap?

230 = 1,073,741,824 ms ÷ 86,400,000 ms per day ≈ 12.4 days. A device left running for weeks will definitely cross the wrap point, so always use ticks_diff.

Exercise 2: Spot the Blockers

Blocking: sleep(1) (waits a fixed time), the while not ...: pass loop (waits for an event), and sock.recv() on a default socket (waits for data to arrive). Non-blocking: button.value() (reads the pin and returns at once) and check_msg() (returns immediately whether or not anything arrived).

Intermediate

Exercise 3: Debounce Without Sleeping
main.py MicroPython
from machine import Pin from time import ticks_ms, ticks_diff button = Pin(14, Pin.IN, Pin.PULL_UP) led = Pin(15, Pin.OUT) stable = 1 # the last settled state of the button last_raw = 1 # what we saw on the previous pass changed_at = ticks_ms() while True: raw = button.value() now = ticks_ms() if raw != last_raw: # it moved: restart the clock last_raw = raw changed_at = now elif raw != stable and ticks_diff(now, changed_at) >= 30: stable = raw # held steady for 30 ms: believe it if stable == 0: # a clean press led.toggle()

The loop never waits; it just keeps checking "has the reading been the same for 30 ms yet?".

Advanced

Exercise 4: Measure Your Loop
main.py MicroPython
from time import ticks_ms, ticks_diff, sleep_ms def passes_per_second(delay_ms): n = 0 start = ticks_ms() while ticks_diff(ticks_ms(), start) < 1000: n += 1 if delay_ms: sleep_ms(delay_ms) return n print("no delay :", passes_per_second(0)) print("10 ms :", passes_per_second(10))

The empty loop manages tens of thousands of passes per second; with a 10 ms sleep it is capped just under 100. Everything the loop must notice (a button, a message) is noticed at that rate, so the sleeping version can be up to 10 ms late every time.
