Some devices need more speed or simpler wiring than I2C offers. SPI is the other bus you will meet constantly: it moves data in both directions at once, runs at megahertz rates, and selects a device by a wire instead of an address. This lesson covers how it works, a loopback test that needs no device at all, and the two SPI parts in your kit.

Part 1. A Faster, Simpler Bus

SPI (serial peripheral interface) is the other common chip-to-chip bus. It uses more wires than I2C but is simpler and faster: a dedicated clock, one data wire each way, and one extra "select" wire per device in place of an address. Because the two data wires are separate, the controller can send and receive at the same moment.

An SPI bus. Clock (SCK), data out (MOSI, "main out, secondary in") and data in (MISO) are shared by every device. Each device also has its own chip-select (CS) wire from the Pico; only the device whose CS is low listens and answers.

Because a device is chosen by its wire and not by an address, you can add as many devices as you have spare pins, and there is nothing to scan: if it does not work, check wiring, CS and mode. A device whose CS is high ignores the bus completely, and its MISO output goes quiet so it does not fight others.

spi_setup.py MicroPython
from machine import SPI, Pin spi = SPI(0, baudrate=1_000_000, polarity=0, phase=0, sck=Pin(18), mosi=Pin(19), miso=Pin(16)) # SPI bus 0 cs = Pin(17, Pin.OUT, value=1) # chip select: high = "not talking to you"

polarity and phase are the SPI mode: whether the clock idles low or high, and which clock edge the data is read on. Most devices use mode 0 (both 0). The mode must match the device’s datasheet, and it is the first thing to check when you read nonsense.

Part 2. What One Byte Looks Like

One byte over SPI in mode 0. The Pico lowers CS to start, then each clock pulse moves one bit: MOSI is set up while the clock is low, and the device reads it on the rising edge. After eight pulses the byte has been transferred, and CS goes high again. At the same moment the device has clocked a byte back out on MISO.

Every SPI transfer is a swap: for each bit the Pico sends, a bit comes back. To read from a device you therefore send something (often zeros) just to generate the clock pulses it needs to answer. That is why the call is named write_readinto, which sends and receives together.

Part 3. Testing Without a Device: Loopback

SPI problems come from three places: your code, your wiring, and the device. Separate them with a loopback test: connect MOSI (GP19) to MISO (GP16) with one jumper, so that everything sent comes straight back. If the loopback works, the Pico side of the bus is fine.

loopback.py MicroPython
from machine import SPI, Pin spi = SPI(0, baudrate=1_000_000, polarity=0, phase=0, sck=Pin(18), mosi=Pin(19), miso=Pin(16)) # SPI bus 0 cs = Pin(17, Pin.OUT, value=1) # chip select: high = "not talking to you" buf = bytearray(5) cs(0) # select the device (here, nobody is listening) spi.write_readinto(b"hello", buf) # send 5 bytes and capture 5 bytes at the same time cs(1) print(buf) # bytearray(b'hello') if MOSI is jumpered to MISO

With the jumper removed, buf stays zeros (or random bits) because nothing drives MISO. Keep this test in mind: it takes ten seconds and tells you whether to look at the code or the module.

Part 4. The 74HC595: More Output Pins from Three Wires

A shift register turns a serial stream into parallel outputs. The 74HC595 has eight output pins and three control inputs: data in (fed from MOSI), shift clock (SCK) and a latch (a plain GPIO pin). Bits are shifted into an internal register as the clock ticks. Nothing changes at the output pins until the latch input is pulsed, which copies all eight bits at once. That is useful: the outputs never show a half-shifted pattern.

A 74HC595. A byte is shifted in over SPI (bottom), then one latch pulse copies all eight bits to the output pins (top) at once. Chain several chips and the same three wires drive 16, 24 or more outputs.
shiftreg.py MicroPython
class ShiftReg: """One 74HC595: eight output pins from three wires. Bit 0 is the first output (QA).""" def __init__(self, spi, latch): self.spi, self.latch, self.bits = spi, latch, 0 self.latch.value(0) self.show() def show(self): self.spi.write(bytes([self.bits])) # shift 8 bits in (MSB first) self.latch.value(1) # latch pulse: copy them to the outputs self.latch.value(0) def set(self, byte): self.bits = byte & 0xFF self.show() def pin(self, n, on): if on: self.bits |= 1 << n else: self.bits &= ~(1 << n) & 0xFF self.show()
shift_demo.py MicroPython
latch = Pin(20, Pin.OUT, value=0) bar = ShiftReg(spi, latch) bar.set(0b10000101) # outputs 0, 2 and 7 on bar.pin(1, True) # turn one more on, leaving the others alone

Wire the 74HC595 with its output-enable pin (OE) to ground and its clear pin (SRCLR) to 3.3 V, and put a resistor in series with every LED you connect to an output; a shift-register pin gives the same few milliamps as a Pico pin.

Part 5. The MFRC522 RFID Reader

The MFRC522 reads small RFID tags and cards: hold one near the reader and it reports a tag number. It talks SPI, and it has dozens of internal registers you read and write. Every transaction starts with an address byte that says which register, and in which direction:

The address byte. The register number is shifted left one place, and the top bit selects read or write. Register 0x37 is the version register, which returns a fixed value (0x92 or 0x91 on a genuine chip) and makes a good "is it alive?" test.
rc522.py MicroPython
from machine import SPI, Pin from time import sleep_ms rst = Pin(21, Pin.OUT, value=1) # MFRC522 reset pin held high (running) cs = Pin(17, Pin.OUT, value=1) def rc522_read(spi, cs, reg): """Read one register. The first byte carries the address, the reply arrives with the second.""" buf = bytearray(2) cs(0) spi.write_readinto(bytes([0x80 | (reg << 1), 0x00]), buf) # bit 7 = 1 means read cs(1) return buf[1] def rc522_write(spi, cs, reg, val): cs(0) spi.write(bytes([(reg << 1) & 0x7E, val])) # bit 7 = 0 means write cs(1) VERSION_REG = 0x37 print(hex(rc522_read(spi, cs, VERSION_REG))) # 0x92 or 0x91 on a real MFRC522 (clones differ)

Wire the reader’s 3.3 V (it is a 3.3 V part, never connect it to 5 V), ground, SCK, MOSI, MISO, its SDA pin (this is the chip select, on GP17) and RST (GP21). Reading the version register back as 0x91 or 0x92 proves that power, wiring, mode and chip select are all right. Reading tag numbers needs a longer sequence of register operations that a ready-made driver handles; your instructor will give you the driver file, and the version read is the part you must get working yourself.

Part 6. I2C or SPI?

Choosing a bus. Mostly the device decides for you: sensors with a lot of data and displays favour SPI, small sensors and anything you want many of on two wires favour I2C. Speed difference matters when you stream data: sending 100 bytes takes about 2.3 ms over I2C at 400 kHz and 0.8 ms over SPI at 1 MHz.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Bit Order

0x1B is binary 0001 1011. Most significant bit first, the eight clock pulses carry 0, 0, 0, 1, 1, 0, 1, 1. A device that expects the other order would read this as 1101 1000 = 0xD8, so a wrong bit order gives a result that is wrong but looks plausible.

Exercise 2: Which Bus Is Faster?

I2C: 9 × 103 = 927 clocks, at 400 kHz that is 2.32 ms. SPI: 100 × 8 = 800 clocks at 1 MHz is 0.80 ms. SPI is about 2.9 times quicker, and it gains more at higher clock rates, because the chip can usually run at several MHz.

Intermediate

Exercise 3: Address Bytes

Read 0x37: 0x80 | (0x37 << 1) = 0x80 | 0x6E = 0xEE. Write 0x01: (0x01 << 1) & 0x7E = 0x02. Read 0x01: 0x80 | 0x02 = 0x82. Check them with the fake SPI class in the next exercise, or in the REPL:

addr.py MicroPython
def rc_addr(reg, read): return (0x80 if read else 0x00) | ((reg << 1) & 0x7E) print(hex(rc_addr(0x37, True)), hex(rc_addr(0x01, False)), hex(rc_addr(0x01, True))) # 0xee 0x2 0x82

Advanced

Exercise 4: A Scanner Light

A sweep goes 0 to 7 and back to 1, so 14 steps repeat. Make it a generator or an index into a precomputed list, and call it from the main loop on a timer so the program can keep doing other work:

scanner.py MicroPython
SWEEP = [1 << i for i in range(8)] + [1 << i for i in range(6, 0, -1)] step = 0 def scanner_tick(bar): global step bar.set(SWEEP[step]) step = (step + 1) % len(SWEEP) print(SWEEP) # [1, 2, 4, 8, 16, 32, 64, 128, 64, 32, 16, 8, 4, 2]

Call scanner_tick(bar) every 80 ms from a ticks_diff timer. The list repeats after 14 steps, and the endpoints (1 and 128) appear once per cycle so they do not look longer than the others.
