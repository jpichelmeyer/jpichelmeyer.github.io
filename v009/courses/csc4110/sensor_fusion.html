This lesson covers combining sensors and computing quantities no sensor measures. You fuse an accelerometer and a gyro with a complementary filter and choose its constant from data, blend two estimates by their variances, turn a pan angle and a range into a point, and triangulate from two bearings while keeping track of how the error depends on geometry.

No single cheap sensor tells you everything you need. An accelerometer knows which way is down but is shaken by every vibration; a gyroscope is smooth but drifts; an ultrasonic range sensor is accurate straight ahead and blind to the side. Sensor fusion combines several imperfect measurements into one better one, and the same idea, extended, builds synthetic sensors: quantities no sensor measures directly, such as the position of an object, calculated from angles and ranges. This lesson builds three tools: the complementary filter for tilt, a way to blend two estimates by their reliability, and the geometry that turns a pan angle and a range into a point, and two bearings into a position.

Part 1. Tilt From Two Imperfect Sensors

The MPU6050 gives two ways to find a tilt angle. The accelerometer measures gravity: atan2(ay, az) is the roll angle directly, with no drift, but every bump and motor vibration adds noise to the reading. The gyroscope measures the rate of rotation: adding up rate × time gives the angle smoothly, but a small constant error in the rate (its bias) adds up into a steadily growing error. One is good at slow changes, the other at fast ones. A complementary filter takes the gyro in the short run and the accelerometer in the long run.

tilt.py MicroPython
# tilt.py -- tilt angle from an accelerometer and a gyro, each covering the other's weakness from math import atan2, degrees from time import ticks_ms, ticks_diff class Tilt: """Roll angle in degrees. alpha near 1 trusts the gyro in the short run and the accelerometer in the long run. Time constant = alpha * dt / (1 - alpha).""" def __init__(self, alpha=0.98): self.alpha = alpha self.angle = None self.t = None def update(self, ay, az, gx_dps, now=None): now = ticks_ms() if now is None else now acc = degrees(atan2(ay, az)) # tilt from gravity: noisy, but never drifts if self.angle is None: self.angle, self.t = acc, now return self.angle dt = ticks_diff(now, self.t) / 1000.0 self.t = now gyro = self.angle + gx_dps * dt # tilt from integrating the gyro: smooth, but drifts self.angle = self.alpha * gyro + (1 - self.alpha) * acc return self.angle

Each update does two things: it advances the previous angle by the gyro (gyro), then pulls it a small fraction 1 − alpha of the way toward the accelerometer’s angle (acc). With alpha = 0.98 at 50 Hz, the pull corrects the drift within about a second (the time constant, alpha × dt / (1 − alpha), is 0.98 s) while the gyro keeps the short-term motion smooth.

The same motion seen four ways, from a simulation of 30 s at 50 Hz with accelerometer vibration noise of 0.1 g and a residual gyro bias of 0.5 degrees per second. The gyro alone (orange) slides away; the accelerometer alone (grey) is jittery; the complementary estimate (green) follows the truth.

Measured over 60 simulated seconds, the root-mean-square error was 5.8 degrees for the accelerometer alone, 17.1 degrees for the gyro alone (and growing), and 1.0 degree for the complementary filter. How should alpha be chosen? A sweep over the same run shows a clear optimum, because the two weaknesses pull in opposite directions:

RMS tilt error against alpha. Too small and the accelerometer’s noise comes through; too large and the gyro’s bias is corrected too slowly. The best value here is 0.98, which means a time constant of about one second; it moves with the noise and the bias of your board.

Two practical points. The result depends on a clean gyro bias: use calibrate() from the I²C lesson with the board still, and the complementary filter does the rest. And the filter assumes the accelerometer is measuring gravity. If the robot accelerates (a hard start, a bump) the accelerometer reads gravity plus that acceleration, and the corrected angle is wrong for a moment: a smaller 1 − alpha limits the damage, which is another reason not to push alpha too low.

Part 2. Blending Two Estimates

Sometimes two sensors measure the same quantity with different quality: two range sensors on the same wall, or a range from the ultrasonic sensor and a range from the pan-servo geometry. Averaging them wastes the better one. Inverse-variance weighting weights each by how much you trust it, which is how much it varies (its variance, in squared units).

blend.py MicroPython
# blend.py -- combine two estimates of the same quantity, trusting the better one more def blend(x1, var1, x2, var2): """Inverse-variance weighting. Returns (estimate, variance). The result is always at least as good as the better input.""" w1, w2 = 1.0 / var1, 1.0 / var2 return (w1 * x1 + w2 * x2) / (w1 + w2), 1.0 / (w1 + w2)
Blending a good and a poor estimate. Measured over 100,000 simulated pairs, the blend is better than either input, and close to the theoretical value of √0.8 = 0.89 cm.

The weights need the variances, and you get those from data: hold the robot still, record a few hundred readings, and compute the variance (Welford’s running variance from the features lesson does it on the node). A claim like “sensor B is twice as noisy” is a measurement, not an opinion.

Part 3. Synthetic Sensors: From Angle and Range to a Point

A synthetic sensor is a computed quantity that no hardware measures. The most useful one in this course comes from the scan head: an ultrasonic sensor on a pan servo. The servo knows the angle it points at; the ranger knows the distance in that direction; together they give a point on the table. With the head at (head_x, head_y), the zero direction of its servo at heading degrees, a pan angle pan and a range r, the target is at x = head_x + r·cos(heading + pan), y = head_y + r·sin(heading + pan).

geometry.py MicroPython
# geometry.py -- from a head's angle and range to a point; from two bearings to a point from math import sin, cos, radians, atan2, degrees, hypot def to_xy(head_x, head_y, pan_deg, range_cm, heading_deg=0.0): """Where is the target, in table coordinates (cm)? The head sits at (head_x, head_y); heading_deg is the direction its pan servo calls 0 degrees, measured counter-clockwise from +x.""" a = radians(heading_deg + pan_deg) return head_x + range_cm * cos(a), head_y + range_cm * sin(a) def intersect(p1, bearing1_deg, p2, bearing2_deg): """Where do two bearings cross? Each is a point and a direction in table coordinates. Returns (x, y), or None if the lines are (nearly) parallel.""" a1, a2 = radians(bearing1_deg), radians(bearing2_deg) d1, d2 = (cos(a1), sin(a1)), (cos(a2), sin(a2)) den = d1[0] * d2[1] - d1[1] * d2[0] # sin of the angle between the rays if abs(den) < 0.05: # less than about 3 degrees: no answer worth having return None dx, dy = p2[0] - p1[0], p2[1] - p1[1] s = (dx * d2[1] - dy * d2[0]) / den # distance along ray 1 if s < 0: return None # the lines cross behind the first head return p1[0] + s * d1[0], p1[1] + s * d1[1]
Two scan heads 60 cm apart, each knowing only the direction in which it saw the target. Where the two rays cross is the target, found without either head knowing its distance: triangulation. (With ranges too, each head would also confirm the answer.)

Bearings come from the scan: sweep the pan servo, record the range at each angle, and take the angle where the range is smallest (or the middle of the angles where it dips below a limit); the ultrasonic beam is wide (about 15 degrees), so this angle is itself uncertain by a few degrees. How much does that matter? That depends heavily on where the target is, as a simulation of 5,000 trials with a 3-degree standard deviation in each bearing shows:

Triangulation error against position. The best crossing is at about 90°; below 30° or so the answer is poor; and the function intersect refuses angles under about 3°, where there is no answer at all.
  • Place the heads so the targets are seen at a wide angle. Heads facing each other across the workspace (rays crossing near 90°) beat two heads side by side.
  • Fuse a second source when you have one. Each head also has a range. Convert it with to_xy and blend it with the triangulated point, weighted by the variances (Part 2).
  • Time-stamp the bearings. Two heads that scanned at different moments are looking at a target that may have moved. Use the t of each message and refuse to combine bearings more than a fraction of a second apart.
  • Say how sure you are. Publish the estimate with the angle between the rays (or an error figure), not as a bare point: the receiver can then decide whether to trust it.

Exercises

Practice problems in three tiers. Do each on paper or on your own board first, and only then open its solution below. Many problems have more than one correct answer; if yours behaves the same way, it is right even if it looks different.

Warm Up

Exercise 1: Which Sensor, Which Frequency?. In the complementary filter, say which sensor dominates (a) a quick jolt lasting a tenth of a second, (b) a slow tilt lasting thirty seconds, (c) a constant gyro bias.

Exercise 2: Blend by Hand. Estimate A is 42 cm with variance 1; estimate B is 46 cm with variance 4. What does blend return, approximately, and why is it closer to A?

Intermediate

Exercise 3: Aim the Head. A head sits at (10, 5) with its servo zero pointing along +y (heading 90°). It reads pan −30° and range 40 cm. Where is the target?

Advanced

Exercise 4: Parallel Rays. Two heads at (0, 0) and (60, 0) see a target straight ahead of each, at bearings 90° and 90°. What does intersect return and why? Give a target position for which the answer exists but is poor, and say what the node should publish.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Which Sensor, Which Frequency?

(a) the gyro: the jolt is much shorter than the filter’s one-second time constant, so the correction toward the accelerometer has no time to act. (b) the accelerometer: over thirty seconds the pull toward it dominates and any gyro drift is corrected. (c) the accelerometer again: a constant bias is a very slow error, which the correction removes (leaving a small residual of about bias × time constant, here 0.5° per second × 1 s = half a degree).

Exercise 2: Blend by Hand

Weights 1/1 = 1 and 1/4 = 0.25: the blend is (42 × 1 + 46 × 0.25) / 1.25 = 42.8 cm, with variance 1 / 1.25 = 0.8. It is closer to A because A is four times as reliable (variance one quarter as big) and so gets four times the weight; and the blended variance 0.8 is smaller than either input’s.

Intermediate

Exercise 3: Aim the Head

The direction is 90° + (−30°) = 60°. x = 10 + 40 cos 60° = 10 + 20 = 30.0; y = 5 + 40 sin 60° = 5 + 34.6 = 39.6. The target is at about (30.0, 39.6) cm. Check with code: to_xy(10, 5, -30, 40, heading_deg=90) returns (30.0, 39.64).

Advanced

Exercise 4: Parallel Rays

It returns None: the rays are parallel, den is 0, and there is no crossing. This is the extreme case of the table above. A target far away along the middle, at bearings 88° and 92°, crosses at (30, 860)-ish: an answer exists but a 1° error moves it by hundreds of centimetres. The node should publish the position with the angle between the rays (here 4°) and a flag such as ok: false below a limit, so a collision checker or a human can see that the number is not worth trusting.
