Real sensor readings are never perfectly steady. Before a reading can be used to decide anything, you need to know how to quiet it without making it slow. This lesson covers where noise comes from, how averaging reduces it, and the three filters you will use all term: the moving average, the exponential moving average and the median.

Part 1. Where Noise Comes From

Hold a sensor perfectly still and its readings still wander. Noise is the small random variation on top of the true value, and it comes from many places: the sensor itself, ripple on the power supply, the converter rounding to the nearest step, and electrical interference from wires, motors and the radio. A WiFi chip transmitting a few centimetres from your analog pin is a real noise source on the Pico W.

A steady value followed by a step, as the ADC sees it, with noise of 0.15 units (simulated). The orange line is the truth, the blue line what you read. You want something between the two: smoother than the blue, not as late as it would be if you averaged blindly.

You cannot remove noise at the source in every case, so you handle it in software with a filter: a rule that combines the latest reading with earlier ones to estimate the true value. Every filter trades two things against each other: smoothness (less noise) and lag (a slower response to real changes). There is no filter that gives you both for free.

Part 2. Averaging

The simplest idea is to average. If the noise is random, readings above the truth and below it tend to cancel. Averaging N independent readings reduces the noise by a factor of the square root of N: 4 readings halve it, 16 readings quarter it, 64 readings cut it to an eighth.

Averaging more readings gives less noise, with diminishing returns: going from 16 to 64 readings costs four times the delay to halve the noise once more. The delay column is the average age of the data you are reporting. The simulated column uses white noise of size 1.

Part 3. The Moving Average

A moving average keeps the last N readings and reports their mean. Every new reading pushes the oldest one out. Recomputing the sum each time would be wasteful, so keep a running total and adjust it: add the new value, subtract the one leaving.

movavg.py MicroPython
class MovingAverage: def __init__(self, n): self.n = n self.buf = [0] * n # the last n readings (a ring: oldest gets overwritten) self.i = 0 # where the next reading goes self.count = 0 # how many readings we really have so far self.total = 0 # running sum def update(self, x): self.total += x - self.buf[self.i] # add the new, remove the one leaving self.buf[self.i] = x self.i = (self.i + 1) % self.n if self.count < self.n: self.count += 1 return self.total / self.count # until it fills, average what we have f = MovingAverage(4) for x in (10, 12, 11, 13, 40, 12): print(f.update(x)) # 10.0 11.0 11.0 11.5 19.0 19.0

It uses a fixed amount of memory (just N numbers) and does the same few operations per reading however large N is, which suits a microcontroller. Use whole numbers when you can (ADC counts are integers): a running total of floating-point values slowly accumulates rounding error, whereas integers are exact.

Part 4. The Exponential Moving Average

The exponential moving average (EMA) needs no buffer at all, only the previous output. Each new reading moves the output a fraction α (alpha, between 0 and 1) of the way toward it:

y = y + alpha * (x - y)

A small α trusts history (smooth, slow); a large α trusts the newest reading (noisy, fast). With α = 1 there is no filtering at all.

ema.py MicroPython
class EMA: def __init__(self, alpha): self.alpha = alpha self.y = None def update(self, x): if self.y is None: self.y = x # start from the first reading, not from zero else: self.y += self.alpha * (x - self.y) return self.y def ema_int(y, x, shift=3): """Integer EMA with alpha = 1 / 2**shift, using only a subtraction and a shift.""" return y + ((x - y) >> shift) f = EMA(0.25) print(f.update(100), f.update(140), f.update(140)) # 100 110.0 117.5
The two filters on the same noisy data. Both settle to the new value after the step with a similar delay and leave roughly a third of the noise (measured on the quiet stretch: raw 0.135, moving average 0.050, EMA 0.048). The moving average has a sharper start and finish; the EMA is a smooth curve that never quite stops approaching.

These two settings were chosen to behave alike. After a clean step the moving average reaches 90 % of the change in 8 samples, the EMA in 11; both delay the signal by about 4 samples on average. So they cost the same lag for the same smoothing, and the choice is practical: the EMA needs no buffer and one multiplication, so it is the usual first choice on a small board; the moving average is easier to explain and has a hard cutoff, because a reading that is more than N samples old has no effect at all.

Part 5. Spikes and the Median Filter

Averaging handles small random noise but not spikes: occasional large wrong readings from a glitch, a dropped bit, a flash of sunlight. One spike of +2.0 in an 8-sample average adds 0.25 to eight outputs in a row. A median filter takes the middle value of the last few readings, so a single outlier never reaches the output:

Three glitches in an otherwise steady signal (grey), then filtered two ways with a window of 5. The averager spreads each spike into five smaller bumps. The median ignores them completely, because a lone outlier is never the middle value. The median costs a sort of five numbers per reading.
median.py MicroPython
class Median: def __init__(self, n=5): self.n = n self.buf = [] def update(self, x): self.buf.append(x) if len(self.buf) > self.n: self.buf.pop(0) # forget the oldest return sorted(self.buf)[len(self.buf) // 2] f = Median(5) print([f.update(x) for x in (10, 11, 90, 12, 11, 10)]) # [10, 11, 11, 12, 11, 11]

A common arrangement is to remove spikes first with a short median (3 or 5), then smooth with an EMA. Do the cleaning step before the smoothing step, or a spike will already have been smeared by the time the median sees it.

Warm Up

Exercise 1: How Much Quieter?

12 / √16 = 12 / 4 = 3 counts. To get below 2 counts you need √N > 6, so N > 36: 37 readings or more (use 64 to be a power of two, which also suits integer division by a shift).

Exercise 2: Do an EMA by Hand

First: 100 + 0.25 × (140 − 100) = 110. Second: 110 + 0.25 × (140 − 110) = 117.5. Each step closes a quarter of the remaining gap.

Intermediate

Exercise 3: The Integer EMA
test_ema_int.py MicroPython
y = 1000 for x in (1080, 1080, 1080, 1000): y = ema_int(y, x, 3) print(y) # 1010 1018 1025 1021

Each step adds an eighth of the gap, rounded down: 1000 + (80 >> 3) = 1010; 1010 + (70 >> 3) = 1018; 1018 + (62 >> 3) = 1025; then the reading drops to 1000, and 1025 + ((1000 − 1025) >> 3) = 1025 − 4 = 1021. Note the last step: shifting a negative number rounds toward minus infinity (−25 / 8 = −3.1 becomes −4), so the output falls slightly faster than it rises. A shift needs whole numbers, and differences smaller than 8 round to zero when rising, so the output stops a few counts short of the input. For ADC counts that is an acceptable cost.

Advanced

Exercise 4: Despike, Then Smooth
clean.py MicroPython
med = Median(5) smooth = EMA(0.2) def clean(x): return smooth.update(med.update(x)) out = [clean(x) for x in [50, 50, 50, 50, 150, 50, 50, 50]] print([round(v, 1) for v in out]) # [50, 50.0, 50.0, 50.0, 50.0, 50.0, 50.0, 50.0]

The spike enters the median window at the fifth reading but is never the middle value, so the EMA sees only 50s. Swap the order of the two filters and the spike drags the output up by 20 and lingers.
