Sample a perfectly steady sensor, a potentiometer held dead still, say, and the raw readings still wobble a little from one sample to the next. That wobble is noise: small, essentially random fluctuations layered on top of the real signal, and it's present in basically every analog sensor you'll ever read. This lesson covers the simplest, most common way to tame it.

Part 1. Where Noise Comes From

Noise isn't a bug in any one sensor, it's a byproduct of physics: thermal jitter in the circuit, tiny voltage fluctuations on the power rail, electrical interference from other components nearby, even the ADC's own quantization contributes a little. The practical upshot is the same regardless of cause: two readings taken a few milliseconds apart, of a value that hasn't truly changed, often won't be identical.

The dial hasn't moved at all between these samples. Every wiggle in the raw line is noise, not signal, and a program that reacts to every tiny change (lighting an LED above some exact threshold, say) would flicker constantly even though nothing meaningful happened.
Software filtering sits after the ADC and before any decision. Whatever the logic does next sees a steadier number.

Part 2. The Moving Average Filter

A moving average filter smooths noisy data by replacing each reading with the average of the last several readings, a sliding window that moves forward one sample at a time. Averaging tends to cancel out random noise (some samples a little high, some a little low) while a real, sustained change in the signal still comes through, since it shows up consistently across the whole window rather than in just one noisy sample.

A window of 3 means every output is the average of only the 3 most recent readings. As a new sample arrives, the oldest one in the window is dropped, so the average always reflects the most recent, not the entire history of every reading ever taken.
main.py MicroPython
from machine import ADC, Pin from time import sleep sensor = ADC(Pin(26)) WINDOW_SIZE = 5 window = [] def filtered_read(): raw = sensor.read_u16() window.append(raw) if len(window) > WINDOW_SIZE: window.pop(0) # drop the oldest sample return sum(window) / len(window) while True: print(filtered_read()) sleep(0.1)

Notice filtered_read() divides by len(window), not by WINDOW_SIZE, which matters for the first few calls before the window has actually filled up; dividing by a fixed WINDOW_SIZE from the very first sample would quietly produce wrong averages until the window reaches full size.

Part 3. The Trade-Off: Smoothness vs. Lag

A bigger window smooths more aggressively, but it also responds to a real change more slowly, since a genuine jump in the signal has to work its way through the whole window before the average fully reflects it. A window of 50 produces a very steady output, but one that lags several hundred milliseconds behind reality at a 10ms sample interval; a window of 2 barely filters anything but reacts almost instantly. There's no universally correct window size, only a trade-off to make deliberately, based on how noisy the sensor actually is and how quickly your program needs to react to real changes.

Exercise 3: A Reusable Filter
filters.py MicroPython
class MovingAverage: def __init__(self, size): self.size = size self.values = [] def add(self, x): self.values.append(x) if len(self.values) > self.size: self.values.pop(0) return sum(self.values) / len(self.values) avg = MovingAverage(5) for x in (10, 12, 11, 50, 12, 11): print(avg.add(x))

Each filter object keeps its own window, so you can run several (for example one per sensor) side by side.

Advanced

Exercise 4: Beat the Spike
median.py MicroPython
def median(window): s = sorted(window) return s[len(s) // 2] data = [10, 12, 11, 50, 12, 11] for i in range(2, len(data)): print(median(data[i - 2:i + 1]))

Output: 11, 12, 12, 12. The spike of 50 vanishes entirely, because it is never the middle value. A median filter is better at rejecting occasional spikes; a moving average is better at smoothing steady, small noise.
