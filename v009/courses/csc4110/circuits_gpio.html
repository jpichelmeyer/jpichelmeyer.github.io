GPIO is the Pico's entire connection to the physical world, so before writing more code, it's worth being precise about what a GPIO pin actually does electrically, and how a breadboard turns your sensor kit's loose parts into an actual working circuit.

Part 1. Breadboards: What the Holes Mean

A breadboard lets you build a circuit without soldering anything, by pushing component legs and wires into holes that are secretly connected to each other underneath the plastic.

How a breadboard is wired underneath. The blue-tinted column and the orange-tinted column share the same number but are not connected, because the trench separates the two halves. Each rail, by contrast, is one long connection, so it is the natural place to put 3.3 V and ground.

Part 2. A Pin Has Three States

A GPIO pin configured as an output can be driven to exactly two voltage levels, and MicroPython calls them 1 and 0:

  • HIGH (1): the pin outputs 3.3V.
  • LOW (0): the pin outputs 0V (connected to ground internally).

That 3.3V figure matters: unlike many Arduino boards, which run at 5V logic, the Pico's GPIO pins are 3.3V, and feeding a genuine 5V signal into one can damage it. Check your sensor kit's datasheet before wiring anything unfamiliar; most of the kit's basic sensors are 3.3V-friendly, but it's worth the ten seconds of checking.

One GPIO pin, simplified. As an output, the driver forces the pin to 3.3 V or 0 V on command. As an input, the buffer reports which side of the halfway point the pin's voltage is on. An optional internal pull-up resistor gently holds an unconnected input at 3.3 V.

Part 3. Lighting an LED

An LED only conducts current in one direction and will happily burn itself out if you don't limit how much current flows through it, which is what the resistor in this circuit is for:

The two parts of the first circuit. An LED only conducts one way, so which leg is which matters; a resistor works either way round, and its colored bands encode its value (here orange-orange-brown, 33 × 10 = 330 Ω).
shell MicroPython
from machine import Pin led = Pin(15, Pin.OUT) led.value(1) # HIGH -- lit led.value(0) # LOW -- off led.toggle() # flips whatever it currently is
The first circuit as it sits on a breadboard. Current leaves GP15, passes through the 330 Ω resistor and the LED (long leg toward the resistor), and returns to ground through the black wires. The green wire joins GP15 to the resistor's column; the orange-tinted column joins the resistor's other end to the LED's long leg.
The same circuit drawn as a schematic: pin, resistor, LED, ground. A schematic shows only what connects to what, not where things physically sit.

Part 4. Reading a Button: Why Pull-Ups Exist

A button, electrically, is just a switch: it connects two points together when pressed, and does nothing (leaves them unconnected) when released. "Does nothing" is the problem. An input pin that isn't firmly connected to either 3.3V or GND doesn't reliably read as HIGH or LOW, it floats, and can register random noise as rapid, meaningless HIGH/LOW flips.

The fix is a pull-up resistor: a resistor that weakly holds the pin HIGH by default, so that pressing the button (which connects it to GND) is the only thing that can pull it LOW. The Pico can do this internally, no extra resistor needed in the kit:

Why a button input needs a pull-up. With one, the pin always has a defined level (HIGH released, LOW pressed). Without it, an unpressed pin is not connected to anything and can read either value, changing from moment to moment.
shell MicroPython
button = Pin(14, Pin.IN, Pin.PULL_UP) print(button.value()) # 1 (HIGH) when not pressed # 0 (LOW) the instant it's pressed

Notice the logic is inverted from what intuition might suggest: 1 means "not pressed," 0 means "pressed." This specific pattern, a pull-up resistor plus a button wired to GND, is common enough across embedded projects that it's worth memorizing rather than re-deriving each time.

A pushbutton straddling the trench, so its top legs are in the top half and its bottom legs in the bottom half. GP14 goes to the top group, ground to the bottom group. Pressing the button connects the two halves, pulling GP14 down to ground.
Schematic of the button circuit. The pull-up resistor is inside the Pico (turned on by Pin.PULL_UP), so the only external parts are the button and a wire to ground.

Exercises

Practice problems in three tiers. Do each on paper or on your own board first, and only then open its solution below. Many problems have more than one correct answer; if yours behaves the same way, it is right even if it looks different.

Warm Up

Exercise 1: Which Holes Are Connected?. Using the breadboard diagram, say whether each pair is electrically connected: (a) 3b and 3d, (b) 3d and 3g, (c) 3a and 4a, (d) two holes in the + rail, even far apart.

Exercise 2: Is 330 Ω Safe?. An LED drops about 2.0 V when lit. With a 3.3 V pin, how much current flows through a 330 Ω resistor? What about a 100 Ω resistor? A Pico pin is happiest supplying only a few milliamps.

Intermediate

Exercise 3: Hold to Light. Wire an LED on GP15 and a button on GP14 (with Pin.PULL_UP). Write a loop that lights the LED only while the button is held.

Advanced

Exercise 4: Two LEDs, One Button. Add a second LED on GP16. While the button is held, the two LEDs should alternate (one on, the other off, swapping every 0.2 s); when released, both are off. Then answer: how quickly does this program notice the button being pressed or released, and why?

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Which Holes Are Connected?

(a) Yes: same column, same half. (b) No: the trench separates the halves. (c) No: different columns are separate unless a wire or part joins them. (d) Yes: a rail is one long connection.

Exercise 2: Is 330 Ω Safe?

Use I = (3.3 − 2.0) / R. With 330 Ω: 1.3 / 330 ≈ 3.9 mA, comfortable for a pin. With 100 Ω: 1.3 / 100 = 13 mA, more than the pin is meant to supply and needlessly hard on the LED. That is why the kit uses a few hundred ohms.

Intermediate

Exercise 3: Hold to Light
main.py MicroPython
from machine import Pin led = Pin(15, Pin.OUT) button = Pin(14, Pin.IN, Pin.PULL_UP) while True: led.value(0 if button.value() else 1)

Remember the inversion: button.value() is 1 when released, so the LED gets 0 then and 1 while pressed.

Advanced

Exercise 4: Two LEDs, One Button
main.py MicroPython
from machine import Pin from time import sleep led1 = Pin(15, Pin.OUT) led2 = Pin(16, Pin.OUT) button = Pin(14, Pin.IN, Pin.PULL_UP) while True: if button.value() == 0: # held led1.value(1); led2.value(0) sleep(0.2) led1.value(0); led2.value(1) sleep(0.2) else: led1.value(0); led2.value(0)

While the button is held it checks only once per 0.4 s (during the two sleeps the program cannot look at anything). A quick tap could be missed completely. This "blocking" problem is exactly what the non-blocking lessons in Week 3 solve.

Checkpoint

Before moving on, make sure you can:

  1. Explain, using the breadboard diagram, why two components plugged into the same group of five holes are electrically connected and two plugged into different groups are not.
  2. Explain what a resistor is doing in the LED circuit, and what would likely happen without it.
  3. Explain why a floating input pin is a problem, and how a pull-up resistor solves it.
  4. State, without looking it up, what button.value() returns when a pull-up button is pressed versus not pressed, and why that might feel backwards at first.
