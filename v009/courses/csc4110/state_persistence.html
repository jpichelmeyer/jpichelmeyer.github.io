A device that forgets everything when power blips is a toy; one that picks up where it left off is a tool. "State" is anything the system should remember: whether the fan was on, the interval someone set, the last calibration. The question is where to keep it, and the answer depends on which failures you want to survive.

Part 1. Where State Can Live

There are four places, each surviving a different set of failures:

Where a piece of state can live, and what it survives. Choosing a layer is choosing which failures you are protecting against.
  • RAM. Fast and free, but gone at every reset.
  • A file in the Pico’s flash. Survives reboots and power loss, but belongs to that board, and flash wears out if written too often.
  • A retained message. Lives on the broker, so it survives losing the Pico entirely (a replacement board can read it). It survives a broker restart only if persistence is enabled.

Often you want two of them: a file for the device’s own settings, and a retained stat message so the rest of the system can see them.

Part 2. Writing a File Safely

Flash writes take time, and power can be cut in the middle. If you overwrite state.json in place, a cut mid-write leaves it empty or half written. The standard fix is to write a new file and then rename it over the old one, so the real file is only ever replaced whole:

Writing a file safely. Overwriting the real file in place can leave it half-written if power is cut. Writing a temporary file and then renaming it means the old good copy is replaced in one step.
state.py MicroPython
import json, os STATE = "state.json" TMP = "state.tmp" def save_state(state): with open(TMP, "w") as f: json.dump(state, f) os.rename(TMP, STATE) # replaces the old file in one step def load_state(default): try: with open(STATE) as f: return json.load(f) except (OSError, ValueError): # missing, or corrupt: fall back safely return default

On the Pico’s default filesystem (littlefs), renaming over an existing file replaces it. Check this on your own firmware before relying on it for anything important.

Part 3. Do Not Wear It Out

Flash memory survives a limited number of erase cycles (often quoted around 100,000 per block). The filesystem spreads writes around, but a program that saves every second can still shorten its life. Save when something changes, and no more than every few seconds:

state.py MicroPython
from time import ticks_ms, ticks_diff last_saved = ticks_ms() dirty = False def set_state(key, value): global dirty if state.get(key) != value: state[key] = value dirty = True def maybe_save(): global dirty, last_saved if dirty and ticks_diff(ticks_ms(), last_saved) > 5000: save_state(state) dirty = False last_saved = ticks_ms()

Part 4. A Start-Up That Remembers

A sensible start-up order for a device that must remember. Restore and apply the saved state first, then connect, then tell the world what you are doing.

The order matters. Restore and apply the saved state before connecting, so the device behaves sensibly even if the network is down. Only then announce it with a retained stat message. And a reboot should never decide to switch a load ON by itself: if the saved state is missing or damaged, fall back to the safe default.

main.py MicroPython
state = load_state({"fan": "off", "interval": 1000}) fan.value(1 if state["fan"] == "on" else 0) # apply before touching the network connect_wifi(); connect_broker() client.publish(b"lab/pico01/stat/fan", state["fan"].encode(), retain=True) client.subscribe(b"lab/pico01/cmd/#")

To find out why the board restarted, machine.reset_cause() returns a code such as machine.PWRON_RESET or machine.WDT_RESET. A watchdog reset is a sign that something hung, and is worth reporting.

Intermediate

Exercise 3: Load With a Default
state.py MicroPython
import json def load_state(default): try: with open("state.json") as f: data = json.load(f) except (OSError, ValueError): return default for key in default: if key not in data: # an older file without a newer setting return default return data

Checking for required keys matters when you add a new setting later: an old file from before the change would otherwise crash the program with a KeyError at the worst moment.

Advanced

Exercise 4: Prove the Rename Trick
state_test.py MicroPython
save_state({"fan": "on", "interval": 500}) # a good save with open("state.tmp", "w") as f: # a crash part-way through the next save f.write('{"fan": "of') # truncated, and never renamed print(load_state({"fan": "off", "interval": 1000})) # {'fan': 'on', 'interval': 500}

The real file was never opened for writing during the "crash", so it is untouched. Had the write gone straight to state.json, the load would have hit invalid JSON and returned the default, losing the setting.
