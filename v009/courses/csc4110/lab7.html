This lab joins the four layers of the Staying safe offline lesson into one node and then attacks it. You assemble a robot that backs off, remembers its restarts, feeds a watchdog only when healthy and keeps control independent of the network, and you measure how it behaves in eight failure drills. Then you give its Decider a second layer, an arbiter with a role, and announce that role to the hub: from this week on your robot is a specialist.

What You Will Build

The Lab 6 robot, made to survive. You take the node that obeys commands and add the four layers from the Staying safe offline lesson: backoff (it reconnects politely), persistence (it remembers its resets and outages across restarts), the watchdog (it recovers from a hang), and the bounded inbox of hub.py. Then you break it on purpose, with drills, and write down what happened. The aim is not a node that never fails; it is a node whose failures are short, safe and visible.

The layers of the Lab 7 node. The order matters: safety (control) first, then the network, then memory, with the watchdog watching all of it.

Step 1. Assemble the Node

Copy these files to the Pico: net.py, config.py, hub.py, robot.py, actuators.py (Lab 6), and the new ones from the Staying safe offline lesson: backoff.py, resilient.py, store.py and state.py. Then replace main.py with the program below. Read it before you run it: every block of it is a decision from a lesson.

main.py MicroPython
# main.py for Lab 7: the Lab 6 robot, made to survive from machine import WDT, reset_cause, WDT_RESET from time import ticks_ms, ticks_diff import hub, resilient, state from robot import Robot from actuators import Actuators st = state.State("state.json", {"resets": 0, "wdt": 0, "outages": 0}, min_gap_ms=30000) st.set("resets", st.data["resets"] + 1) if reset_cause() == WDT_RESET: st.set("wdt", st.data["wdt"] + 1) st.tick(force=True) h = resilient.ResilientHub(keepalive=30, wifi_timeout_s=5) h.presence() robot = Robot(Actuators(), allow_spin=True) # starts IDLE, outputs off, always def on_cmd(topic, payload): kind = topic.rsplit("/", 1)[-1] d = hub.decode(payload) h.publish("evt/ack", robot.command(kind, d, ticks_ms())) # the robot's id table makes this idempotent h.on(h.mine("cmd/#"), on_cmd) wdt = WDT(timeout=8000) shown, was_online, last_pass, t_report = None, False, ticks_ms(), ticks_ms() while True: now = ticks_ms() last_pass = now h.poll() # the link may be down: this must not block for why in robot.tick(now): # the control step runs whatever the network does h.publish("evt/stopped", {"why": why}) online = h.status == "ONLINE" if was_online and not online: st.set("outages", st.data["outages"] + 1) shown = None # a restarted broker may have lost the retained state was_online = online s = robot.state() if s != shown and online: h.publish("stat/state", {"state": s[0], "owner": s[1], "resets": st.data["resets"], "wdt": st.data["wdt"]}, retain=True) shown = s if online and ticks_diff(now, t_report) >= 1000: t_report = now h.publish("tele/health", {"attempts": h.attempts, "outages": st.data["outages"], "dropped": h.rx_dropped}) st.tick() if ticks_diff(ticks_ms(), last_pass) < 2000: # healthy: the loop came round wdt.feed()

Five things to notice. (1) wifi_timeout_s=5 keeps every blocking call inside the watchdog’s 8 seconds. (2) The robot is built idle each time, never from saved state. (3) h.poll() returns at once when the link is down, so robot.tick keeps running and the deadman keeps working. (4) State is published only when online, because a publish on a dead link only adds to the confusion. (5) The watchdog is fed at the end of a pass, and only if the pass was healthy.

Before the lab, the program was run on the test fixture (a fake broker and clock) through a scripted outage: claim at 4 s, a spin command at 5 s, the network cut at 7 s and restored at 67 s, then a simulated watchdog restart. The motor ran from 6 s (about a second after the command) and was off by 8 s with the network still down, because the deadman needs no network. After the link returned, the node was back online 6 to 33 seconds later (six runs with different jitter, average 22 s), because its backoff was already at the 30-second ceiling. The counters after the simulated watchdog reset was {resets: 2, wdt: 1, outages: 1}. Your numbers will differ; the shapes should match.

Step 3. Give the Decider a Role

Write down your role from the role menu of the architectures lesson, and the pose of your robot on the arena: its position in centimetres from the arena's corner, and the direction its pan servo calls 0°. Then add an arbiter above the Lab 6 robot logic. Its job is small but important: decide, every 50 ms, whether the robot is being commanded (Obey), is unhealthy (Safe), or is free to do its own job (the role's default behaviour). The example is a Scout's slow sweep; a Watcher or Pointer would hold its last aim, a Signaler would show an idle screen.

The Decider grows a layer. The Lab 6 Robot still handles commands, ownership and the deadman (its reactive and command logic is untouched); the arbiter above it decides who is in charge right now. When nobody owns the robot, its role's own default behaviour runs, so the robot is never just waiting. The retained stat/role tells the hub and every teammate what this robot is and where it sits.

Your role also changes the body. Fit your role's hardware this week, following its Stage 2 drawing; keep the Unit 1 parts your role still uses and unplug the rest, so the zones stay readable.

role.py MicroPython
# role.py -- Lab 7, Step 3: an arbiter above the Lab 6 robot, and a role announcement from time import ticks_diff from arbiter import Behaviour, Arbiter # architectures lesson ROLE = "scout" # your role from the role menu POSE = {"x": 0.0, "y": 0.0, "heading": 90.0} # where your robot sits on the arena (cm, degrees) def percepts(robot, now, healthy): return {"owned": robot.owner is not None, "cmd_age_ms": ticks_diff(now, robot.last_cmd) if robot.last_cmd else 10**9, "fault": not healthy} class Safe(Behaviour): # 1: something is wrong with me: hold still name = "safe" def wants(self, p, m): return p["fault"] def act(self, p, m, dt): return {"stop": True} class Obey(Behaviour): # 2: an owner is commanding me: Robot.command drives name = "obey" def wants(self, p, m): return p["owned"] and p["cmd_age_ms"] < 2000 def act(self, p, m, dt): return {} # nothing extra: the Lab 6 logic already acted class Sweep(Behaviour): # 3: my role's default: a slow scan (a Scout) name = "sweep" def wants(self, p, m): return True def act(self, p, m, dt): m.pan += m.sweep_dir * 30 * dt # 30 deg/s, inside the -90..90 range of pan() if not -80 <= m.pan <= 80: m.sweep_dir = -m.sweep_dir m.pan = max(-80, min(80, m.pan)) return {"pan": m.pan} class RoleMemory: def __init__(self): self.pan, self.sweep_dir, self.active, self.switches = 0.0, 1, None, 0 class RoleArbiter(Arbiter): # the same idea, but act() may return {} or a stop def decide(self, p, m, dt): for b in self.behaviours: if b.wants(p, m): if b.name != m.active: m.switches, m.active = m.switches + 1, b.name return b.name, b.act(p, m, dt) def announce(h): h.publish("stat/role", dict(POSE, role=ROLE), retain=True)

Warm Up

Exercise 1: Read the Backoff

At the ceiling the next attempt is up to 30 × 1.25 = 37.5 s after the last failed one, and, because the link returns at a random point in that wait, the average is about half the wait: 15 to 19 s. The ceiling is a good idea because without it the waits would keep doubling (1, 2, 4 ... 64, 128 s), and a node would sit out minutes after a long outage; with a ceiling it tries every half minute at a trivial cost.

Intermediate

Exercise 2: Stuck Online

(1) Subscription lost: it reconnected but did not resubscribe; check that connect resubscribes (the Hub does) and that cmd/# is in the filter list. (2) Publishing to a topic the ACL denies: a denied publish is silent; check the broker log or publish from a known-good client to the same topic. (3) Stale shown state: the node thinks the state was already published but a restarted broker lost the retained copy, so it never republishes; the listing resets shown to None when the link drops. Take that line out, restart the broker without persistence, and see the retained state go missing.
