Each of your robots has a Memory, and so far it has been private: what the Scout remembers about the target is invisible to the Pointer unless the Scout says it, and the Pointer happens to be listening at that moment. A team needs more than that. It needs a shared world model: one place that holds what the team currently believes (who is on the team and alive, where the target is, what it is), how old each belief is and who it came from, and that any robot can read at any time, including one that has just rebooted. This lesson builds that place on the class hub, out of three things you already have: retained MQTT messages, the topic conventions, and the access list.

Part 1. Private Memories, Shared Memory

Private memories and a shared one. Each robot keeps its own Memory for its own job, reports what it knows in its own subtree, and reads the team's beliefs from world/#. The world model is one program on the hub that turns many reports into one consistent view. Because its messages are retained, a robot that joins late, or reboots mid-mission, gets the whole current view the moment it subscribes.

In SAM terms, where does the shared world model live? Not inside any robot. For each robot, it is part of the environment: something it perceives through messages (with all the usual care: messages can be late, stale or missing) and influences only by reporting. It lives in the Memory of the hub agent, whose Perceptor is its subscriptions and whose Actuator is its retained publications. Thinking of it this way keeps one rule clear: a robot must never treat the world model as true. It is a belief, with an age, that the robot weighs like any other percept.

The world model drawn with SAM. The team's memory is the hub agent's Memory. Each robot reaches it only through its own Actuator (reporting) and its own Perceptor (reading world/#), exactly as it reaches the physical world. Nothing writes directly into another agent's Memory.

Part 2. One Writer per Fact

The simplest design would let every robot write its beliefs straight into shared topics: the Scouts both publish world/target, the Watchers both publish world/ident. It fails in a way that is easy to miss on the bench. MQTT keeps only the last retained message on a topic, so the shared “truth” is whichever robot spoke most recently, and it flips every time the other one speaks.

Why each shared fact needs exactly one writer. Above, two Scouts publish their own estimates to the same retained topic, and every reader sees the answer flip back and forth. Below, the Scouts report in their own subtrees and one program on the hub combines them, so every reader sees the same, stable answer. This is also what the access list already enforces: each user may write only to lab/<own name>/#.

So the rule is: robots report, the world model decides, everyone reads. Robots never write world/#, and the world model never writes into a robot's subtree. One new broker user, world, owns the shared topics:

Part 3. Beliefs Have Ages, Not Timestamps

Every shared fact is a belief: a value, who it came from, how old it is, and whether it is still fresh enough to act on. Fresh is not the same for every fact. A target position is useless after a couple of seconds if the target can move; an identification (“it is the red one”) stays good for much longer. The world model keeps a freshness limit per kind of fact and publishes the verdict along with the value.

Freshness limits for two kinds of belief. A stale value is still published (it is better than nothing for a display), but it is flagged, and a robot's Decider should not aim a pointer at a two-second-old position. Sending ages instead of timestamps sidesteps the fact that the Picos' clocks are not synchronised with the hub or with each other.

Part 4. The World Model, as Pure Logic

Write the merging logic with no network code at all, so that you can test every rule with scripted reports. It keeps the roster (role, presence, last heard), the latest fused target and the latest identification from each Watcher, and produces the shared view on request. Two Watchers that disagree are settled by a confidence-weighted vote, and the result says who took part.

world.py Python
# world.py -- the team's shared memory, kept by ONE writer on the hub (pure logic, no network) class WorldModel: FRESH_S = {"target": 2.0, "ident": 10.0} # how long each kind of belief stays fresh OFFLINE_AFTER_S = 10.0 # silent this long = treat as offline def __init__(self): self.roster = {} # user -> {"role", "online", "seen"} self.target = None # {"x", "y", "q", "src", "t"} self.votes = {} # user -> (label, conf, t): each Watcher's latest identification def ingest(self, topic, d, now): """One report from a robot. topic is lab/<user>/<kind>/<name>; d is the decoded payload.""" parts = topic.split("/") if len(parts) != 4 or parts[0] != "lab" or not isinstance(d, dict): return False _, user, kind, name = parts r = self.roster.setdefault(user, {"role": None, "online": True, "seen": now}) r["seen"] = now if (kind, name) == ("stat", "role"): r["role"] = d.get("role") elif (kind, name) == ("stat", "online"): r["online"] = bool(d.get("online")) # the last will sets this False elif (kind, name) == ("tele", "fix"): self.target = {"x": d["x"], "y": d["y"], "q": d.get("q", 0.0), "src": user, "t": now} elif (kind, name) == ("evt", "ident"): self.votes[user] = (d["label"], d["conf"], now) else: return False # not something the world model keeps return True def _belief(self, value, src, t, kind, now): age = now - t return {"value": value, "src": src, "age_s": round(age, 2), "fresh": age <= self.FRESH_S[kind]} def snapshot(self, now): """Everything the world model publishes: {topic: payload}.""" roster = {} for u, r in sorted(self.roster.items()): alive = r["online"] and now - r["seen"] < self.OFFLINE_AFTER_S roster[u] = {"role": r["role"], "online": alive, "seen_s": round(now - r["seen"], 1)} out = {"world/roster": roster} if self.target: t = self.target out["world/target"] = self._belief({"x": t["x"], "y": t["y"], "q": t["q"]}, [t["src"]], t["t"], "target", now) fresh = [(u, lab, c, t) for u, (lab, c, t) in self.votes.items() if now - t <= self.FRESH_S["ident"]] if fresh: score = {} for u, lab, c, t in fresh: # confidence-weighted vote score[lab] = score.get(lab, 0.0) + c best = max(score, key=score.get) out["world/ident"] = self._belief( {"label": best, "conf": round(score[best] / sum(score.values()), 2)}, sorted(u for u, lab, c, t in fresh), max(t for *_, t in fresh), "ident", now) return out

A Decider downstream (the mission coordinator in the next lesson) can then ask for a second look instead of acting on a split decision.

Look at the last line of the output. When Kim's robot drops off, its last will marks it offline at once; the target belief, now five seconds old, is still in the view but flagged stale. Neither fact is deleted. Deleting would make a late joiner believe there had never been a target, which is a different and worse belief than “there was one, five seconds ago”.

Part 5. Running It on the Hub

The service that wraps the logic is short. It runs on the class Pi as an ordinary Python program, using the paho-mqtt library (pip install paho-mqtt). It subscribes to everything in lab/# (any message at all proves its sender is alive, which keeps the roster honest), feeds each one to the model, which keeps only what it needs, and publishes the view retained, whenever it changes and once a second as a heartbeat so that ages keep moving.

worldsvc.py Python
# worldsvc.py -- runs on the class Pi: the ONLY program that writes world/# import json, time import paho.mqtt.client as mqtt from world import WorldModel BROKER, USER, PASSWORD = "localhost", "world", "PASSWORD" w = WorldModel() last = {} # what we last published on each topic def on_message(client, userdata, msg): try: d = json.loads(msg.payload) except ValueError: return # a malformed report changes nothing w.ingest(msg.topic, d, time.monotonic()) def on_connect(client, userdata, flags, reason_code, properties): client.subscribe("lab/#") # everything: any message proves its sender is alive c = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id="world") c.username_pw_set(USER, PASSWORD) c.on_connect, c.on_message = on_connect, on_message c.connect(BROKER) c.loop_start() # network on its own thread beat = 0.0 while True: now = time.monotonic() for topic, payload in w.snapshot(now).items(): text = json.dumps(payload, sort_keys=True) if text != last.get(topic) or now - beat >= 1.0: # on change, and a 1 s heartbeat c.publish(topic, text, qos=1, retain=True) # retained: late joiners get it at once last[topic] = text if now - beat >= 1.0: beat = now time.sleep(0.1)

On each robot, a small reader turns the shared view into percepts with ages. It belongs to the Perceptor: it receives, checks and ages the world model's messages, and the Decider asks it questions such as “is there a fresh target?”.

worldview.py MicroPython
# worldview.py -- on each robot: the team's beliefs, as percepts with ages from time import ticks_ms, ticks_diff import hub class WorldView: LIMIT_S = {"target": 2.0, "ident": 10.0} # the same freshness rules as the hub def __init__(self, h): self.msgs = {} # key -> (payload, ms when received) for key in ("roster", "target", "ident"): h.on("world/" + key, self.on_world) def on_world(self, topic, payload): d = hub.decode(payload) if isinstance(d, dict): self.msgs[topic.split("/")[1]] = (d, ticks_ms()) def get(self, key): """(value, age_s, fresh) or (None, None, False). Age = age at publish + time since.""" if key not in self.msgs: return None, None, False d, rx = self.msgs[key] if key == "roster": return d, ticks_diff(ticks_ms(), rx) / 1000, True age = d["age_s"] + ticks_diff(ticks_ms(), rx) / 1000 return d["value"], age, d["fresh"] and age <= self.LIMIT_S.get(key, 2.0)

Use it as one more source of percepts. A Pointer's Perceptor might return {"target": (x, y), "target_fresh": True, "ident": "red"} next to its own eye readings, and its arbiter's Track behaviour wants control only when target_fresh is true. If the hub goes silent, ages grow, beliefs turn stale, and the robot falls back to its own behaviours. Nothing in the robot waits for the world model.

Part 6. What Can Still Go Wrong

A shared world model removes the flip-flopping of Part 2, but distributed memory always has hazards. Name them in your designs:

  • Stale reads. Every robot sees the world a little late (network delay, plus up to a heartbeat). Act on ages, never on the bare value.
  • Ghosts. A retained message outlives its writer. If the world model itself crashes, its last retained view stays on the broker, with ages frozen at the moment it was sent. That is why robots add the time since arrival: a frozen view still ages, on the robot, and turns stale.
  • Split decisions. Two robots read the same fresh belief and both act on it (both Pointers turn to the target). Shared memory is not coordination. Who acts is decided by a lease or a coordinator, the subject of the next two weeks.
  • Garbage in. One robot reporting nonsense (a Watcher with a dead LED reporting “red” at 0.99) can outvote the rest. The contract checker of Week 11 should run on every report before ingest, and a very confident outlier deserves a log line.

Warm Up

Exercise 1: Who Writes?

(a) Only amy (the pattern write lab/%u/# rule) and the instructor. (b) and (c) Only the world user (and the instructor). (d) The world user, through the same pattern rule: it is that user's own subtree, which is where the world service should put its own last will, so that robots can tell the world model itself has gone away.

Exercise 2: How Old?

0.6 + 1.1 = 1.7 s: fresh under 2 s, just. If the heartbeat stops, no newer message arrives and the robot keeps adding time since arrival: after another 0.3 s the belief crosses 2 s and turns stale, even though nobody told the robot anything. That is the protection against ghosts in Part 6.

Intermediate

Exercise 3: A Three-Way Vote

Scores: red 0.7 + 0.4 = 1.1, green 0.8. Red wins with confidence 1.1 / 1.9 = 0.58, sources all three. Two lukewarm votes beat one confident one, which is a choice built into summing. When the green report expires, only the red votes count: red with confidence 1.1 / 1.1 = 1.0. The label did not change, but the confidence jumped, and nothing new was observed. A coordinator that requires confidence 0.8 before marking would act at this moment, purely because a dissenting vote aged out. Whether that is acceptable is a design decision; write it down.

Paper Practice: Answers

Recall

P1. Where It Lives

In the Memory of the hub agent. A robot reaches it only through its own Actuator (reporting) and its own Perceptor (reading world/#), as part of its environment.

P2. One Writer

Robots report, the world model decides, everyone reads: each shared fact has exactly one writer. Only the world user may write world/#; robots write only their own subtrees.

P3. Ages, Not Timestamps

The hub's clock and the robots' clocks are not synchronised; an age at sending plus the time since arrival (measured on the robot's own clock) gives each robot a usable age.

P4. Four Hazards

Stale reads; ghosts (retained messages outliving their writer); split decisions (two robots acting on the same belief); garbage in (a robot reporting nonsense that outvotes the rest).

Apply

P5. How Old Now

1.7 s, fresh. It turns stale 0.3 s later (2.0 − 1.7), with no message needed.

P6. Vote

Red 1.1 vs green 0.8: red, confidence 1.1 / 1.9 = 0.58. After green expires: red, confidence 1.1 / 1.1 = 1.0, although nothing new was observed.

P7. Roster

By silence: last message at about t = 30, so shown offline at about t = 40 (the will would come later, between 30 and 45 s after the failure, so the silence rule fires first).

P8. Who May Write

(a) amy (and the instructor). (b) only the world user (and the instructor). (c) the world user, through the general rule for its own subtree.

Analyze and Design

P9. Flip-Flop

world/target flips between the two answers every time either Scout reports (and its source changes). Fix by merging in the world model (a quality-weighted mean of fresh fixes) or by giving positions a single writer (a fuser that crosses the bearings).

P10. Don't Delete

Deleting would make a late joiner believe there had never been a target, a different and worse belief than "there was one, five seconds ago"; a stale value is still useful for a display, and the flag stops anyone acting on it.

P11. Liar

Blue (0.99 against 1.0 for red is nearly a tie, and any slightly higher blue confidence wins). Defences: check every report against the contract and plausibility before ingesting; cap individual confidence or vote by count; log and flag confident outliers; require agreement for a decision.

P12. Percept, Not Truth

After the world service dies, the last retained world/target stays on the broker; a Pointer trusting it keeps aiming at an old position while the target moves. The rule: act only on fresh beliefs, adding the time since arrival to the published age.
