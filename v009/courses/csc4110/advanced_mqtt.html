You now have the everyday features of MQTT: publish, subscribe, topics and permissions. This lesson covers the behaviours that decide whether a system feels solid or flaky: retained messages, keep-alive, and sessions. None of them is complicated, but each one has a default that surprises people the first time.

Part 1. Retained Messages

Normally a message is delivered to whoever is subscribed at that instant and then forgotten. A retained message is also stored by the broker (one per topic) and given to every new subscriber the moment it subscribes. That makes it ideal for state: the latest value is always available, even to a client that starts later.

A retained message is stored by the broker and handed to every new subscriber immediately. Without retain, a subscriber that joins late sees nothing until the next publish.
main.py MicroPython
client.publish(b"lab/pico01/stat/led", b"on", retain=True) # store it on the broker
Pi terminal Shell
mosquitto_sub -h localhost -u dashboard -P pw -v -t 'lab/+/stat/#' # new subscribers see stored states at once mosquitto_pub -h localhost -u instructor -P pw -r -n -t lab/pico01/stat/led # -r -n: clear a retained message

To remove a retained message you publish an empty payload to the same topic with retain set; -n sends the empty payload. Retained messages are the wrong tool for readings that keep changing and should not be replayed to latecomers, such as a stream of telemetry.

Part 2. Keep-Alive

A TCP connection can die without either end noticing, for example when WiFi drops. MQTT detects this with a keep-alive: the client promises to send something within a stated number of seconds, and the broker closes the connection if it hears nothing for one and a half times that.

Keep-alive proves a silent client is still there. The client promises to send something within the keep-alive time; if the broker hears nothing for one and a half times that, it drops the connection.

MicroPython’s umqtt.simple does not do this for you. The default keep-alive is 0, which disables it, and even when you set one the library never sends a ping by itself. Set the keep-alive and send a ping in your loop more often than that time:

main.py MicroPython
from time import ticks_ms, ticks_diff KEEPALIVE = 30 client = MQTTClient("pico01", BROKER_IP, keepalive=KEEPALIVE) client.connect() last_ping = ticks_ms() while True: client.check_msg() if ticks_diff(ticks_ms(), last_ping) > KEEPALIVE * 1000 // 2: # half the time: a safe margin client.ping() last_ping = ticks_ms()

Any message you publish also counts as activity, so a device that publishes every few seconds needs no separate ping. A device that mostly listens does.

Part 3. Sessions

A session is what the broker remembers about a client. With clean_session=True (the default) it remembers nothing between connections. With clean_session=False and the same client id every time, it keeps the subscriptions and queues messages sent at QoS 1 or higher while the client is away.

What the broker remembers while a client is away. A clean session forgets everything on disconnect; a persistent session keeps the subscriptions and queues QoS 1 messages until the client returns.
main.py MicroPython
client.connect(clean_session=False) # resume the previous session (same client id!)

A persistent session is useful for a device that must not miss commands while briefly offline. It also means the broker holds a queue for a client that might never return, so use it deliberately and only where it earns its keep.

Part 4. Which MQTT?

The protocol has two versions in use. Everything in this course is MQTT 3.1.1, which is what Mosquitto and umqtt.simple speak. MQTT 5 adds features worth knowing about, but the Pico’s library cannot use them, so any design here must work without them.

MQTT 3.1.1 is what Mosquitto, umqtt and this course use. MQTT 5 adds useful features, but the Pico's library cannot use them yet.

Intermediate

Exercise 3: A Keep-Alive Helper
keepalive.py MicroPython
from time import ticks_ms, ticks_diff class KeepAlive: def __init__(self, client, seconds): self.client = client self.every = seconds * 500 # half the keep-alive, in ms self.last = ticks_ms() def sent(self): self.last = ticks_ms() # call after any publish def tick(self): if ticks_diff(ticks_ms(), self.last) >= self.every: self.client.ping() self.last = ticks_ms()

Calling sent() after each publish avoids pinging when the connection is already busy. ticks_diff keeps it correct across the tick counter wrapping.

Advanced

Exercise 4: A Retained Config Topic
main.py MicroPython
interval_ms = 1000 # default until the broker tells us otherwise def on_message(topic, msg): global interval_ms if topic == b"lab/class/config/interval": try: v = int(msg) except ValueError: return if 100 <= v <= 60000: interval_ms = v client.set_callback(on_message) client.subscribe(b"lab/class/config/interval") # retained: arrives right after subscribing

Because the topic is retained, a Pico that boots later still receives the current value as soon as it subscribes. The range check protects against a mistyped setting reaching every device at once.
