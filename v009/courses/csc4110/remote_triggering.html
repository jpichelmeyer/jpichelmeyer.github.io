Now you can switch a load from a pin, and you can receive messages from anywhere on the network. Joining the two creates something with real consequences: someone, or some bug, can switch a physical object on remotely. This lesson is about doing that responsibly. The theme is simple: decide in advance what the safe state is, and make the system return to it whenever anything goes wrong.

Part 1. A Command Is Not an Action

Between a command arriving and an output changing, a well-built device does several things in order. It checks the command is one it knows and that the value is sensible; it checks that it is allowed right now; only then does it drive the pin; and finally it reads back what it really did and reports that.

A safe remote command, step by step. The device checks the request, changes the output, then reads back and reports what it really did.

Part 2. Decide the Safe State First

For every way things can go wrong, write down what the output should do, before writing any code. For a load that could cause harm, the safe state is almost always off.

Decide the safe state in advance. For each way things can go wrong, the output should return to a state that cannot cause harm, and a boot or reconnect should never switch something on by itself.

Two of these deserve emphasis. A timed command ("on for 10 seconds") means a lost "off" cannot leave something running forever. And a silence timeout turns the load off if the device has lost contact with whoever is supposed to be supervising it.

Part 3. The Output as a State Machine

The output as a state machine. Every arrow is a deliberate rule: commands move it, timers and silence move it back to OFF.
main.py MicroPython
from time import ticks_ms, ticks_add, ticks_diff out = Pin(15, Pin.OUT, value=0) state = "off" off_at = None # a deadline for a timed "on", or None last_contact = ticks_ms() # last time we heard from the broker def apply(cmd): """cmd is b"on", b"off", or b"on 10".""" global state, off_at parts = cmd.split() if not parts or parts[0] not in (b"on", b"off"): return if parts[0] == b"off": out.value(0); state = "off"; off_at = None else: out.value(1); state = "on"; off_at = None if len(parts) == 2: try: secs = int(parts[1]) except ValueError: return if 1 <= secs <= 300: # a sane limit off_at = ticks_add(ticks_ms(), secs * 1000) client.publish(b"lab/pico01/stat/out", state.encode(), retain=True) def supervise(): global state, off_at now = ticks_ms() if off_at is not None and ticks_diff(now, off_at) >= 0: out.value(0); state = "off"; off_at = None # the timer ran out if ticks_diff(now, last_contact) > 30000 and state == "on": out.value(0); state = "off"; off_at = None # the broker went quiet

supervise() runs on every pass of the main loop, and last_contact is refreshed whenever a message or ping response arrives. The commands can be repeated safely: on twice is the same as once.

Part 4. Layers of Protection

Defence in depth. A command passes four independent barriers; each one assumes the one before it failed.

No single layer is enough. The WiFi password can leak; a login can be guessed or reused; code can have a bug. Each barrier assumes the one outside it has failed, and the innermost, the hardware, should keep working even if everything else is wrong: the pull-down keeps the load off at power-up, the supply limits the damage, a fuse covers the rest.

Warm Up

Exercise 1: Choose the Safe State

(a) off: an unattended heater is a fire risk. (b) unlocked: people must be able to leave; “safe” depends on the harm, not on “off”. (c) closed (off): a stuck-open valve overflows. (d) either: there is no harm; pick the one that makes a fault visible. The lesson of (b) is to decide per device.

Exercise 2: Idempotent or Not?

(a) safe: setting it on twice is the same as once. (b) unsafe: the second one flips it back. (c) safe: it restarts the same 10-second window. (d) unsafe: it counts twice. A repeated QoS 1 delivery makes this matter.

MAX_ON_MS = 5 * 60 * 1000 ... else: out.value(1); state = "on" limit = MAX_ON_MS if len(parts) == 2: try: limit = min(MAX_ON_MS, int(parts[1]) * 1000) except ValueError: return off_at = ticks_add(ticks_ms(), limit) # always set a deadline

Every path now ends with a deadline. The maximum is a property of the device, not of the sender, so no command can override it.
