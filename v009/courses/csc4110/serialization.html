This lesson covers how a measurement becomes a message and back. You will see what JSON is, what the three envelope fields on every class message are for, how rounding keeps messages short, and how to write a decoder that never crashes on bad input.

SAM lens. Serialization is how one agent's percept becomes bytes and another agent's percept again. The decoder that never crashes is a Perceptor filter for messages, exactly as a median filter is for spikes.

MQTT carries bytes and has no opinion about what they mean. Somebody has to decide how a temperature, a timestamp and a sequence number become bytes at one end and numbers again at the other. That decision, serialization, sets the size of every message, how much work the Pico does to build and read it, and how hard the format is to change later. We use JSON, because it is simple and you can read it with your eyes. This lesson looks at what goes into every class message and how to read one safely.

Part 1. JSON and the Envelope

JSON (JavaScript Object Notation) writes a dictionary as text: keys in double quotes, numbers as digits, lists in square brackets. json.dumps turns a dictionary into a string and json.loads turns the string back into a dictionary. The two ends only have to agree on the key names. Every message in this course is a JSON object that starts with the same three envelope fields, which net.py adds for you, followed by the data for that topic.

Anatomy of a class message. The envelope (purple) is the same on every topic and lets any receiver check the format, notice a lost message and tell how old a reading is. The body (blue) is the data, and only it changes from topic to topic.

Each envelope field answers a question the receiver would otherwise have to guess. v is the format version: if you ever change what the fields mean, you raise v, and a receiver that sees a version it does not know discards the message instead of misreading it. seq is a sequence number that counts up by one with each message from that sender: a jump from 41 to 44 means two messages were lost, and a second 41 is a duplicate. t is the sender’s ticks_ms() when the reading was taken. Two boards’ clocks started at different moments, so a t from one board cannot be compared with another board’s clock, but the difference between two t values from the same sender is real time.

Here is one IMU sample built by hand, the same way net.py builds it. It runs the same in desktop Python and on the Pico:

message.py MicroPython
import json def make(seq, t, ax, ay, az): """One IMU sample as a class message: the envelope, then the body.""" msg = {"v": 1, "seq": seq, "t": t, "ax": round(ax, 2), "ay": round(ay, 2), "az": round(az, 2)} return json.dumps(msg) text = make(17, 34120, 0.019775390625, -0.0071, 0.98046875) print(text) print(len(text), "bytes") back = json.loads(text) # and back to a dictionary print(back["az"], back["seq"])

The message is 68 bytes. That is small enough that the class limits (about ten messages a second each) are set by how often you send, not by how big each message is.

Part 2. Numbers, Not Text

In JSON every digit is a byte. 0.019775390625 is what a float prints as when it came from an ADC count divided by 4096, and it costs 14 characters where 0.02 costs 4. Rounding before sending (round(x, 2)) is the cheapest saving in the course, and it also shows what precision the sensor really has: the digits past the second or third decimal place of an MPU6050 reading are noise, not information.

That is the same reasoning as the ADC lesson: send the precision the measurement deserves, not the precision the variable happens to hold.

Part 3. Trust Nothing You Receive

Everything arriving from the network is input from outside your program: it may be truncated, from the wrong version, or not what you thought. A receiver that crashes on a bad packet lets any other node take it down. The decoder below turns bytes into a dictionary or None, and never raises an exception. Callers check for None and carry on.

decode.py MicroPython
import json def decode(payload): """Turn bytes from the network into a dict, or None. Never raises.""" try: d = json.loads(payload) except (ValueError, TypeError): return None # not JSON at all if not isinstance(d, dict) or d.get("v") != 1: return None # not an object, or a version we do not know if not isinstance(d.get("seq"), int) or not isinstance(d.get("t"), int): return None # the envelope is incomplete return d

Notice what it checks: it is JSON; it is an object (not a list or a number); the version is one we know; the envelope fields have the right types. It does not yet check ranges (is this roll angle possible?) or that the fields for this particular topic are present; that is the job of the contract in Week 11. The habit starts here.

Exercise 2: Decode These

(a) The dictionary: it passes every check. (b) None: it is valid JSON but a list, not an object. (c) None: version 2 is not one this receiver knows. (d) None: seq is the string "4", not an integer. Advanced

Exercise 3: Lost, Duplicate or Restart
seqwatch.py MicroPython
def classify(prev, seq): """Compare a message's seq with the previous one from the same sender.""" if prev is None or seq == prev + 1: return "ok" if seq > prev + 1: return "lost %d" % (seq - prev - 1) if seq == prev: return "duplicate" return "restart" # seq went backwards: the sender rebooted prev = None for seq in [1, 2, 3, 6, 6, 7, 1, 2]: print(seq, classify(prev, seq)) prev = seq

The output is ok, ok, ok, lost 2, duplicate, ok, restart, ok. A sequence number that goes backwards almost always means the sender rebooted: its counter started again from the beginning. Treat it as a fresh start rather than as thousands of lost messages.

Paper Practice: Answers

Recall

P1. What Serialization Decides

The size of every message; how much work the processor does to build and read it; how hard the format is to change later, and whether a person can read it.

P2. Three Envelope Fields

v: is this a format I understand? seq: did I miss a message, or get one twice? t: when was this reading taken, by the sender’s clock?

P3. Version Field

So that the meaning of the fields can change later without silently breaking old receivers. A receiver that sees an unknown version should discard the message, not guess what the fields mean.

Apply

P4. Rounding Saves

About 10 characters per value × 6 values × 10 messages = 600 bytes per second.

P5. Lost or Duplicate

41 arrived twice (a duplicate), and 42 and 43 never arrived (two lost). 40, the first 41, 44 and 45 are normal.

Analyze and Design

P6. Never Crash

It parses as JSON; the result is an object (dict), not a list or number; the version is one it knows; the envelope fields (v, seq, t) have the right types. Otherwise it returns None and never raises.

P7. Comparing Times

No. Each t is that board’s own ticks_ms(), counted from when that board started, and the two boards started at different moments. Only differences between two t values from the same sender mean anything. To compare across boards, the hub uses its own clock: when each message arrived.
