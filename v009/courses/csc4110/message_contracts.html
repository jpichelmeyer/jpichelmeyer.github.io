This lesson covers agreeing on messages and roles. You write a contract with its seven items, enforce it with a schema checker that cannot crash, change it additively without breaking readers, and let agents announce roles and choose a leader by a rule everyone computes from the same retained messages.

Agents written by different people, on different days, must still work together. What makes that possible is not good intentions but a contract: a precise, written description of every message, so exact that two people who never speak can each write one side and have the sides fit. You have been using one since Unit 2 (the envelope, the topic kinds, the robot interface spec for Lab Practical 2). This lesson shows what a contract contains, how to enforce it in code on the receiving side, how to change one without breaking anyone, and how agents announce roles so that a group can organise itself.

Part 1. What a Contract Contains

The seven items of a contract. Almost every integration failure in Labs 9 to 12 will be one of these left unwritten: a unit (cm or mm?), a range, or what silence means.

The row people forget is the fifth: the meaning of silence. A message that stops is also a message. If the contract says “no tele/range for 2 seconds means the sensor is lost”, then the receiver knows what to do; if it does not, every receiver invents its own rule, and they differ.

Part 2. The Envelope

The envelope is the part every message shares, so the receiver can handle it before it understands the content. You have used it since Lab 3:

envelope Text
{"v": 1, "seq": 412, "t": 98234, ...fields...} v contract version, an integer. Changes only when a field's meaning changes. seq a counter per publisher, up by one for every message it sends. t the sender's ticks_ms() when it made the message (a clock that restarts at every boot).

seq lets a receiver count what it missed and spot repeats, and t lets it judge age. Neither requires the sender and receiver to share a clock. Fields are flat, next to the envelope, because on a 200-byte budget every nested level of {} is bytes and RAM spent for nothing.

Part 3. Check Everything You Receive

Anything that arrives from the network is a stranger’s input, even from a classmate you trust, because their code may have a bug or yours may. The receiver therefore checks each message against the contract before using any of it, and the rule that matters most is that checking never raises: a malformed message must be rejected quietly, counted, and not crash the node. The cheapest way to do that for many messages is to write the contract as data and one function to check it:

contract.py MicroPython
# contract.py -- one table describes a message; one function checks it # field: (type, low, high, required) RANGE_TELE = { "cm": (float, 2.0, 400.0, True), # HC-SR04 range in centimetres "ok": (bool, None, None, False), } LED_CMD = { "to": (str, None, None, True), "state": (int, 0, 1, True), "id": (int, 0, 2**31, True), } def check(schema, d): """Returns (True, "") or (False, "reason"). Extra fields are allowed (they may come from a newer version of the contract); a missing or wrong field is not.""" if not isinstance(d, dict): return False, "not an object" for name, (typ, lo, hi, required) in schema.items(): if name not in d: if required: return False, "missing " + name continue v = d[name] if typ is float and isinstance(v, int) and not isinstance(v, bool): v = float(v) # JSON writes 20.0 as 20: accept an int for a float if not isinstance(v, typ) or (typ is not bool and isinstance(v, bool)): return False, name + " has the wrong type" if lo is not None and not (lo <= v <= hi): return False, name + " out of range" return True, ""

A few choices are worth a second look. Extra fields are allowed: a newer sender may add one, and an older receiver should ignore what it does not know (the next part uses this). A bool is not accepted as a number, though in Python True is the integer 1, because a state: true where a 0 or 1 was agreed is a different mistake from state: 1 and should be noticed. And NaN and infinity are both rejected by the range test, because every comparison with NaN is false.

To test the checker, 100,000 random inputs (None, booleans, huge integers, floats, strings with braces and quotes, lists, dictionaries with some of the right keys and random values) were fed to both schemas. No input raised an exception, and none was accepted. Then ten hand-written cases were checked, including an int where a float is expected (accepted: JSON drops the .0), a bool (rejected), {"cm": 500.0} (out of range), and a message with an extra field and a newer v (accepted). Write a test like this for every contract you publish: the cases you think of are the cases you already handle.

The receive path. A message passes two gates before anything acts on it; at each gate the failure is the same: reject, count, report once (not on every message, which would flood your own log).

Part 4. Changing a Contract Without Breaking Anyone

Contracts change, and the agents using them will not all be updated on the same day. Two kinds of change need different handling. An additive change adds a field: old receivers ignore it, because check allows extra fields, and nothing breaks. A breaking change alters the meaning of an existing field (centimetres become millimetres) or removes one; every receiver must change, so the version number changes, and for a time the sender publishes both (tele/range with v: 1, and a new topic or field for the new meaning).

Four changes and how to treat them. The safest rule: never change the meaning of a name; add a new name.

Part 5. Roles, and a Leader Without a Boss

A group of agents often needs to know who does what: “who is the coordinator?”, “which agents are scan heads?”. Rather than configure this by hand, each agent announces its role, retained, so that a late joiner finds out at once, and the last will from Unit 2 retracts it when the agent dies. Roles in this course are few: sensor (publishes measurements), actuator (obeys commands and reports the real state), coordinator (reads sensors, commands actuators) and observer (reads only, for example a logger or dashboard).

roles.py MicroPython
# roles.py -- announce what I am, and agree who leads without a boss import json def announce(hub, role, caps): """Retained: a late joiner learns the role at once. The will (hub.presence) retracts it.""" hub.publish("stat/role", {"role": role, "caps": caps}, retain=True) class Roster: """Who is alive and what they are, learned from lab/+/stat/role and lab/+/stat/online.""" def __init__(self): self.role = {} # name -> role self.online = {} # name -> True / False def on_role(self, name, d): self.role[name] = d.get("role") def on_online(self, name, d): self.online[name] = bool(d.get("online")) def alive(self, role=None): out = [n for n, up in self.online.items() if up and (role is None or self.role.get(n) == role)] return sorted(out) def leader(self, role): """The lowest name among the live agents of this role. Everyone computes the same answer from the same retained messages, so there is no vote and no boss.""" a = self.alive(role) return a[0] if a else None

When there are several coordinators and only one should act, they must agree who. A group with no boss can still agree if every member follows the same rule on the same information: here, the live coordinator with the lowest name leads. With c1 and c2 both live, c1 leads; when c1’s will says it is offline, c2 leads, with no message sent and no vote taken; when both are gone, there is no leader (None) and the actuators’ fail-safe is what remains. In the test, those three answers came out exactly so.

  • It is only as good as the shared information. If c2 has not yet heard that c1 is back, for a moment both lead. The actuator’s rule (obey only the most recent leader, or only the leader it chose) must make that harmless.
  • A silent but online agent is not covered by the will. Combine with the age rule of the previous lesson: a leader that has not published for stale_ms is treated as gone.
  • Keep roles few. Each role is a promise that others can rely on; an agent that is “sensor, but sometimes coordinator” is a contract nobody can state.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Spot the Violation

(a) valid. (b) violates: a string, not a number. (c) violates: 0 is below the 2 cm minimum of the sensor; it more likely means a timeout, and the contract says it must not be sent as a distance (use ok: false or send nothing). (d) valid: extra fields are allowed, so this is how a contract grows.

Exercise 2: Breaking or Not?

(a) additive: old receivers ignore temp. (b) breaking, and nasty, because the same number now means something else and no check can catch it (30 degrees is 0.52 radians, and both are legal numbers). Use a new field name (rad) or a new version. (c) breaking for any receiver that prints or logs why; add it back, or version the ack.

Intermediate

Exercise 3: Write the Contract
stopped_schema.py MicroPython
STOPPED = { "why": (str, None, None, True), "cmd_id": (int, 0, 2**31, False), } print(check(STOPPED, {"why": 5})) # (False, 'why has the wrong type') print(check(STOPPED, {"why": "deadman"})) # (True, '')

The length limit is not expressible in this schema (it handles ranges of numbers); a string-length check is a natural extension, (str, 0, 20, True) with len(v) compared, or a separate test. Note what the schema does not say: what the receiver does with why = "lease expired" or an unknown reason. That belongs in the written contract.

Advanced

Exercise 4: Who Leads?

When c1 crashes its will fires (online: false), so c2 and c3 compute c2 as leader. When c1 returns, its hello (online: true) arrives immediately, so c2 and c3 switch back to c1; c1 itself, restarting, may also think it leads before it has received the retained roles of the others. For a short moment two agents command. A harmless rule: actuators obey only a command whose sender they currently believe is leader, and refuse a command with an older t than the last they accepted from the same leader; and a new leader first observes for a second or two (the actuators’ lease expires) before acting.
