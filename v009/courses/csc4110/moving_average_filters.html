The noise-filtering lesson introduced the moving average as a tool. This lesson looks at it as an object worth understanding: what it costs, how it behaves in time, why it works, and exactly when something else would be better.

Part 1. The Definition

A moving average of window size N replaces each sample with the mean of the most recent N samples. For every new sample, one new value enters the window and the oldest leaves. In symbols, yn = (xn + xn−1 + … + xn−N+1) / N.

Part 2. Doing It Cheaply

The version in the previous lesson keeps a growing list and calls sum() over all N values on every update, so the work grows with N. On a small, fixed-memory device a better design keeps a circular buffer of exactly N slots and a running sum: subtract the value being overwritten, add the new one, and divide.

A circular buffer holds the last N samples in fixed memory. New readings overwrite the oldest, and a running sum makes each update a single add and subtract.
filters.py MicroPython
class RunningAverage: def __init__(self, size): self.size = size self.buf = [0] * size # fixed memory, allocated once self.i = 0 # which slot to overwrite next self.count = 0 # how many real samples so far self.total = 0 def add(self, x): self.total += x - self.buf[self.i] # new in, oldest out self.buf[self.i] = x self.i = (self.i + 1) % self.size if self.count < self.size: self.count += 1 return self.total / self.count

Each add now does the same small amount of work however large the window, and the memory use never changes. That is the difference between code that works on a laptop and code that is happy on a microcontroller running for months.

Part 3. Lag and Noise Reduction

Two simple rules describe what the filter does. Noise falls like 1 / √N for uncorrelated noise: a window of 16 makes random noise four times smaller, a window of 100 only ten times. And lag is about (N − 1) / 2 samples: the average is centered on the middle of the window, which is already in the past.

A moving average responds to a sudden change as a ramp N samples long. The bigger the window, the longer the ramp.

Both rules point the same way: a bigger window helps with noise but costs response time, with steadily diminishing returns. The right N depends on how noisy the sensor is and how quickly your program must react.

Part 4. A Filter in the Frequency Sense

A moving average is also a low-pass filter. Any frequency that fits a whole number of cycles into the window is averaged to exactly zero, because the positive and negative halves cancel. At 200 samples per second, a window of 4 spans 20 ms, one full cycle of 50 Hz mains interference, so that interference vanishes:

A moving average is also a filter in the frequency sense: any frequency that fits a whole number of cycles into the window is cancelled completely.

Part 5. When Something Else Is Better

  • Occasional large spikes: a median filter ignores them completely, while a moving average smears each spike across N outputs.
  • Memory-starved or very long smoothing: the exponential moving average, avg += alpha * (x - avg), stores a single number whatever the smoothing. It returns in Unit 2.
  • Sharp edges that must be tracked: any averaging filter blurs them; choose a smaller window or none.

Warm Up

Exercise 1: How Much Lag?

Delay ≈ (N − 1) / 2 samples = 4 samples = 0.4 s at 10 Hz. The average is centered on the middle of the window, which is already in the past.

Exercise 2: How Much Quieter?

Uncorrelated noise falls as 1 / √N. N = 16: 8 / 4 = ±2 counts. N = 100: 8 / 10 = ±0.8 counts. Diminishing returns: 6× more samples bought only 2.5× more quietness.

Advanced

Exercise 4: A Cheaper Smoother
ema.py MicroPython
class EMA: def __init__(self, alpha): self.alpha = alpha self.avg = None def add(self, x): if self.avg is None: self.avg = x # start from the first sample else: self.avg += self.alpha * (x - self.avg) return self.avg

It stores one number no matter how smooth you want it. A larger alpha reacts faster; a smaller one smooths more. Roughly, alpha = 0.2 behaves like a window of about 9.
