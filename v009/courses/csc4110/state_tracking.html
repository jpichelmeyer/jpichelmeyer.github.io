This lesson covers keeping a belief about things you cannot see. You store a value with its age, track a position and speed with an alpha-beta filter, coast through missing data and measure how the error grows, set a limit after which the track is declared lost, and keep commanded, reported and unknown state apart.

SAM lens. Beliefs with ages and the alpha-beta filter are Perceptor and Memory together: the filter remembers position and speed, predicts when data is missing, and reports how old its belief is.

Every agent in a multi-agent system acts on a belief about the others: where the target is, what state the door is in, whether the actuator did what it was told. A belief is built from messages, and messages are late, noisy, and sometimes missing. State tracking is the craft of turning such a stream into a usable estimate and of knowing, at every moment, how far to trust it. This lesson covers three tools: a belief that remembers its own age, a tracking filter that estimates position and speed from noisy readings, and the rule for how long an estimate may be carried forward when the data stops.

Part 1. A Belief Knows Its Age

The simplest wrong design is a variable: target = msg["deg"]. It has no history and no age, so a message from ten seconds ago is indistinguishable from one from ten milliseconds ago. A belief stores the value and when it arrived, and reports both. What to do with a stale value is the caller’s choice, but the caller is forced to look.

belief.py MicroPython
# belief.py -- what I think a peer's value is, and how sure I am from time import ticks_ms, ticks_diff class Belief: def __init__(self, stale_ms=3000): self.value, self.t, self.stale_ms = None, None, stale_ms def update(self, value, now=None): self.value, self.t = value, ticks_ms() if now is None else now def age_ms(self, now=None): return None if self.t is None else ticks_diff(ticks_ms() if now is None else now, self.t) def get(self, now=None): """(value, age_ms, fresh). A stale value is still returned, but flagged: the caller decides.""" a = self.age_ms(now) return self.value, a, (a is not None and a <= self.stale_ms)

Where to take the time from? There are two choices, and the right answer is often both. The arrival time (ticks_ms() when the message was handled) is on your own clock and always available; it includes the network delay and any queueing. The sender’s t field is when the value was measured, closer to the truth, but on the sender’s clock, which you cannot compare with yours. Use the arrival time for staleness, and the sender’s t for ordering messages from one sender and for the interval between two of them.

Part 2. Tracking Position and Speed

A scan head reports the bearing of a target a few times a second, each reading off by a few degrees. Averaging helps if the target is still; if it moves, an average lags behind it. The alpha-beta filter estimates the position and the speed together: each step it predicts where the target should be (the old position plus speed times the time passed), compares that with the measurement, and corrects the position by a fraction alpha of the difference and the speed by a fraction beta. It is the two-number cousin of the EMA, and, like it, needs almost no memory.

alphabeta.py MicroPython
# alphabeta.py -- track a position and its speed from noisy, sometimes missing, measurements class AlphaBeta: def __init__(self, alpha=0.5, beta=0.15): self.a, self.b = alpha, beta self.x = None # position estimate self.v = 0.0 # speed estimate, units per second def predict(self, dt): """Where do I think it is dt seconds later, with no new measurement? (coasting)""" if self.x is not None: self.x += self.v * dt return self.x def update(self, z, dt): """Fold in a measurement z that is dt seconds after the last step. Missing: call predict().""" if self.x is None: self.x = z return self.x self.predict(dt) r = z - self.x # how far off the prediction was self.x += self.a * r self.v += self.b * r / dt return self.x
Tracking through a gap. The estimate follows the moving target between the noisy dots, carries on through the three missing seconds by extrapolating its speed, and picks the target up again when the data returns.
Mean error of the estimate against the truth (30 s, readings every 0.2 s, 3° of noise), for different gains and different fractions of readings lost. Smoothing halves the error; large gains (0.8 and 0.4) follow the noise; tiny gains (0.2 and 0.01) cannot follow the turn and fall apart when readings are missing.

The choice of gains is a trade-off, the same one as in the filtering lesson: a high alpha trusts each measurement (fast, noisy), a low one trusts the model (smooth, slow to follow a turn). Here (0.3, 0.05) was best with no loss (1.3° against 2.5° raw) and (0.5, 0.15) held up better as readings were lost. Pick the gains from a recording of your own target, as in the learning lesson, not from this table.

Part 3. Coasting, and When to Stop

When a measurement is missing the filter calls predict: it coasts on its speed estimate. For a target moving steadily that is a large improvement over simply holding the last value; for a target that changes direction it is a liability, because the estimate keeps going straight. Worst error during a gap. Coasting is five times better than holding for a steady target (3 s: 4.5° against 23.5°) and still much better across a stop (7.3° against 19.3°), but it is wrong in a new way: its error does not stop growing, and after 6 s over the stop it is 13.4°.
  • Limit the coast. Coast for a short, fixed time (a second or two for a fast target), then declare the track lost and stop publishing it. A lost track is information; a confident wrong one is a hazard.
  • Say how old. Publish the estimate together with its age, or a flag coasting: true, so the receiver can discount it, as Belief does.
  • Re-acquire carefully. When data returns after a long gap, do not blend it with the old estimate as if nothing had happened: if the first new measurement is far from the prediction, restart the filter from it.
  • Gate the data. A reading very far from the prediction (several noise-widths) is probably an outlier (crosstalk, a reflection) and should not pull the estimate. Count it and let the next one decide.

Part 4. Believing an Actuator

The same discipline applies to things you command. After cmd/led state 1, what is the LED’s state? Three honest answers: commanded 1, reported 1, and unknown. Keep them separate. The commanded value is what you asked for; the reported value (the actuator’s retained stat/…) is what it says it did; and between sending and hearing there is a window where you do not know. A coordinator that treats “commanded” as “done” misses every lost message; one that waits for the report, with a timeout and a retry (the pattern of the agents and state machines lesson), knows. The belief about the actuator is the reported value with its age, and a mismatch lasting longer than the round trip is an event worth publishing.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Age or Fresh?

At 11,500 the age is 1,500 ms, within 3,000: (value, 1500, True). At 13,500 the age is 3,500 ms, beyond the limit: (value, 3500, False), the value is still returned but flagged stale. Before any update, value is None, age_ms is None and fresh is False: the caller must handle “never heard” as well as “heard long ago”.

Exercise 2: Predict

x = 20 + 5 × 0.2 = 21.0°. After a 2 s gap (ten calls of 0.2 s) x = 20 + 5 × 2 = 30°, if the speed estimate is right. If the target has actually stopped, the estimate is 10° out and growing by 5° per second, which is why the coast must be limited.

Intermediate

Exercise 3: Update by Hand

Predict: x = 20 + 5 × 0.2 = 21. Residual r = 22 − 21 = 1. New x = 21 + 0.5 × 1 = 21.5. New v = 5 + 0.2 × 1 / 0.2 = 6.0 °/s. The measurement was higher than predicted, so both the position and the speed estimate were nudged up; a run of such measurements pushes the speed up until the predictions match.

Advanced

Exercise 4: Lose the Track
alphabeta2.py MicroPython
class AlphaBeta2(AlphaBeta): def __init__(self, alpha=0.5, beta=0.15, coast_limit=1.5): super().__init__(alpha, beta) self.limit, self.coasted = coast_limit, 0.0 def predict(self, dt): self.coasted += dt if self.coasted > self.limit: self.x, self.v = None, 0.0 # lost: stop pretending return None return super().predict(dt) def update(self, z, dt): self.coasted = 0.0 return super().update(z, dt) # x is None after a loss: starts again from z

After x is None, update takes its first branch (self.x is None), so the filter restarts from the new measurement with zero speed. The caller must treat None from predict as “no track” and publish accordingly.

Paper Practice: Answers

Recall

P1. Belief

The value and when it arrived (so its age can be reported). A variable cannot distinguish a message from ten seconds ago from one ten milliseconds old.

P2. Which Clock

Arrival time on your own clock for staleness. The sender's t for ordering messages from one sender and for intervals between them.

P3. Alpha-Beta

It predicts the position from the old position plus speed × elapsed time, compares the prediction with the measurement, and corrects the position by a fraction α and the speed by a fraction β of the difference.

P4. Three States of an Actuator

The commanded value (what it asked for), the reported value (what the actuator says it did, with its age) and the unknown window in between.

Apply

P5. One Step

Prediction 10.0 + 2.0 × 0.2 = 10.4. Residual 0.6. x = 10.4 + 0.3 × 0.6 = 10.58. v = 2.0 + 0.05 × 0.6 / 0.2 = 2.15 °/s.

P6. Coast

10.58 + 2.15 × 1 = 12.73°. Error 1.73°, and growing while it coasts.

P7. Hold Versus Coast

Holding: about 8 × 3 = 24° (the lesson measured 23.5°). Coasting: small, limited by the speed estimate's error (the lesson measured 4.5°).

P8. Gate

No: it is 6 noise-widths away, probably an outlier (crosstalk, a reflection). Gate readings more than about 3 to 4 standard deviations from the prediction; count them and let the next reading decide.

Analyze and Design

P9. Gains

High gains trust each measurement: fast to follow a turn but noisy. Low gains trust the model: smooth but slow to follow a turn, and they fall apart when readings are missing. Choose from a recording of your own target.

P10. Limit the Coast

Coasting error grows without limit (especially if the target changes direction); a confident wrong position is a hazard. After the limit, declare the track lost and publish that (or a coasting flag with the age before then).

P11. Re-acquire

Restart from the measurement (reset x, and v to zero or a fresh estimate) rather than blending; the old prediction has drifted and blending would pull the new estimate toward a stale guess.

P12. Commanded Is Not Done

If the command (or ack) is lost, the coordinator believes the LED is on when it is off and never retries. Better: wait for the actuator's reported state with a timeout and retry; treat the state as unknown until reported; publish a mismatch lasting longer than the round trip as an event.
