Every digital pin so far has only ever meant HIGH or LOW, two values, nothing in between. Most of the physical world doesn't work that way: temperature, light level, and the position of a dial all vary continuously. This lesson is about the circuit that bridges the two, the ADC (analog-to-digital converter), and the one unavoidable compromise it makes to do that job at all.

Part 1. What "Analog" Actually Means Here

An analog sensor doesn't output HIGH or LOW, it outputs a voltage somewhere in a continuous range, say anywhere from 0V to 3.3V, and that exact voltage encodes the reading. A photoresistor in bright light might put out 3.1V; in near-dark, 0.2V; in between, genuinely any value in between, not a fixed set of steps.

A plain digital input pin can't represent that. It's built to answer one question, "is this above or below roughly half of 3.3V," and collapse everything else into a single bit. An ADC exists specifically to answer a much more detailed question: "where, numerically, does this voltage fall?"

Part 2. The ADC's One Unavoidable Compromise: Quantization

An ADC can't report a truly continuous voltage as a number, computers don't have infinitely precise numbers to give it. Instead it rounds the real voltage to the nearest of a fixed set of discrete levels. That rounding is called quantization, and it happens on every single reading, not as a bug but as the fundamental nature of converting analog to digital at all.

The dashed curve is the true, continuously varying voltage. The solid stepped line is what an ADC actually reports: the nearest of a fixed ladder of levels. More levels (a "higher bit depth") makes the steps smaller and the approximation closer, but never eliminates them.

Part 3. Bit Depth: How Many Steps

The RP2040's ADC is a 12-bit converter internally, meaning it distinguishes 212 = 4,096 discrete levels across its input range. MicroPython's ADC class reports readings as 16-bit numbers instead (0–65,535) for consistency with other boards, scaling the real 12-bit result up to fill that range, so you'll see values in multiples of 16 in practice, not every integer from 0 to 65,535.

The path of an analog reading. The input voltage is frozen for an instant, compared against 4,096 possible levels, and the winning level is reported as a number.
shell MicroPython
from machine import ADC, Pin sensor = ADC(Pin(26)) # GP26 is ADC0, one of three usable ADC pins raw = sensor.read_u16() # 0 .. 65535 voltage = raw * 3.3 / 65535 # convert to volts print(raw, voltage)

The Pico exposes exactly three general-purpose ADC-capable pins, GP26, GP27, and GP28 (ADC0–ADC2), plus an internal ADC4 permanently wired to an onboard temperature sensor. Any analog sensor in your kit, the potentiometer, the photoresistor, has to land on one of those three pins; every other GPIO pin is digital-only.

Only three GPIO pins (GP26, GP27, GP28) feed the ADC, plus a fourth input wired internally to a temperature sensor. A multiplexer connects one of them at a time to the single converter.
One reading, three ways of writing it. The raw count is just a fraction of full scale, so converting to volts is a single multiplication.

Part 4. Quantization Error

The gap between the true voltage and the nearest level an ADC can report is called quantization error, and at 12 bits across a 3.3V range, each step represents about 0.8 millivolts, small enough to ignore for most sensor work in this course, but worth knowing exists: no ADC reading is ever exactly right, only close, by an amount bounded by how many bits it has to work with.

Warm Up

Exercise 1: Raw to Volts

voltage = raw × 3.3 / 65535. 16384 → 0.825 V (a quarter of the range), 49152 → 2.475 V (three quarters), 65535 → 3.3 V (full scale).

Exercise 2: Which Pins?

Only GP26 (ADC0) and GP27 (ADC1); GP28 is the third. GP14 and GP22 are digital-only. ADC4 is not a pin at all: it is wired inside the chip to a temperature sensor.

Intermediate

Exercise 3: Live Voltmeter
main.py MicroPython
from machine import ADC, Pin from time import sleep pot = ADC(Pin(26)) while True: volts = pot.read_u16() * 3.3 / 65535 print("{:.2f} V".format(volts)) sleep(0.5)

Turn the knob end to end: you should see roughly 0.00 V to 3.30 V.

Advanced

Exercise 4: Chip Thermometer
main.py MicroPython
from machine import ADC from time import sleep sensor = ADC(4) # ADC4 is the on-chip temperature sensor while True: volts = sensor.read_u16() * 3.3 / 65535 celsius = 27 - (volts - 0.706) / 0.001721 print("{:.1f} C".format(celsius)) sleep(1)

Expect a value a few degrees above room temperature, since it measures the chip itself, and expect it to wobble by a degree or so: that is quantization and noise, this week's whole subject.
