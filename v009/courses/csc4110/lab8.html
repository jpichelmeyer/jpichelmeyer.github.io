This lab gives your robot a learned sense. You turn a 50 Hz IMU stream into six features on the node, log them at the hub, record labelled sessions of four gestures, train a decision tree and a small neural network on the laptop, and send the network back to the robot as a file it checks before trusting. Then you measure what it costs, how well it works live (not just on the laptop), and what happens when the network goes away. Every role uses this pipeline in Lab Practical 2, with its own sensor and its own labels; this lab builds it once on the sensor every robot has.

What You Will Build

A robot that recognises how it is being handled (still, tapped, shaken or tilted) and a hub that remembers and teaches. In SAM terms, the model is the last stage of the Perceptor; a small Decider only accepts a gesture that wins two verdicts in a row; the Actuator shows it on the Lab 1 LEDs and publishes it. The node publishes its features at 2 Hz as well, because the hub needs them to train the next model.

The Lab 8 loop. Features go up to the hub at 2 Hz (plan B of the edge inference lesson, needed for training), labels go up only when the gesture changes (plan C, what the team uses), and a model comes down as a file. Between runs, the database is the only thing that links what happened to what you changed.

# main.py for Lab 8: a robot whose Perceptor has a learned stage import math, json from time import ticks_ms, ticks_diff from machine import I2C, Pin import resilient from mpu6050 import MPU6050 from profile import Cost from mlp import MLP # edge inference lesson N, HOP = 100, 25 # a 2 s window at 50 Hz; a new verdict every 0.5 s # ---------------- PERCEPTOR: IMU -> window -> features -> learned label ---------------- class GestureSense: def __init__(self, imu, model): self.imu, self.model = imu, model self.a, self.g = [1.0] * N, [0.0] * N # rings of |accel| (g) and |gyro| (deg/s) self.i = self.count = 0 def sample(self): """Read the IMU once. True when it is time for a new verdict.""" a, _, g = self.imu.read() self.a[self.i] = math.sqrt(a[0] * a[0] + a[1] * a[1] + a[2] * a[2]) self.g[self.i] = math.sqrt(g[0] * g[0] + g[1] * g[1] + g[2] * g[2]) self.i = (self.i + 1) % N self.count += 1 return self.count >= N and self.count % HOP == 0 def features(self): """The six features, in the SAME order and units as in training.""" a = self.a[self.i:] + self.a[:self.i] # oldest first (the jerk needs the order) g = self.g ma, mg = sum(a) / N, sum(g) / N sa = (sum((x - ma) ** 2 for x in a) / N) ** 0.5 sg = (sum((x - mg) ** 2 for x in g) / N) ** 0.5 jerk = max(abs(a[k + 1] - a[k]) for k in range(N - 1)) return [ma, sa, max(a) - min(a), jerk, mg, sg] def label(self, f): return self.model.predict(f)[0] if self.model else None # ---------------- MEMORY ---------------- class Memory: def __init__(self): self.candidate, self.stable, self.changes = None, None, 0 # ---------------- DECIDER: accept a label only when it repeats ---------------- def decide(label, m): """A gesture must win two verdicts in a row (0.5 s apart) before it counts.""" if label == m.candidate and label != m.stable: m.stable, m.changes = label, m.changes + 1 return label # a new gesture: report it m.candidate = label return None # ---------------- ACTUATOR: LEDs and the network ---------------- SHOW = {"still": (0, 0), "tilt": (0, 1), "tap": (1, 0), "shake": (1, 1)} red, green = Pin(8, Pin.OUT), Pin(9, Pin.OUT) def load_model(path="model.json"): """Load, then check before trusting (edge inference lesson, Part 6).""" try: d = json.load(open(path)) m = MLP(path) if len(d["mu"]) != 6 or m.predict(d["test"]["f"])[0] != d["test"]["label"]: return None, {"version": d.get("version", 0), "ok": False, "why": "self-test"} return m, {"version": d["version"], "ok": True} except (OSError, ValueError, KeyError) as e: return None, {"version": 0, "ok": False, "why": str(e)} i2c = I2C(0, sda=Pin(4), scl=Pin(5), freq=400000) imu = MPU6050(i2c) imu.calibrate() # hold still for a second at boot model, status = load_model() sense, mem = GestureSense(imu, model), Memory() h = resilient.ResilientHub(keepalive=30, wifi_timeout_s=5) h.presence() h.publish("stat/model", status, retain=True) c_read, c_feat, c_model = Cost(), Cost(), Cost() t_sample = t_cost = ticks_ms() while True: h.poll() now = ticks_ms() if ticks_diff(now, t_sample) >= 20: # 50 Hz t_sample = now if c_read.run(sense.sample): f = c_feat.run(sense.features) label = c_model.run(sense.label, f) h.publish("tele/feat", {"f": [round(x, 4) for x in f], "label": label}) # 2 Hz new = decide(label, mem) if new: red.value(SHOW.get(new, (1, 1))[0]); green.value(SHOW.get(new, (1, 1))[1]) h.publish("evt/gesture", {"label": new, "n": mem.changes}) if ticks_diff(now, t_cost) >= 10000: t_cost = now c_read.report("imu read", 20) c_feat.report("features", 500) # once per 0.5 s verdict c_model.report("model", 500)

Before any model exists, load_model fails, the robot publishes stat/model with ok: false, and the label is None. That is fine: the features still flow, and that is all the hub needs for Step 2. Two details deserve a second look. The features are computed exactly as in training: same order, same units, the population standard deviation, the jerk taken over the window in time order. Any difference here makes a model that works on the laptop and fails on the board. And the Decider's “two in a row” rule is the debounce of Lab 1 applied to a learned percept: a single wrong verdict never reaches the LEDs or the network.

The feature function and the Decider were checked on the laptop with a fake IMU: the six features match the ones used to build the training set to within rounding, a verdict is due exactly every 25 samples once the window is full, and the label stream still, still, tap, still, tap, tap, tap, shake, shake produces exactly three reported gestures (still, tap, shake).

Step 3. Train, Test Honestly, Export

Fill in your user name and the session times, then run python3 train.py lab.db 1. It trains a depth-3 tree and a 6-8-4 network on the training sessions, reports both on the test sessions with a confusion matrix, and writes the network to model.json with a version number and a self-test vector.

train.py Python
# train.py -- on the laptop: logged features -> three models -> honest test -> model.json import json, sqlite3, sys from sklearn.tree import DecisionTreeClassifier from sklearn.neural_network import MLPClassifier from sklearn.preprocessing import StandardScaler from sklearn.metrics import accuracy_score, confusion_matrix USER = "YOURNAME" LABELS = ["still", "tap", "shake", "tilt"] # From your notebook: (label, start, end) as Unix times (SELECT MIN(ts), MAX(ts) helps) TRAIN = [("still", 0, 0), ("tap", 0, 0), ("shake", 0, 0), ("tilt", 0, 0)] TEST = [("still", 0, 0), ("tap", 0, 0), ("shake", 0, 0), ("tilt", 0, 0)] def load(db, spans): X, y = [], [] rows = db.execute("SELECT ts, payload FROM msgs WHERE user = ? AND topic LIKE '%/tele/feat'", (USER,)).fetchall() for ts, payload in rows: for label, t0, t1 in spans: if t0 <= ts < t1: X.append(json.loads(payload)["f"]) y.append(label) return X, y db = sqlite3.connect(sys.argv[1]) Xtr, ytr = load(db, TRAIN) Xte, yte = load(db, TEST) print("windows: train", len(Xtr), "test", len(Xte)) scaler = StandardScaler().fit(Xtr) tree = DecisionTreeClassifier(max_depth=3, random_state=0).fit(Xtr, ytr) mlp = MLPClassifier(hidden_layer_sizes=(8,), max_iter=3000, random_state=0).fit(scaler.transform(Xtr), ytr) for name, pred in (("tree", tree.predict(Xte)), ("mlp", mlp.predict(scaler.transform(Xte)))): print(name, "test accuracy %.3f" % accuracy_score(yte, pred)) print(confusion_matrix(yte, pred, labels=LABELS)) # rows: truth, columns: predicted layers = [{"n_in": W.shape[0], "n_out": W.shape[1], "W": [round(float(v), 5) for v in W.T.ravel()], "b": [round(float(v), 5) for v in b]} for W, b in zip(mlp.coefs_, mlp.intercepts_)] k = next(i for i, lab in enumerate(yte) if mlp.predict(scaler.transform([Xte[i]]))[0] == lab) json.dump({"version": int(sys.argv[2]), "labels": [str(c) for c in mlp.classes_], "mu": list(scaler.mean_), "sd": list(scaler.scale_), "layers": layers, "test": {"f": Xte[k], "label": yte[k]}}, open("model.json", "w")) print("wrote model.json version", sys.argv[2])

To check the script end to end, it was run on a synthetic database of the same shape (240 training windows and 400 test windows generated from the gesture model of the edge inference lesson). The tree scored 97.5 % on the test windows and the network 99.0 %, and the model file it wrote passed the robot's self-test, while a copy with a deliberately wrong self-test label was refused. Your own numbers will be lower, because real hands are less tidy than a simulation; that is expected, and the report should say why.

How to read a confusion matrix: the network's result on the synthetic test set (100 windows per gesture). Accuracy is the diagonal divided by the total, 99 %, but the matrix says more: the errors are two light taps mistaken for stillness, one shake taken for a tilt and one tilt for stillness. On your data, find your biggest off-diagonal cell and explain it physically in the report.

Advanced

Exercise 3: How Long Before It Knows? A gesture starts at time 0. The window is 2 s long, a verdict is made every 0.5 s, and the Decider needs two agreeing verdicts. Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Count the Windows

About 120 windows (one every 0.5 s), though the first three end before the window is full of the new gesture: a 2 s window that ends 1 s into the session is half the previous activity. Neighbouring windows share 1.5 s of their 2 s of data (75 %), so two of them are much more alike than two random examples; 120 windows are worth far fewer independent samples than 120. That is one more reason the test set must come from different sessions.

Intermediate

Exercise 2: Too Good to Be True

Every test window overlaps its training neighbours by 75 % and comes from the same hands at the same minute, so the test is close to a test on the training data: 100 % measures memory, not learning. Live, with different handling, transitions and timing, the model meets data unlike anything it saw, and 55 % is the truthful number. The fix is a test set recorded separately, ideally by someone else, as in Step 2.

Advanced

Exercise 3: How Long Before It Knows?

A window is half new gesture once it ends 1 s after the start. Verdicts fall on a 0.5 s grid whose phase relative to the gesture is random, so the first right verdict comes between 1.0 and 1.5 s, and the second, which the Decider needs, 0.5 s later: the gesture is reported between 1.5 and 2.0 s after it starts. Halving the window to 1 s roughly halves that (0.5 + 0.5 to 1.0 s, so 1.0 to 1.5 s), at a cost: shorter windows hold less evidence, so the features are noisier, accuracy usually falls, and slow gestures (a tilt lasting more than a second) may no longer fit in one window. Verdicts every 0.25 s instead would shave 0.25 to 0.5 s at twice the processing cost. These are the trade-offs between processing, data and latency that the course outcome asks you to analyse.
