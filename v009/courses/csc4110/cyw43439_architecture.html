The WiFi lesson treated the radio as a black box that network.WLAN controls. This lesson opens the box far enough to explain behaviour you will otherwise find baffling: why four of your GPIO pins are missing, why the LED is addressed by name, what the status numbers mean, and why a connection can silently drop.

Part 1. A Second Computer on the Board

The CYW43439 is a complete, separate chip: a 2.4 GHz WiFi radio (802.11n) and a Bluetooth radio, with its own small processor and its own firmware. The RP2040 does not drive the radio signals directly. It sends commands and data over an internal serial link, much like talking to a modem.

The radio talks to the RP2040 over an internal link that uses four of the Pico's GPIO pins, which is why those pins are not available for your own projects.

The firmware the radio runs is stored inside the MicroPython firmware you flashed in the first lesson, and is loaded into the radio each time the WiFi is switched on. That is part of why enabling WiFi takes a moment and uses a chunk of the Pico's memory.

Part 2. Shared Pins and the Onboard LED

The link between the two chips uses GP23, GP24, GP25 and GP29, which is why those are unavailable on a Pico W/WH (and why GP29 also doubles as a supply-voltage monitor input). The onboard LED is connected to one of the radio chip's own spare outputs, not to a GPIO pin of the RP2040:

shell MicroPython
from machine import Pin led = Pin("LED", Pin.OUT) # the name "LED" tells MicroPython to go via the radio chip led.toggle()

This has a subtle consequence: switching the LED means sending a message to the radio chip, so it is slightly slower than a normal pin, and it only works once the radio driver is running.

Part 3. Reading the Connection Status

wlan.isconnected() only tells you yes or no. wlan.status() gives a code that says how far the connection got and, if it failed, why:

The status codes returned by wlan.status(). Positive numbers are progress, negative numbers are specific failures, so polling the number tells you not just whether it failed but why.
main.py MicroPython
import network from time import sleep NAMES = {0: "idle", 1: "connecting", 2: "link up, no IP yet", 3: "got IP", -1: "connect failed", -2: "no access point found", -3: "wrong password"} wlan = network.WLAN(network.STA_IF) wlan.active(True) wlan.connect(SSID, PASSWORD) last = None while True: s = wlan.status() if s != last: print(s, NAMES.get(s, "unknown")) last = s if s == 3 or s < 0: break sleep(0.25)

A wrong password (−3) will never fix itself, so retrying forever is pointless; −2 can be temporary (out of range, router restarting), so a retry is reasonable.

Part 4. Signal Strength

wlan.scan() reports each network's RSSI, the received signal strength in dBm. It is a negative number, and a value nearer zero is stronger. The Pico's tiny printed antenna is weaker than a laptop's, so a spot where your laptop is happy may be marginal for the Pico.

Rough guide to RSSI. WiFi range is not a fixed distance: walls, other networks and the Pico's small antenna all move these boundaries.

Part 5. Connections Drop

Routers restart, people walk between the antennas, and channels get crowded. MicroPython does not promise to rejoin automatically in every situation, so a program meant to run unattended should check and repair the connection itself:

wifi.py MicroPython
def ensure_wifi(): if wlan.isconnected(): return True wlan.disconnect() wlan.connect(SSID, PASSWORD) for _ in range(40): # wait up to ~10 s if wlan.isconnected(): return True sleep(0.25) return False

Call it from the main loop (every few seconds is plenty), and treat a False as "carry on, try again later" rather than as a fatal error.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Spoken-For Pins

GP23, GP24, GP25 and GP29 are used by the CYW43439 link (power-on, data, chip select, clock). A design needing GP25 must use another pin; the headers do not even expose all of these.

Exercise 2: Read the Status

First run: connecting, connecting, connecting, link up but no IP yet, then got an IP: success. Second run: connecting, then −3: the password was rejected; retrying with the same password will never work.

Intermediate

Exercise 3: Identify Your Radio
main.py MicroPython
import network, binascii wlan = network.WLAN(network.STA_IF) wlan.active(True) mac = wlan.config("mac") # 6 raw bytes print("MAC:", binascii.hexlify(mac, ":").decode()) # ... connect as in the previous lesson, then: print("IP :", wlan.ifconfig()[0])

The MAC address is burned into the radio and is how a router recognises a particular device (and how it keeps assigning the same IP).

Advanced

Exercise 4: Power Versus Latency

(a) Power-saving suits the battery node: it only needs the radio awake briefly each minute, and a little added latency is irrelevant. (b) The mains node should keep the radio fully awake, since sleeping adds delay before it can hear a command. Look up the power-management option of wlan.config() in the docs for your firmware version to see how to choose.
