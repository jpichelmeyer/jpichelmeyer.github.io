Everything in this course runs on a Raspberry Pi Pico W. This lesson gets one working: what is on the board, how MicroPython is installed, how Thonny talks to it, and what the difference is between running a program and saving it on the board. Do the setup steps on your own board as you read.

SAM lens. This lesson sets up the body that will hold the Decider and Memory: the RP2040 runs your program (the Decider), its RAM holds what changes while it runs (Memory that is lost at power-off), and flash keeps the program and anything you choose to remember across restarts.

Part 1. What Is on the Board

The Pico W is a microcontroller board: one chip that holds a processor, memory, and a set of built-in hardware blocks for talking to the outside world, all on a board a few centimetres long. Unlike a laptop it has no operating system to speak of; it starts running your program the moment power arrives. Its chip is the RP2040, and a second small chip, the CYW43439, supplies WiFi.

What is on the Pico W. The RP2040 chip holds the processor, the RAM and the hardware blocks that talk to the world. Program storage (flash), the WiFi chip and the USB connector sit beside it on the board.

Your program lives in flash and runs from there; the RAM only holds what changes while it runs, and it is wiped each time power is lost. Three of those hardware blocks (the ADC, PWM and I2C) are the subject of the next four weeks. Each is a small circuit inside the chip that does one job for you, so your code only has to say what you want.

Part 2. Putting MicroPython on the Board

MicroPython is a version of Python small enough to run on a microcontroller. The board arrives without it, so the first job is to install it once. After that you simply write programs.

Installing MicroPython. This is done once per board. The special BOOTSEL mode makes the board look like a USB drive so you can copy the firmware file onto it.

Make sure you download the file for the Pico W (WiFi) and not the plain Pico: the two are different. If a board ever stops responding properly, repeating these steps wipes it back to a clean start.

Part 3. Thonny

Thonny is the free editor we use. Install it on your laptop, plug in the Pico (without holding BOOTSEL this time), and choose MicroPython (Raspberry Pi Pico) as the interpreter in the bottom-right corner or in Tools, Options, Interpreter. If it cannot find the board, pick the right serial port in the same dialog.

The Thonny window. Write code in the editor, run it on the Pico with the green button, and watch the shell at the bottom. Turn on View, Files to see both this computer and the Pico’s own storage.

The shell at the bottom is the REPL (read, evaluate, print, loop). Anything you type runs on the Pico immediately, which makes it the best tool for trying out a pin or a sensor before you write a program around it. Press the Stop button (or Ctrl+C) to interrupt a program that is running.

REPL session MicroPython
>>> from machine import Pin >>> led = Pin("LED", Pin.OUT) >>> led.on() # the on-board LED lights >>> led.off() >>> import os, gc >>> os.listdir() # files stored on the Pico >>> gc.mem_free() # bytes of RAM currently free >>> import machine >>> machine.freq() # processor speed in Hz 125000000

Part 4. Run Versus Save: main.py

Pressing Run executes the file in the editor on the Pico, but it does not store it there. When you unplug the board, the program is gone. To make a program start every time the board gets power, you save it on the Pico itself with the exact name main.py (File, Save as, choose the Raspberry Pi Pico).

What the board does at power-up. It runs boot.py then main.py if they exist. A program that never finishes keeps the board busy, which is correct for a robot but surprising the first time you want to reprogram it.
main.py MicroPython
from machine import Pin from time import sleep_ms led = Pin("LED", Pin.OUT) while True: # blink forever: the board's first heartbeat led.toggle() sleep_ms(500)

If you saved something that locks the board up, you are not stuck: press Stop in Thonny a few times until the REPL returns, then delete or fix main.py in the Files panel. Because a main.py starts on its own, keep it for finished programs, and run work-in-progress code with the Run button.

Part 5. Libraries and the Network Client

A library is code someone else has written that you import. MicroPython includes the standard pieces (time, machine, os), and most Pico W firmware builds include the MQTT client you will use in Unit 2. Check yours now so that you find out early:

REPL check MicroPython
>>> import umqtt.simple # no error means it is already installed

If you see ImportError, install it once with Thonny’s Tools, Manage packages (search for micropython-umqtt.simple), or from the board with import mip; mip.install("umqtt.simple"), which needs the board to be on WiFi (the Network On-ramp lesson shows how). Installed libraries are stored as files in a lib folder on the Pico.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Run or Save?

Run executes the code but never stores it, so the board only has the empty flash. Save the file on the Pico (not on the computer) with the name main.py; the board then runs it at each power-up.

Exercise 2: Read the Boot Order

boot.py runs first, then main.py. A file named blink.py never starts by itself: only the two special names are run automatically, so blink.py is only run when you press Run or import blink from another program.

Intermediate

Exercise 3: Board Report
info.py MicroPython
import machine, gc from binascii import hexlify print("clock MHz:", machine.freq() // 1_000_000) print("free RAM kB:", gc.mem_free() // 1024) print("board id:", hexlify(machine.unique_id()).decode())

The values depend on your board: expect 125 MHz, a free-RAM figure of a few tens of kilobytes less than the 264 kB total, and a 16-character id. The unique id is useful later: it gives every board a distinct name for network messages.

Advanced

Exercise 4: A Blink You Can Interrupt
blink_nb.py MicroPython
from machine import Pin from time import ticks_ms, ticks_diff led = Pin("LED", Pin.OUT) last = ticks_ms() while True: now = ticks_ms() if ticks_diff(now, last) >= 500: # 500 ms have passed led.toggle() last = now # ...other work can go here, and runs thousands of times per blink...

ticks_ms counts milliseconds but wraps around to zero after a long time, so a plain subtraction gives a wrong (possibly negative) answer at the wrap. ticks_diff handles the wrap correctly. This non-blocking style appears again in the Pulses and Interrupts lesson.

Paper Practice: Answers

Recall

P1. Two Chips

The RP2040 is the microcontroller: processor, RAM and hardware blocks (ADC, PWM, I2C, SPI). The CYW43439 is the separate WiFi chip.

P2. What Survives

Only the file in flash survives; RAM is wiped when power is lost. Your saved program (for example main.py) lives in flash.

P3. The REPL

Read, evaluate, print, loop. It is good for trying a pin or sensor interactively before writing a program, for listing files (os.listdir()), and for checking free memory (gc.mem_free()). Any two.

P4. Boot Order

boot.py first, then main.py, if they exist.

Apply

P5. Clock Period

1 / 125 000 000 s = 8 ns.

P6. Run Versus Save

Run executes the editor's file without storing it on the board; nothing was saved to start at power-up. Save the program on the Pico with the exact name main.py (File, Save as, Raspberry Pi Pico).

P7. Firmware Choice

Only the Pico W build contains the driver for the WiFi chip (and the on-board LED, which is wired through it). With the plain Pico firmware the network module would be missing and Pin("LED") would not work.

P8. Case Matters

The board looks for exactly main.py; the file system distinguishes upper and lower case, so Main.py is just an ordinary file.

Analyze and Design

P9. Locked Board

Press Stop (or Ctrl+C) repeatedly until the REPL prompt returns, then rename, fix or delete main.py in the Files panel. If that fails, reinstalling MicroPython through BOOTSEL wipes the board back to a clean start.

P10. Missing Library

Thonny's Tools, Manage packages (search for micropython-umqtt.simple); or import mip; mip.install("umqtt.simple") on the board, which needs the board to be on WiFi. Either way the library lands in the lib folder.

P11. Safe Mode
listing MicroPython
from machine import Pin import sys if Pin(6, Pin.IN, Pin.PULL_UP).value() == 0: # held at boot print('safe mode: robot not started') sys.exit() # back to the REPL # ... the robot program follows ...

Any version that checks the button before the robot starts and then stops cleanly is correct.

P12. Development Habit

A main.py starts by itself at every power-up; buggy code there can lock the board or drive outputs unexpectedly every time it is plugged in, and makes reprogramming awkward. Running from the editor leaves the board clean when it is unplugged.
