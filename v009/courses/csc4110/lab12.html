This capstone lab joins the course into one system. Two scan heads follow a target and take turns to ping on a leased schedule, a fuser crosses their bearings into a position with a quality, and you validate the result with a test plan that includes faults. You measure what the geometry, the schedule and the faults do to the answer, and report the system as it is, with the evidence. In the last step you plug the fuser into the world model and the mission coordinator and run the whole Find, Identify, Mark mission for the first time, with stand-ins for any teammate who is not ready: the dress rehearsal for Lab Practical 3.

What You Will Build

Two ultrasonic scan heads, each on a servo, 60 cm apart. Each one finds a cardboard tube in front of it and follows it as it is moved. Neither head knows where the tube is, only the direction it lies in. A third node takes the two directions, crosses them, and publishes a position. That is triangulation, and it is a small version of what a multi-robot system does whenever several cheap, partial views are combined into one useful fact.

This is the capstone because nothing in it is new. The scan head is the tracker of Week 12 (Stop, Track and Search behaviours under an arbiter) with an alpha-beta filter on its bearing (Week 13). The two heads share the air by taking turns to ping, on a schedule that the third node keeps in step by message, and that schedule is a lease: it is trusted for a limited time and then given up. The third node fuses the bearings with the geometry of Week 12 and keeps beliefs with ages (Week 13). The heads, the fuser and the contract between them are the agents and messages of Week 11. What is new is that you must show, with a test plan (Week 14), that the whole thing works, and say honestly where it does not.

The Lab 12 system. Bearings go up to the fuser; the fuser sends a time reference down (evt/sync) and publishes the position. Each head reads the others’ messages only through the broker.

The Layout

Stand the heads on a straight edge 60 cm apart, each with its servo arm pointing perpendicular to the edge when the pan angle is 0, and its sensor at the same height. Call head A the origin and put x along the edge toward B and y straight out from it. Measure these with a ruler, because every error in them is an error in the answer.

Top view. Each head measures only the direction of the target (blue rays). The fuser intersects them. The angle between the rays, the spread, decides how much a small bearing error is magnified: 62° here, which is a good crossing; 20° would be a poor one.

Step 1. One Head Alone

Load the files of the earlier weeks: agent.py, behaviors.py, tracker.py (add from behaviors import Behavior as its first line, which the lesson showed without), alphabeta.py, slots.py, servo.py and your Ranger from the pulse lesson, plus hub.py and net.py. Then add the new file below. The head is an agent with one rule for each situation: if a range has come back, update the tracker, move the servo, publish the bearing; otherwise, if the servo has had time to settle and it is this head’s turn, send a ping.

head.py MicroPython
# head.py -- one scan head: finds the target, follows it, takes its turn to ping, publishes a bearing import random from time import ticks_ms, ticks_diff, ticks_add import hub from agent import Agent from behaviors import Arbiter from tracker import Stop, Track, Search from alphabeta import AlphaBeta from slots import Slots SETTLE_MS = 80 # time for the servo to arrive before we ping LEASE_MS = 30000 # the slot schedule is trusted for this long after the last sync FRAME_MS = 200 # two slots of 100 ms; this head owns slot `me` class Head(Agent): def __init__(self, h, ranger, servo, me, fuser): super().__init__("head", h, period_ms=10) self.r, self.servo = ranger, servo self.slots = Slots(me, 2, slot_ms=100, guard_ms=30) self.t_sync = None # when the leader last told us the time self.track = Track() self.arb = Arbiter([Stop(), self.track, Search()]) self.s = {"pan": 0.0, "range": None, "halt": False, "found": None, "aimed": False} self.filt = AlphaBeta(0.3, 0.05) # smooths the bearing and estimates its speed self.t_step = self.settle_until = self.next_free = ticks_ms() h.on("lab/%s/evt/sync" % fuser, self.on_sync) def on_sync(self, topic, payload): d = hub.decode(payload) if d and isinstance(d.get("pos"), int) and 0 <= d["pos"] < FRAME_MS: self.slots.sync(ticks_add(ticks_ms(), -(d["pos"] + 15))) # frame began pos ms ago, plus ~15 ms in the network self.t_sync = ticks_ms() def scheduled(self, now): return self.t_sync is not None and ticks_diff(now, self.t_sync) < LEASE_MS def may_ping(self, now): if self.scheduled(now): return self.slots.may_ping(now) # our slot, away from its edges return ticks_diff(now, self.next_free) >= 0 # no schedule: slow down, at random times def step(self): now = ticks_ms() if self.r.busy: if not self.r.update(): return # still listening for the echo self.s["range"] = self.r.cm # the range at the pan we are holding dt = ticks_diff(now, self.t_step) / 1000.0 self.t_step = now self.s["pan"] = self.arb.step(self.s) self.servo.angle(self.s["pan"]) self.settle_until = ticks_add(now, SETTLE_MS) locked = self.arb.winner == "track" if locked: est = self.filt.update(self.track.c, dt) else: self.filt.x, self.filt.v = None, 0.0 # a lost target: forget its speed too est = None self.hub.publish("tele/bearing", {"deg": est, "lock": locked, "pan": self.s["pan"], "cm": self.s["range"], "sched": self.scheduled(now)}) elif ticks_diff(now, self.settle_until) >= 0 and self.may_ping(now): self.r.start() self.next_free = ticks_add(now, 400 + random.randint(0, 400))

Read it for the decisions. A head does not wait for an echo: it starts a ping and comes back later, so the loop keeps running (the non-blocking Ranger of Week 3). The result is used for one decision, then the servo moves, then the head waits SETTLE_MS before pinging again, because a ping taken while the servo is still moving measures the wrong direction. The published deg is the filtered bearing, not the dithered pan angle, and a head that has lost the target publishes lock: false and forgets its speed estimate (otherwise it would coast away on old information when it finds something new).

Start only head A, with no fuser. It has no schedule, so it falls back to pinging at random intervals, about once or twice a second. Put the tube about 50 cm in front of it and watch lab/<you>/tele/bearing with mosquitto_sub. It should find the tube (lock: true) within one or two sweeps. Check three bearings against a protractor, and record the bias: the average of (published minus true). Fix a consistent offset by adjusting the servo trim, not by editing the filter.

Step 2. The Fuser

fuser.py MicroPython
# fuser.py -- two bearings in, one position out, with an honest account of how good it is from time import ticks_ms, ticks_diff from math import atan2, degrees import hub from agent import Agent from belief import Belief from geometry import intersect HEADS = {"amy": (0.0, 0.0, 90.0), "jsmith": (60.0, 0.0, 90.0)} # who, x cm, y cm, direction of pan 0 (measure yours!) JUMP_CM = 25.0 # a fix that jumps further than this is doubted FRAME_MS = 200 class Fuser(Agent): def __init__(self, h, heads=HEADS): super().__init__("fuser", h, period_ms=200) self.heads = heads self.b = {u: Belief(stale_ms=800) for u in heads} # the newest bearing from each head self.fix = None # last accepted (x, y) and its time self.rejected = self.in_a_row = 0 self.state = "?" self.frame0 = ticks_ms() self.t_sync = ticks_ms() for u in heads: h.on("lab/%s/tele/bearing" % u, self.on_bearing) def on_bearing(self, topic, payload): u = topic.split("/")[1] d = hub.decode(payload) if u in self.b and d and isinstance(d.get("lock"), bool) and (d.get("deg") is None or isinstance(d["deg"], (int, float))): self.b[u].update(d) def sense(self): out = [] for u, (x, y, hd) in self.heads.items(): m, age, fresh = self.b[u].get() if m and fresh and m["lock"] and m["deg"] is not None: out.append(((x, y), hd + m["deg"], age)) # a point and a world direction return out def decide(self, rays): if len(rays) < 2: return ("one" if rays else "lost"), None (p1, a1, _), (p2, a2, _) = rays xy = intersect(p1, a1, p2, a2) if xy is None: return "poor", None # nearly parallel: no answer worth having spread = abs((a1 - a2 + 180) % 360 - 180) # angle between the rays if self.fix is not None and ticks_diff(ticks_ms(), self.fix[2]) < 1500: jump = ((xy[0] - self.fix[0]) ** 2 + (xy[1] - self.fix[1]) ** 2) ** 0.5 if jump > JUMP_CM and self.in_a_row < 2: # doubt it twice, then believe it self.rejected += 1 self.in_a_row += 1 return "doubt", None self.in_a_row = 0 self.fix = (xy[0], xy[1], ticks_ms()) return ("tracking" if spread >= 30 else "poor"), (xy[0], xy[1], spread) def act(self, decision): pass def tell(self, rays, decision): state, fix = decision now = ticks_ms() if fix: self.hub.publish("tele/target", {"x": round(fix[0], 1), "y": round(fix[1], 1), "spread": round(fix[2])}) if state != self.state: self.state = state self.hub.publish("stat/fuser", {"state": state, "rejected": self.rejected}, retain=True) if ticks_diff(now, self.t_sync) >= 1000: # the leader's job: keep the heads in step self.t_sync = now self.hub.publish("evt/sync", {"pos": ticks_diff(now, self.frame0) % FRAME_MS})

The fuser is deliberately cautious. It publishes a position only when two heads, each with a fresh bearing (less than 0.8 s old), report a lock. If only one does, it says one; if none, lost. If the rays are nearly parallel (intersect returns None) it says poor and publishes nothing. If the new position is more than 25 cm from the last in under 1.5 s, it doubts it and waits: it rejects two such fixes in a row and believes the third, because by then the target has probably really moved (or one head locked onto something else, and the doubt has done its job). The spread is published with every position so that a reader can judge it: one of the rules of this course is that a number without an indication of its quality is only half a message.

Notice the other job of the fuser: every second it publishes evt/sync with its position in a 200 ms frame. That is the time reference the heads use to take turns, and it is the one place where the leader is a single point of failure. The next step shows what the heads do without it.

Step 3. Taking Turns

Ultrasonic sensors in the same room hear each other. A ping from head B arriving while head A is listening gives A a false, short echo, and A’s tracker will happily follow it. The cure is the one from the collision lesson: two slots in a 200 ms frame, 100 ms each, with 30 ms of guard at each end of a slot; head A pings only in the middle of slot 0 and head B in slot 1. The heads have no shared clock, so each aligns its frame to the fuser’s evt/sync, adding a typical 15 ms for the time the message spent in the network.

That schedule is a lease. It is trusted for LEASE_MS (30 s) after the last sync, because two crystals drift apart by a few parts in 100,000 and the guard can absorb that for a while, but not for ever. After 30 s without a sync a head stops trusting its schedule, says so (sched: false in its bearing) and pings less often, at random times, which reduces collisions without needing agreement. Both choices have a price, which the simulation below measures.

The system was simulated (a fake broker, a fake clock, a target moving in a 10 cm circle at 4 cm/s centred on (30, 50), the heads and the fuser as given, a link delay of 5 to 40 ms; a reading counts as corrupted if the other head started a ping within 30 ms before it or during its 6 ms wait for the echo). Step 4. How Accurate?

Mark five points on the table with a ruler, hold the tube still for 20 s at each, and record the fuser’s mean position and the spread. A rough prediction of the error you should expect is:

error estimate Text
error ≈ sqrt(r1² + r2²) × σ / sin(spread) r1, r2 distances from the two heads to the target (cm) σ the typical error of one head's bearing, in radians (measure it in Step 1) spread the angle between the two rays

In the simulation each head’s published bearing had an RMS error of 2.7° (0.047 rad). At the centre point (30, 50) both distances are 58.3 cm and the spread is 62°, so the prediction is 82.5 × 0.047 / 0.88 = 4.4 cm, and the simulated RMS position error was 4.2 cm. The formula says what the geometry does: the error grows in proportion to the distance, and it grows steeply as the rays become parallel. With a still target and the same code the simulated errors were:

Position error of a still target (simulated, 45 s after the first 20 s). It is a steady offset, not noise: the tracker settles with its 3° steps on one side or the other of the true direction. The farthest point has the largest error, as the formula says. Your table should have the same columns, with your own numbers.

Two cautions. The errors of a still target are mostly a bias (the tracker stopped on one side of the target) and so they are not reduced by averaging; the errors of a moving target are mostly lag, and grow with speed. In the simulation the RMS error of the fused position was 4.2, 5.6, 8.0, 10.3 and 12.5 cm for a target moving at 4, 6, 8, 10 and 12 cm/s. And the heads can only see what is within 100 cm (SEE_CM) and within ±60° of straight ahead: a target outside that region is not an error of the system but of the test.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Why Send a Position in the Frame?

The Picos have different clocks: ticks_ms() counts from each board’s own power-on, so a value from another board means nothing. What is shared is the phase of a repeating frame, which the receiver can use to place its own frame start: it began pos ms before the message was sent, and the message took some time to arrive, so the head adds an estimate of that delay. 15 ms is a typical one-way time here (with delays between 5 and 40 ms, the error of the estimate is at most about 25 ms, which the 30 ms guard is sized to survive). A better design would send several syncs and trust the one that arrived first, since it is the one with the least delay.

Exercise 2: Why Does the Spread Matter?

The label is a threshold on one quantity (30°); the number lets the reader apply its own threshold, and discount the position in proportion. From the formula the error grows as 1/sin(spread): 62° gives a factor 1.13, 40° gives 1.56 and 30° gives 2.0, so the position at 31° is about twice as uncertain as at 62° while both are labelled tracking. A consumer such as a planner or a display can weight, smooth, or refuse, depending on need. Publishing the evidence together with the conclusion is a general habit.

Intermediate

Exercise 3: The Cost of Taking Turns

5 pings a second give 2.5 corrections a second, so at most 2.5 × 3° = 7.5°/s; at 60 cm that is 60 × 7.5 × π/180 = 7.9 cm/s. With a 6° step the limit doubles to 15°/s (about 16 cm/s), at the price of coarser steering (the estimate wanders in steps of 6° around the target). In the simulation the error grew with speed rather than failing outright: RMS 8.0 cm at 8 cm/s and 12.5 cm at 12 cm/s, with the heads still locked, because the tracker lags behind the target rather than losing it. The limit is a lag limit; the pass rule decides how much lag is tolerable.

Exercise 4: Which Failure Is Worse?

Expected states: tracking, then one when B’s last bearing is older than 0.8 s, then (once B returns and, if it must, searches again) tracking. Publishing the last position would be wrong for a moving target: the position goes stale and grows more wrong each second while looking confident. Publishing nothing says “I do not know”, which a consumer can act on (stop, search, use its own belief with an age). Where a consumer needs something, publish a position with a flag, and the age, and let it decide; never let a stale value look fresh. This is the same rule as for Belief and for the alpha-beta coast limit.

Advanced

Exercise 5: An Error Estimate to Publish
sigma.py MicroPython
from math import sqrt, sin, radians def sigma_cm(r1, r2, spread_deg, sigma_deg=2.7): """Expected position error in cm, given the two ranges, the spread and one head's bearing error.""" s = sin(radians(spread_deg)) if s < 0.05: # rays nearly parallel: no meaningful answer return None return sqrt(r1 * r1 + r2 * r2) * radians(sigma_deg) / s

For the centre point, sigma_cm(58.3, 58.3, 62) gives 4.4 cm. In Fuser.decide, after the intersection, compute r1 and r2 as the distances from each head to the fix and add "sigma": round(sigma_cm(...), 1) to tele/target; then replace the fixed 30° threshold for tracking with “sigma below your requirement”. That turns a rule about an angle into a rule about what you actually care about, the size of the error, and it also catches the case of a far target with a good spread.
