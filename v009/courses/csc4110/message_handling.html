A message arriving at a Pico is somebody else’s data landing in your program. It may be malformed, unexpected, repeated, or arrive at a bad moment. Handling messages well is mostly a matter of discipline: do very little in the callback, check everything, and never let one bad message stop the device.

Part 1. What a Callback Really Is

You register a function with client.set_callback(). It is called from inside check_msg() whenever a message has arrived, with the topic and payload as bytes. That has two consequences. The callback runs in the middle of your main loop, so anything slow in it delays everything else; and what it receives is raw, so decoding and checking are your job.

Handling an incoming message in five small steps. Most of the steps are checks; the actual action is the shortest part, and every check that fails ends the handling safely.

Part 2. Dispatch Instead of a Chain of ifs

A callback that grows an if/elif branch for every command becomes hard to read and easy to get wrong. A dispatch table maps the command name, the last level of the topic, to the function that handles it:

A dispatch table. The last part of the topic picks the handler, so adding a new command is one new entry rather than another branch in a growing if/elif chain.
main.py MicroPython
def set_led(msg): if msg not in (b"on", b"off"): return led.value(1 if msg == b"on" else 0) def set_interval(msg): global interval_ms v = int(msg) # may raise ValueError if 10 <= v <= 60000: interval_ms = v HANDLERS = {"led": set_led, "interval": set_interval} def on_message(topic, msg): parts = topic.decode().split("/") if len(parts) != 4 or parts[2] != "cmd": return # not for us handler = HANDLERS.get(parts[3]) if handler is None: print("unknown command:", parts[3]) return try: handler(msg) except Exception as e: # one bad message must not stop the device print("handler failed:", parts[3], e)

Adding a command is now one function and one dictionary entry. The try/except around the handler matters: a payload of b"banana" raises ValueError in int(), and without it that exception would escape through check_msg() and end the program.

Part 3. Validate Everything

Every incoming message is untrusted input. Check what it is, whether it makes sense, and whether it is safe, before it touches an output.

Treat every message as hostile or mistaken, even from your own dashboard. Check the topic is one you know, the payload decodes, the value is in a sensible range, and the request is allowed right now. Reject and log; never "do your best" with garbage.

Part 4. Keep the Callback Tiny

If handling a message is slow (writing a file, a long calculation, publishing a reply), do not do it inside the callback. Put the message in a small queue and let the main loop deal with it when it is ready, so the network connection is never left waiting:

Keep the callback tiny. It only drops the message into a short queue; the main loop does the real work when it is ready, so a slow handler can never stall the network connection.
main.py MicroPython
inbox = [] def on_message(topic, msg): if len(inbox) >= 8: inbox.pop(0) # full: drop the oldest rather than run out of RAM inbox.append((topic, msg)) while True: client.check_msg() # callbacks only enqueue: they return instantly while inbox: topic, msg = inbox.pop(0) handle(topic, msg) # the real work, outside the callback ...

Two more habits. A retained message is delivered when you subscribe, possibly long after it was published, so decide whether it is still worth acting on. And rate-limit anything with side effects: a buggy dashboard sending commands every millisecond should not be able to chatter a relay.

Warm Up

Exercise 1: What Goes Wrong?

b"banana" raises ValueError, which escapes through check_msg() and can end the program. b"0" or b"-5" converts fine but sets a nonsensical interval, so the loop could spin or never publish. Both need handling: catch the exception and check the range.

Exercise 2: Add a Command
main.py MicroPython
def do_blink(msg): for _ in range(3): led.toggle(); sleep_ms(100) led.toggle(); sleep_ms(100) HANDLERS["blink"] = do_blink

Only a function and one dictionary entry; on_message is untouched. (Blocking for 600 ms in the handler is acceptable for a demo; a production device would schedule it instead.)

Intermediate

Exercise 3: Validate a Setpoint
main.py MicroPython
def parse_setpoint(msg): try: v = float(msg) except ValueError: return None return v if 5.0 <= v <= 35.0 else None print(parse_setpoint(b"21.5")) # 21.5 print(parse_setpoint(b"hot")) # None print(parse_setpoint(b"99")) # None

Returning None gives the caller one simple test, if v is None: return, instead of exceptions leaking everywhere.

A rejected command is simply dropped. Whether to drop or queue depends on the device: for a relay, dropping is the safer choice, because a queue of old commands could fire in a burst later.
