Most of the interesting sensors in a robot are not analog at all. A motion sensor, a touch pad and a character display all talk to the Pico over a shared two-wire bus called I2C. This lesson shows how the bus works, how to find a device on it, and how to use the three I2C devices in your kit: the MPU6050 motion sensor, the LCD1602 display and the MPR121 touch sensor.

SAM lens. I²C widens the Perceptor (the IMU) and gives the Actuator a voice a human can read (the LCD). Each device contains its own small converter, so the Pico receives numbers that still need scaling and calibration before they are percepts.

Part 1. Two Wires, Many Devices

Analog pins are scarce (three on the Pico) and many useful sensors, such as a motion sensor, already contain their own converter and send you finished numbers. I2C (pronounced "I squared C") is a two-wire bus made for exactly this. One wire, SDA, carries data; the other, SCL, carries a clock. Any number of devices share the same two wires, and each has its own address, so the Pico can talk to them one at a time.

An I2C bus. The Pico (the controller) drives the clock on SCL and shares SDA with whoever it is talking to. Two pull-up resistors hold both wires high; devices only ever pull them low. Each device answers to one address, shown here in hexadecimal.

The Pico has two I2C blocks. We use bus 0 on GP4 (SDA) and GP5 (SCL). The clock runs at 100 kHz (standard) or 400 kHz (fast); the modules in the kit accept 400 kHz. The wires are open-drain: a device can pull a line down, but only the pull-up resistors can raise it. Most breakout modules include them (4.7 kΩ is common), which is why you rarely add your own.

One practical consequence: every module adds its own pull-up in parallel with the others. Three 4.7 kΩ resistors in parallel make 1.57 kΩ. That is fine, because the bus specification wants roughly 1 kΩ or more (a device is only required to sink 3 mA, and (3.3 V − 0.4 V) / 3 mA ≈ 970 Ω). A bus with a dozen modules can end up too strongly pulled up and stop working; the cure is to remove or de-solder a few pull-ups.

You will also see a second sensor bus, SPI, on datasheets and pin maps. It uses four wires instead of two (a clock, a data line each way, and a chip-select line per device) and runs much faster, which suits SD cards and colour screens. None of the parts in this course needs it, so we stay with I2C.

Part 2. Find What Is There: the Scan

Wire a device to GP4 and GP5 (plus power and ground), and run a scan. The scan asks every possible address whether anyone answers:

scan.py MicroPython
from machine import I2C, Pin i2c = I2C(0, sda=Pin(4), scl=Pin(5), freq=400_000) # I2C bus 0 on GP4 (SDA) and GP5 (SCL) print([hex(a) for a in i2c.scan()]) # e.g. ['0x27', '0x5a', '0x68']
The usual addresses. The scan is the first test for every I2C device you wire: an empty list means a wiring problem (swapped SDA and SCL, no power or ground, a loose jumper), not a software problem.

An empty scan is the most common beginner problem and has three usual causes: SDA and SCL swapped, a missing ground or power connection, or the wrong pins in the I2C(...) call. Check those before suspecting the module.

Part 3. What Travels on the Wires

One complete register read of 14 bytes from the MPU6050. Every byte is acknowledged, and the last one is refused (NACK) to say "no more", then the Pico releases the bus with a STOP. MicroPython does all of this inside one call, but knowing the shape helps when a device behaves oddly.

MicroPython wraps this pattern into three calls you will use again and again:

  • i2c.readfrom_mem(addr, reg, n): read n bytes starting at register reg.
  • i2c.writeto_mem(addr, reg, data): write bytes to a register.
  • i2c.writeto(addr, data): send bytes with no register address at all (the LCD backpack works this way).

Each transaction takes real time. A byte is 9 clock cycles (8 data bits and an acknowledge), so at 400 kHz one byte takes 22.5 µs. Reading 14 bytes with the three extra bytes of overhead (address, register, address) takes 9 × 17 = 153 clocks, which is 0.38 ms at 400 kHz and 1.53 ms at 100 kHz. That matters when your whole sample period is 10 ms.

Part 4. The MPU6050 Motion Sensor

The MPU6050 is an inertial measurement unit (IMU): a 3-axis accelerometer (which senses the direction and size of acceleration, including gravity), a 3-axis gyroscope (which senses rotation rate), and a temperature sensor, on one chip. It is the heart of any self-balancing or orientation-aware robot, and it will return in the Unit 3 weeks.

The MPU6050 data block. One 14-byte read returns acceleration, temperature and rotation rate together, taken at the same moment, which is better than reading them separately. The scale factors follow from the default measurement ranges; a smaller range gives finer steps.
mpu6050.py MicroPython
import struct from math import atan2, degrees class MPU6050: ACCEL_LSB_PER_G = 16384.0 # at the default +-2 g range GYRO_LSB_PER_DPS = 131.0 # at the default +-250 deg/s range def __init__(self, i2c, addr=0x68): self.i2c, self.addr = i2c, addr self.i2c.writeto_mem(addr, 0x6B, b'\x00') # PWR_MGMT_1: clear the sleep bit self.bias = (0.0, 0.0, 0.0) # gyro offsets, degrees per second def who_am_i(self): return self.i2c.readfrom_mem(self.addr, 0x75, 1)[0] # 0x68 on a genuine part def read(self): """Return (ax, ay, az) in g, temperature in C, (gx, gy, gz) in deg/s.""" d = self.i2c.readfrom_mem(self.addr, 0x3B, 14) # one read: 14 bytes in a row ax, ay, az, t, gx, gy, gz = struct.unpack('>hhhhhhh', d) # big-endian signed 16-bit k, s = self.ACCEL_LSB_PER_G, self.GYRO_LSB_PER_DPS b = self.bias return ((ax / k, ay / k, az / k), t / 340 + 36.53, (gx / s - b[0], gy / s - b[1], gz / s - b[2])) def calibrate(self, n=200): """Hold the board still: average the gyro and remember it as the zero.""" from time import sleep_ms sx = sy = sz = 0.0 self.bias = (0.0, 0.0, 0.0) for _ in range(n): g = self.read()[2] sx += g[0]; sy += g[1]; sz += g[2] sleep_ms(5) self.bias = (sx / n, sy / n, sz / n) def roll_deg(ax, ay, az): """Tilt about the x axis, from the direction gravity points.""" return degrees(atan2(ay, az))

Two details deserve attention. First, the chip starts asleep, so the constructor clears the sleep bit; reading a sleeping MPU6050 returns zeros. Second, the gyroscope never reads exactly zero at rest: it has a small constant bias (maybe half a degree per second), so calibrate() averages it while the board is still and subtracts it afterwards. Skipping this makes a robot appear to rotate slowly all the time.

At rest, flat on the desk, gravity points straight down, so az reads about +1 g and ax, ay about 0. Tilt the board and the gravity is shared among the axes. The tilt angle can be found from where gravity points: roll_deg(ax, ay, az) returns the rotation about the x axis. Hold the board still when you use it: acceleration from motion adds to gravity and fools the estimate. (Combining it with the gyroscope to fix that is sensor fusion, in Unit 3.)

imu_demo.py MicroPython
i2c = I2C(0, sda=Pin(4), scl=Pin(5), freq=400_000) imu = MPU6050(i2c) print("WHO_AM_I:", hex(imu.who_am_i())) # 0x68 for a genuine MPU6050 imu.calibrate() # keep the board still for a second while True: (ax, ay, az), temp, (gx, gy, gz) = imu.read() print("roll %.1f deg gyro_x %.1f deg/s" % (roll_deg(ax, ay, az), gx)) sleep_ms(100)

Some inexpensive modules carry a clone chip whose identity register returns a different value (0x70 and 0x72 are seen). They usually work with this code. The identify helper below reports it so you are not surprised.

identify.py MicroPython
KNOWN = {0x27: "LCD backpack", 0x3F: "LCD backpack", 0x68: "MPU6050", 0x69: "MPU6050 (AD0 high)", 0x5A: "MPR121 touch"} def identify(i2c): """Scan the bus and name what answers, checking the MPU6050's identity register.""" found = {} for a in i2c.scan(): name = KNOWN.get(a, "unknown device") if a in (0x68, 0x69): who = i2c.readfrom_mem(a, 0x75, 1)[0] if who != 0x68: name += " (clone? WHO_AM_I = %s)" % hex(who) found[hex(a)] = name return found

Part 5. The LCD1602 Display

A two-line, 16-character display gives your node a way to show status without a laptop. The display itself (an HD44780-type controller) normally needs about ten wires. The little board on its back, a PCF8574 port expander, turns that into I2C: each byte you send to it sets eight output pins at once, wired to the display.

How the backpack maps a byte to the display’s pins (the common wiring; some backpacks differ, which shows up as garbage characters). The display works in 4-bit mode, so each character is sent as two nibbles, each framed by a pulse on E.
lcd1602.py MicroPython
from time import sleep_ms class LCD: """HD44780 16x2 character display behind a PCF8574 I2C backpack (the common wiring).""" RS, RW, E, BL = 0x01, 0x02, 0x04, 0x08 # bits of the expander byte; D4..D7 are bits 4..7 def __init__(self, i2c, addr=0x27, cols=16, rows=2): self.i2c, self.addr, self.cols, self.rows = i2c, addr, cols, rows self.light = self.BL sleep_ms(50) # let the display power up for n in (0x30, 0x30, 0x30, 0x20): # wake it, then switch it to 4-bit mode self._nibble(n) sleep_ms(5) self._cmd(0x28) # 4-bit, two lines, 5x8 font self._cmd(0x0C) # display on, cursor off self._cmd(0x06) # cursor moves right after each character self.clear() def _put(self, b): self.i2c.writeto(self.addr, bytes([b | self.light])) def _nibble(self, n, rs=0): # n holds the 4 data bits in its upper half self._put(n | rs) self._put(n | rs | self.E) # raise E ... self._put(n | rs) # ... and drop it: the display reads on the fall def _byte(self, b, rs=0): self._nibble(b & 0xF0, rs) # high half first self._nibble((b << 4) & 0xF0, rs) # then the low half def _cmd(self, c): self._byte(c) sleep_ms(2) def clear(self): self._cmd(0x01) def text(self, s, col=0, row=0): self._cmd(0x80 | (col + (0x40 if row else 0x00))) # set the cursor position for ch in s[:self.cols - col]: self._byte(ord(ch), self.RS) # RS = 1 means "this is a character" def line(self, s, row): self.text('{:<{w}}'.format(s, w=self.cols), 0, row) # pad with spaces to wipe old text def backlight(self, on): self.light = self.BL if on else 0 self._put(0)
lcd_demo.py MicroPython
lcd = LCD(i2c) # address 0x27; use LCD(i2c, 0x3F) if the scan shows 0x3F lcd.line("Hello robot", 0) lcd.line("dist 23 cm", 1)

line pads the string with spaces so a short message fully replaces a longer old one: the display does not clear itself. If the backlight is on but no characters appear, turn the small blue contrast screw on the backpack; if you see rows of solid blocks, the display powered up but never received its initialisation, so check the address.

Powering the LCD backpack. Many backpacks have pull-up resistors tied to their own supply pin. If that pin is 5 V, the I2C wires idle at 5 V, which the Pico’s pins cannot take. Power the backpack from 3V3 first; the instructor will show you how to check for and remove its pull-ups if you want the 5 V version.

Check before you wire: with the backpack unpowered, a multimeter on resistance between SDA and the VCC pin will read about 4.7 kΩ if the backpack carries a pull-up to VCC.

Part 6. The MPR121 Touch Sensor

The MPR121 senses touch with no moving parts: it measures the small change in capacitance when a finger approaches one of its 12 pads, and tells you which are touched. It needs a little configuration (thresholds that say how big a change counts as a touch) and then a two-byte read:

mpr121.py MicroPython
from time import sleep_ms class MPR121: """12-channel capacitive touch sensor.""" def __init__(self, i2c, addr=0x5A): self.i2c, self.addr = i2c, addr i2c.writeto_mem(addr, 0x80, b'\x63') # soft reset sleep_ms(5) i2c.writeto_mem(addr, 0x5E, b'\x00') # stop mode: settings can be changed for e in range(12): # thresholds for each electrode i2c.writeto_mem(addr, 0x41 + 2 * e, b'\x0C') # touch threshold i2c.writeto_mem(addr, 0x42 + 2 * e, b'\x06') # release threshold i2c.writeto_mem(addr, 0x5E, b'\x8F') # run: electrodes enabled def touched(self): """Bit n of the result is 1 while pad n is touched.""" lo, hi = self.i2c.readfrom_mem(self.addr, 0x00, 2) return ((hi << 8) | lo) & 0x0FFF

Wire it like any I2C device and print bin(pad.touched()) while you touch a pad. The thresholds above (12 to touch, 6 to release) are common starting values; if a pad flickers, raise them. Check the datasheet or your module’s documentation for anything specific to your board.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Read the Scan

0x27 is the LCD backpack, 0x5A the MPR121 and 0x68 the MPU6050. Two MPU6050s at the same address 0x68 cannot be told apart: both answer at once and the bus fails or returns garbage. Tie one module’s AD0 pin to 3.3 V to move it to 0x69, and then both appear on the scan.

Exercise 2: Bus Timing

6 bytes: 9 × 9 = 81 clocks, which is 81 / 400 000 = 0.20 ms. The 14-byte read takes 0.38 ms, only 1.9 times as long for 2.3 times as many bytes, because the fixed overhead is shared. Reading everything in one transaction is cheaper than three separate ones.

Intermediate

Exercise 3: Tilt From Raw Numbers

ay = 8192 / 16384 = 0.5 g and az = 14189 / 16384 = 0.866 g. The roll is atan2(0.5, 0.866) = 30°, as the sine of 30° is 0.5 and the cosine is 0.866: the board is tilted 30° about the x axis.

test_roll.py MicroPython
ay, az = 8192 / 16384, 14189 / 16384 print(ay, round(az, 3), round(roll_deg(0, ay, az), 1)) # 0.5 0.866 30.0

Paper Practice: Answers

Recall

P1. Two Wires

SDA carries data; SCL carries the clock driven by the controller (the Pico). Bus 0 on GP4 (SDA) and GP5 (SCL).

P2. Open Drain

Devices can only pull a line low; they never drive it high. The pull-up resistors raise the lines when nobody pulls them down.

P3. Empty Scan

SDA and SCL swapped; missing power or ground; the wrong pins in the I2C(...) call. (A loose jumper is a variant of the second.)

P4. Sleeping Sensor

The chip starts asleep. Write 0 to register 0x6B (power management) to clear the sleep bit, as the constructor in the lesson does.

Apply

P5. Parallel Pull-ups

Three: 4.7 / 3 = 1.57 kΩ, fine. Ten: 470 Ω, below 970 Ω, so the bus is pulled up too strongly for a device that only has to sink 3 mA; remove some pull-ups.

P6. Transaction Time

9 × (6 + 3) = 81 clocks: 0.20 ms at 400 kHz, 0.81 ms at 100 kHz.

P7. Share of a Loop

1.53 / 10 = 15 % of the loop; at 400 kHz, 0.38 ms = 3.8 %.

P8. Raw to Units

az = 16000 / 16384 = 0.977 g; gx = 262 / 131 = 2.0 °/s.

P9. Roll Angle

atan2(0.5, 0.866) = 30°.

Analyze and Design

P10. Uncorrected Bias

0.5 × 60 = 30° of false rotation. calibrate() averages the gyro while the board is still and subtracts that average from every later reading.

P11. 5 V Backpack

Many backpacks carry pull-up resistors to their own supply pin. At 5 V the SDA and SCL lines idle at 5 V, which the Pico's pins are not rated to receive. Power the backpack from 3V3, or remove its pull-ups.

P12. Two of the Same

Two, yes: the AD0 pin selects address 0x68 or 0x69. A third would collide with one of them on the same bus; use the Pico's second I2C bus (or a multiplexer).
