This lesson adds the return path. You meet hub.py, which lets a node subscribe and receive without ever blocking; the acknowledgement convention that turns publish and subscribe into a conversation; the logic of the instructor’s robot, with validation, ownership and idempotent commands; and the layered fail-safes that keep a robot safe when its controller disappears.

So far data has flowed one way: from nodes to the broker. A robot also has to listen. This lesson adds the return path: commands that reach a node from somewhere else, the acknowledgements that tell the sender what happened, and the fail-safes that keep a robot from doing something dangerous when the person or program commanding it disappears. It also introduces hub.py, the receiving half of the class helper, and ends with the logic of the instructor’s robot, which is the logic you will be commanding in Lab Practical 2.

Part 1. Commands Need Answers

Publish and subscribe has no reply: when you publish a command, publish returning tells you only that the bytes left your board. Whether the broker accepted the topic, whether the robot was listening, whether it obeyed, whether it was allowed to: none of that is visible. The convention that fills the gap is simple and universal. Every command carries an id. The node answers on an ack topic with the same id and a verdict. It also publishes its state as a retained message, so that anyone can check what the robot is doing without asking.

A command conversation. The id ties each answer to its question, since many commands may be in flight and acks can arrive out of order. A refusal is an answer too: the controller learns why, instead of waiting in silence.

Part 2. hub.py: A Node That Listens

hub.py extends net.Link from the on-ramp lesson. Everything net.py did (queue, retry, never block) still works; the new methods subscribe, receive, keep the connection alive and announce the node. Read it through once: it is the working form of the callback, ping and keepalive ideas from the MQTT basics lesson.

hub.py MicroPython
# hub.py -- net.py with ears: it can subscribe, receive and announce itself. # import hub # h = hub.Hub() # h.on(h.mine("cmd/#"), handler) # handler(topic, payload) for every matching message # while True: # h.poll() # call once per pass of your main loop import json from time import ticks_ms, ticks_diff import net def match(filt, topic): """MQTT wildcards: + is exactly one level, # is everything that remains.""" f, t = filt.split("/"), topic.split("/") for i, part in enumerate(f): if part == "#": return True if i >= len(t) or (part != "+" and part != t[i]): return False return len(f) == len(t) def decode(payload): """bytes -> dict, or None if it is not a valid version-1 message. Never raises.""" try: d = json.loads(payload) except (ValueError, TypeError): return None if not isinstance(d, dict) or d.get("v") != 1: return None if not isinstance(d.get("seq"), int) or not isinstance(d.get("t"), int): return None return d class Hub(net.Link): def __init__(self, keepalive=30, inbox_max=20, **kw): super().__init__(**kw) self.keepalive = keepalive # seconds; the broker drops us after 1.5 x of silence self.handlers = [] # (filter, function) self.inbox = [] # messages the callback has caught, waiting for poll() self.inbox_max = inbox_max self.rx_dropped = 0 self.will = None # set by presence() self.hello = None self.last_ping = ticks_ms() def mine(self, topic): """A full topic inside your own subtree: mine("cmd/#") -> "lab/jsmith/cmd/#".""" return self.root + topic def on(self, filt, handler): self.handlers.append((filt, handler)) if self.client: try: self.client.subscribe(filt.encode()) except OSError: self._drop() def send(self, topic, data, retain=False): """Publish to a FULL topic outside your own subtree (the access list must allow it).""" mine, self.root = self.root, "" try: return self.publish(topic, data, retain) finally: self.root = mine def presence(self, topic="stat/online"): """Register a last will, and announce 'online' at every connect. Both are retained.""" t = self.root + topic self.will = (t, json.dumps({"v": 1, "seq": 0, "t": 0, "online": False})) self.hello = (t, json.dumps({"v": 1, "seq": 0, "t": 0, "online": True})) def close(self): """A planned shutdown: say so, then disconnect. (A clean disconnect suppresses the will.)""" if self.client and self.will: try: self.client.publish(self.will[0].encode(), self.will[1].encode(), retain=True) self.client.disconnect() except OSError: pass self.client = None def _make_client(self): c = super()._make_client() c.set_callback(self._on_msg) if self.will: c.set_last_will(self.will[0].encode(), self.will[1].encode(), retain=True) return c def _on_msg(self, topic, payload): # runs inside check_msg(): only remember, never work self.inbox.append((topic.decode(), payload)) if len(self.inbox) > self.inbox_max: self.inbox.pop(0) self.rx_dropped += 1 def connect(self): if not super().connect(): return False try: for filt in {f for f, _ in self.handlers}: self.client.subscribe(filt.encode()) except OSError: self._drop() return False if self.hello: self.log.insert(0, (self.hello[0], self.hello[1], True)) # first thing sent self.last_ping = ticks_ms() return True def poll(self, budget=5): """Receive, keep the connection alive, and run handlers for up to `budget` messages.""" if self.client is None: if self.last_try is None or ticks_diff(ticks_ms(), self.last_try) >= self.retry_ms: self.connect() return 0 try: for _ in range(budget): before = len(self.inbox) self.client.check_msg() if len(self.inbox) == before: break if self.log: self._flush(5) if ticks_diff(ticks_ms(), self.last_ping) >= self.keepalive * 500: self.client.ping() self.last_ping = ticks_ms() except OSError: self._drop() return 0 n = 0 while self.inbox and n < budget: topic, payload = self.inbox.pop(0) for filt, fn in self.handlers: if match(filt, topic): fn(topic, payload) n += 1 return n
What one pass of poll() does. Every step is short and bounded, so a node that polls inside its control loop stays responsive however much the network sends it.

Three methods are worth remembering. h.mine("cmd/#") builds a full topic in your own subtree. h.on(filter, handler) registers a handler for every message matching a filter. h.send(topic, data) publishes to a full topic outside your subtree, which the access list will allow only where you have been given write access (the robot’s cmd topics, for example). The plain h.publish("evt/ack", ...) still writes into lab/<you>/.

Part 3. The Robot’s Logic

The instructor’s robot, and the node you will build in Lab 6, run the logic below. It contains no hardware: it takes an actuator object that provides pan(deg), drive(pct) and stop(), which is why the same code can be tested on a laptop with a stand-in that only records what it was told. The first function is the validate check you met in the last lesson, extended to the user field and the claim command.

robot.py MicroPython
# robot.py -- the command logic of a robot node. No hardware in here: it calls an actuator object, # so the same logic can be tested on a PC with a stand-in. from time import ticks_ms, ticks_diff def validate(kind, d, allow_spin=False): """Check a command against the interface specification. Returns (True, "") or (False, why).""" if not isinstance(d, dict): return False, "bad payload" if not isinstance(d.get("id"), int): return False, "missing id" if not isinstance(d.get("user"), str) or not d["user"]: return False, "missing user" if kind == "pan": deg = d.get("deg") if not isinstance(deg, (int, float)): return False, "deg must be a number" if not -90 <= deg <= 90: return False, "deg out of range" elif kind == "drive": pct, ms = d.get("pct"), d.get("ms") if not isinstance(pct, (int, float)) or not isinstance(ms, int): return False, "pct and ms are required" if not -100 <= pct <= 100: return False, "pct out of range" if not 0 < ms <= 1500: return False, "ms out of range" elif kind == "spin" and allow_spin: pct = d.get("pct") if not isinstance(pct, (int, float)) or not -100 <= pct <= 100: return False, "pct out of range" elif kind not in ("stop", "claim"): return False, "unknown command" return True, "" class Robot: def __init__(self, act, lease_ms=30000, deadman_ms=2000, pan_gap_ms=200, allow_spin=False): self.act = act # needs pan(deg), drive(pct), stop() self.lease_ms, self.deadman_ms, self.pan_gap_ms = lease_ms, deadman_ms, pan_gap_ms self.allow_spin = allow_spin self.owner = None self.owner_seen = 0 # time of the owner's last valid command self.run_until = None # when a timed drive must end self.running = False self.last_cmd = 0 self.last_pan = None self.acks = {} # id -> ack, so a repeated command is answered, not repeated self.order = [] def _remember(self, cid, ack): self.acks[cid] = ack self.order.append(cid) if len(self.order) > 8: self.acks.pop(self.order.pop(0), None) def _stop(self): self.act.stop() self.running = False self.run_until = None def command(self, kind, d, now): """Handle one command. Always returns an ack dict; never raises.""" ok, why = validate(kind, d, self.allow_spin) if not ok: return {"cmd_id": d.get("id") if isinstance(d, dict) else None, "ok": False, "why": why} cid, user = d["id"], d["user"] if cid in self.acks: return self.acks[cid] # a repeat: same answer, no second action ack = {"cmd_id": cid, "ok": True, "why": ""} free = self.owner is None if kind == "claim": if free or self.owner == user: self.owner, self.owner_seen = user, now else: ack.update(ok=False, why="busy") elif self.owner != user: ack.update(ok=False, why="not owner") else: self.owner_seen = self.last_cmd = now if kind == "stop": self._stop() elif kind == "pan": if self.last_pan is not None and ticks_diff(now, self.last_pan) < self.pan_gap_ms: ack.update(ok=False, why="too fast") else: self.act.pan(d["deg"]) self.last_pan = now else: # drive or spin self.act.drive(d["pct"]) self.running = d["pct"] != 0 self.run_until = now + d["ms"] if kind == "drive" else None self._remember(cid, ack) return ack def tick(self, now): """Call every pass of the main loop. Returns a list of reasons for anything it stopped.""" out = [] if self.running and self.run_until is not None and ticks_diff(now, self.run_until) >= 0: self._stop(); out.append("time up") if self.running and ticks_diff(now, self.last_cmd) > self.deadman_ms: self._stop(); out.append("deadman") if self.owner and ticks_diff(now, self.owner_seen) > self.lease_ms: self._stop(); self.owner = None; out.append("lease expired") return out def state(self): if self.owner is None: return "IDLE", None return ("BUSY" if self.running else "READY"), self.owner

Walk through command in order, because the order is the design. Validate first, so that nothing malformed reaches any other logic. Then look for a repeat: if this id has been answered, return the stored answer and do nothing, which makes a retransmitted command harmless (idempotent). Then the owner check: a claim succeeds if the robot is free or already yours; anything else requires you to be the owner. Only then does it act, and the act itself is bounded: pan is rate-limited, and drive carries its own duration.

The glue between this logic and the broker is a dozen lines. The callback gets the kind from the last level of the topic, decodes the payload (None if invalid, which validate turns into “bad payload”), hands both to the robot, and publishes whatever comes back.

main.py MicroPython
# main.py: a robot node on the broker (in your own subtree for Lab 6) import hub from robot import Robot from actuators import Actuators # Lab 6: servo on GP14, motor driver or LED from time import ticks_ms h = hub.Hub() h.presence() # last will + retained "online" robot = Robot(Actuators()) def on_cmd(topic, payload): kind = topic.rsplit("/", 1)[-1] # ".../cmd/pan" -> "pan" ack = robot.command(kind, hub.decode(payload), ticks_ms()) h.publish("evt/ack", ack) h.on(h.mine("cmd/#"), on_cmd) shown = None while True: h.poll() now = ticks_ms() for why in robot.tick(now): h.publish("evt/stopped", {"why": why}) st = robot.state() if st != shown: # publish state only when it changes h.publish("stat/state", {"state": st[0], "owner": st[1]}, retain=True) shown = st

Notice how little this program decides. The rules are in Robot, the transport is in Hub, and main.py only connects them. When something goes wrong you can ask which of the three failed.

Part 4. Fail-Safes

A robot has to be safe when its controller fails, because a controller will fail: the laptop sleeps, the program crashes, the WiFi drops, a student closes the lid. The design rule is: the safe state must be the default state, and staying out of it must require continuous effort. Three mechanisms in Robot.tick implement it at three time scales.

Four independent safeguards. None depends on the network being up at the moment of failure, which is the point: a safeguard that needs a message to trigger is useless when messages stop arriving.

Two points about the table. First, the motor-protecting mechanisms live in the node, not in the controller: asking the controller to “remember to send stop” fails in exactly the situation it is meant for. Second, a command with a bounded duration is safer than an unbounded one plus a stop, because there is nothing to forget. Continuous control, the joystick style, exists too, and uses the deadman: the controller must keep repeating the command (say every 200 ms) or the motor stops after 2 s. In Lab 6 you will run the robot with allow_spin=True and watch the deadman work.

Part 5. Retrying Without Doing It Twice

The network can lose a command, or it can lose the ack. The controller cannot tell which: both look like silence. The only strategy that works is to send again, with the same id, and let the robot recognise the repeat. The Controller class below does exactly that: it remembers what is pending, resends after retry_ms, and after tries attempts reports a failure.

controller.py MicroPython
# controller.py -- sends commands, matches acknowledgements, retries with the SAME id. from time import ticks_diff from hub import decode class Controller: def __init__(self, hub, root, user, retry_ms=500, tries=3): self.hub, self.root, self.user = hub, root, user # root: "robot/r1/" self.retry_ms, self.tries = retry_ms, tries self.next_id = 1 self.pending = {} # id -> [kind, fields, time last sent, attempts] self.done = {} # id -> the ack, or a "no answer" failure hub.on(root + "evt/ack", self._on_ack) def send(self, kind, now, **fields): cid = self.next_id self.next_id += 1 fields["id"], fields["user"] = cid, self.user self.pending[cid] = [kind, fields, now, 1] self.hub.send(self.root + "cmd/" + kind, fields) return cid def _on_ack(self, topic, payload): d = decode(payload) if d and d.get("cmd_id") in self.pending: self.done[d["cmd_id"]] = d del self.pending[d["cmd_id"]] def tick(self, now): for cid, p in list(self.pending.items()): if ticks_diff(now, p[2]) < self.retry_ms: continue if p[3] >= self.tries: self.done[cid] = {"cmd_id": cid, "ok": False, "why": "no answer"} del self.pending[cid] else: p[2], p[3] = now, p[3] + 1 self.hub.send(self.root + "cmd/" + p[0], p[1]) # same id: the robot will not act twice
A lost ack, repaired by a retry. The robot panned once, when it first saw id 3, and answered the repeat from its table of recent ids. Without the id table every retry would pan the servo again; with a drive command it would drive again.

One question has no clean answer: after three attempts with no ack, did the robot act? It may have received every one of them and every ack may have been lost. The controller can only say “I do not know.” The safe response is to treat the state as unknown, command a stop, and read the robot’s retained stat/state before doing anything else. That is why stop is always honored, and why the state is retained: it is the one message a controller can fetch at any moment to find out the truth.

Warm Up

Exercise 1: Which Safeguard?

(a) The bounded command: the motor stops at its 1.5 s deadline, about 1.1 s after the crash. (b) The deadman: 2 s after the last command (spin does not time out by itself). (c) The lease: 30 s after the last valid command, the robot releases the owner and returns to IDLE. (d) Power failure removes the motor’s power as well as the logic’s, so the motor stops physically; the last will (after about 45 s) lets everyone know the robot is gone. If the motor had its own battery and the driver inputs floated, this is where a pull-down resistor on the inputs earns its place.

Exercise 2: Read the Ack

The claim is refused with ok false, why “busy”, because bob is not the owner and the robot is not free. The pan is refused with ok false, why “not owner”. The robot moves nothing, and jsmith’s lease is not refreshed by either, so bob’s traffic cannot keep jsmith’s claim alive nor interfere with it.

Intermediate

Exercise 3: How Long to Give Up?

Attempts are sent at 0, 500 and 1,000 ms, and the controller gives up at about 1,500 ms, when the third attempt’s time is also up. The danger: the first attempt may actually have arrived and started the motor, only the acks were lost. The controller now says “no answer” while a motor is running for up to 1,500 ms from the first arrival. After a “no answer” it must send stop (repeating until acknowledged) and then read stat/state. It must never assume that no answer means no action.

Exercise 4: Five Per Second
ratelimit.py MicroPython
from time import ticks_diff class RateLimit: """Allow at most n events in any window of window_ms (sliding window).""" def __init__(self, n, window_ms): self.n, self.w = n, window_ms self.times = [] def allow(self, now): self.times = [t for t in self.times if ticks_diff(now, t) < self.w] if len(self.times) >= self.n: return False self.times.append(now) return True
test_rate.py MicroPython
r = RateLimit(5, 1000) print([r.allow(t) for t in (0, 100, 200, 300, 400, 500, 1001)]) # [True, True, True, True, True, False, True]

The first five are allowed; the sixth, at 500 ms, would be the sixth event inside one second, so it is refused. By 1,001 ms the event at 0 has aged out of the window, leaving four, so the next is allowed. Unlike the fixed gap of 200 ms, this permits a burst of five followed by a pause, which is what the specification actually says. A refused event is not recorded, so a flood does not extend its own punishment.
