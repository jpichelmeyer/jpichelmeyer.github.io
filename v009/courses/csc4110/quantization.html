The ADC lesson introduced quantization in a paragraph. It deserves more, because quantization is the one limit that every analog measurement you will ever make runs into. This lesson puts numbers on it: how big the steps are, how much error they cause, and how many of the bits the Pico's ADC gives you can actually be trusted.

Part 1. Bits, Levels and Step Size

An ADC with n bits can report 2n different numbers. Spread those evenly across the input range and the distance between neighbouring levels is the step size, usually called one LSB (least significant bit):

  • levels = 2n
  • LSB = Vrange / 2n

The Pico's ADC is 12 bits over a 3.3 V range, so it has 4,096 levels and each step is 3.3 / 4096, about 0.81 mV. An 8-bit converter over the same range would have only 256 levels and 12.9 mV steps: a fine adjustment of the voltage would be invisible to it.

The same sine wave measured with 2, 3, 4 and 12 bits. Every extra bit doubles the number of levels and halves the step, but the staircase never disappears completely.
How step size comes from bit depth and range. This number, the "LSB", sets the finest change the ADC can possibly report.

Part 2. Quantization Error

Because every reading is rounded to the nearest level, the reported value is almost never exactly the true voltage. The difference is the quantization error. Rounding to the nearest level means the error can never be more than half a step in either direction: plus or minus ½ LSB.

Quantization error is the gap between the true signal and the nearest level. It zig-zags between plus and minus half a step, however the signal moves.

For a busy, changing signal the error looks like random noise (called quantization noise), and an ideal n-bit converter has a best-possible signal-to-noise ratio of roughly 6 × n decibels. Each extra bit buys about 6 dB, which is a factor of two in precision. That is why bit depth is the headline number on every ADC data sheet.

Part 3. How Many Bits Do You Really Get?

Twelve bits is what the converter produces, not what it delivers cleanly. Real converters have extra noise and small non-linearities, and the RP2040's ADC behaves more like an 8 to 9-bit converter once those are counted (its data sheet calls this the effective number of bits). In practice the lowest few bits of every reading are partly noise.

Two habits follow. First, do not quote more precision than you have: if the noise is a few millivolts, printing a voltage to four decimal places is meaningless. Second, noise is not entirely bad news: averaging many noisy readings (the filtering lessons) can recover precision between the steps, as long as there is a little noise to dither the readings across a step boundary.

Recovering the converter's own 12-bit number is easy, because MicroPython scaled it up by 16:

shell MicroPython
raw = adc.read_u16() # 0..65535, always a multiple of 16 code12 = raw >> 4 # back to the ADC's own 0..4095 volts = (code12 + 0.5) * 3.3 / 4096 # middle of that level, in volts

Part 4. A Free Thermometer

The Pico has one more analog input that needs no wiring at all: ADC(4), connected to a temperature sensor inside the chip. It is a good example of quantization in practice, because a temperature changes slowly while the reading jitters by a degree or so.

The on-chip temperature sensor is just one more analog input. Convert its reading to volts, then to degrees with the datasheet formula.

Warm Up

Exercise 1: Levels and Step Size

levels = 2n, step = range / levels. (a) 256 levels, 19.5 mV. (b) 1024 levels, 3.22 mV. (c) 4096 levels, 0.806 mV.

Exercise 2: A Three-Bit Ladder

Step = 3.3 / 8 = 0.4125 V, so the boundaries are 0, 0.4125, 0.825, 1.2375, 1.65, 2.0625, 2.475, 2.8875, 3.3 V. 1.0 V falls in the third level (0.825 – 1.2375 V). The worst-case error is half a step, about 0.206 V.

Intermediate

Exercise 3: Write Your Own ADC
quantize.py MicroPython
def quantize(v, bits, vref=3.3): levels = 2 ** bits code = int(v / vref * levels) return min(code, levels - 1) # clamp v == vref def to_volts(code, bits, vref=3.3): return (code + 0.5) * vref / (2 ** bits) # check: worst-case round-trip error should be <= half a step bits = 4 step = 3.3 / 2 ** bits worst = 0 for i in range(0, 331): # 0.00 .. 3.30 V v = i / 100 err = abs(v - to_volts(quantize(v, bits), bits)) worst = max(worst, err) print(worst, step / 2)

worst comes out at (almost exactly) step / 2, never more.

Advanced

Exercise 4: How Many Bits Are Real?
main.py MicroPython
from machine import ADC, Pin adc = ADC(Pin(26)) # wire the pin to 3.3 V or GND via a steady source readings = [adc.read_u16() for _ in range(200)] print(min(readings), max(readings), max(readings) - min(readings))

log2(192) ≈ 7.6, so 16 − 7.6 ≈ 8.4 useful bits. The voltage is really only known to roughly ±7 mV, so printing "2.0761 V" implies precision that the measurement does not have.
