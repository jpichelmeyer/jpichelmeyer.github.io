Before layering MQTT on top of anything next week, this lab confirms the plumbing underneath it actually works: your Pico on WiFi, the Pi 3B+ reachable at a known address and port, and a real TCP connection succeeding between them. No MQTT yet, deliberately, so that if something goes wrong next week, you'll already know the network path itself isn't the problem.

Three separate things have to be true for this to work: your Pico actually on the network, the Pi's broker software actually running and listening, and nothing (a firewall, a typo'd IP) blocking the path between them. Testing with plain TCP isolates that from any MQTT-specific issue next week.
The three devices in this lab and the addresses that matter. The lab's single question is whether a connection from the left box can reach port 1883 on the right box.

Before You Start

You'll need the Pi 3B+'s IP address on the classroom network, get this from your instructor or read it directly off the Pi if you have access to it (hostname -I at a Pi terminal). Confirm the Pi's mosquitto service is installed and running, sudo systemctl status mosquitto should show active (running); this course's broker setup is covered separately, today you're just a client confirming it's reachable.

Procedure

  1. Connect your Pico to the classroom WiFi (last lesson's script) and confirm you get a valid IP address back.
  2. Using MicroPython's built-in socket module, a lower-level networking tool than anything used so far, open a raw TCP connection to the Pi's IP address on port 1883.
  3. Confirm the connection succeeds without error, and then cleanly close it.
  4. Deliberately connect to the wrong port (try 9999, almost certainly nothing is listening there) and observe what error MicroPython raises. Compare that error to what happened when you connected to the correct port.
main.py MicroPython
import network, socket from time import sleep SSID = "your-network-name" PASSWORD = "your-network-password" BROKER_IP = "192.168.1.42" # replace with your Pi's actual address BROKER_PORT = 1883 wlan = network.WLAN(network.STA_IF) wlan.active(True) wlan.connect(SSID, PASSWORD) while not wlan.isconnected(): sleep(0.5) print("on WiFi, IP:", wlan.ifconfig()[0]) addr_info = socket.getaddrinfo(BROKER_IP, BROKER_PORT)[0][-1] s = socket.socket() try: s.connect(addr_info) print("connected to broker machine on port", BROKER_PORT) except OSError as e: print("connection failed:", e) finally: s.close()

A successful run here doesn't mean MQTT is working, a raw TCP connection carries no MQTT-specific information at all yet, it just proves the broker's listening socket is reachable from your Pico over the actual classroom network. That's exactly the layer this lab is isolating: next week's umqtt.simple library builds its MQTT logic on top of a socket connection very much like this one.

If It Doesn't Connect

  • Double-check the IP address. A typo'd digit is the single most common cause.
  • Confirm the Pi and Pico are on the same network. A Pico connected to a phone hotspot, say, can't reach a Pi on the classroom WiFi, there's no path between them regardless of how correct the IP is.
  • Confirm mosquitto is actually running on the Pi (see "Before You Start" above). A correct address and port with nothing listening behaves identically, from the Pico's side, to a wrong address.
The three outcomes of a TCP connection attempt and what each one means. Reading the error is half of debugging a network problem.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Read the Error

111 (refused): the Pi answered, so the network path works; look at the broker (is mosquitto running? right port?). 110 (timed out): nothing answered at all; look at the address, whether both devices are on the same network, and whether the Pi is powered on.

Exercise 2: Why Raw TCP First?

To separate problems. If a raw connection to port 1883 works, the network, address and broker are all fine, so any later failure must be in the MQTT code. Testing everything at once leaves too many possible culprits.

Intermediate

Exercise 3: Reachability Test
net.py MicroPython
import socket def can_reach(ip, port, timeout=3): s = socket.socket() s.settimeout(timeout) try: s.connect(socket.getaddrinfo(ip, port)[0][-1]) return True except OSError: return False finally: s.close() print(can_reach("192.168.1.42", 1883))

The timeout stops a dead address from freezing your program for a long time, and finally guarantees the socket is closed on every path.

Advanced

Exercise 4: Poke a Few Ports
net.py (continued) MicroPython
for port in (22, 80, 1883, 9999): state = "open" if can_reach("192.168.1.42", port) else "closed" print(port, state)

Expect 1883 open (mosquitto), 22 probably open (SSH, if enabled on the Pi), and 80 and 9999 closed unless something else is running. Which ports are open is a quick fingerprint of what a machine is doing.
