This lab joins fusion, PID and the agent cycle into a working stabiliser. You calibrate and mount an IMU, build the tilt estimate, tune a PID against a real servo, measure how the loop fails with delay, saturation and sensor loss, and keep the network out of the loop.

What You Will Build

A self-leveling platform: a servo carries a small platform with the MPU6050 on it, the whole thing sits on a base you can tilt by hand, and the Pico keeps the platform level. It is a complete little control system: the synthetic sensor is the tilt from the complementary filter of the fusion lesson, the controller is the PID of Unit 1, the agent is the Stabilizer below, and the network has only a supporting role (telemetry out, a setpoint in). The important design rule of this lab is that the loop closes on the board, never over the network, and the measurements will show why.

The Lab 10 setup. The platform’s own tilt is measured, compared with the setpoint (level), and the servo is driven to cancel the difference; the network is only for watching and for changing the setpoint.

Step 1. Build and Check the Sensing

Mount the servo on a cardboard base, a stiff arm on its horn, and the MPU6050 flat on the arm so that its x axis is parallel to the servo axis (the servo then rotates the sensor about x, which is the roll angle Tilt computes). Power the servo from its own battery pack with a common ground (the rule of the PWM lesson), and wire the MPU6050 to GP0 and GP1 as in Lab 3. Copy to the Pico: hub.py, mpu6050.py, agent.py, tilt.py (fusion lesson), pid.py and contract.py, plus the two files below.

servo.py MicroPython
# servo.py -- one hobby servo, angle in degrees from its centre from machine import Pin, PWM class Servo: def __init__(self, pin=14, trim=0.0, sign=1): self.pwm = PWM(Pin(pin), freq=50) self.trim, self.sign = trim, sign # trim: degrees of offset; sign: -1 flips the direction self.angle(0) def angle(self, deg): deg = self.sign * deg + self.trim deg = max(-90, min(90, deg)) self.pwm.duty_ns(1_000_000 + int((deg + 90) / 180 * 1_000_000)) # 1.0 to 2.0 ms

First test the sensing alone, without the servo moving: run imu.calibrate() with the board still, then print Tilt.update(...) while you rock the platform by hand. The tilt should read about 0 flat and about ±90 when held on its side, and change sign in the same direction as your rocking. Next find the servo’s own centre and direction: command Servo.angle(0), +20, −20 and read the platform tilt each time. If +20 tilts the platform the wrong way for your mounting, set sign=-1; if the platform is not level at 0, note the offset (half a degree is fine, five is not) and set trim. Record the three readings in your report.

Step 2. The Stabilizer Agent

This is the Agent of Unit 3 again: sense the tilt, decide with the PID, act on the servo, tell at 5 Hz. The PID class is the one from the PID lesson, with a reset added.

pid.py MicroPython
# pid.py -- from the PID lesson class PID: def __init__(self, kp, ki, kd, out_min=0.0, out_max=1.0): self.kp, self.ki, self.kd = kp, ki, kd self.out_min, self.out_max = out_min, out_max self.i = 0.0 self.prev = None def reset(self): self.i, self.prev = 0.0, None def update(self, setpoint, measurement, dt): error = setpoint - measurement d = 0.0 if self.prev is None else -(measurement - self.prev) / dt # on the measurement self.prev = measurement i_new = self.i + self.ki * error * dt out = self.kp * error + i_new + self.kd * d if out > self.out_max: out = self.out_max # saturated: do not let the integral grow elif out < self.out_min: out = self.out_min else: self.i = i_new return out
stabilizer.py MicroPython
# stabilizer.py -- keep a platform level while its base is tilted from time import ticks_ms, ticks_diff from agent import Agent from tilt import Tilt # the complementary filter of the fusion lesson from pid import PID class Stabilizer(Agent): LIMIT = 60.0 # the servo may move at most this far either side of its centre def __init__(self, hub, imu, servo, kp=1.0, ki=12.0, kd=0.0): super().__init__("stab", hub, period_ms=20) # 50 Hz self.imu, self.servo = imu, servo self.tilt = Tilt(alpha=0.98) self.pid = PID(kp, ki, kd, -self.LIMIT, self.LIMIT) self.setpoint = 0.0 # level self.cmd = 0.0 self.t_prev = ticks_ms() # (not self.last: the Agent base class owns that) self.t_tell = ticks_ms() self.sat_since = None def sense(self): a, _, g = self.imu.read() now = ticks_ms() return self.tilt.update(a[1], a[2], g[0], now), now def decide(self, obs): phi, now = obs dt = max(ticks_diff(now, self.t_prev), 1) / 1000.0 self.t_prev = now self.cmd = self.pid.update(self.setpoint, phi, dt) return self.cmd def act(self, cmd): self.servo.angle(cmd) # -60 .. +60 degrees from centre def tell(self, obs, cmd): phi, now = obs sat = abs(cmd) >= self.LIMIT - 0.5 if sat and self.sat_since is None: self.sat_since = now elif not sat: self.sat_since = None if ticks_diff(now, self.t_tell) >= 200: # 5 Hz self.t_tell = now self.hub.publish("tele/level", {"tilt": round(phi, 1), "servo": round(cmd, 1), "sat": sat}) if self.sat_since is not None and ticks_diff(now, self.sat_since) > 1000: self.hub.publish("evt/warn", {"what": "out of range"}) # the base is tilted beyond what we can cancel self.sat_since = now

Two lines deserve attention. Stabilizer keeps its own previous-time variable t_prev: an earlier version reused the name self.last, which the Agent base class also uses for its period, and the PID’s time step came out as one millisecond instead of twenty. The integral then accumulated sixteen times too slowly and the platform took seconds to settle. It was found by testing against a simulated plant, and the lesson is general: when you subclass, check that your attribute names do not shadow the parent’s. And act clamps nothing itself: the PID’s output limits (±60°) are what keep the servo inside its range, and when they are reached for more than a second tell publishes a warning, because a controller that is pinned at its limit is not controlling.

main.py MicroPython
# main.py for Lab 10: a self-leveling platform from machine import I2C, Pin, WDT from time import ticks_ms import hub from mpu6050 import MPU6050 from servo import Servo from stabilizer import Stabilizer from contract import check SETPOINT = {"deg": (float, -30.0, 30.0, True)} # the contract for cmd/setpoint i2c = I2C(0, sda=Pin(0), scl=Pin(1), freq=400000) imu = MPU6050(i2c) imu.calibrate() # hold the board STILL for the second this takes h = hub.Hub() h.presence() stab = Stabilizer(h, imu, Servo(14)) refused = 0 def on_setpoint(topic, payload): global refused d = hub.decode(payload) ok, why = check(SETPOINT, d) if d else (False, "bad envelope") if ok: stab.setpoint = float(d["deg"]) # hold the platform at this tilt instead of level else: refused += 1 h.on(h.mine("cmd/setpoint"), on_setpoint) wdt = WDT(timeout=5000) while True: h.poll() stab.tick(ticks_ms()) wdt.feed()

The setpoint command is validated like any other message (the contract lesson): a deg outside ±30 is refused and counted. In the test, with the base held at 15°, a setpoint of 10 moved the platform to 10° (9.9 to 10.5 over the next 5 seconds), and a second message with deg = 99 was refused (refused = 1) without disturbing it.

Step 3. Tune It

Start from the gains in the code (kp = 1.0, ki = 12.0, kd = 0), tilt the base quickly by about 20° and let go, and record the platform’s tilt at 50 Hz for ten seconds (put print(phi) in Stabilizer.tell, open Thonny’s plotter, and remove it afterwards: printing is slow). Then change one gain at a time. The table below is from the simulation of this exact controller, with a servo that is slew-limited and 50 ms slow, a noisy IMU, and a base that either swings ±15° at 0.5 Hz (“sine”) or steps to 20° and then to −10° (“step”); your hardware will differ, but the pattern will not.

The step test in simulation. With the loop off the platform simply follows the base. With it on, the 20° jump is cancelled in about a third of a second and the larger 30° jump at 10 s within about a second, leaving a ripple under one degree.
Tuning in simulation. Proportional action alone leaves an error of about 1/(1 + Kp); the integral term removes the rest. Too little integral is slow (1 and 2); too much rings (1 and 40 is best on the sine, a little worse on the step); and a high proportional gain (4, 8) makes the loop oscillate against the servo’s lag.
  • Raise Kp until it just starts to buzz, then back off by half. A buzzing servo means the loop gain at the servo’s lag is too high.
  • Then raise Ki until the platform returns to level in about half a second after a jolt, and stop before it overshoots by more than a few degrees.
  • Leave Kd at zero unless you can show it helps: the derivative amplifies the accelerometer’s noise (in the simulation a derivative gain of 0.1 made the error four times worse).

Step 4. Break It

A controller is not finished until you have seen how it fails. Each test below has a simulated prediction; measure yours and compare.

A delay between measuring and acting. The loop tolerates about 60 ms of extra delay; at 80 ms it starts to oscillate and the error is larger than with the loop switched off (10.6° and 14.6°). Four samples of delay turn a stabiliser into a shaker.
  • Delay. Add time.sleep_ms(60) and then time.sleep_ms(100) to the loop and watch the platform. Then answer: what would happen if the PID ran on a laptop, with the tilt sent by MQTT and the servo command sent back? (Use the latency you measured in Lab 5.)
  • Saturation. Tilt the base by 70°, beyond the servo’s ±60° range. What does the platform do, what does tele/level say (sat), and when does evt/warn appear? Does the integral wind up (watch what happens when you bring the base back)?
  • Sensor failure. Unplug the MPU6050’s SDA wire while it runs. What does your program do, and what does the servo do? Add a guard so that an I²C error holds the servo where it is and publishes a warning, and test it.
  • Bias. Skip calibrate() once and leave the board still. Does the platform drift? How quickly? (This is the gyro bias of the fusion lesson at work.)

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: P Only

With P only, the servo command is −Kp × platform angle, so platform = base − Kp × platform, so platform = base / (1 + Kp) = 20 / 4 = 5°. (For the 15° swing the same rule gives 15 / 4 = 3.75° peak, 2.65° RMS, close to the simulation’s 2.76°.) An integral term keeps adding to the command until the error is zero, which is why the PI controller levels the platform completely.

Intermediate

Exercise 2: Why Does Delay Hurt?

The controller corrects the error it measured some time ago. If that time is long compared with how fast the error changes, the correction arrives when the situation has already changed: it pushes the platform past level, the measurement then says “too far the other way”, and the next, late, correction overshoots again. With enough delay each correction makes things worse than doing nothing, and the loop swings with growing size. A slower sample rate is a delay by another route (a measurement is on average half a period old, and the correction then lasts a whole period), which is why the Nyquist lesson and the PID lesson both ask for the loop to run several times faster than the thing it controls.

Advanced

Exercise 3: Guard the Sensor
guard.py MicroPython
# in Stabilizer def sense(self): try: a, _, g = self.imu.read() except OSError: return None, ticks_ms() # no reading: say so, do not guess now = ticks_ms() return self.tilt.update(a[1], a[2], g[0], now), now def decide(self, obs): phi, now = obs if phi is None: return self.cmd # hold the last command ... # the normal PID step def tell(self, obs, cmd): phi, now = obs if phi is None: if not self.warned: self.hub.publish("evt/warn", {"what": "imu error"}) self.warned = True return self.warned = False ... # the normal telemetry

The key choices: a sensor failure is a value (None) that flows through the cycle, not an exception that escapes it; the controller holds the last command instead of inventing one; and the warning is sent once, with the flag cleared when readings return. Whether “hold” is safe depends on the application: for a platform it is; for a motor you would want to stop.
