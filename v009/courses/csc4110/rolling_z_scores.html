How do you decide a reading is unusual when you do not know in advance what usual looks like? The z-score answers it with the signal’s own history: measure how far a reading is from the recent average, in units of the recent spread. One number, no tuning to the units of the sensor, and cheap enough for a microcontroller.

Part 1. The Idea

The z-score of a reading x is z = (x − mean) / std: how many standard deviations it sits from the mean. A z of 0 is exactly average, +2 is two spreads above, −3 is three below. Because it is measured in units of the signal’s own variation, the same threshold works for a light sensor, a temperature and a vibration trace.

What a z-score means. It counts how many standard deviations a reading is from the recent average. For well-behaved noise, nearly everything lands within three.

For well-behaved, bell-shaped noise, about 68 % of readings fall within ±1, 95 % within ±2 and 99.7 % within ±3. A reading beyond ±3 is therefore rare, which makes it a reasonable definition of “unusual”.

Part 2. Rolling, So It Follows the Signal

A real signal drifts: the room warms up, daylight changes. A z-score against the average of all time would flag every drift. Instead the mean and spread are kept over a rolling recent past, so “usual” follows the signal and only a sudden departure stands out.

Anomaly detection by z-score. The shaded band is the mean ± 3 standard deviations, tracked as the signal drifts; a reading that leaves the band is flagged.

Part 3. Mean and Variance One Reading at a Time

You cannot store a long history, so the statistics must be updated incrementally. Welford’s method does it with three numbers and stays accurate even in 32-bit floats, where the textbook shortcut fails:

Computing mean and variance without storing the samples (Welford's method). Each new reading updates three numbers, so memory use never grows however long the device runs.
stats.py MicroPython
class Welford: def __init__(self): self.n = 0 self.mean = 0.0 self.m2 = 0.0 # running sum of squared deviations def add(self, x): self.n += 1 d = x - self.mean self.mean += d / self.n self.m2 += d * (x - self.mean) def std(self): return (self.m2 / (self.n - 1)) ** 0.5 if self.n > 1 else 0.0

This grows its sample count forever, so it averages the whole history. For a rolling version, give old readings less weight by using an exponential average of the mean and variance, which is the subject of the next lesson. The detector below already uses that update, with alpha as the forgetting rate:

zscore.py MicroPython
class ZScore: def __init__(self, alpha=0.05, warmup=30, floor=1.0): self.alpha = alpha self.warmup = warmup self.floor = floor # smallest std we will divide by self.n = 0 self.mean = 0.0 self.var = 0.0 def update(self, x): """Returns the z-score of x, and learns from x unless it is an outlier.""" self.n += 1 if self.n == 1: self.mean = x return 0.0 std = max(self.var ** 0.5, self.floor) z = (x - self.mean) / std if self.n > self.warmup and abs(z) > 3: return z # an outlier: report it, do not learn from it d = x - self.mean self.mean += self.alpha * d self.var = (1 - self.alpha) * (self.var + self.alpha * d * d) return z

Part 4. Where It Goes Wrong

Three ways a z-score detector goes wrong, and the usual fix for each. All three are about the statistics, not the code.

The numbers behind “rare” deserve respect. A two-sided 3σ threshold is exceeded by pure noise about 0.27 % of the time. At 10 samples a second that is roughly 97 false alarms an hour, one every 37 seconds. Real alarms must therefore usually require persistence: several anomalous readings in a row. Three in a row would, for independent Gaussian noise, happen about once in two months at that rate, and real signals are rarely that tidy, which is why you tune on recorded data. The rate is also worse than the 0.27 % figure suggests, because the standard deviation is itself estimated from a short history. In a test of this lesson’s detector on 270 quiet readings, 7 single readings crossed ±3 (about 2.6 %), yet no run of three did, and a genuine dip was caught within three samples. That is exactly the case for persistence.

Exercise 2: How Often Is “Rare”?

3σ is exceeded about 0.27 % of the time: 0.0027 × 5 × 3600 ≈ 49 false alarms an hour. Requiring, say, three consecutive anomalous samples makes a false alarm vastly less likely while delaying a real one by only three samples (0.6 s here).

# in __init__: self.streak = 0 if self.n > self.warmup and abs(z) > 3: self.streak += 1 if self.streak >= 20: # the "outlier" is the new normal self.mean = x self.var = 0.0 self.n = 1 self.streak = 0 return z self.streak = 0

The two safeguards pull in opposite directions: not learning from outliers protects against spikes, and the streak rule rescues the detector from a permanent change. How long the streak should be is a judgement about how long a real anomaly can last.
