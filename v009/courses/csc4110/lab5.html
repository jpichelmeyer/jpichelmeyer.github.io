This lab turns the week into a working system. You will secure the shared broker, give every student a login limited to their own subtree, and then make your Pico a good citizen of the room: it publishes structured telemetry, reports its own availability, and obeys a setting broadcast by the instructor.

The Network You Are Building

The Lab 5 network. Each Pico owns one subtree and may only write inside it; a dashboard on the Pi watches everything; one retained topic broadcasts a setting to every Pico.

Part 1. Secure the Broker

Work in pairs on the Pi. Replace the open configuration with a password file and an ACL like the one in the broker lesson. Add one user per student (named pico01, pico02, and so on), a dashboard user and an instructor user.

/etc/mosquitto/acl Config
pattern readwrite lab/%u/# pattern read lab/class/config/# user dashboard topic read lab/# user instructor topic readwrite lab/#
The access rules for Lab 5 as a table. The pattern lines use %u so one rule gives every student write access to their own subtree and nothing else.

Part 2. Your Pico

Your program must, in one non-blocking loop (Unit 1): connect with its own username and password; keep alive with pings; publish a JSON telemetry packet with a sequence number every interval to lab/<id>/tele/light; publish online retained to lab/<id>/stat/online after connecting; and subscribe to the retained lab/class/config/interval, adopting a valid new value immediately.

main.py (outline) MicroPython
ID = "pico01" # your assigned id: also your username interval_ms = 1000 seq = 0 def on_message(topic, msg): global interval_ms if topic == b"lab/class/config/interval": try: v = int(msg) except ValueError: return if 100 <= v <= 60000: interval_ms = v client = MQTTClient(ID, BROKER_IP, user=ID, password=PASSWORD, keepalive=30) client.set_callback(on_message) client.connect() client.subscribe(b"lab/class/config/interval") client.publish(("lab/%s/stat/online" % ID).encode(), b"online", retain=True) last = ticks_ms() while True: client.check_msg() if ticks_diff(ticks_ms(), last) >= interval_ms: seq += 1 payload = json.dumps({"seq": seq, "value": filtered_read()}).encode() client.publish(("lab/%s/tele/light" % ID).encode(), payload) last = ticks_ms()

Warm Up

Exercise 1: Trace a Denial

The Pico sees nothing: publish() returns normally. The broker drops the message because pico01 has no write permission outside lab/pico01/#. The denial is recorded in the broker log (journalctl -u mosquitto); a subscriber on lab/pico02/# will also never see the message.

Exercise 2: Why Retained?

Only Picos connected at that instant would hear it; any Pico that booted or reconnected later would keep its default forever. A retained message waits on the broker and is delivered to every new subscriber the moment it subscribes.

Intermediate

Exercise 3: Report Online and Offline
main.py MicroPython
def shutdown(): client.publish(("lab/%s/stat/online" % ID).encode(), b"offline", retain=True) client.disconnect()

A deliberate disconnect does not trigger the broker’s last-will message (next week), so the device has to say goodbye itself. Next week’s last will covers the case where it cannot.

Advanced

Exercise 4: Check for Gaps
dashboard.py MicroPython
last_seq = {} def on_message(topic, msg): device = topic.decode().split("/")[1] seq = json.loads(msg)["seq"] prev = last_seq.get(device) if prev is not None and seq != prev + 1: print(device, "missed", seq - prev - 1, "readings") last_seq[device] = seq

A dictionary keyed by device gives each Pico its own count, which is only possible because the device id sits at a fixed level of the topic.
