This lesson covers computing facts from a stream of samples. You summarise a window with a mean, spread, range and slope, keep statistics with no buffer using Welford’s method, and detect unusual readings with a rolling z-score whose threshold you choose from measured false-alarm rates.

SAM lens. Features are a Perceptor stage that turns many samples into a few meaningful numbers; Welford's running statistics and the rolling z-score are Memory of what normal looks like.

A sensor produces numbers; a decision needs facts about those numbers: is it steady, is it rising, is this reading unusual? Facts like these are called features, and computing them on the node, from a short memory of recent samples, is what separates a robot that streams raw data from one that understands it. This lesson builds three tools that fit in a few lines and a few bytes: a window that summarises the last N samples, a running mean and variance that need almost no memory, and a rolling anomaly test that learns what “normal” looks like and flags what is not.

Part 1. Features of a Window

A window is the most recent N samples. Over it you can compute a mean (the level), a standard deviation (the noise or activity), a minimum and a maximum (the range), and a slope (the trend). Five numbers, perhaps 40 bytes in a message, can replace a hundred raw samples.

window.py MicroPython
# window.py -- features of the last N samples, in a fixed-size ring class Window: def __init__(self, n): self.n = n self.buf = [0.0] * n self.i = 0 self.count = 0 def add(self, x): self.buf[self.i] = x self.i = (self.i + 1) % self.n if self.count < self.n: self.count += 1 def values(self): # oldest first if self.count < self.n: return self.buf[:self.count] return self.buf[self.i:] + self.buf[:self.i] def features(self): v = self.values() k = len(v) if k < 2: return None mean = sum(v) / k var = sum((x - mean) ** 2 for x in v) / (k - 1) return {"mean": mean, "std": var ** 0.5, "min": min(v), "max": max(v), "slope": (v[-1] - v[0]) / (k - 1)} # change per sample, end to end
The window after seven samples, with a size of five. The values and features come from running Window on the numbers 1 to 7.

Choose N for the time you want to look back over, not for tidiness: at 20 Hz, N = 20 is one second. A short window reacts quickly and is noisy; a long window is steady and slow. That is the same trade-off as the filter lesson’s α, now seen from the other side.

Part 2. Statistics Without Memory

A window needs N numbers of RAM. Sometimes you want the statistics of everything so far, over hours, with no buffer. The standard-looking formula, variance = mean of squares minus square of mean, needs only two running sums, and fails exactly when you need it: on a microcontroller with 32-bit floats, adding squares of numbers near 1,000 loses the small differences. Welford’s algorithm updates the mean and a running sum of squared deviations instead, and stays accurate.

running.py MicroPython
# running.py -- mean and variance of a stream with three numbers of memory class Running: def __init__(self): self.n = 0 self.mean = 0.0 self.m2 = 0.0 def add(self, x): self.n += 1 d = x - self.mean self.mean += d / self.n self.m2 += d * (x - self.mean) def std(self): return (self.m2 / (self.n - 1)) ** 0.5 if self.n > 1 else 0.0
The same data, three computations. The naive formula subtracts two huge, nearly equal numbers and the result is negative: its square root is not a number. The cost of Welford is three variables.

This is an instance of a rule worth remembering: subtract the typical value first, then work with the small differences. It is also why you should remove an offset (such as the IMU’s calibration bias) before you compute a feature, not after.

Part 3. What Is Unusual?

An alarm with a fixed threshold (“range below 20 cm”) is simple and often right. It is wrong when the normal level changes: a slow drift, a different surface, another room. A rolling z-score asks a better question: is this reading unusual compared with the recent past? It keeps a running mean and variance with an exponential weight (the EMA again, and its cousin for variance), and flags a reading more than k standard deviations from the mean.

anomaly.py MicroPython
# anomaly.py -- is this reading unusual compared with the recent past? class Anomaly: def __init__(self, alpha=0.05, k=4.0, warmup=30, floor=0.05): self.alpha, self.k, self.warmup, self.floor = alpha, k, warmup, floor self.mean = None self.var = 0.0 self.n = 0 def update(self, x): """Returns True if x is more than k deviations from the running mean.""" self.n += 1 if self.mean is None: self.mean = x return False d = x - self.mean sd = max(self.var ** 0.5, self.floor) odd = self.n > self.warmup and abs(d) > self.k * sd if not odd: # do not let a spike teach us that spikes are normal self.mean += self.alpha * d self.var = (1 - self.alpha) * (self.var + self.alpha * d * d) return odd
The rolling z-score (k = 4) on a simulated signal. It finds both spikes and follows the drift without complaint, while a fixed threshold at 21 would fire on 205 samples once the drift carried the signal over it. (Across eleven runs with different random noise, nine were as clean as this one and two raised a single extra alarm.)

The one line that matters is the if not odd: a reading flagged as unusual is not allowed to update the mean and variance. Without it, a burst of faults raises the variance, and the detector learns that faults are normal. Choosing k is a trade between missing real events and raising false alarms. On 100,000 samples of pure noise the test with k = 4 raised 18 false alarms (0.02 %); with k = 3 it raised 695 (0.7 %). At 20 samples a second, k = 3 would cry wolf every seven seconds.

The cost of sensitivity, measured on noise only. A bigger k trades missed small events for a much quieter detector.
  • Warm-up. The first samples give no estimate of the spread. The class waits warmup samples, and has a floor so that a perfectly steady signal (variance 0) does not flag every rounding step.
  • Features of a feature. Anomalies are events: publish them to evt/… (rare, with the value and the time), not to tele. The hub’s log of events then answers “when was the signal odd?”.
  • Learn on the robot, check on the bench. Replay a recorded signal through the detector offline (the TinyML training lesson shows how to record one) and choose k from data, not from hope.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Window Arithmetic

After five samples a window of four holds 12, 11, 15, 14 (the 10 was overwritten). Mean = 52 / 4 = 13. The slope is (14 − 12) / (4 − 1) = +0.67 per sample. Note the slope is end to end and so is sensitive to the two end samples: a more robust trend is a least-squares line, at the price of more code.

Exercise 2: Choose N

N = 25 × 0.4 = 10. In 0.4 s the robot moves 0.2 × 0.4 = 0.08 m. An average over a window lags the signal by about half the window (0.2 s), so the feature describes where the robot was 4 cm ago. Fine for a gentle trend, but not for collision avoidance, which should use the latest sample.

Intermediate

Exercise 3: Why Not Update?

If flagged readings update the statistics, the mean slides toward the fault and the variance grows, so after a few readings the deviation test is no longer exceeded: the detector reports the first few faults and then calls the fault normal. The drawback of not updating is the opposite: if the signal makes a real, permanent step to a new level, every later reading is flagged forever. A practical fix is to let the statistics adapt if the alarm has been on for a long time (say 5 seconds), and publish that as a different event.

Advanced

Exercise 4: Trend Alarm
rising.py MicroPython
def rising(w, limit): if w.count < w.n: return False # not enough history yet return w.features()["slope"] > limit # 1 degree per minute = 1/60 = 0.0167 per sample at 1 Hz. # N = 30 (half a minute) smooths the noise; limit = 0.0167.

A window of 30 s at 1 Hz covers half a minute, over which the temperature would need to rise 0.5 degrees to alarm. Note the end-to-end slope is noisy: with a sensor noise of 0.3 degrees the end samples alone can fake a slope of 0.02 per sample. Average the first and last five samples, or fit a line, before trusting a slow trend.

Paper Practice: Answers

Recall

P1. Five Features

Mean (level), standard deviation (noise or activity), minimum and maximum (range), slope (trend).

P2. Welford

The naive formula subtracts two huge, nearly equal numbers; with 32-bit floats the small difference is lost and the result can even be negative. Welford updates the mean and a running sum of squared deviations, which stays accurate.

P3. Don't Learn Faults

Otherwise a burst of faults would raise the variance, and the detector would learn that faults are normal and stop flagging them.

P4. Events, Not Telemetry

To evt/... topics: they are rare events with a value and a time, and the hub's event log then answers "when was the signal odd?".

Apply

P5. Window Trace

Values 3 to 7. Mean 5; deviations −2, −1, 0, 1, 2, squares sum to 10, divided by 4 gives 2.5, so sd ≈ 1.58; min 3; max 7; slope (7 − 3) / 4 = 1.0.

P6. Welford by Hand

After 2: n 1, mean 2, M2 0. After 4: n 2, mean 3, M2 = 0 + (4 − 2)(4 − 3) = 2. After 6: n 3, mean 4, M2 = 2 + (6 − 3)(6 − 4) = 8. Sample variance 8 / 2 = 4, sd 2.

P7. z-Score

Flag if |x − 20| > 2.0: 21.5 no (1.5); 22.3 yes (2.3); 18.1 no (1.9).

P8. False Alarm Rate

k = 3: 0.007 × 20 = 0.14 per second, one every 7 s. k = 4: 0.0002 × 20 = 0.004 per second, one every 250 s (about 4 minutes).

Analyze and Design

P9. Window Length

N = 10 looks back 0.5 s: reacts quickly, noisier features. N = 100 looks back 5 s: steady but slow to notice a start or stop. Choose from the time scale you care about.

P10. Fixed Threshold or z-Score

A fixed threshold when the limit is physical and the normal level does not move (range below 20 cm means danger). A rolling z-score when the normal level drifts (temperature over a day, a different surface) and you want readings unusual relative to the recent past.

P11. Offset First

Subtracting the typical value first keeps the numbers small, which avoids the precision loss of working with large, nearly equal values; and features such as the mean of absolute values or energy are not linear, so removing the bias afterwards does not give the same result.

P12. Choose k

Once an hour at 20 Hz is a rate of about 1.4 × 10⁻⁵ per sample. k = 4 gave 2 × 10⁻⁴, about one false alarm every 4 minutes: not enough. Increase k (5 or more) and verify by replaying a long recording of normal operation through the detector and counting alarms.
