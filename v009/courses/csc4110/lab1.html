This lab starts the robot you will keep all term. You build a robot base (a breadboard with fixed zones for sensing and acting), wire its first Perceptor (two buttons, one acting as a bumper) and its first Actuator (two status LEDs), and program it as a Situated Agent: a Perceptor, a Memory, a Decider and an Actuator in separate classes, run by a loop that never sleeps. The device is small. The structure is the one every later lab adds to.

What You Will Build

A sentry: the simplest autonomous robot there is. Button A is the operator's arm/disarm switch. Button B is a bumper: on a real robot it would be a lever switch on the front edge that closes when the robot touches something. When the sentry is armed and the bumper is hit, it raises an alarm. If nobody resets the alarm within ten seconds, the sentry re-arms itself. That last rule is the reason the robot needs a Memory: to give up on an alarm it has to remember when the alarm started.

Step 2. Wiring

Lab 1 connections as a list of loops. Each LED has its own resistor between the pin and the LED, and its other leg goes to ground. Each button connects its pin to ground when pressed and uses the Pico’s internal pull-up (no external resistor). Put the buttons in the Perceptor zone and the LEDs in the Actuator zone, with B (the bumper) on the front edge of the board.

Build it in two halves and test each: first the Actuator (use led.on() in the REPL), then the Perceptor (print button.value() while pressing). Do not write the full program until both halves work. If you have a lever microswitch, use it for B and tape it to the front edge of the base so its lever sticks out: it is now a real bumper.

Step 3. Design the Agent Before You Code It

Before writing code, fill in the four units on paper. This is the habit for every lab this term: if you cannot say what each unit does, the program will blur them together.

The sentry as a SAM agent. The Perceptor hides the buttons and the debouncing: all it reports is which event happened this tick. Memory holds the state, the time the state was entered and an alarm count. The Decider is the state table plus one timed rule. The Actuator turns a state name into a blink pattern.

Step 4. The Decider: a State Machine

The sentry's states. The black arrows are driven by percepts (button events). The gold arrow is different: no button causes it. It fires because Memory says the robot has been in ALARM for ten seconds. A Decider that only looks at the current percept could never make that transition.

Here is the whole program, one class per SAM unit. Read it once from top to bottom, then once more from the loop at the bottom, following one button press through the four units.

sentry.py MicroPython
from machine import Pin from time import ticks_ms, ticks_diff from button import Button # the debounced Button class from the Circuits lesson # ---------------- PERCEPTOR: buttons in, events out ---------------- class Perceptor: def __init__(self, arm_pin=6, bump_pin=7): self.arm = Button(arm_pin) # A: operator's arm / reset switch self.bump = Button(bump_pin) # B: the bumper def sense(self): ea, eb = self.arm.pressed(), self.bump.pressed() # poll BOTH every tick return 'A' if ea else ('B' if eb else None) # ---------------- MEMORY: what the robot knows over time ---------------- class Memory: def __init__(self, now): self.state = 'IDLE' self.entered_ms = now # when we entered the current state self.alarms = 0 # how many alarms since power-up # ---------------- DECIDER: percept + memory -> new state ---------------- TABLE = { ('IDLE', 'A'): 'ARMED', ('ARMED', 'A'): 'IDLE', ('ARMED', 'B'): 'ALARM', ('ALARM', 'A'): 'IDLE', } ALARM_TIMEOUT_MS = 10_000 def next_state(state, event): return TABLE.get((state, event), state) # unknown pairs: stay where you are class Decider: def decide(self, event, memory, now): new = memory.state if event: new = next_state(memory.state, event) elif memory.state == 'ALARM' and ticks_diff(now, memory.entered_ms) >= ALARM_TIMEOUT_MS: new = 'ARMED' # nobody came: give up and re-arm if new != memory.state: # update Memory on every change if new == 'ALARM': memory.alarms += 1 memory.state, memory.entered_ms = new, now return memory.state # ---------------- ACTUATOR: state -> light ---------------- def leds_for(state, now_ms): """Return (red, green) for this state at this moment. No sleeping, just arithmetic.""" if state == 'IDLE': return (0, (now_ms // 500) % 2) # green: 500 ms on, 500 ms off (1 Hz) if state == 'ARMED': return (0, 1) return ((now_ms // 125) % 2, 0) # ALARM: red toggles every 125 ms (4 Hz) class Actuator: def __init__(self, red_pin=8, green_pin=9): self.red, self.green = Pin(red_pin, Pin.OUT), Pin(green_pin, Pin.OUT) def act(self, state, now): r, g = leds_for(state, now) self.red.value(r) self.green.value(g) def off(self): self.red.off(); self.green.off() # ---------------- THE AGENT LOOP ---------------- perceptor, decider, actuator = Perceptor(), Decider(), Actuator() memory = Memory(ticks_ms()) try: while True: now = ticks_ms() event = perceptor.sense() # observe before = memory.state state = decider.decide(event, memory, now) # decide actuator.act(state, now) # act if state != before: # one log line per change print(now, before, '->', state, 'alarms:', memory.alarms) finally: actuator.off() # whatever happens, leave outputs off

Save button.py (from the Circuits lesson) on the Pico next to this file. The loop never sleeps: each pass senses, decides and acts, thousands of times a second. The blinking comes from arithmetic on the clock inside the Actuator, not from sleep_ms, so the Perceptor is never blind to a press. Notice how the Decider and the Actuator split the work: the Decider chooses what to show (a state name), and the Actuator chooses how to show it on this particular body. Give the robot a buzzer instead of LEDs and only the Actuator changes.

The loop in time. Because nothing in a tick waits, every unit runs hundreds of times per second. This is the cooperative pattern the whole course builds on: later you will add sensor sampling, a display and the network as more short steps inside the same tick.

The Lab 1 tests. Test 6 checks the Memory: the only thing that can end an alarm without a button is the remembered entry time. Warm Up

Exercise 1: Trace It

A: ARMED. B: ALARM. A: IDLE. B: IDLE (ignored). A: ARMED. B: ALARM. Memory counts 2 alarms (the first and the last B). The fourth event is ignored because B only matters in ARMED.

Exercise 2: Read the Pattern

IDLE: green is (now // 500) % 2, which gives 0, 0, 1 at 0, 400 and 600 ms, and red is always 0. ALARM: red is (now // 125) % 2, which gives 0, 1, 0 (0 // 125 = 0, 400 // 125 = 3, 600 // 125 = 4), and green is always 0. So IDLE gives (0,0), (0,0), (0,1) and ALARM gives (0,0), (1,0), (0,0), as (red, green) pairs.

Intermediate

Exercise 3: Test the Decider Without Hardware

Copy Memory, TABLE, next_state and Decider into a laptop file (they import nothing from machine). On a laptop, ticks_diff(a, b) is just a - b.

The Decider can be tested at any simulated time because it takes now as an argument instead of reading the clock itself. Passing time in is a small habit that makes every time-based rule in the course testable.

Advanced

Exercise 4: Long Press Resets

It belongs to the Perceptor: a long press is a pattern in the button signal, just as a debounced press is. The Perceptor reports a new event, say 'HOLD_A', and the Decider gains one rule: HOLD_A in any state goes to IDLE. The Decider never learns how long a second is.

longpress.py MicroPython
class LongPress: def __init__(self, hold_ms=1000): self.hold_ms = hold_ms self.down_at = None self.fired = False def update(self, is_down, now_ms): if not is_down: self.down_at, self.fired = None, False return False if self.down_at is None: self.down_at = now_ms if not self.fired and now_ms - self.down_at >= self.hold_ms: self.fired = True return True # true exactly once per long press return False
test_longpress.py MicroPython
lp = LongPress() events = [] for t in range(0, 3000, 100): held = 200 <= t < 2500 # held from 200 ms to 2.5 s if lp.update(held, t): events.append(t) print(events) # [1200]: once, a second after pressing
