This week's lab puts Thonny, GPIO output, and GPIO input together into one small device: a button that doesn't just turn an LED on and off, but counts, keeping state across presses the way a real embedded device almost always has to.

What You're Building

A single pushbutton cycles one LED through a repeating pattern: off → on → blinking → off → on → blinking →…, advancing one step every time the button is pressed. The twist that makes this a real lab and not just wiring: the board has to remember which of the three states it's in between presses, and it has to tell a clean, debounced press apart from the messy electrical reality of a human finger on a mechanical switch.

Three states, one button, one direction of travel. The circuit has no way to "ask" which state it's in except by remembering, in a variable, what the last press changed it to.

The Debounce Problem

A mechanical button doesn't transition cleanly from "not touching" to "touching", the contacts physically bounce for a few milliseconds, which a microcontroller is easily fast enough to see as several rapid presses instead of one. Poll the button too naively and one human press might advance your state machine two or three steps instead of one.

Switch bounce. The metal contacts inside a button physically rebound for a few milliseconds, which a fast microcontroller sees as several presses in a row. Waiting out a short debounce delay (about 30 ms here) and then reading once treats the whole burst as one press.
main.py MicroPython
from machine import Pin from time import sleep, sleep_ms led = Pin(15, Pin.OUT) button = Pin(14, Pin.IN, Pin.PULL_UP) state = 0 # 0 = off, 1 = on, 2 = blinking def wait_for_press(): # Block here until the button goes from "not pressed" (1) # to "pressed" (0), with a debounce delay after it does. while button.value() == 1: pass sleep_ms(30) # let the contacts settle while button.value() == 0: pass # wait for release too, so one press # can't be read as several sleep_ms(30) while True: if state == 0: led.value(0) elif state == 1: led.value(1) elif state == 2: led.toggle() sleep(0.3) # Only check for a press between blinks when state == 2, # otherwise this loop would just sit on wait_for_press() # forever and never blink. if state != 2: wait_for_press() state = (state + 1) % 3 elif button.value() == 0: sleep_ms(30) state = (state + 1) % 3 while button.value() == 0: pass

Read through wait_for_press() carefully before running anything: it doesn't just check if button.value() == 0, it blocks until the value changes, then waits for release too. A version that only checked the value once per loop iteration would see a single human press as however many loop iterations happened to occur while the button was down, this is next week's "sampling" idea showing up early, in a button instead of a sensor.

Procedure

  1. Build and test the LED and button circuits independently first (reuse last lesson's checks) before combining them.
  2. Type the script above into Thonny, save it to the Pico as main.py, and run it.
  3. Press the button repeatedly and confirm the LED visibly cycles off → on → blinking → off in order, advancing exactly one step per press, no skipped or repeated states.
  4. Remove the two sleep_ms(30) debounce lines (both of them) and re-run. Press the button at a normal, un-careful pace several times and record what you observe, does it still advance reliably one step per press?
  5. Put the debounce delays back and confirm reliable behavior returns.

Solutions

Give each exercise an honest try before opening its solution.

Warm Up

Exercise 1: Trace the State Machine

Three presses return to OFF (OFF → ON → BLINK → OFF). Seven presses is 7 mod 3 = 1, so you finish in ON. The line (state + 1) % 3 is what makes the sequence wrap.

Exercise 2: How Long Should the Debounce Be?

30 ms is comfortably more than 15 ms, so it is enough. For an 80 ms switch it is not: the pin could still be changing when you read it, so you would raise the delay above 80 ms. A very long delay makes the device feel sluggish and can swallow genuinely fast double-presses, so choose the smallest delay that is reliably longer than the bounce.

Intermediate

Exercise 3: Add a Fast-Blink State
main.py (changes only) MicroPython
# 1. cycle through four states state = (state + 1) % 4 # 2. in the main loop, add a branch for the new state elif state == 3: led.toggle() sleep(0.1) # 3. the "only check for a press between blinks" test must now # treat state 3 like state 2: if state not in (2, 3): wait_for_press() state = (state + 1) % 4 elif button.value() == 0: ...

Three edits: the modulus, one new branch, and widening the "is this a blinking state?" test. Missing the third edit is the classic bug: the program would sit in wait_for_press() and never blink in state 3.

Advanced

Exercise 4: Long Press Resets
main.py (changes only) MicroPython
from time import ticks_ms, ticks_diff def wait_for_press(): while button.value() == 1: pass sleep_ms(30) t0 = ticks_ms() while button.value() == 0: pass sleep_ms(30) return ticks_diff(ticks_ms(), t0) # how long it was held, in ms # in the main loop (the non-blinking branch): held = wait_for_press() state = 0 if held > 1000 else (state + 1) % 3

The function now returns the hold time; the caller decides what to do with it. ticks_diff is used rather than plain subtraction for the wraparound reason from the non-blocking lessons.
