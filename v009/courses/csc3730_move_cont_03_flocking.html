Flocking is what happens when you give a group of agents nothing but local, short-sighted rules about their nearest neighbors (no leader, no shared plan) and let the group-level motion emerge on its own. Steering so far has been one desired heading at a time: seek this, avoid that. A boid wants several things simultaneously (don't crowd your neighbors, match their heading, stay near the group), and that's a genuinely different problem: how do you combine multiple desires into one heading? This lesson reintroduces the idea of a steering force specifically to answer that, and then builds flocking on top of it.

Part 1. The Idea

Craig Reynolds' original 1986 "boids" model comes down to three rules, each agent applying them only to whatever neighbors are nearby:

  • Separation: steer away from neighbors that are too close, so the flock doesn't collapse into a pile.
  • Alignment: steer to match the average heading of nearby neighbors, so the flock tends to move together.
  • Cohesion: steer toward the average position of nearby neighbors, so the flock stays a flock instead of drifting apart.

None of these rules mentions "the flock" as a thing; each boid only ever looks at whoever is close to it. The flocking shape is a side effect, not something anyone's steering toward directly. That's the part worth sitting with; it's the same idea behind a lot of the swarm-intelligence topics later this unit. Notice, too, that a boid needs all three of these at once, every frame, not one at a time the way Seek or Avoid did.

A loose cluster: near-parallel headings, close but not overlapping.

Part 2. From Heading to Force

So far, each behavior directly returned one desired heading and one desired speed. That works cleanly when there's exactly one thing to react to at a time. A boid has to weigh three influences against each other and land on a single heading, and averaging three angles together doesn't work well: angle averaging is awkward at the wraparound point, and a plain average throws away how strongly each influence should count. A neighbor about to collide with you should matter more than a distant one gently pulling the flock together.

Force handles this cleanly, because forces are vectors, and vectors add. Sum as many of them as you want into one net force, and only then convert that combined vector into the single heading the agent actually turns toward, using the same Vector2.UP.angle_to() and angle_difference() pattern from steering:

(illustrative) GDScript
var steering: Vector2 = desired_force_1 + desired_force_2 + desired_force_3 if steering.length() > 0.0: var desired_angle: float = Vector2.UP.angle_to(steering) var diff: float = angle_difference(rotation, desired_angle) rotation += clamp(diff, -turn_rate * delta, turn_rate * delta)

A neighbor pushing hard on Separation naturally dominates that sum more than a weak, distant pull from Cohesion, without needing any special-case logic to make that happen.

Part 3. Finding Neighbors

Every rule needs a list of "nearby boids" to work with. The simplest approach: put every boid in a group called "boids", then ask the scene tree for everyone in it and filter by distance.

boid.gd GDScript
extends Node2D @export var speed_max: float = 140.0 @export var turn_rate: float = PI @export var neighbor_radius: float = 90.0 var velocity: Vector2 = Vector2.ZERO func _ready(): rotation = randf() * TAU add_to_group("boids") func _get_agent_forward() -> Vector2: return -transform.y func _move_forward(delta_passed: float, move_speed: float) -> void: global_position += delta_passed * move_speed * _get_agent_forward() func get_neighbors() -> Array: var neighbors: Array = [] for other in get_tree().get_nodes_in_group("boids"): if other == self: continue if global_position.distance_to(other.global_position) < neighbor_radius: neighbors.append(other) return neighbors

_get_agent_forward() and _move_forward() are the exact same two methods from the agent scripts; a boid is still just a rotation-plus-forward-speed agent underneath. Give each boid a different modulate color on its Sprite2D, the same idea as AgentA and AgentB, so a flock on screen reads as a group of distinct individuals rather than one shape stamped over and over.

Worth flagging early: checking every boid against every other boid like this is O(n²), fine for the flock sizes you'll use in class (a few dozen), but the same cost problem you may have run into with the background particle life on the homepage. If you ever push this toward hundreds of boids, that's the first thing to optimize (e.g. a spatial grid, so you only check boids that are already nearby).

Part 4. Separation

For each neighbor inside a (smaller) separation radius, steer away from it, weighted so closer neighbors push harder:

boid.gd GDScript
@export var separation_radius: float = 40.0 func separation(neighbors: Array) -> Vector2: var push: Vector2 = Vector2.ZERO for other in neighbors: var offset: Vector2 = global_position - other.global_position var dist: float = offset.length() if dist > 0.0 and dist < separation_radius: push += offset.normalized() / dist # closer = stronger return push

Part 5. Alignment

Steer toward the average velocity of your neighbors, i.e. the direction most of the flock around you is already heading:

boid.gd GDScript
func alignment(neighbors: Array) -> Vector2: if neighbors.is_empty(): return Vector2.ZERO var avg_velocity: Vector2 = Vector2.ZERO for other in neighbors: avg_velocity += other.velocity avg_velocity /= neighbors.size() return avg_velocity - velocity # steer toward that average

Every boid moves at the same constant speed_max (only heading varies this lesson), so in practice this rule mostly ends up comparing headings, but it's written the general way so it still works if you ever let speed vary per boid too.

Part 6. Cohesion

Steer toward the average position of your neighbors; this is a Seek, using the neighborhood's center of mass as the target instead of a fixed node:

boid.gd GDScript
func cohesion(neighbors: Array) -> Vector2: if neighbors.is_empty(): return Vector2.ZERO var center: Vector2 = Vector2.ZERO for other in neighbors: center += other.global_position center /= neighbors.size() return (center - global_position).normalized() * speed_max - velocity

Notice the shape: Cohesion is just the Seek force from Part 2, aimed at a computed point instead of a node reference. Alignment and Separation both follow the same "desired thing minus current velocity" logic underneath, too: three rules, one recurring pattern.

Part 7. Combining the Rules

Sum the three forces with weights (exported, so you can tune the flock's personality live in the Inspector), then convert the sum into a heading exactly the way Part 2 previewed, and move forward with the same _move_forward every agent script has been using all along.

boid.gd GDScript
@export var weight_separation: float = 1.6 @export var weight_alignment: float = 1.0 @export var weight_cohesion: float = 1.0 func _process(delta: float) -> void: var neighbors: Array = get_neighbors() var steering: Vector2 = Vector2.ZERO steering += separation(neighbors) * weight_separation steering += alignment(neighbors) * weight_alignment steering += cohesion(neighbors) * weight_cohesion if steering.length() > 0.0: var desired_angle: float = Vector2.UP.angle_to(steering) var diff: float = angle_difference(rotation, desired_angle) rotation += clamp(diff, -turn_rate * delta, turn_rate * delta) _move_forward(delta, speed_max) velocity = _get_agent_forward() * speed_max

Instance 20-30 of this scene into a parent node and press Play. You should see loose clumps form, drift, and reshape themselves, with no single boid, and no code anywhere, that's actually in charge of "the flock."

Part 8. Tuning

This is the part that's genuinely more art than algorithm, and it's worth spending real time on:

  • Separation weight too low (or radius too small): the flock collapses into a single overlapping clump.
  • Separation weight too high: boids fly apart and barely look like a group at all.
  • Alignment dominating: a flock that all snaps to face the same way too rigidly, losing the organic drift.
  • Cohesion with a very large neighbor_radius: everything gets pulled toward one global center, which stops looking like local flocking and starts looking like one big Seek.
  • turn_rate too low: boids can't turn fast enough to actually respond to their neighbors, and the flock looks sluggish or unravels entirely.

Because every weight above is @exported, none of this requires touching code to experiment with: select a boid in the running scene's remote tree, or just tweak the values before pressing Play, and watch how the group-level behavior shifts.
