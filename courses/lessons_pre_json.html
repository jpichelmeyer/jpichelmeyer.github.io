Definition?

Two distinct, but important perspectives.

Definition (Knuth): An alorithm is a set of rules satisfying the following properties:
  1. Input
  2. Output
  3. Finiteness
  4. Definiteness
  5. Effectiveness
Definition (Turing): Any process that can be executed by a Turing machine.

But, intuitively...

Definition (NIH):An algorithm is a set of instructions that is designed to accomplish a task.

Definition?

Definition (Collective intuition): An algorithm is a set of instructions that is designed to accomplish a task.

This is not very formal (and so hard to do much with), so people have tried to take more formal and mathematical approaches. Among them, there have been three notable perspectives:
  • Lambda Calculus (Alonzo Church). An algorithm is a series of applications of mathematical functions and transformations.
  • Recursive Functions (Kurt Godel, Stephen Kleene). An algorithm is a set of simple mathematical functions that can be built into increasingly complex functions through repetition.
  • Turing Machines (Alan Turing). An algorithm is a set of rules for a hypothetical machine that reads and writes symbols on an infinite tape.
We will look at how a Turing Machine works later in this unit.

Pseudocode: Examples

Here is the same task (addition of two numbers), but approached in three very different ways.
Version: Accumulation 
Input: a,b\n
Output: sum of a and b\n
\n
ADD(a,b)\n
1  sum <-- 0\n
2  sum <-- sum + a>\n
3  sum <-- sum + b>\n
4  RETURN sum

Version: Iteration 
Input: a,b\n
Output: sum of a and b\n
\n
ADD(a,b)\n
1  sum <-- a\n
2  REPEAT b times\n
3      sum <-- sum + 1\n
4  END REPEAT\n
5  RETURN sum
Version: Recursion 
Input: a,b\n
Output: sum of a and b\n
\n
ADD(a,b)\n
1  IF b == 0 THEN\n
2      RETURN a\n
3  END IF\n
4  RETURN Add(a+1, b-1)

Tedium

Try carrying out the steps of the algorithm below very carefully and methodically. 
Input: sequence A = {a1, a2, ..., aN} of integers
Output: a reordering B = {b1, b2, ..., bN} of a1, a2, ..., aN such that bi <= bj whenever i<= j 
\n
InsertionSort(A)\n
1  FOR j from 2 to n\n
2      key <-- A[j]\n
3      i <-- j-1\n
4      WHILE i > 0 and A[i] > key\n
5          A[i+1] <-- A[i]\n
6          i <--i-1\n
7      END WHILE\n
8      A[i+1] <-- key\n
9  END FOR\n
10 RETURN A
As we start to formalize algorithms, carrying them out becomes quite tedious. If only we had a happy little helper who would gladly punch away at these highly precise, yet highly monotonous microtasks. If only...
But first we should maybe ask outselves whether having such a helper would even be useful. In particular, could we even reasonably guarantee that it would be competent? That is, that it would be able to solve any algorithm that we threw at it? To that, we be tur-n-ing to the Turing machine.
